# 走查报告模板

输出报告严格按此结构。存为 `设计走查报告-YYYYMMDD.md`，截图存于同目录 `screenshots/` 文件夹并用相对路径引用。

```markdown
# {产品名} 设计走查报告

- 走查日期：YYYY-MM-DD
- 走查方式：{本地运行实际走查 / 线上 URL / 静态截图审查（降级模式需声明限制）}
- 检查标尺：{用户设计规范（文件路径）+ 内建框架 / 仅内建框架}
- 视口覆盖：{桌面 1440 / 平板 768 / 手机 375，按实际勾选}

| XX 弹窗 | ❌ 未查 | 入口无法触发，原因：… |

（全部页面/状态列出，未覆盖必须给原因）
```

## 填写要求

- 每条问题的「现象」只写可观察事实（"主按钮与次按钮同为蓝色填充，大小相同"），评价放「违反标尺」处（"层级维度：主操作无法识别"）。
- 全局性问题（跨页同根因）在标题注明【全局】，位置处列出全部出现页面。
- 问题数按实际，不凑数也不删减；0 个 P0 就如实写 0。
- 「整体评价」必须写——用户要的不只是清单，还有设计师的判断。
