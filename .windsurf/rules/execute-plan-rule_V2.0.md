# 方案执行登记与防偏机制

当你开始执行任何已经确认的方案、实施方案或执行计划时，必须遵守以下规则。

## 1. 触发条件

当用户明确要求你开始执行、实施、落地、按计划推进某个方案时，本规则自动生效。

仅进行讨论、分析、制定方案、优化方案、评审方案时，不触发本规则。

## 2. 执行前确认

在正式执行前，你必须先向用户说明你已理解本次执行要求，并等待用户确认。

在用户确认前，不得开始任何实际执行动作，包括但不限于：

* 修改文件
* 新建文件
* 删除文件
* 执行脚本
* 修改配置
* 提交代码
* 调整目录结构
* 写入正式文档内容

你需要向用户确认的内容至少包括：

```md
我理解本次执行要求：

1. 开始执行前，我会先新建执行登记文档。
2. 我会按照执行计划分步骤推进。
3. 每完成一个步骤，我都会更新执行登记文档，记录当前进展和下一步。
4. 每完成 5 个步骤，我会对照实施方案、执行计划和执行登记文档进行一次回顾，检查是否跑偏，并将回顾结果写入执行登记文档。
5. 如果发现计划不清晰、执行偏离、上下文冲突或需要用户决策，我会暂停执行并向你确认。

请确认是否开始执行。
```

只有在用户明确确认后，才能进入正式执行。

## 3. 创建执行登记文档

正式执行开始后，你必须先创建一个执行登记文档。

文档命名格式为：

```md
[任务名称]执行登记.md
```

例如：

```md
登录功能重构执行登记.md
产品周期管理系统初始化执行登记.md
```

如果当前目录中存在 `执行登记-模板.md`，则必须优先参照该模板创建执行登记文档。

如果没有找到模板，则使用以下基础结构创建：

```md
# [任务名称]执行登记

## 1. 执行对象

- 实施方案：
- 执行计划：
- 执行目标：

## 2. 执行状态

- 当前状态：
- 当前步骤：
- 已完成步骤数：
- 最近更新时间：

## 3. 步骤执行记录

### 步骤 1：[步骤名称]

- 执行内容：
- 执行结果：
- 当前进展：
- 下一步：
- 是否存在问题：
- 记录时间：

## 4. 周期回顾记录

### 第 1 次回顾：完成第 5 个步骤后

- 已完成步骤范围：
- 对照实施方案：
- 对照执行计划：
- 对照执行登记文档：
- 是否存在偏离：
- 偏离说明：
- 修正动作：
- 下一阶段执行重点：
- 记录时间：

## 5. 问题与决策记录

| 时间 | 问题/风险 | 影响 | 处理方式 | 是否需要用户确认 |
|---|---|---|---|---|

## 6. 最终执行总结

- 最终完成情况：
- 未完成事项：
- 遗留问题：
- 后续建议：
```

## 4. 分步骤执行规则

执行必须严格按照执行计划分步骤推进。

每完成一个步骤后，必须立即更新执行登记文档，记录：

* 本步骤做了什么
* 本步骤完成到了什么程度
* 产生了什么结果
* 是否出现问题或偏差
* 下一步准备做什么

不得等全部执行完成后再统一补写执行记录。

如果由于工具限制或执行环境限制导致无法实时写入，必须在下一次可写入时补写，并明确说明该记录为补录。

## 5. 每 5 个步骤的回顾规则

每完成第 5、10、15、20……个步骤后，必须暂停继续执行，进行一次防偏回顾。

回顾时必须同时对照以下三个对象：

1. 实施方案
2. 执行计划
3. 执行登记文档

回顾内容至少包括：

* 当前执行是否仍然服务于原始目标
* 当前步骤是否与执行计划一致
* 是否出现未记录的变更
* 是否存在执行顺序偏移
* 是否出现新增风险或隐藏问题
* 是否需要调整后续执行方式
* 是否需要用户确认新的决策

回顾完成后，必须将回顾结果写入执行登记文档。

如果没有发现偏差，也必须明确记录：

```md
本次回顾未发现明显执行偏差，后续继续按照原执行计划推进。
```

## 6. 偏差与异常处理

如果执行过程中出现以下情况，必须暂停执行，并向用户确认后再继续：

* 实施方案与执行计划存在冲突
* 执行计划中的步骤无法执行
* 当前上下文不足以判断下一步
* 发现执行结果偏离原目标
* 需要修改原方案或新增重要步骤
* 涉及破坏性操作或不可逆操作
* 需要用户做判断、取舍或授权

暂停时，你需要说明：

```md
当前执行出现需要确认的问题：

- 问题：
- 影响：
- 可选处理方式：
- 我的建议：
- 需要你确认的点：
```

## 7. 执行完成规则

全部步骤完成后，必须在执行登记文档中写入最终执行总结。

总结至少包括：

* 实际完成了什么
* 是否完全符合实施方案
* 是否完全符合执行计划
* 执行中发生了哪些调整
* 是否存在遗留问题
* 后续建议是什么

完成总结写入后，再向用户汇报最终执行结果。

## 8. 核心原则

执行过程必须满足以下原则：

1. 先登记，后执行。
2. 先确认，后实施。
3. 步骤推进必须可追踪。
4. 每一步执行都必须留下记录。
5. 每 5 步必须回顾防偏。
6. 发现偏差必须暂停确认。
7. 不得用最终总结替代过程记录。
8. 执行登记文档是本次执行过程的唯一追踪载体。
