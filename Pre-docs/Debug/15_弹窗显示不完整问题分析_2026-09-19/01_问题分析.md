## 4. 为什么动画已经结束，仍可能改变 fixed 定位

这一点不能仅凭最终 `transform: none` 排除。

1. [CSS Animations Level 1](https://www.w3.org/TR/css-animations-1/) 规定：动画未结束，或结束后以 forwards / both 填充时，浏览器按动画属性已包含在 will-change 中的方式处理。
2. [CSS Will Change Level 1](https://www.w3.org/TR/css-will-change-1/#will-change) 规定：若属性的非初始值会建立 fixed 定位包含块，对该属性的 will-change 也必须建立相应包含块。
3. [CSS Transforms Level 1](https://www.w3.org/TR/css-transforms-1/#transform-rendering) 规定：非 none 的 transform 会为后代 fixed 元素建立包含块。

据此推导，书架的 fadeUp + forwards 可以在可见动画结束后继续让书架成为删除遮罩的定位基准。不要要求开发者工具必须显示字面上的 `will-change: transform` 才承认这种行为；规范要求的是相应效果。

于是 `fixed inset-0` 不再自动意味着覆盖整个浏览器视口。列表较短时，遮罩可用高度随书架内容高度变小，而固定的上下 6rem 留白和确认框内容并不同比变小，确认框下部会进入遮罩的滚动溢出区。main 和 tablet 的裁剪可能进一步限制显示。

**截图的辅助吻合：**确认框宽约 734 图片像素，相对代码 420 CSS px 的比例约 1.75；书架内容宽约 1120 图片像素，相对 640 CSS px 也约 1.75。书架顶部约 y=161，弹窗顶部约 y=328，差约 167 图片像素，接近 96×1.75=168。这支持“从书架顶部加 py-24 定位”的推断。比例只是图片几何校验，不代表已测得浏览器缩放。

### 7.1 基线采样

在发生问题的版本中，用原浏览器打开书架，等入场动画结束，打开更多菜单，再打开删除确认；不要点击确认删除。

记录浏览器版本、页面构建版本、窗口 CSS 宽高、visualViewport 尺寸、页面缩放、devicePixelRatio、根字号、是否启用减少动态效果、当前筛选和条目数、各层 scrollTop。

采集书架动画容器、删除遮罩、确认框、按钮、main、tablet 的 getBoundingClientRect；采集每层 overflow、transform、animationName、animationFillMode、position、z-index、clientHeight、scrollHeight。计算按钮矩形与各裁剪矩形的交集；用命中测试区分被覆盖与被裁剪。

### 7.2 单变量判别实验

仅在开发者工具当前页面临时调整，逐次恢复基线，不写入源码、不保存为修复：

| 实验 | 首要原因成立时的预期 | 反证或下一步 |
| --- | --- | --- |
| 临时禁用书架容器 animation | 遮罩定位范围转向视口，位置/高度明显变化 | 若不变，检查其他包含块祖先及实际加载 CSS |
| 对比正常动态效果与减少动态效果 | 本项目减少动态效果规则将动画设为 none，应改变该原因的触发条件 | 若仍截断，继续检查独立超高及其他祖先 |
| 仅临时降低遮罩上下 padding | 同一短遮罩中可见内容增加，证实留白的放大作用 | 这不证明定位基准已经正确 |
| 在遮罩内滚动并记录 scrollTop | 若按钮进入可见区，支持遮罩自身滚动裁剪 | 若不能，逐层检查 main 和 tablet 边界、事件命中 |

## 9. 复核新增：真实组件隔离实验

### 9.1 方法与环境

使用临时页面直接 import 当前 `src/components/ImportItemList.jsx` 和 `src/index.css`，通过项目 Vite 转换，未复制或修改删除组件。放入两条内存虚拟文章，所有业务回调为空或本地文本反馈，不连接数据库。祖先重建为 `.canvas → .tablet → h-full flex flex-col → main → .w-full.animate-fade-up`；保留 tablet 约束、main 滚动、书架 640px 最大宽度，页头/页脚和筛选栏简化为占位内容。

环境：Windows 内置 Chromium，UA 标识 Chrome/152.0.0.0，CSS 视口 1280×720。测试用日间样式，没有复刻截图主题或假定其缩放。实际测量由页面调用 getBoundingClientRect、getComputedStyle、elementFromPoint 以及 scrollHeight/clientHeight/scrollTop，结果展示在诊断面板；诊断面板位于右侧，与按钮采样点不重叠。

在浏览器 UI 中点击真实“更多 → 删除”，等动画结束后采样。之后分别禁用祖先动画、恢复动画只提高 z-index、恢复普通层级并滚动遮罩，最后恢复全部基线。实验调整仅作用于临时页面 DOM 样式，不是源码修复。临时验证文件与服务在采样结束后清理。

### 9.2 实测结果（CSS px，四舍五入）

| 状态 | 遮罩 x / y / 宽 / 高 | 遮罩 clientHeight / scrollHeight / scrollTop | 确认按钮 y / bottom | 按钮中心命中自身 |
| --- | --- | --- | --- | --- |
| 初始基线，动画结束 | 64 / 114 / 640 / 221.48 | 221 / 401 / 0 | 346.16 / 386.80 | 否 |
| 仅禁用书架 animation | 0 / 0 / 1280 / 720 | 720 / 720 / 0 | 232.16 / 272.80 | 是 |
| 恢复动画，仅 z-index=999999 | 64 / 114 / 640 / 221.48 | 221 / 401 / 0 | 346.16 / 386.80 | 否 |
| 原样式，遮罩滚动到底 | 64 / 114 / 640 / 221.48 | 221 / 401 / 179.43 | 166.73 / 207.38 | 是 |
| 完全恢复基线 | 64 / 114 / 640 / 221.48 | 221 / 401 / 0 | 346.16 / 386.80 | 否 |

原书架矩形为 x=64、y=114、width=640、height=221.48，完全等于基线遮罩矩形。基线确认框 y=210，正好是 114+96；确认框 bottom=419.38，而遮罩 bottom=335.48。main bottom=632，tablet bottom=696，远低于当前截断位置。因此本实验直接裁剪来源可精确确定为遮罩自身。

基线动画结束时，实际 computed transform 为 `matrix(1, 0, 0, 1, 0, 0)`，禁用动画后才变成 `none`。这是对原报告的重要补充：关键帧源码写 none，不等于目标浏览器动画填充期间必然返回 computed none；单位矩阵虽无肉眼位移，仍属于非 none transform。规范中的动画填充副作用与本次计算样式结果相互支持。

视觉结果：基线出现与用户截图相同的“正文可见、底边横向截断、按钮消失、下方大面积空白”；禁用动画后确认框完整；滚动到底后按钮出现但标题被上边界裁剪。最后恢复基线，原故障再次出现。

### 9.3 对结论的影响

书架删除弹窗原因由“高置信度静态推断”升级为“真实组件隔离实验已验证”。禁用动画是因果鉴别实验，不等于推荐全局移除动画。提高层级无效、滚动可找回按钮，分别排除了层级作为主因以及按钮未渲染的解释。原应用账号状态、更多菜单边缘行为、其他弹窗、缩放及多浏览器矩阵仍未完成实测；这些边界不被本实验覆盖。
