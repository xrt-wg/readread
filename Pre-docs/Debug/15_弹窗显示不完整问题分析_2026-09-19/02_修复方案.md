# 书架删除弹窗显示不完整：修复方案

日期：2026-09-19。状态更新：核心删除弹窗修复已实施，本地浏览器验收通过；详情及未覆盖项见 [03_修复与验收记录.md](./03_修复与验收记录.md)。下文保留实施前方案，用于对照设计与实际结果。

依据：[01_问题分析.md](./01_问题分析.md)，尤其第 9 节真实组件隔离实验。用户已授权在原因确认后制定本方案；本次交付仅包括文档，不修改产品功能代码。

## 1. 决策及范围

**将书架删除确认弹窗通过 React Portal 挂到 document.body，并将其布局改为基于视口、顶部可达、内容超高可滚动的独立模态层。** 保留书架动画与页面滚动布局。

实验已经证实：当前遮罩被书架动画祖先限制为约 221px 高；禁用动画后恢复为 720px 视口高，而增加 z-index 无效。因此修复必须解除该 DOM 祖先约束。Portal 改变实际挂载位置，能直接切断已验证的原因链。

本次必须完成的范围为 ImportItemList 删除确认弹窗。不同筛选、不同条目数共用此实现，统一验收。其他浮层先按第 6 节验证后分支处理，避免把尚未确认的风险扩成全站弹窗重构。

## 2. 目标行为

- 打开删除确认时，遮罩覆盖浏览器视口，定位范围不随书架条目数、列表滚动位置、入场动画状态改变。
- 常规视口下，标题、说明、取消及确认按钮一起可见；矮窗口、放大字号或长文案下，全部内容可通过弹窗滚动到达，顶部不落到不可滚回的区域。
- 保留现有文案、配色、420px 最大宽度及删除业务调用；打开和取消均不触发 onDelete。
- 模态层高于页面工具按钮；弹窗期间背景不可操作。关闭后恢复背景状态及合理焦点，不留下滚动锁或 inert。

“完整”不要求极矮视口一次容纳所有内容，而要求信息和操作都可达，不能像当前那样借用短列表区域作为弹窗视口。

## 3. 具体改动

预计涉及 `src/components/ImportItemList.jsx` 与 `src/index.css` 两个产品文件；验证夹具按现有 scripts/fixtures 约定增补。初次实现不建立全站通用弹窗框架。

### 3.1 改变挂载位置

在 ImportItemList 引入 `createPortal`，将 `deleteTarget` 条件下的完整遮罩及确认框输出到 `document.body`。状态和回调仍由 ImportItemList 管理，保留 React 的卸载和更新关系，不使用手动 appendChild 移动 React 节点。

该项目首次选文已使用 document.body Portal，可参考其生命周期处理；不得让删除弹窗仍挂到 `.tablet`、main 或书架节点下。

本应用为客户端渲染；若之后引入服务端渲染，应另外处理 document 可用性。当前不要为未知运行模式引入额外框架。

### 3.2 弹窗布局

为该遮罩添加明确的删除弹窗专用样式，替换目前 `py-24` 和局部滚动布局。建议约束如下：

```css
/* 设计约束示意，实施时整合现有类名，避免冲突声明 */
.delete-confirm-backdrop {
  position: fixed;
  inset: 0;
  z-index: 10020;
  display: flex;
  align-items: flex-start;
  justify-content: center;
  overflow-y: auto;
  overscroll-behavior: contain;
  padding: 24px 16px;
}

.delete-confirm-dialog {
  width: 100%;
  max-width: 420px;
  flex-shrink: 0;
  margin-block: auto;
}
```

解释：遮罩为唯一纵向滚动容器。内容短时，上下 auto margin 分配剩余空间使其居中；内容超高时 auto margin 不制造负的顶部空间，确认框从顶部内边距开始，底部通过遮罩滚动可达。避免同时为外遮罩和整个确认框设两套纵向滚动条。手机安全区可通过 env(safe-area-inset-*) 增加边距；如调整视口单位，提供兼容回退并测试键盘弹出情形。

确认框沿用原有圆角、背景、阴影和文案。按钮容器在窄屏允许换行，正文允许长词换行，防止横向溢出。这里的 10020 是在当前首次选文 10010、纹理 9999、页面工具 50 的已有层级基础上选择；它解决 Portal 后的层叠关系，不是本故障单独的修复手段。

### 3.3 模态行为与清理

布局修复落地时补齐与独立模态层相配套的行为，参考 FirstReadingChoiceModal 的既有实现：

- 确认框设 `role="dialog"`、`aria-modal="true"`，用稳定 ID 关联标题与说明。
- 初始焦点落到“取消”，不自动聚焦破坏性按钮；Tab / Shift+Tab 在确认框内循环，Escape 执行取消。
- 记录触发条目的“更多”按钮引用作为优先恢复焦点目标。菜单中的“删除”按钮随后会卸载，不能只依赖打开时 document.activeElement。若条目已移除则回到仍存在的书架控制按钮或可聚焦的书架区域。
- Portal 在 root 外，弹窗打开期间可令应用 root inert 并锁住 body 滚动；保存旧值，在取消、确认关闭以及组件卸载时恢复。React StrictMode 下反复 setup/cleanup 也须正确。
- 如果实施时发现模态框能够并发打开，先建立统一的锁计数或明确互斥，再使用 root inert/body 锁，避免一层关闭解锁另一层。本阶段不盲目复制多个独立全局锁。
- 点击遮罩背景可取消；点击确认框内部不取消，仍以 `event.target === event.currentTarget` 判断背景点击。Portal 保留 React 事件冒泡语义，应验证不会误触发条目编辑或其他父层操作。

删除请求的等待策略、重试、数据模型与服务端级联删除均不在这次布局方案中变更。当前确认后关闭的业务语义保留，异步失败继续由既有页面路径展示。取消清理时一并清空 deleteTarget 与 deleteTargetItem，避免两份目标状态残留；不得因此引入新的删除调用。

## 4. 为什么不选择其他做法

| 备选 | 不采用为主方案的原因 |
| --- | --- |
| 单纯增加 z-index | 已有对照实验反证；不改变包含块、尺寸和裁剪边界 |
| 只减小 py-24 | 能增加短区域内的可见内容，但遮罩仍受列表高度约束 |
| 删除全局 fadeUp / forwards | 可作为诊断开关，但影响书架、推荐、阅读等共享动画；也不保证以后其他祖先样式不再限制浮层 |
| 去掉 tablet / main 的 overflow | 本次直接裁剪层是遮罩自身，并且外层滚动承担页面布局职责 |
| 只给确认框设置 max-height:100vh | 遮罩仍是短列表高度；子框按窗口限高不能解除父级裁剪 |
| 一次迁移所有 Modal 与悬浮卡 | 当前类似场景并未全部复现，且菜单/锚点卡与模态框交互不同，不应共用未经验证的改动 |

## 5. 实施顺序与检查点

1. 保留当前未提交修改，建立针对当前组件的浏览器回归夹具。使用真实 ImportItemList 与项目 CSS，虚拟数据和 onDelete 计数器；确保原实现稳定出现短列表裁剪。
2. 实现 Portal、专用布局和必要模态生命周期；保持删除业务路径不变。
3. 在同一夹具复跑原失败用例与边界矩阵，随后在完整应用书架验证。只有几何检查和实际交互均通过，才将问题标记为修复完成。
4. 执行 `npm run build` 检查集成；构建成功只是代码可构建证据，不替代浏览器排版测试。
5. 按第 6 节核查其他入口，逐项记录“通过 / 复现另一个问题 / 尚未验证”，不要用删除弹窗通过代替全站通过。

## 6. 其他类似情景的处理边界

| 入口 | 必须验证的内容 | 仅在复现后采取的方向 |
| --- | --- | --- |
| 书架更多菜单 | 首尾条目、左右边缘、滚动后位置、hover 状态下点击外部能否关闭 | 作为独立锚点菜单处理定位和边界；如需 Portal，以按钮矩形定位并处理翻转、横向夹紧、滚动/缩放时重定位或关闭。不要套用模态居中布局 |
| 提交推荐 | 短窗口与完整表单中，标题、关闭按钮、提交操作是否全部可达 | 修正超高时居中造成的顶部溢出；若有层叠冲突，再按独立模态层处理 |
| 推荐详情 | 长摘录滚动、关闭、外部工具遮挡 | 依据现场证据处理；现有 85vh 内部滚动不预先删除 |
| 编辑器未保存确认 | 短窗口、放大字号、取消返回编辑 | 若超高复现，沿用已验证的可达布局；不改编辑器正文滚动模型 |
| 首次选文 | 焦点、背景锁、页面切换时清理，是否与删除模态互斥 | 作为已有 Portal 的兼容对照，避免无依据改动 |
| 翻译卡、收藏卡、目录、收藏侧栏 | 用户报告具体入口后检查对应窗口边界 | 独立定位；本轮保留 BookmarkPanel、TranslationPopup 原有未提交修改 |

ReviewModal 在 src 中无调用入口，不纳入本次必修列表。

## 7. 验收矩阵与断言

### 7.1 核心排版

最低覆盖 1280×720、720×600、375×667、375×300 CSS 视口；增加 200% 浏览器缩放实测并记录最终 CSS 视口，不把改 viewport 当作缩放替代品。覆盖 1 条、2 条、长列表，未读/未读完/已读完/全部筛选，以及 main 顶部、中部、底部滚动状态。

必须断言：遮罩位于 body Portal，矩形覆盖布局视口；其 x/y 与书架滚动和动画无关。常规尺寸下确认框及按钮矩形完整位于遮罩可视区域；小高度下可从标题滚动到按钮，顶部和底部均可到达。按钮中心及内侧采样点的 elementFromPoint 命中按钮或其后代；不能仅依赖 DOM 存在或自动化框架 isVisible。

分别在动画进行中和结束后打开；正常动态效果及减少动态效果都通过。检测没有页面横向溢出，没有额外的背景滚动，没有被账号按钮等工具覆盖。

### 7.2 交互与业务边界

- 打开、取消、点击背景、Escape 的 onDelete 调用次数都是 0。
- 在虚拟回调夹具中确认一次仅调用一次 onDelete，参数为当前目标条目；不得用真实书架内容做破坏性布局验证。
- Tab 焦点不落到背景，初始焦点为取消；取消后回到触发位置；条目已移除或页面切换时不会将焦点恢复到失效节点。
- 弹窗内点击、滚动不触发关闭或编辑；连续开关、切换视图、组件卸载后 body/root 状态恢复。
- 完整应用下核查失败提示仍走原路径；不为验证布局而改变服务端数据。

### 7.3 完成标准

原隔离失败用例修复前失败、修复后通过，完整应用书架复测通过，上述最低矩阵和构建通过，且修改未覆盖原有未提交工作。其他入口没有完成测试时必须列出，不能宣称“所有类似弹窗已修复”。当前文档没有声称方案实现或验收已经通过。

## 8. 风险与回退

Portal 后主题变量需来自 html/body 等祖先；实施时核查三种主题，若有只定义在局部父容器的变量，显式传递所需主题而非复制整个页面样式。根节点 inert 与滚动锁的清理是交互风险重点，初始焦点和恢复焦点同样必须测试。

回退按本次实际 diff 撤销 ImportItemList 的 Portal/生命周期与新增专用 CSS，同时保留诊断记录；不使用整个文件回退或 git reset 覆盖用户既有修改。回退只恢复旧行为，不表示原缺陷得到解决。
