## 2. 验收中发现并处理的缺陷

首轮回归定位到焦点恢复问题：删除后恢复焦点到 main，再立即移除临时 tabindex，会使 Chromium 在 main 没有滚动内容时丢失焦点；较矮窗口因 main 本身可滚动而没有同样表现。

现改为焦点离开后再移除临时 tabindex。修正后重新执行完整 19 组回归，全部通过。未将首轮失败结果算作通过。

每组检查包括：

- Portal 是 body 的直接子节点，遮罩 x/y 为 0，宽高与当前 iframe 视口一致。
- root inert、body 滚动锁生效；初始焦点为取消；弹窗顶部不处于负坐标。
- 滚动至底部后确认按钮中心命中按钮；页面无横向溢出。
- 弹窗内部点击不取消、不触发条目编辑；Tab / Shift+Tab 循环处理正确。
- Escape、取消、点击背景均关闭弹窗且不调用删除；背景状态恢复，焦点回到更多按钮。
- 虚拟确认恰好调用一次 onDelete，目标为 fixture-0；返回仍存在的 main。
- 两条及多条用例还检查弹窗打开时组件卸载，Portal 和全局锁均清理。卸载由夹具驱动，不代表用户可以点击 inert 背景。

原实现裁剪失败的浏览器数据记录在分析报告第 9 节，本次确认修复后的遮罩范围不再等于书架内容范围。

## 4. 真实 ImportPage 集成验收

加载实际 ImportPage，而非复制页面布局；提供两条虚拟书架数据和模拟账号状态。所有 fetch 均被拦截，所有写请求被拒绝，未接触线上数据。首次选文流程没有启用，本夹具也不覆盖 App 的账号初始化/迁移。

实际操作路径：书架 → 第一条更多 → 删除。

观察和操作结果：

1. 夜间主题、常规窗口下，标题、完整警告文字、取消、确认按钮及整个弹窗底边全部可见，遮罩覆盖页面。
2. 浏览器实际按 Tab：取消 → 确认 → 取消，背景内容未进入焦点序列。
3. 实际按 Escape 关闭后，焦点回到原条目的更多按钮。
4. 重开后将浏览器视口设为 375×180，顶部标题与说明可见；实际滚动遮罩后，取消与确认按钮完整可见。
5. 在该矮窗口中点击取消，弹窗关闭，焦点回到更多按钮；随后恢复浏览器视口设置。

该集成路径没有点击确认执行后端删除。删除调用次数和正确目标已在内存组件夹具中验收。
