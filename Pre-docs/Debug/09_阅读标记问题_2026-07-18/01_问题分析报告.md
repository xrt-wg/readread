# 问题分析报告 — 收藏标注后页面滚回阅读标记位置

- **日期**：2026-07-18
- **文件**：`src/components/ReaderPage.jsx`
- **严重程度**：P1 体验
- **状态**：待修复

---

## 1. 现象

继续往下阅读时，选中文字进行收藏标注后，页面平滑滚动回到之前设置的阅读标记（书签图标）所在段落。

---

## 2. 根因

### 精确定位

`ReaderPage.jsx:609` 的 `useEffect` 以 `readingMark` 对象引用为依赖，每次收藏后的 `loadReaderState` 从服务端拉取新的 `readingMark` 对象（即使数据完全相同），新引用触发 effect 执行 `scrollIntoView`。

### 关键代码

```jsx
// ReaderPage.jsx:609-629
useEffect(() => {
    if (!readingMark || readingMark.completed) return
    const { sectionId, paragraphIndex } = readingMark
    // book 分页切章...
    const timer = setTimeout(() => {
      const el = document.querySelector(sel)
      if (el) el.scrollIntoView({ behavior: 'smooth', block: 'center' })
    }, 400)
    return () => clearTimeout(timer)
  }, [readingMark, paginated, chapterIdxOfSection, currentChapterIdx])
  //     ↑ 对象引用变化即触发
```

### 因果链

```
用户往下读到 paragraph 20 → 选中文字收藏
  → handleBookmark()
    → saveBookmark()
    → loadReaderState()                        ← ReaderPage.jsx:272
      → getReadingMark() → 返回 { paragraphIndex: 5 }（之前标记位置，数据未变）
      → setReadingMark({ paragraphIndex: 5 })  ← 新对象引用
        → React 检测 readingMark 引用变化 (Object.is 为 false)
        → useEffect (line 609) 触发
        → 400ms 后 scrollIntoView(paragraph 5) ← 🔴 页面滚回之前标记处
```

### 为什么 `readingMark` 数据未变但引用变了

`getReadingMark` 从 Supabase 查询返回新构造的对象，即使数据库行未变，每次查询结果都是一个全新的 JS 对象。React 的 `useEffect` 依赖比较使用 `Object.is`（同值比较），新引用 ≠ 旧引用 → effect 触发。

### 为什么这个 effect 存在

该 effect 的设计意图是：当用户点击段落旁的 Bookmark 图标设置/改变阅读标记时（`handleSetReadingMark`），自动滚动到新标记位置。这是一个有意的 UX 设计。但它无法区分"用户主动改变标记位置"和"收藏操作触发数据刷新导致对象替换"——两者都通过 `setReadingMark` 更新状态，effect 无条件响应。

---

## 3. 证据链

| 步骤 | 发现 | 结论 |
|------|------|------|
| 收藏调用链追踪 | `handleBookmark` → `loadReaderState` → `setReadingMark` | 收藏操作会刷新 readingMark 状态 |
| `getReadingMark` 返回值 | 每次调用返回新对象 | 即使 DB 数据未变，引用必然变化 |
| useEffect 依赖 | `[readingMark, ...]` | 引用变化触发 effect |
| effect 内部行为 | `setTimeout(400) → scrollIntoView` | 滚动到标记段落 |

---

## 4. 结论

**根因确定。** `useEffect` 以对象引用为依赖，收藏操作引发的数据刷新产生新引用 → 误触发滚动。修复方向：改为按值比较（比较 `paragraphIndex` + `sectionId`），只有实际位置变化时才滚动。
