# URL 导入显示「已保存到书架」但内容不可见 — 问题分析报告

**日期**：2026-07-20
**分支**：`feat/unify-readings-model`
**现象**：在书架区通过 URL 导入内容，页面提示「已保存到书架」，但书架列表中看不到导入的内容。

---

## 1. 调用链分析

```
用户输入 URL → 点击导入
  ├─ ImportPanel.handleUrlImport()                       [ImportPanel.jsx:72]
  │     └─ EXTRACTORS.url()                              → 抓取文章内容
  │     └─ createReading(result, { userId, origin: 'imported' })
  │           │                                           ← ❌ 缺少 canUseCloudLibrary
  │           └─ useCloudSource({ canUseCloudLibrary, userId })
  │                 → Boolean(undefined && userId)
  │                 → false
  │                 → 写入 localStorage (rr_articles)     ← 🔴 写入路径
  │
  └─ handleImportSuccess()                               [ImportPage.jsx:161]
        └─ loadImportItems()
              └─ fetchImportItems(userId)                 [readings.js:1000]
                    └─ client.from('readings').select()   ← 🔴 读取路径（Supabase）
```

**写入走了 localStorage，读取走了 Supabase——两条路径完全断开。**

---

## 2. 根因

`ImportPanel` 组件缺少 `canUseCloudLibrary` 属性，导致 `createReading` 判断 `useCloudSource()` 始终为 `false`。

### 2.1 ImportPanel 未声明参数

```js
// ImportPanel.jsx:7
export default function ImportPanel({ userId, requireAuth, onImportSuccess }) {
  //                                  ↑ 没有 canUseCloudLibrary
```

### 2.2 ImportPage 未传递参数

```js
// ImportPage.jsx:658
<ImportPanel userId={userId} requireAuth={requireAuth} onImportSuccess={handleImportSuccess} />
//           ↑ 没有 canUseCloudLibrary

// ImportPage.jsx:720（折叠面板中的第二个 ImportPanel）
<ImportPanel userId={userId} requireAuth={requireAuth} onImportSuccess={...} />
//           ↑ 同样缺少
```

### 2.3 对比 ImportPage 内其他调用

```js
// 所有其他服务调用都正确传了 canUseCloudLibrary：
startReading(item.id, { canUseCloudLibrary, userId })       // ✅
returnToShelf(reading.id, { canUseCloudLibrary, userId })   // ✅
deleteReading(item.id, { canUseCloudLibrary, userId })      // ✅
loadLibrarySnapshot({ canUseCloudLibrary, userId })          // ✅
// ...
```

唯一的例外是导入操作——`ImportPanel` 内部直接调用 `createReading`，没有经过 `ImportPage` 的中间层，也没有接收 `canUseCloudLibrary`。

---

## 3. 后果链

1. `useCloudSource({ canUseCloudLibrary: undefined, userId })` → `Boolean(undefined)` → `false`
2. `createReading` 走 localStorage 分支，调用 `articleStore.save()`
3. 数据写入 `localStorage.rr_articles`
4. `handleImportSuccess` → `loadImportItems()` → `fetchImportItems()` 直接查 Supabase `readings` 表
5. Supabase 中无此数据 → 列表不显示
6. `loadImportItems` 的 catch 块只处理 `isLibraryAccessError`，其他异常静默吞噬，无用户可见错误

---

## 4. 验证

DevTools → Application → Local Storage → `rr_articles` 键中确实存在导入的文章数据，确认写入走了 localStorage。

---

## 5. 影响范围

`ImportPanel` 的三个导入模式均受影响：
- URL 导入 (`handleUrlImport`)：调用 `createReading`
- 粘贴导入 (`handleSubmit`)：调用 `createReading`
- 文件上传 (`handleFile` 对于 epub)：调用 `createReading`

文件上传（md/html）调用 `createReading` 前的预览步骤虽然不受影响，但最终 `handleSubmit` 提交时同样会走 localStorage。
