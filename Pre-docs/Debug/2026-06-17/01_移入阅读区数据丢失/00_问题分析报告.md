- **分支**：feat/community-recommendations
- **问题**：点击「移入阅读区」后提示成功，但阅读区看不到内容，数据库中无记录
- **严重程度**：P0 数据丢失

### 2.2 写入路径排查

`saveArticle` 的路由逻辑（[library.js:175-177](src/services/library.js#L175-L177)）：

```js
export async function saveArticle(article, options) {
  if (!useCloudSource(options)) {
    return articleStore.save(article)   // → localStorage
  }
  // upsert to Supabase...
}
```

`useCloudSource` 判断（[library.js:11-13](src/services/library.js#L11-L13)）：

```js
function useCloudSource({ canUseCloudLibrary, userId }) {
  return Boolean(canUseCloudLibrary && userId)
}
```

`copyToReadingZone` 传递的 options（[importItems.js:272](src/services/importItems.js#L272)）：

```js
return saveArticle(document, { userId: importItem.userId })
//                               ^^^^^^^^^^^^^^^^^^^^^^^^
//                               缺少 canUseCloudLibrary 字段
```

由于 `canUseCloudLibrary` 为 `undefined`，`Boolean(undefined && userId)` = `false`，`saveArticle` 落在 localStorage 分支。

### 2.3 穷举所有调用点

| `saveArticle` 调用点 | 传入的 options | 是否正确 |
|---|---|---|
| [App.jsx:51](src/App.jsx#L51) | `{ canUseCloudLibrary: true, userId }` | ✅ |
| [App.jsx:119](src/App.jsx#L119) | `{ canUseCloudLibrary, userId }` | ✅ |
| [library.js:511](src/services/library.js#L511) | 透传上层 `options`（含 `canUseCloudLibrary`） | ✅ |
| **[importItems.js:272](src/services/importItems.js#L272)** | **`{ userId: importItem.userId }`** | **❌ 缺失** |

唯一出错点。

### 2.4 排除其他可能性

| 假设 | 排除理由 |
|------|---------|
| 网络/RLS 权限问题 | 同一用户 `articles` 表中有旧记录，Supabase 写入通道正常 |
| sections JSONB 格式非法 | PostgREST 会返回错误 → `saveArticle` throw → UI 显示失败，不显示成功提示 |
| `createDocument` 产出错误 | localStorage 记录字段齐全、值正确 |
| 偶发时序问题 | 清空 localStorage 后重测，100% 稳定复现 |
| `importItem.userId` 为空 | 书架列表正常渲染（书架是纯云端的 `import_items` 表），用户已认证 |

## 3. 根因

### 精确定位

**`copyToReadingZone()` 在 [importItems.js:272](src/services/importItems.js#L272) 调用 `saveArticle()` 时，options 参数中缺少 `canUseCloudLibrary` 字段。**

```js
// 当前（错误）
return saveArticle(document, { userId: importItem.userId })

// 缺少 canUseCloudLibrary 导致 useCloudSource() 返回 false
// → 数据写入 localStorage 而非 Supabase
```

### 问题本质：写入路径与读取路径的存储后端不一致

| 操作 | 路径 | 存储后端 | 原因 |
|------|------|---------|------|
| **写入** | `copyToReadingZone` → `saveArticle({ userId })` | **localStorage** | `useCloudSource` 因 `canUseCloudLibrary` 缺失返回 `false` |
| **读取** | `loadLibraryState` → `listArticles({ canUseCloudLibrary: true, userId })` | **Supabase** | `useCloudSource` 正确返回 `true` |

两个操作对同一数据（"阅读区的文章"）使用了不同的存储后端，写入对读取不可见。

### 历史成因

参考[文章删除 BUG 分析](Pre-docs/2026-06-14/文章删除BUG/00_问题分析报告.md#L155)：ReadRead 在早期阶段文章库主要走 localStorage 路径，`useCloudSource` 的返回取决于 `canUseCloudLibrary && userId` 两者都为真。`copyToReadingZone` 的设计文档（[实施方案.md §3.2.3](Pre-docs/2026-06-14/01_导入区与阅读区/01_开发管理/03_实施方案.md#L156)）中签名即为 `saveArticle(document, { userId: importItem.user_id })`，当时 `saveArticle` 尚未引入 `canUseCloudLibrary` 检查。随着 `saveArticle` 的逻辑完善，这个调用点未被同步更新。

---

## 4. 影响范围

- **影响用户**：所有已登录用户（书架功能仅对登录用户开放）
- **影响操作**：书架 → 移入阅读区（核心流程）
- **数据完整性**：数据写入 localStorage 而非 Supabase，不会丢失但不可见于正常阅读区
- **不受影响的操作**：直接导入到阅读区（`App.jsx` 中的 `handleImport`）、推荐区加入书架（`addRecommendationToBookshelf`）、推荐区提交（`submitRecommendation`）
