# 修复方案 — 「移入阅读区」数据写入静默丢失

- **日期**：2026-06-17
- **关联问题**：[00_问题分析报告.md](00_问题分析报告.md)
- **状态**：⏳ 待实施

---

## 1. 修复策略

**将 `canUseCloudLibrary` 参数沿调用链传递到 `saveArticle`**，使 `useCloudSource()` 正确返回 `true`，数据走 Supabase 写入路径。

## 2. 改动清单

涉及 **2 个文件，2 处改动**：

### 2.1 [src/services/importItems.js](src/services/importItems.js) — 函数签名 + 调用参数

**位置**：第 237 行 `copyToReadingZone` 函数

**改动 1**：函数签名增加 `options` 参数

```diff
- export async function copyToReadingZone(importItem) {
+ export async function copyToReadingZone(importItem, { canUseCloudLibrary }) {
```

**改动 2**：`saveArticle` 调用增加 `canUseCloudLibrary`

```diff
-   return saveArticle(document, { userId: importItem.userId })
+   return saveArticle(document, { canUseCloudLibrary, userId: importItem.userId })
```

### 2.2 [src/components/ImportPage.jsx](src/components/ImportPage.jsx) — 调用点传参

**位置**：第 124 行 `handleMoveToReading` 回调

`canUseCloudLibrary` 已在组件作用域中可用（第 67 行 `useAuth()` 解构）。

**改动 3**：调用处传递 `canUseCloudLibrary`

```diff
-       await copyToReadingZone(item)
+       await copyToReadingZone(item, { canUseCloudLibrary })
```

## 3. 修复后的数据流

```
handleMoveToReading(item)
  → copyToReadingZone(item, { canUseCloudLibrary: true })
      → saveArticle(document, { canUseCloudLibrary: true, userId: item.userId })
          → useCloudSource({ canUseCloudLibrary: true, userId }) → true
          → Supabase upsert ✅
  → setSuccessMessage('已移入阅读区')
  → loadLibraryState()
      → listArticles({ canUseCloudLibrary: true, userId })
          → Supabase 查询 → 包含刚移入的文章 ✅
```
