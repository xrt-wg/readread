## 二、逐条处理意见

### A1（I-5 方向）→ 采纳，选 (a)

「预览镜像阅读区引用块」与总原则「阅读区=目标态、预览=镜像」一致，改动集中在「抽共享解析 + 预览复用」，不触碰阅读区现有引用块语义。落点：新增 `parseFrontmatter`（[markdownUtils.js](../../../src/utils/markdownUtils.js)）供两处共用，预览剥离后渲染为 `.article-quote` 引用块（非隐藏、非裸显）。

### B1（I-4 前提）→ 采纳，三处统一 1.8em

原方案只改 `MarkdownPreview` 一处。已定位全库 3 处 `1.6em` 并全部收敛 1.8em，消除阅读区 markdown（1.8em）与纯文本降级（1.6em）的内部分裂：

- `MarkdownPreview` 的 `p`（[SectionContentEditor.jsx:70](../../../src/components/SectionContentEditor.jsx#L70)）
- `PlainTextPreview` 的 `p`（[SectionContentEditor.jsx:106](../../../src/components/SectionContentEditor.jsx#L106)）
- `PlainTextContent` 的 `p`（[SectionFlow.jsx:194](../../../src/components/SectionFlow.jsx#L194)）

### B2（I-2 缺两细节）→ 采纳，写入单独立项清单

两个细节已补进 [01_修复方案.md](01_修复方案.md) §三「单独立项前须补齐」：merge 条件 tag 化、段级 tag × range 级高亮切片映射。本轮不实施 I-2，进入单独评审时按此清单补齐。

### B3（I-1 未验证 Context）→ 采纳，已 spike + 版本更正

- `InQuoteContext` 定义在模块作用域，context 身份稳定；
- `Provider` 不产生 DOM，`useContext` 穿透 react-markdown 的自定义组件树为标准的 React 行为；
- **版本更正**：本项目实际安装 **react-markdown 10.1.0**（[package.json](../../../package.json) `^10.1.0`），文档此前误写「v9」。二者均经 JSX runtime 渲染自定义组件，Context 机制一致；以 `vite build` 通过作为编译级验证（运行时视觉由 [03 附录](../../../src/components/SectionFlow.jsx) 的手测清单覆盖）。

### C1（I-3 容器令牌）→ 采纳

容器承载与预览容器同组令牌（`fontFamily + fontSize + lineHeight + letterSpacing: 0.01em + color`），补齐此前阅读区 `li` 与预览 `0.01em` 字距差；保留 `p` 内联 style 作为同值双保险。

### C2 / C3（00 完备性核对）→ 采纳

[00_问题分析报告.md](00_问题分析报告.md) §六两处由绝对 ✅ 改为 ⚠️ 澄清：夜间模式补充 `.article-inline-code`/`.article-code-block` 未变量化、无 night 覆盖的既有例外；段落序号降级为「基本对齐（多行引用块已知分歧 + 收藏索引 DOM 派生）」。

### C4（验证清单缺口）→ 采纳

[01_修复方案.md](01_修复方案.md) §七补齐：引用块内段落划选收藏（入口仍在 + charOffset 稳定）、`paraIndex=-1` 引用块收藏回归、链接内嵌粗体 `[**粗**](url)`（I-2 单独立项后）。
