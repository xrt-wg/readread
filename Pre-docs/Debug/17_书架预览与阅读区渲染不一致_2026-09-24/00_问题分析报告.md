# 书架预览与阅读区 Markdown 渲染不一致分析报告

> 日期：2026-09-24
> 范围：书架「编辑 → 预览」（`MarkdownPreview`）与阅读区正文（`MarkdownContent`）两条 markdown 渲染管线
> 结论：两套渲染器复用同一套 `.article-*` 样式契约，但阅读区为「段落可收藏 / 可标记阅读进度」引入的 DOM 外壳与文本拍平，产生了 3 处阅读区侧缺陷 + 2 处预览侧缺口，共 5 处不一致；另发现 1 处两套共有的列表样式缺陷（非不一致，附带记录）。**本问题属渲染保真类，不涉及数据完整性。**

---

## 一、结论摘要

| 级别 | 编号 | 不一致 | 修复方向 | 一句话 |
|------|------|--------|---------|--------|
| 🔴 高 | I-1 | 引用块上下间距失衡 | 修阅读区 | `div.group` 外壳破坏 `.article-quote > p` 直接子元素选择器 |
| 🔴 高 | I-2 | 行内格式（粗体/斜体/删除线/行内代码）在阅读区丢失 | 修阅读区 | `extractSegments` 为收藏偏移把正文拍平成纯文本 |
| 🟡 中 | I-3 | 列表项/标题字号不随阅读字号 | 修阅读区 | `fontSize` 只内联到 `p`，`li`/标题继承 body 16px |
| 🟢 低 | I-4 | 段落下边距 1.6em vs 1.8em | 修预览 + 阅读区纯文本路径 | 全库共 3 处 `1.6em`，统一收敛 1.8em（含阅读区纯文本降级） |
| 🟢 低 | I-5 | frontmatter 在预览裸显 | 修预览 | 阅读区剥离并渲染为顶部引用块，预览未同步 |

**一致无需改动（类名/组件层面）**：标题类（`article-h1..h4`）、列表/引用/代码块类名、链接（`ArticleLink`）、图片（`ArticleFigure`）、块级代码块、表格、水平线——两套使用同一组件/类。**补充（实施后审核 D-3）**：其中 em 基元素（标题、行内码 `.article-inline-code` 0.88em、块级码 `.article-code-block` 0.85em、表格）的 em 字号相对基准在阅读区（body 16px）与预览（18px）间同样存在漂移，随 I-3 容器方案一并修复；此处「一致」仅指类名/组件一致，非字号完全一致。

**附带发现（非不一致，两套共有）**：F-1 列表项无项目符号/序号（Tailwind preflight 的 `list-style:none` 未被恢复），见第四节。

## 二、两套渲染管线对照

| | 书架编辑预览 | 阅读区正文 |
|---|---|---|
| 组件 | `MarkdownPreview`（[SectionContentEditor.jsx:64](../../../src/components/SectionContentEditor.jsx#L64)） | `MarkdownContent`（[SectionFlow.jsx:30](../../../src/components/SectionFlow.jsx#L30)） |
| 用途 | 编辑时 WYSIWYG 预览 | 读者最终呈现 + 收藏高亮 / 阅读标记 |
| 渲染器 | react-markdown + remark-gfm | react-markdown + remark-gfm |
| 段落 DOM | `<p style="marginBottom:1.6em">`（`.article-quote` 的直接子元素） | `<div class="group relative">` 外壳 + 阅读标记按钮 + `<p data-para-index style="marginBottom:1.8em">` |
| 段落内容 | 完整 children（粗斜体 / 行内代码保留） | `ParagraphRenderer`（文本被拍平，仅保留链接 / 图片） |
| 字号基准 | 容器固定 18px | `p` 内联 `${fontSize}px`（可调，默认 18）；`li`/标题未内联 |
| frontmatter | 不处理（原样渲染） | 剥离后渲染为引用块（[SectionFlow.jsx:116-150](../../../src/components/SectionFlow.jsx#L116-L150)） |

全库仅上述两处 react-markdown 渲染入口（已 grep 确认 `ReactMarkdown` 只出现在这两个文件），其余均为共享组件/类。

## 三、问题清单

### 🔴 I-1 引用块上下间距失衡

**位置**：[SectionFlow.jsx:48-83](../../../src/components/SectionFlow.jsx#L48-L83) 的 `p` 组件 + [index.css:465-471](../../../src/index.css#L465-L471)

**现象**：同一段引用块，书架预览上下紧凑，阅读区底部多出约 1.8em 空档；多段引用时段间距也偏大；hover 时「标记读到这里」按钮冒进引用块。

**根因**：
- 引用块间距由 `.article-quote > p:first-child / :last-child` 两条「直接子元素」规则清零（[index.css:465-471](../../../src/index.css#L465-L471)）。
- 阅读区 `p` 组件把段落包进 `<div class="group relative">`（含阅读标记按钮），blockquote 内的 `<p>` 被 `div` 隔开，不再是 `.article-quote` 的直接子元素 → 两条规则失效。
- 预览 `p` 为 1.6em 且因 `> p:last-child` 清零而紧凑；阅读区 `p` 为 1.8em 且规则失效，底部空档整体留出。

**影响**：引用块是高频格式（工具栏专设「引用块」按钮），观感与编辑预期明显不符，用户已明确点名。

### 🔴 I-2 行内格式在阅读区丢失

**位置**：[markdownUtils.js:36-65](../../../src/utils/markdownUtils.js#L36-L65) `extractSegments` + [ParagraphRenderer.jsx](../../../src/components/ParagraphRenderer.jsx)

**现象**：正文中的 `**粗体**`、`*斜体*`、`~~删除线~~`、`` `行内代码` ``、任务列表 `- [ ]` 复选框，在阅读区全部退化为纯文本；书架预览则正常渲染。

**根因**：
- 阅读区 `p`/`li` 通过 `extractSegments` 把 children 拍平成「文本段」数组，只为保证收藏 charOffset 稳定；该函数只识别链接（`a`）与图片（`img`），其余行内节点（`strong`/`em`/`del`/`code`/`input`）被丢弃、仅保留文本。
- 这是「可收藏高亮」与「忠实渲染」之间的既有取舍（见 [markdownUtils.js:30-35](../../../src/utils/markdownUtils.js#L30-L35) 注释），但造成预览与阅读区对同一 markdown 的呈现差异。

**影响**：读者在阅读区看不到任何强调 / 斜体 / 行内代码语义，是所有不一致中影响面最大的一条（作用于全部正文段落与列表项）。

### 🟡 I-3 列表项 / 标题字号不随阅读字号

**位置**：[SectionFlow.jsx:50](../../../src/components/SectionFlow.jsx#L50)（`p` 内联 fontSize）vs [SectionFlow.jsx:84-100](../../../src/components/SectionFlow.jsx#L84-L100)（`li`/标题无 fontSize）

**现象**：阅读区默认字号 18px 下，段落是 18px，列表项与标题却按 body 继承的 16px（标题按 em 相对 16px），明显比正文小一号；调节阅读字号时段落变、列表项与标题不变。书架预览统一 18px 基准，无此错位。

**根因**：
- `fontSize` 只内联在 `p` 的 style；`li` 走 `.article-li`（[index.css:446-451](../../../src/index.css#L446-L451)，无 font-size），标题走 `.article-h1..h4`（[index.css:436-439](../../../src/index.css#L436-L439)，em 单位相对继承字号）。
- 阅读区未在容器层统一设置 fontSize，导致 `li`/标题继承 body 16px。

**影响**：列表 / 标题与正文字号脱节，调节字号体验割裂；与预览不一致。

### 🟢 I-4 段落下边距 1.6em vs 1.8em

**位置**：[SectionContentEditor.jsx:70](../../../src/components/SectionContentEditor.jsx#L70)、[SectionContentEditor.jsx:106](../../../src/components/SectionContentEditor.jsx#L106)、[SectionFlow.jsx:194](../../../src/components/SectionFlow.jsx#L194)

全库 `marginBottom: '1.6em'` 共 **3 处**：预览 markdown（`MarkdownPreview`）、预览纯文本（`PlainTextPreview`）、阅读区纯文本降级（`PlainTextContent`）。阅读区 markdown 段落用 1.8em。即「阅读区 = 1.8em」只对 markdown 段落成立，阅读区自身在 markdown（1.8em）与纯文本降级（1.6em）之间就存在内部分裂。按「预览镜像阅读区」原则，三处统一收敛为 1.8em，消除阅读区内部分裂。影响极小，仅段落间距略有差异。

### 🟢 I-5 frontmatter 在预览裸显

**位置**：[SectionFlow.jsx:116-150](../../../src/components/SectionFlow.jsx#L116-L150)（阅读区剥离）vs [SectionContentEditor.jsx:64-89](../../../src/components/SectionContentEditor.jsx#L64-L89)（预览不处理）

**现象**：正文含 YAML frontmatter（`--- ... ---`）时，阅读区将其剥离并渲染为顶部引用块；书架预览不剥离，把 `---` 当水平线、YAML 键值当普通段落裸显。

**根因**：仅阅读区实现了 frontmatter 剥离（[SectionFlow.jsx:116](../../../src/components/SectionFlow.jsx#L116) 正则），预览侧未同步。「剥离后渲染为顶部引用块」是阅读区的有意设计（导入书在顶部露出标题/作者/来源），按「预览=镜像」原则，预览应镜像该引用块，而非裸显、亦非隐藏。

**影响**：边缘场景（主要来自 markdown 文件导入的书籍），预览与阅读区对同一内容呈现不一致。

## 四、附带发现 F-1（非不一致，两套共有）

**列表项无项目符号 / 序号**：`@tailwind base` 的 preflight 将 `ol/ul` 的 `list-style` 置为 `none`，而 `.article-ul/.article-ol` 只恢复了 `padding-left` / `margin-bottom`，未恢复 `list-style`（全站 [index.css](../../../src/index.css) 无任何 `list-style` 规则）。两套渲染器同样受影响——列表显示为无符号的缩进文本块。**不属于本次「预览 vs 阅读区不一致」范畴**，单独列出供后续决定是否修复。

## 五、对齐原则对照表

原则：**阅读区 = 读者最终呈现（目标态），书架预览 = WYSIWYG 镜像**。据此逐条定方向。

| 条目 | 目标态 | 现状 | 判定 |
|------|--------|------|------|
| 引用块间距 | 共享 `.article-quote` 契约（= 预览现状） | 阅读区 div 外壳破坏契约 | ❌ 修阅读区 |
| 行内格式 | 忠实渲染（预览现状） | 阅读区拍平丢失 | ❌ 修阅读区 |
| 列表 / 标题字号 | 阅读区字号系统（可调） | li / 标题未继承 | ❌ 修阅读区 |
| 段落下边距 | 阅读区 1.8em（markdown）；纯文本路径亦收敛 1.8em | 预览 1.6em；阅读区纯文本降级 1.6em | ❌ 修预览 + 阅读区纯文本路径 |
| frontmatter | 阅读区「剥离后渲染为顶部引用块」 | 预览裸显 | ❌ 修预览（镜像引用块） |
| 标题类 / 列表 / 引用 / 代码块类名、链接、图片、表格、水平线、块级代码 | 两套一致 | 两套一致 | ✅ |

## 六、完备性核对

- **渲染器入口**：✅ 全库仅 `MarkdownPreview`（编辑预览）与 `MarkdownContent`（阅读区）两处 react-markdown，无第三处渲染源。
- **共享组件**：✅ 链接 / 图片经 `ArticleLink` / `ArticleFigure` 共享，无 drift。
- **共享样式**：✅ 全部 `.article-*` 类集中在 [index.css:427-544](../../../src/index.css#L427-L544)，两套引用同一契约。
- **段落序号一致性**：⚠️ 基本对齐，但非「逐段严格一致」——收藏索引实为 DOM 派生（bookmark 的 `paragraphIndex` 取自选区锚点 `data-para-index`，[ReaderPage.jsx:292-293](../../../src/components/ReaderPage.jsx#L292-L293)），与 [progress.js:30-74](../../../src/services/progress.js#L30-L74) 无运行时强绑定；且多行引用块（`> a\n> b`）上 [progress.js:41-44](../../../src/services/progress.js#L41-L44) 补空行拆为 2 段，而 react-markdown/CommonMark 解析为单段落、阅读区 `paraIdxRef` 只计 1 段，二者在该边界已知分歧（进度已迁移 scroll% 快照、bookmark 走 DOM 索引，影响有限）。I-1 修复的关键约束是「保持 `paraIdxRef.current++`」，而非与 progress.js 逐段对齐。
- **夜间模式**：⚠️ 本文所涉类**大部分**走 CSS 变量；但 `.article-inline-code`（[index.css:473-480](../../../src/index.css#L473-L480)）与 `.article-code-block`（[index.css:482-493](../../../src/index.css#L482-L493)）使用硬编码 `rgba(28,25,23,0.07/0.05)` 背景与 `rgba(28,25,23,0.1)` 边框，既非变量也无 `[data-theme="night"]` 覆盖，属既有例外（随 I-2 把行内代码带入正文高频路径时需一并评估）。
