## 二、I-1 修复：引用块内段落改纯 `<p>`

**文件**：[src/components/SectionFlow.jsx](../../../src/components/SectionFlow.jsx)

**思路**：用 React Context 标记「当前在引用块内」，`p` 组件读到该标志时改渲染为纯 `<p>`（`.article-quote` 的直接子元素），保留 `data-para-index` + `ParagraphRenderer`（收藏高亮照常工作），去掉 `div.group` 外壳与阅读标记按钮。如此 [index.css:465-471](../../../src/index.css#L465-L471) 的直接子元素规则重新生效，间距与预览一致。

**关键约束**：段落序号必须继续 `paraIdxRef.current++`，保持 `data-para-index` 稳定。收藏索引实为 DOM 派生（bookmark 的 `paragraphIndex` 取自选区锚点 `data-para-index`），并非与 [progress.js:30-74](../../../src/services/progress.js#L30-L74) 逐段对齐；I-1 只需保证计数规则不变即可。

**Context 机制已验证（B3 spike）**：react-markdown（本项目实际 10.1.0，文档此前误写 v9）经 JSX runtime 渲染自定义 `blockquote`/`p` 组件，`Provider` 不产生 DOM、`useContext` 穿透有效；`InQuoteContext` 定义在模块作用域以保持 context 身份稳定（不落在 `useMemo`/组件体内）。构建通过（`vite build` 无错）。

已实施结构：

```jsx
const InQuoteContext = createContext(false)   // 模块作用域

// blockquote 组件：
blockquote: ({ children }) => (
  <blockquote className="article-quote">
    <InQuoteContext.Provider value={true}>{children}</InQuoteContext.Provider>
  </blockquote>
),

// p 组件：
p({ children }) {
  const inQuote = useContext(InQuoteContext)
  const idx = paraIdxRef.current++            // 序号照旧
  const segments = extractSegments(children)
  const rawText = segments.map((s) => s.text).join('')
  const paraBMs = bookmarksRef.current.filter((b) => b.paragraphIndex === idx)
  if (inQuote) {
    // 纯 <p>：直接子元素，无阅读标记按钮；收藏高亮仍经 ParagraphRenderer 生效
    return <p data-para-index={idx} style={style}>
      <ParagraphRenderer text={rawText} segments={segments} bookmarks={paraBMs} onHoverBookmark={onHoverRef.current} />
    </p>
  }
  // …既有「div.group + 阅读标记按钮 + p」分支保持不变
}
```

**权衡**：引用块内不再提供「标记读到这里」按钮（预览本无此按钮）；高亮收藏仍保留。

**替代（轻量，未推荐）**：仅改 CSS 选择器适配嵌套结构（`.article-quote > div > p:first-child/last-child`）可修间距，但阅读标记按钮仍冒进引用块，且与「对齐预览标准」不符，仅作免重构兜底。

## 三、I-2 修复：行内格式恢复（需单独评审）

**文件**：[src/utils/markdownUtils.js](../../../src/utils/markdownUtils.js) + [src/components/ParagraphRenderer.jsx](../../../src/components/ParagraphRenderer.jsx)

**现状**：`extractSegments` 只产出 `{ text, href?, img? }`，行内节点被丢弃；`ParagraphRenderer` 基于纯文本 charOffset 切片叠加高亮。

**方案方向（推荐）**：扩展 `extractSegments` 为「带格式标签的段」，`ParagraphRenderer` 在切片时按标签包裹子 span，把「高亮层」与「格式标签」正交叠加：

1. `extractSegments` 增加对 `strong` / `em` / `del` / `code` 的识别，段上记录 `tag`（嵌套格式用 tag 栈，如「粗体里含链接」需同时保留 `tag` 与 `href`）；`img` / `a` 逻辑不变。
2. `ParagraphRenderer` 的 `renderBgs` / `renderSpan` 在 emit 文本切片时，按该切片所属段的 `tag` 包裹：`strong` → `<strong>`、`em` → `<em>`、`del` → `<del>`、行内 `code` → `<code class="article-inline-code">`；高亮背景 / 下划线样式叠加在外层或内层需明确层级（建议格式标签在内、高亮背景在外，或反之，取视觉更清晰者，实施前定）。

**关键不变量（风险最低点）**：格式标签零字符宽度，`extractSegments` 拼接 text 的规则不变 → **charOffset 收藏偏移完全不受影响**，既有收藏 / 进度无需迁移。`buildLayers` / `resolveRanges` 仍在纯文本上工作，改动集中在「渲染切片如何包标签」。

**复杂度与风险**：
- 嵌套格式（粗体嵌套斜体 / 粗体+链接）需要 tag 栈，`extractSegments` 与 `ParagraphRenderer` 都要相应扩展，改动面较大。
- 行内代码的背景与高亮背景的视觉叠加需定义层级，避免互相遮盖。
- 需回归：收藏高亮 / 划选弹窗 charOffset / 链接图标 / 图片段，确保不因加标签而破坏。

**单独立项前须补齐（B2）**：
1. **merge 条件 tag 化**：现有合并逻辑 [markdownUtils.js:41](../../../src/utils/markdownUtils.js#L41) `if (last && !last.img && last.href === href) last.text += text` 只比较 `href`。引入 tag 后，同一链接内「粗体段」与「普通段」会被误合并、粗体边界丢失；合并条件须升级为 `href 相等 && tag 栈相等`，否则「粗体里含链接」直接退化。
2. **段级 tag × range 级高亮切片的映射设计**：`ParagraphRenderer` 高亮层（`renderBgs`/`renderSpan`）基于整段 `text` 的 charOffset 区间切片，与 `segments` 段边界是两套正交切分网格。实施前需给出 tag 与 `seg` 的绑定结构 + 一次同时消解「高亮 range」与「格式 tag」的切片算法（伪代码即可），并明确「格式标签在内 / 高亮在外」的层级。

另：`li` 同样经 `extractSegments` + `ParagraphRenderer`（[SectionFlow.jsx:90-99](../../../src/components/SectionFlow.jsx#L90-L99)），I-2 对列表项同样生效。

**建议**：单独立项、单独评审实施，不在本方案首轮捆绑交付。

## 四、I-3 修复：列表 / 标题继承阅读字号

**文件**：[src/components/SectionFlow.jsx](../../../src/components/SectionFlow.jsx)

**思路**：在 `MarkdownContent` 的返回外层包一个承载**完整排版令牌**的容器（与预览容器同组令牌：`fontFamily + fontSize + lineHeight + letterSpacing + color`，C1），覆盖 frontmatter 引用块与 `<ReactMarkdown>`。如此：

- `p` / `li`（`.article-li`，无 font-size）自然继承容器字号；
- 标题 `article-h1..h4` 的 em 单位相对容器字号缩放，随阅读字号联动；
- `letterSpacing: 0.01em` 与预览容器对齐（此前阅读区 `li` 继承 body 的 `0`，与预览差 0.01em）；
- 一处设置，消除 16px / 18px 错位，无需逐组件内联。

**注意**：
- 保留 `p` 内联 style（与容器同值）作为双保险，容器主要为 `li` / 标题 / 引用块提供基准（C1）；
- `PlainTextContent`（纯文本降级路径）的 `p` 已内联 fontSize、且无列表/标题，不受影响，可不改。
