## 场景一：单章节 Markdown 文章 — 段落进度基本验证

**目的**：验证段落索引统一后，阅读器的标记位置与列表进度百分比一致。

### 步骤

| # | 操作 | 预期 | ✓ |
|---|------|------|---|
| 1 | 切换到「阅读」标签 | 文章列表正常显示 | |
| 2 | 找一篇**有标题和列表**的 markdown 文章（或从书架导入一篇 EPUB 单章） | — | |
| 3 | 点击打开文章 → 进入阅读器 | 文章正常渲染 | |
| 4 | 观察文章中**第一个 `<p>` 段落**（非标题行）的左侧 | 鼠标悬停时出现书签图标（opacity-0 → group-hover 显示） | |
| 5 | 点击第 1 段的书签图标 | 书签变为金色实心（表示标记成功），控制台无报错 | |
| 6 | 点击工具栏「返回」→ 回到阅读标签列表 | 该文章卡片上显示**金色进度百分比**（如 "12%"） | |
| 7 | 再次打开同一文章 → 点击第 5 段书签 | 标记移动到新位置 | |
| 8 | 返回列表 → 查看进度 | 百分比数字**增大**了（因为标记到更后面的段落） | |
| 9 | 再次打开文章 → **再次点击第 5 段**（同一段落） | 书签标记**消失**（清除标记） | |
| 10 | 返回列表 → 查看进度 | 该文章的进度百分比**消失**（无标记 = 无进度） | |

**关键检查**：第 6、8 步的百分比是否与你标记的段落位置直观匹配（不是随机数字）。

## 场景二：Markdown 元素跳过验证

**目的**：验证标题（h1-h6）、代码块、水平线、引用块不占段落索引。

### 步骤

| # | 操作 | 预期 | ✓ |
|---|------|------|---|
| 1 | 如果手头没有含代码块的测试文章，打开 Supabase Dashboard → SQL Editor，手动插入一篇测试文章（见附录 A） | — | |
| 2 | 打开这篇测试文章 | 阅读器渲染：标题、代码块、引用块、水平线均正常显示 | |
| 3 | 找到**标题下方第一个正文段落**，点击书签 | 标记成功 | |
| 4 | 返回列表 → 查看进度 | 百分比基于**段落 0**（标题不占索引） | |
| 5 | 找到代码块**之后的**段落，点击书签 | 标记成功，段落索引**不包含代码块内的行** | |
| 6 | 返回列表 → 对比之前段落 0 的进度 | 新进度 > 旧进度，差值合理（基于实际段落数） | |

**关键检查**：步骤 4 中段落 0 是标题之后第一个正文 `<p>`，而非标题行本身。

## 场景三：多章节书（EPUB）— 章节独立标记

**目的**：验证 Fix 5（`sectionId` 比对）——不同章节的段落标记互相独立。

### 步骤

| # | 操作 | 预期 | ✓ |
|---|------|------|---|
| 1 | 如果手头没有多章节 EPUB，使用「导入」→ 粘贴或上传一个含多章节的文档 | — | |
| 2 | 打开这本书 → 阅读器显示**目录按钮**（右上角） | 目录按钮可见（表示多章节） | |
| 3 | 在**第 1 章**中找到第 3 段，点击书签标记 | 标记成功（金色书签） | |
| 4 | 点击目录按钮 → 切换到**第 2 章** | 内容切换到第 2 章 | |
| 5 | 在第 2 章中找到第 1 段，点击书签标记 | **标记成功**（不应清除第 1 章的标记） | |
| 6 | 切换回**第 1 章** | 第 1 章第 3 段的标记**仍在** | |
| 7 | 再次点击第 1 章第 3 段书签 | **仅清除第 1 章的标记**，第 2 章的标记不受影响 | |
| 8 | 切换回第 2 章确认 | 第 2 章第 1 段标记**仍在** | |

**关键检查**：步骤 5 中不会弹出错误提示（修复前：切换章节后标记 → 触发 clear 而非 save，导致前一章标记被清除）。

## 场景四：进度保留验证（completed/completedSections 不丢失）

**目的**：验证 Fix 3 和 Fix 4——标记位置变更时已有的完成状态和章节记录不会被覆盖。

### 步骤

| # | 操作 | 预期 | ✓ |
|---|------|------|---|
| 1 | 打开一篇文章 → 标记第 8 段 | 标记成功 | |
| 2 | 点击底部「✓ 标记已读完」按钮 | 按钮变为已读完状态（样色/样式变化） | |
| 3 | **重新打开同一篇文章**（返回列表再进入） | 阅读器恢复：标记在第 8 段，且「已读完」状态保持 | |
| 4 | 点击第 5 段书签（把标记**往前移**） | 标记移动到第 5 段 | |
| 5 | 返回列表再重新打开文章 | **「已读完」状态仍在**（修复前：云端路径会丢失 completed 状态） | |
| 6 | 点击第 5 段书签**取消标记** | 标记清除 | |
| 7 | 再次打开文章 | 无标记，但如果有过章节完成记录（`completedSections`），**不被清空**（修复前：会丢失） | |

**关键检查**：步骤 5——标记往前移后已读完状态不丢失。步骤 7——清除标记不连带清除章节记录。

## 附录 A：SQL 插入测试文章（含多种 Markdown 元素）

在 Supabase SQL Editor 中执行以下语句，然后刷新页面：

```sql
insert into public.articles (id, user_id, title, text, markdown, word_count, source_type, kind)
values (
  'doc_test_progress_001',
  auth.uid(),
  'Progress Test — Markdown Elements',
  'Getting Started
This is the first real paragraph of the article. It contains some text that should be counted as paragraph index zero.

Here is the second paragraph with more content to make the word count meaningful.

Point one of the list
Point two of the list
Point three

After the list we have another regular paragraph that continues the discussion.

The final paragraph wraps things up.',
  '# Getting Started

This is the first real paragraph of the article. It contains some text that should be counted as paragraph index zero.

Here is the second paragraph with more content to make the word count meaningful.

- Point one of the list
- Point two of the list
- Point three

After the list we have another regular paragraph that continues the discussion.

The final paragraph wraps things up.',
  50,
  'manual',
  'article'
);
```

段落索引预期：
- 段落 0：「This is the first real paragraph...」
- 段落 1：「Here is the second paragraph...」
- 段落 2：「Point one of the list」
- 段落 3：「Point two of the list」
- 段落 4：「Point three」
- 段落 5：「After the list we have...」
- 段落 6：「The final paragraph wraps things up.」

（`# Getting Started` 是标题，不占索引）
