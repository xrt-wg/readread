## 四、修复方案 — 合理性审核

### 4.1 核心修复（改 1）：✅ 合理且充分

```diff
- const displayExcerpts = rec.excerptsTrans && rec.excerptsTrans.length > 0
-   ? rec.excerptsTrans
-   : rec.excerpts
+ const displayExcerpts = rec.excerpts && rec.excerpts.length > 0
+   ? rec.excerpts
+   : rec.excerptsTrans
```

将主展示字段从"翻译优先"反转为"原文优先"，语义正确。仅 1 行变更，风险最低。

### 4.2 增强修复（改 2）：✅ 现有渲染逻辑已正确

翻译行（L150-157）的守卫 `rec.excerptsTrans && rec.excerptsTrans[i]` 在修复后行为正确——当 `excerpts` 存在时展示英文原文 + 中文翻译，当 `excerptsTrans` 不存在时不渲染翻译行。

### 4.3 三场景分析表：⚠️ 场景 3 需修正

| 场景 | 文档声称效果 | 实际效果 | 差异 |
|------|------------|---------|------|
| AI 新数据 | 原文=英文 + 翻译=中文 | 同文档 | ✅ 一致 |
| 旧手写数据 | 原文=英文（无翻译行） | 同文档 | ✅ 一致 |
| 旧迁移数据（excerpts 为空/null，excerptsTrans 有值） | 原文=中文（**无翻译行**） | 原文=中文 + **翻译行=同样的中文（重复）** | ⚠️ 有差异 |

**原因**：修复后 `displayExcerpts = excerptsTrans`（中文 fallback），但 L150 的翻译行检查 `rec.excerptsTrans && rec.excerptsTrans[i]` 仍然为 true，导致同一条中文原文在"原文"位置和"翻译"位置各渲染一次。

**实际风险评级：低**。因为：
- `SubmitRecommendationModal.jsx:269` 阻止提交全空 `excerpts`
- `recommendationService.js:390` 的 DB 写入中 `excerpts` 始终为数组（至少 `[]`），但不会为 `null`
- 此场景主要存在于假设性的"历史迁移数据"，正常 AI 流程不会产生

### 4.4 边界情况增强建议（可选）

如果希望在场景 3 完全避免重复渲染，可将 L150 的翻译守卫收紧为同时检查 `excerpts` 对应位置存在：

```js
// 当前守卫（L150）
{rec.excerptsTrans && rec.excerptsTrans[i] && (
  <p>...</p>
)}

// 建议收紧为（仅在英文原文存在时才展示翻译）
{rec.excerptsTrans && rec.excerptsTrans[i] && rec.excerpts && rec.excerpts[i] && (
  <p>...</p>
)}
```

**是否必要**：非必须。当前修复已覆盖所有实际场景，此增强仅为理论完备性。由实施者自行决定。

### 4.5 关键词检查（改 2 附加检查）：✅ 正确

```js
const displayKeywords = rec.keywordsTrans && rec.keywordsTrans.length > 0
  ? rec.keywordsTrans : rec.keywords
```

此逻辑与 `displayExcerpts` 的 bug 模式相同，但对关键词而言是**正确的 UX 选择**——推荐区面向中文用户，优先展示中文关键词合理。**不需修改**，判断准确。
