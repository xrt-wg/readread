# 问题分析报告：阅读完成时评分组件不可见、无法评分

- 日期：2026-09-16
- 状态：**根因已确证** —— `handleMarkCompleted` 在读完标记后同步调用 `onBack()`，阅读页立即卸载，评分组件随页面销毁，用户无法在「阅读完成」时刻看到并操作评分。另有一处设计缺口（推荐列表卡片评分入口未实现）与两处待验证的数据兜底风险。
- 影响范围：推荐评分功能的可达性 —— `recommendation_ratings` 写入的唯一前端入口被阻断
- 本文只做问题定位，不含修复方案（遵循 `.windsurf/rules/problem-analysis-guide.md`）

---

## 1. 现象

用户从推荐区加入书架 → 打开阅读 → 读完点击「标记已读完」→ 期望看到评分组件（推荐 / 一般 / 不行）进行评分，但评分组件未出现、无法评分。

---

## 2. 结论（根因已确证）

### 2.1 评分组件的渲染条件

评分组件位于 `src/components/ReaderPage.jsx:939-978`，被一个三元表达式包裹：

```
readingMark?.completed === true
  → 显示「已读完」badge + 评分组件（{recSubmissionId && ...}）
  → 否则显示「标记已读完」按钮
```

评分组件出现需**同时**满足：

| # | 条件 | 代码位置 |
| --- | --- | --- |
| ① | `readingMark.completed === true` | `src/components/ReaderPage.jsx:939` |
| ② | `recSubmissionId` 非空 | `src/components/ReaderPage.jsx:957` |

`recSubmissionId` 由 `useEffect`（`src/components/ReaderPage.jsx:218-228`）在满足 ③④ 时设置：

| # | 条件 | 代码位置 |
| --- | --- | --- |
| ③ | `article.origin === 'featured' \|\| 'featured_legacy'` | `src/components/ReaderPage.jsx:220` |
| ④ | `article.shareSourceId` 非空 | `src/components/ReaderPage.jsx:221` |

`article` 来自 `src/App.jsx:173-177` 的 `handleOpen` → `getReading(id)`，字段由 `mapReadingRow` 映射（含 `origin` / `shareSourceId`，`src/services/readings.js:100-102`）。

### 2.2 根因：读完标记后立即 `onBack()`，页面卸载

`handleMarkCompleted`（`src/components/ReaderPage.jsx:569-592`）：

```js
const handleMarkCompleted = useCallback(async () => {
  try {
    const mark = await setReadingMarkCompleted(articleId, { canUseCloudLibrary, userId })
    setReadingMark(mark)                          // ← readingMark.completed 变 true
    try { await returnToShelf(articleId, { completed: true, ... }) } catch (_) {}
    onBack()                                      // ← 立即返回书架
  } catch (e) { ... }
})
```

`onBack` 即 `src/App.jsx:179-182` 的 `handleBack = () => setArticle(null)`；而 `src/App.jsx:284-288` 中 `article === null` 时渲染书架页，`ReaderPage` 被卸载。

**论证链（四环，均已核实）**：

| # | 环节 | 位置 | 判定 |
| --- | --- | --- | --- |
| 1 | `completed` 变 `true` 的唯一入口是「标记已读完」按钮 → `handleMarkCompleted` | `ReaderPage.jsx:982`；`saveReadingMark` 只更新位置、保留 `completed`（`readings.js:868-869`） | 成立 |
| 2 | 因此「阅读完成」状态只能由 `handleMarkCompleted` 产生 | — | 成立 |
| 3 | 该函数在 `setReadingMark` 之后**同一函数内同步** `onBack()` → `setArticle(null)` → 卸载 | `ReaderPage.jsx:584`；`App.jsx:180` | 成立 |
| 4 | 评分组件只渲染在 `completed` 分支，且 `recSubmissionId` 还需 `useEffect` 在**渲染之后**异步设置 | `ReaderPage.jsx:218-228` | 成立 |

> 时序细节：即使 React 有机会提交一次 `completed` 渲染，`recSubmissionId` 仍依赖 `useEffect` 在渲染后执行 `setRecSubmissionId`；`onBack()` 紧随其后，用户等不到这个 effect 落地。

**结论**：在当前实现下，「阅读完成」这一时刻，评分组件在结构上必然不可见、不可操作。

## 3. 机制分析

### 3.1 时序推演

| 事件 | 状态变化 | 结果 |
| --- | --- | --- |
| 点击「标记已读完」 | `setReadingMarkCompleted` 落库 → `setReadingMark(mark)` | `readingMark.completed = true` |
| （紧随）`returnToShelf` | `readings.reading_status → completed` | 不影响评分组件显示 |
| （紧随）`onBack()` | `setArticle(null)` | `ReaderPage` 卸载，评分组件随页面销毁 |
| （本应发生但未发生）`useEffect` | `setRecSubmissionId(article.shareSourceId)` | 被 `onBack` 打断 |

### 3.2 触发条件链

| # | 环节 | 位置 | 判定 |
| --- | --- | --- | --- |
| 1 | 内容来自推荐区（`origin ∈ {featured, featured_legacy}`） | `readings` 表 | 用户前提 |
| 2 | 用户读到末尾点击「标记已读完」 | `ReaderPage.jsx:982` | 用户前提 |
| 3 | `handleMarkCompleted` 同步 `onBack()` | `ReaderPage.jsx:584` | **缺陷所在** |
| 4 | 评分组件未及渲染即卸载 | `ReaderPage.jsx:939-978` | 结果 |

## 4. 次要发现

### 4.1 设计规划的两个评分入口均未落地

设计文档 `Pre-docs/2026-06-16/01_社区众包推荐系统/01_开发管理/03_实施方案.md` §4.5 规划评分出现在两处：

| 规划入口 | 现状 |
| --- | --- |
| ① 推荐列表卡片（展示评分分布 + 可评分） | **未实现** —— 推荐卡片只有「加入书架」按钮，无评分入口（`ImportPage.jsx:621`） |
| ② 阅读完成时（提示「你已读完，去评分」） | **被 `onBack` 阻断** —— 即本报告根因 |

即评分功能当前 **0 个可用前端入口**，`rateRecommendation` / `getMyRating` 服务层虽完整，但无 UI 可达。

### 4.2 「再次打开已完成文章」是唯一理论可达路径，但有数据兜底风险

读完被踢回书架后，再次打开这篇已完成文章：

1. `handleOpen` → `getReading(id)` → `mapReadingRow`（云端数据正确时含 `origin` / `shareSourceId`）；
2. `readingMark` 恢复 `completed = true`；
3. `useEffect` 设置 `recSubmissionId` → 评分组件出现。

此路径在云端数据正确时**理论可用**，但存在两处兜底风险（见 §5 推测 B1/B2）。

---

## 5. 结论 vs 推测

**结论（可定案，证据 = 代码逻辑完备论证）：**

1. **根因 A**：`handleMarkCompleted` 读完标记后立即 `onBack()`（`ReaderPage.jsx:584`），评分组件随页面卸载，「阅读完成」时刻必然不可见。
2. 触发条件链四环全部核实成立。
3. **设计缺口 C**：设计文档规划的「推荐列表卡片评分入口」未实现（`ImportPage.jsx:621` 只有加入书架），评分功能当前无任何可用 UI 入口。

**推测（待验证，不影响根因 A 定案）：**

- **B1**：`mapReadingRow` 中 `origin: row.origin || 'imported'`（`readings.js:100`）——若 `readings` 表该行 `origin` 为 `null`（旧数据 / 迁移残留），会被回退为 `'imported'`，使「再次打开」路径的条件 ③ 恒不成立。
- **B2**：`createReading` 的 localStorage 分支构造 `legacyArticle` 时未带 `origin` / `shareSourceId`（`readings.js:344-366`）——若从推荐区加入书架走了 localStorage 路径，两字段丢失。（评分本身需登录 + 云端 RPC，故可能性偏低。）

**尚缺信息：**

1. 精确复现路径——是「点『标记已读完』的那一刻」，还是「再次打开已完成文章仍不显示」。
2. 该篇记录的 `readings.origin` / `share_source_id` 实际 DB 值（仅当现象为「再次打开仍不显示」时需要）。
3. 测试环境为云端登录态还是 localStorage / 匿名。

以上信息可通过 Supabase 控制台查询，或在 `handleOpen` 后打印 `article.origin` / `article.shareSourceId` 获取。
