# 问题分析报告：表格、标题、引用文本无法进行收藏标记/标注

**日期**：2026-08-06
**版本**：develop (85d4cd9)

---

## 一、问题描述

在阅读区测试发现三类内容无法正常进行收藏标记或阅读位置标注：

| 问题 | 描述 |
|------|------|
| **表格** | 表格区域的内容不能进行收藏标记 |
| **标题** | 标题文本无法标注 |
| **引用文本** | 引用（blockquote）文本无法标注 |

"收藏标记" = 划选文字 → 弹出翻译/收藏弹窗 → 点击 Bookmark 按钮保存收藏
"标注" = 段落左侧 Bookmark 图标 → 点击设置/取消阅读位置标记

---

## 二、核心数据流

```
Markdown 正文
  ↓
react-markdown + remarkGfm 解析 AST
  ↓
MarkdownContent.components 自定义渲染器 → DOM 元素
  ↓  (data-para-index / data-section-id 附着在 DOM 上)
用户划选文字 → handleMouseUp
  ↓  (DOM 上游走查找 data-para-index / data-section-id)
弹出翻译弹窗 / 保存收藏 → createBookmark({ paragraphIndex, sectionId, ... })
```

**关键前提**：收藏和标注功能依赖两个 `data-*` 属性：
- `data-para-index` — 段落索引，附着在 `<p>` 和 `<li>` 元素上
- `data-section-id` — 所属 section，附着在 SectionFlow 的外层 `<div>` 上

这两个属性是 `handleMouseUp` 定位选区、计算 `contextSentence`、设置阅读标记的唯一依据。

---

## 三、逐类分析

### 3.1 表格（结论）

#### 3.1.1 根因

`MarkdownContent` 的 `components` 映射（[SectionFlow.jsx:52-127](src/components/SectionFlow.jsx#L52-L127)）中**未定义** `table`、`thead`、`tbody`、`tr`、`th`、`td` 的自定义渲染器。

```javascript
// 当前 components 中定义了这些：
{ p, h1, h2, h3, h4, ul, ol, li, blockquote, code, img }

// 缺失表格相关：table, thead, tbody, tr, th, td
```

#### 3.1.2 后果链

```
react-markdown 对表格使用默认 HTML 渲染
  → <table>, <tr>, <td> 等元素上没有 data-para-index
  → 用户划选表格内文字时，handleMouseUp DOM 上游走寻找 data-para-index：
     <td> → <tr> → <tbody> → <table> → <div data-section-id> → …
     全程无匹配 → anchorEl 最终为 null
  → paraIndex 保持默认值 0（错误）
  → paraText = (null?.textContent) || paragraphs[0]（完全错误的段落文本）
  → contextSentence 从错误文本中推导
  → 保存的 bookmark.paragraphIndex = 0（实际不应是 0）
  → 保存的 bookmark.contextSentence 与选中文字不匹配
```

同时：
- 表格单元格内无左侧 Bookmark 按钮 → **无法设置阅读位置标记**
- 表格单元格内无 `ParagraphRenderer` → **已有收藏在表格区域无高亮**

#### 3.1.3 论据链

1. **[SectionFlow.jsx:52-127](src/components/SectionFlow.jsx#L52-L127)**：`components` 对象中不存在 `table`/`tr`/`td`/`th` 等 key，react-markdown 对此类节点走默认 `<table>` 渲染
2. **[SectionFlow.jsx:54-56](src/components/SectionFlow.jsx#L54-L56)**：`data-para-index` 仅在自定义 `p` 和 `li` 组件中设置 (`<p data-para-index={idx}>`, `<li data-para-index={idx}>`)
3. **[ReaderPage.jsx:178-187](src/components/ReaderPage.jsx#L178-L187)**：`handleMouseUp` 中通过 `while (anchorEl && anchorEl.dataset?.paraIndex === undefined) { anchorEl = anchorEl.parentElement }` 查找段落索引 — 从 `<td>` 出发会一路走到 `null`
4. **[ReaderPage.jsx:199](src/components/ReaderPage.jsx#L199)**：`paraText` 通过 `anchorEl?.textContent` 或 `paragraphs[0]` 兜底 — 两者都不匹配实际表格内容
5. **[index.css](src/index.css)**：全文无任何 `table`/`th`/`td` 选择器 → 表格仅依赖浏览器默认样式，无任何自定义 CSS 干扰

### 3.2 标题（结论）

#### 3.2.1 根因

`h1`-`h4` 自定义组件（[SectionFlow.jsx:89-92](src/components/SectionFlow.jsx#L89-L92)）**仅渲染纯 HTML 标题标签**，无 `data-para-index`、无左侧 Bookmark 按钮、无 `ParagraphRenderer`。

```javascript
// 当前实现
h1: ({ children }) => <h1 className="article-h1">{children}</h1>,
h2: ({ children }) => <h2 className="article-h2">{children}</h2>,
h3: ({ children }) => <h3 className="article-h3">{children}</h3>,
h4: ({ children }) => <h4 className="article-h4">{children}</h4>,
```

#### 3.2.2 后果链

```
用户划选标题文字
  → <h1> 元素上无 data-para-index
  → handleMouseUp DOM 上游走失败
  → paraIndex = 0（错误）
  → paraText 来自不相干的 paragraphs[0]
  → 收藏内容错乱

同时：
  → 无左侧 Bookmark 按钮 → 无法设置阅读位置标记（标注"读到这里"）
  → 无 ParagraphRenderer → 无法高亮已有收藏
```

#### 3.2.3 论据链

1. **[SectionFlow.jsx:89-92](src/components/SectionFlow.jsx#L89-L92)**：`h1`-`h4` 组件定义为纯展示——只设 `className`，未走 `p` 组件的 `data-para-index` + `ParagraphRenderer` + Bookmark 按钮模式
2. **[ReaderPage.jsx:178-187](src/components/ReaderPage.jsx#L178-L187)**：同上 DOM 游走逻辑
3. 对比 `p` 组件（[SectionFlow.jsx:53-87](src/components/SectionFlow.jsx#L53-L87)）和 `li` 组件（[SectionFlow.jsx:95-103](src/components/SectionFlow.jsx#L95-L103)）——它们正确设置了 `data-para-index` 且包含 `ParagraphRenderer`
4. `getParagraphs()` 在 [progress.js:61](src/services/progress.js#L61) 显式跳过标题行 (`if (/^#{1,6}\s/.test(block)) continue`)，因此标题既不在 `paragraphs` 数组中，也不在 `paraIdxRef` 递增范围内 —— 这是**设计意图**（标题不是段落），但副作用是标题区域无法标注

#### 3.2.4 补充说明

标题不参与 `data-para-index` 索引并非 bug——这是段落系统的设计决策：`getParagraphs()` 跳过了标题行，`paraIdxRef` 也不为标题递增。问题在于：**当标题文本被选中时，系统没有任何机制来处理这种"非段落内容"的标注需求**。

---

### 3.3 引用文本 / Blockquote

#### 3.3.1 已验证事实

**✅ 已确认**：DevTools 实测 blockquote 内部的 `<p>` 元素**确实携带 `data-para-index`**：

```html
<blockquote class="article-quote">
  <div class="group relative">
    <button>📑</button>                    ← 左侧 Bookmark 按钮（存在）
    <p data-para-index="2" style="...">    ← ✅ data-para-index 存在
      <span>引用文本内容</span>
    </p>
  </div>
</blockquote>
```

`blockquote` 组件透传 `children`，内部段落走完整 `p` 组件路径 → DOM 基础设施完整。

#### 3.3.2 如果引用文本「无法标注」，根因需进一步缩小

既然 `data-para-index` 和 Bookmark 按钮都存在，blockquote 常规段落文本的**划选收藏流程理论上应能工作**（DOM 上游走能找到 `data-para-index`）。如果用户实测仍无法标注，可能原因降为两类：

**方向 A：CSS 视觉遮挡（当前最可能）**

左侧 Bookmark 按钮 `position: absolute; left: -32px`，相对于 `.group.relative`（`position: relative`）。blockquote 的 `padding: 0.6em 1.2em` + `border-left: 3px` 使视觉区域紧凑：
- 按钮可能被 blockquote 左侧边框遮挡
- 或与相邻元素的视觉区域重叠，点击命中到错误目标

**验证方法**：hover 在 blockquote 段落上，观察 Bookmark 图标是否**肉眼可见**并**可点击**。

**方向 B：测试内容含非段落子元素（子场景已结论）**

Blockquote 内嵌套的标题（`> # heading`）走 `h1`-`h4` 组件 → 同 3.2 节，无 `data-para-index`，属已知不可标注范畴。若测试数据恰好以这类内容为主，则用户感知为「引用文本无法标注」。

## 四、总结

| 问题 | 定位状态 | 根因 |
|------|---------|------|
| 表格无法收藏/标注 | **结论** | `components` 缺失 `table`/`tr`/`td`/`th` → 无 `data-para-index`、无 Bookmark 按钮、无 `ParagraphRenderer` |
| 标题无法标注 | **结论** | `h1`-`h4` 组件仅渲染纯 HTML → 无 `data-para-index`、无 Bookmark 按钮、无 `ParagraphRenderer` |
| 引用文本无法标注 | **推测** | ✅ 已验证 `<p>` 有 `data-para-index` + Bookmark 按钮。若仍不可用 → CSS 视觉遮挡，或测试内容含非段落子元素 |
| blockquote 内嵌套标题 | **结论（子场景）** | 与 3.2 节同根因——标题无 `data-para-index` |

### 根本矛盾

收藏/标注系统将内容二分为"段落"（`<p>` / `<li>` → 可标注）和"非段落"（`<h1>`-`<h4>` / `<table>` / `<pre>` → 不可标注）。任何非 `<p>` / `<li>` 渲染的内容都天然不支持标注。表格和标题是这种二分法的直接受害者。
