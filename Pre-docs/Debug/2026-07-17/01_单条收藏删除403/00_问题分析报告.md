# 问题分析报告：单条收藏软删除返回 403

- 日期：2026-07-17
- 状态：已完成根因定位，待确认修复方案
- 影响范围：阅读器正文高亮与侧边栏中的单条收藏删除

## 1. 现象

用户删除收藏时，浏览器向 `PATCH /rest/v1/bookmarks` 发送软删除请求，返回 HTTP 403：

```text
new row violates row-level security policy for table "bookmarks"
```

两个删除入口均会复现：

- 正文中的收藏高亮/悬浮操作；
- 阅读器侧边栏收藏列表。

## 2. 结论

根因是**单条收藏删除路径的修复回归**。

历史实现已通过 `soft_delete_bookmark(text)` RPC 处理单条收藏软删除；当前 `develop` 分支在阅读模型重构后将实际实现迁移到 `src/services/readings.js`，但新实现重新使用 REST PATCH，未沿用 RPC。线上数据库仍有该 RPC，但当前代码未调用，且当前代码库也没有对应 migration 定义。

这使删除重新进入已知会返回 RLS 403 的 REST PATCH 边界。

## 3. 证据链

### 3.1 实际失败请求与当前实现一致

`src/services/readings.js` 的 `deleteBookmark` 云端路径执行：

```js
client
  .from('bookmarks')
  .update({ deleted_at: new Date().toISOString() })
  .eq('user_id', options.userId)
  .eq('id', bookmarkId)
  .is('deleted_at', null)
```

这与控制台中的 `PATCH /rest/v1/bookmarks?...&deleted_at=is.null` 一致。

正文与侧边栏最终都通过 `ReaderPage` 调用相同的 `deleteBookmark`，因此两处同时失败是同一条调用链的结果，而不是两个 UI 问题。

### 3.2 数据库拒绝发生在 RLS 新行校验

失败响应为：

```json
{
  "code": "42501",
  "message": "new row violates row-level security policy for table \"bookmarks\""
}
```

线上策略已确认：

| 策略 | 命令 | 条件 |
| --- | --- | --- |
| `bookmarks_select_own` | SELECT | `auth.uid() = user_id AND deleted_at IS NULL` |
| `bookmarks_update_own` | UPDATE | `USING (auth.uid() = user_id AND deleted_at IS NULL)`；`WITH CHECK (auth.uid() = user_id)` |

故失败发生在直接 PATCH 与 RLS 的交互边界，而不是记录不存在或前端本地状态删除失败。

### 3.3 身份、归属和会话均已排除

| 项目 | 已确认结果 |
| --- | --- |
| 书签 ID | `bm_1784274983480_ce4qh` |
| 书签 `user_id` | `3f0a83cd-40b6-4c55-93dc-2fc24aad95a6` |
| 当前浏览器会话 `userId` | `3f0a83cd-40b6-4c55-93dc-2fc24aad95a6` |
| 会话是否过期 | 否 |
| 请求是否有 Authorization | 是 |
| 书签是否已经软删除 | 否（`deleted_at IS NULL`） |

因此，不能将本问题归因为用户切换、会话过期、书签归属错误或目标行已删除。

### 3.4 历史修复和当前回归

历史提交 `664dd3c` 曾：

1. 创建 `public.soft_delete_bookmark(bookmark_id text)`；
2. 将 `deleteBookmark` 从 PATCH 改为 `.rpc('soft_delete_bookmark', { bookmark_id })`；
3. 在函数内部以 `auth.uid()` 限定书签所有权。

线上确认该函数仍存在：

```text
soft_delete_bookmark(text)
```

但该历史提交不在当前 `develop` 分支祖先链中；现在的 `src/services/library.js` 只是对 `readings.js` 的 re-export，当前有效实现已回到 PATCH。当前 migration 目录也没有该 RPC 的定义，造成代码、迁移与线上数据库状态不一致。

## 4. 影响

- 已登录用户无法删除任意单条云端收藏；
- 正文和侧边栏均受影响；
- 收藏关联阅读内容时的批量软删除不受此问题影响，因为它使用的是另一条 RPC 路径 `soft_delete_bookmarks_for_reading`；
- 本地存储模式不受影响，因为本地路径不经过 Supabase RLS。

## 5. 根因边界说明

已能确定 REST PATCH 路径在当前线上策略下触发 RLS 403，且恢复 RPC 是项目历史上已使用的受控机制。

PostgREST 在内部如何构造 RLS 校验上下文不可由前端直接观测；因此报告不将某个内部实现细节作为唯一前提。修复应以可观测事实为依据：直接 PATCH 稳定失败，受所有权检查保护的 RPC 已存在且专为该操作设计。
