## 二、P1-1 修复：重新阅读后刷新书架 + 阅读区

**文件**：[src/components/ImportPage.jsx](../../src/components/ImportPage.jsx)

`handleRestartReading` 成功后刷新三个列表（与 `handleMoveToReading` 同构），依赖数组同步补上（已实施）：

```js
const handleRestartReading = useCallback(async (reading) => {
  if (!confirm('将清除本书的所有书签和阅读进度，确定要重新开始吗？此操作不可撤销。')) return
  try {
    await restartReading(reading.id, { canUseCloudLibrary, userId })
    await loadLibraryState()
    await loadReadingZone()   // ← 重新开始直接进阅读区，需刷新阅读区
    await loadImportItems()   // ← 书架列表同步（条目移出书架）
  } catch (e) {
    if (isLibraryAccessError(e)) refreshAuthState()
    setError(e.message || '重新开始失败')
  }
}, [canUseCloudLibrary, userId, loadLibraryState, loadReadingZone, loadImportItems, refreshAuthState])
```

**说明**：统一取书模型下，重新阅读与「取书」走同一条「取书到阅读区」路径，故成功后的刷新动作与 `handleMoveToReading` 完全一致。

## 三、P1-2 修复：云端 mark 清理改为原子 RPC

### 方案 A（已采用）：新增原子 RPC `restart_reading`

与现有 `delete_reading` RPC 同构（SECURITY DEFINER 绕过 RLS，可 `DELETE FROM reading_marks`），把「清场 + 置 reading」收进一个数据库事务，根治「mark 清不掉」与「半重置」。

**新增迁移文件**：`supabase/migrations/20260921000001_add_restart_reading_rpc.sql`（已创建）

```sql
CREATE OR REPLACE FUNCTION public.restart_reading(p_reading_id text)
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
AS $$
BEGIN
  IF auth.uid() IS NULL THEN
    RAISE EXCEPTION 'unauthenticated' USING ERRCODE = '42501';   -- B1：带 errcode，JWT 重试可命中
  END IF;

  PERFORM public.lock_reading_user(auth.uid());                  -- 显式 advisory lock，对齐新版 RPC

  UPDATE public.bookmarks
  SET deleted_at = now()
  WHERE reading_id = p_reading_id
    AND user_id = auth.uid()
    AND deleted_at IS NULL;

  DELETE FROM public.reading_marks
  WHERE reading_id = p_reading_id
    AND user_id = auth.uid();

  UPDATE public.readings
  SET reading_status = 'reading',        -- 统一取书模型：清场后直接进阅读区
      reading_started_at = now(),
      reading_finished_at = NULL,
      updated_at = now()
  WHERE id = p_reading_id
    AND user_id = auth.uid()
    AND deleted_at IS NULL;
END;
$$;

REVOKE ALL ON FUNCTION public.restart_reading(text) FROM public, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.restart_reading(text) TO authenticated;
```

（迁移文件含 `begin;`/`commit;` 与 `notify pgrst, 'reload schema';`，沿用最新迁移约定。）

**JS 侧**（[src/services/readings.js](../../src/services/readings.js)）`restartReading` 云端路径为单次 RPC + 错误检查 + 鉴权重试（已实施）：

```js
export async function restartReading(readingId, options) {
  if (!useCloudSource(options)) {
    bookmarkStore.deleteByArticle(readingId)
    readingMarkStore.delete(readingId)
    const article = articleStore.getById(readingId)
    if (article) {
      article.readingStatus = 'reading'
      article.readingStartedAt = new Date().toISOString()
      article.readingFinishedAt = null
      article.updatedAt = new Date().toISOString()
      articleStore.save(article)
    }
    return
  }

  const client = getSupabaseClient()
  const { error } = await client.rpc('restart_reading', { p_reading_id: readingId })

  if (isLibraryAccessError(error)) {
    try { await getSession() } catch (_) { if (error) throw error; return }
    const { error: retryError } = await client.rpc('restart_reading', { p_reading_id: readingId })
    if (retryError) throw retryError
    return
  }

  if (error) throw error
}
```

## 四、P2 决策（已定稿：统一取书模型）

书架所有条目的动作心智统一为**「取书到阅读区」**，视觉样式仍区分，区别只在取之前是否清场：

| 状态 | 入口 | 动作 | 是否清场 | 结果 |
|------|------|------|---------|------|
| unread | 主按钮「取书」图标 | `startReading` | 否 | `reading` |
| in_progress | 主按钮「XX%」 | `startReading` | 否 | `reading` |
| in_progress | more menu「重新开始」 | `restartReading` | 是 | `reading`（从头开读） |
| completed | 主按钮「重新开始」 | `restartReading` | 是 | `reading`（从头开读） |

**P2-1（已实施）**：`in_progress` more menu 补「重新开始」（[ImportItemList.jsx](../../src/components/ImportItemList.jsx)），补齐其从头开读的路径。

**P2-2（不设「保留完成标记继续」，改为清场后开读）**：`completed → reading` 的入口是「重新开始」而非「继续阅读」。依据（B2 的根因即完成标记的一次性语义）：`start_reading` RPC 不清 `completed`/`reading_finished_at`，复用会制造「继续不了」的坏状态；阅读器把 `reading_marks.completed=true` 当终态（进度保存 `isSameMark` 恒 false、跳转标记禁用、已读完徽标只读）。文档动作：C5/D3 状态流转已同步为「任意状态 → reading 重新阅读」（[02_决策记录.md](../../开发/05_阅读区书架区数据模型统一_2026-07-11/02_决策记录.md)）。
