## 三、问题清单

### 🔴 P1-1 重置后书架列表状态不刷新（确定性 UI bug）

**位置**：[ImportPage.jsx:188-198](../../src/components/ImportPage.jsx#L188-L198) `handleResetReading`

**现象**：点击「重新阅读」→ toast 提示「已重置，可重新阅读」，但该条目仍停留在「已读完」Tab、仍显示「已读完」胶囊和「重新阅读」按钮；切换 Tab 也不变，需整页刷新才归位。

**根因**：
- 书架列表渲染自 `importItems`（[ImportPage.jsx:789](../../src/components/ImportPage.jsx#L789)），由 `loadImportItems`（[149-155](../../src/components/ImportPage.jsx#L149-L155)）维护。
- `handleResetReading` 成功后只调用 `loadLibraryState()`（刷新 `articles/bookmarks/readingMarks`），**未调用 `loadImportItems()`，也未本地更新 `importItems`**。

**对照**：同文件 `handleMoveToReading`、`handleReturnToShelfFromList`、`handleDeleteImportItem` 均正确刷新或本地更新 `importItems`，唯独 reset 漏掉。

**影响**：用户无法从 UI 确认重置已生效；重复点击会再次触发重置（幂等但体验混乱）。

---

### 🔴 P1-2 云端 reading_mark 永远清不掉（确定性数据完整缺陷）

**位置**：[readings.js:580-605](../../src/services/readings.js#L580-L605) `resetReading` 云端路径

**现象**：云端「重新阅读」后，`reading_marks` 表残留 `completed=true` / `progress_percent=100` / 末尾 `paragraph_index`，进度与完成标记**从未被清除**。表现：
- Header「已读篇数」仍计入该书（`completedCount = readingMarks.filter(m => m.completed).length`）。
- 用户重新取书阅读时，阅读器加载到旧 mark，可能显示「已读完」态或跳到文末。

**根因（确定性，非偶发）**：
1. `reading_marks` 表仅有 SELECT/INSERT/UPDATE 三条 RLS 策略，**无 DELETE 策略**；`grant` 也仅 `select, insert, update`（[create_core_user_tables.sql:131-155](../../supabase/migrations/20260509170000_create_core_user_tables.sql#L131-L155)）。全迁移链无任何 reading_marks 的 DELETE 授权/策略。
2. 因此 [readings.js:588-592](../../src/services/readings.js#L588-L592) 的 `client.from('reading_marks').delete()` 被授权/RLS 拒绝，行不会被删除。
3. 且该调用未解构 `{ error }`、未抛错，失败被静默吞掉——用户看到「已重置」成功提示，但 mark 依旧。

**旁证（团队已知此限制，唯独 reset 漏用）**：
- `deleteReading` 的 `executeCloudDelete` 用 `.upsert()` 把 mark 清空（`paragraph_index=null, completed=false`）而非 `.delete()`（[readings.js:620-632](../../src/services/readings.js#L620-L632)）。
- `clearReadingMark` 走 `rpc('clear_reading_mark_position')`（[readings.js:854-867](../../src/services/readings.js#L854-L867)）。
- 全代码库对 `reading_marks` 的直接 `.delete()` 仅 `resetReading` 一处。

**次要问题（同函数内）**：云端三步（书签 RPC / mark 删除 / readings 更新）均未检查 `error`，也未像 `deleteReading` 那样做 JWT 过期重试。即便 mark 删除被修正，任何一步失败仍会静默半重置。

---

### 🟡 P2-1 `in_progress` 无重置入口（与规范 Z1 冲突）

**位置**：[ImportItemList.jsx:276-296](../../src/components/ImportItemList.jsx#L276-L296)

`in_progress` 主按钮固定为「继续 XX%」，More menu 无重置项。**未读完的书没有任何办法清零进度**——只能删除重导入（丢失 sections/元数据/推荐分享关联）或先读完再重置。

**规范冲突**：C5「任意状态 → unread」；Z1 测试对象为「in_progress/completed 书」。06 视觉刷新（v4.1.1）把 `in_progress` 主按钮定为「继续」并移除 more menu 的重置项，实质收窄了 D3 的入口，但未同步修订 C5/Z1 文档。

### 🟡 P2-2 `completed` 无继续阅读入口（与规范 C5 冲突）

**位置**：[ImportItemList.jsx:255-275](../../src/components/ImportItemList.jsx#L255-L275)

`completed` 主按钮是破坏性的「重新阅读」。C5 规定的「completed → reading 继续阅读」（保留数据重新打开）无入口，用户只能被强制先清空。

### 🟢 P3 破坏性操作交互不一致

**位置**：[ImportPage.jsx:189](../../src/components/ImportPage.jsx#L189)

重置用原生 `confirm()`，而删除用带焦点圈/aria-modal/Escape 的可访问弹窗（[ImportItemList.jsx:413-469](../../src/components/ImportItemList.jsx#L413-L469)）。`confirm()` 不可键盘/aria 管理，部分容器环境会被禁用。

| 规范条目 | 期望 | 现状 | 判定 |

## 五、影响范围与复现路径

**复现 P1-1**：登录 → 书架「已读完」Tab → 对某 completed 条目 hover 点击「重新阅读」→ 确认 → 观察该条目仍显示「已读完」且按钮不变（toast 已提示「已重置」）。

**复现 P1-2（云端）**：同上操作后，Supabase SQL Editor 查
`SELECT completed, progress_percent, paragraph_index FROM reading_marks WHERE reading_id = '<id>'`，行仍存在且 `completed=true`；随后重新取书，阅读器停在末尾/显示已读完。
