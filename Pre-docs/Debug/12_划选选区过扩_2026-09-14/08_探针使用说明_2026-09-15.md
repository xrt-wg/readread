# 选区探针 — 使用说明

> **日期**：2026-09-15
> **代码**：`src/debug/selectionProbe.js`（接入点：`ReaderPage.jsx` 挂载时幂等初始化）
> **性质**：只读诊断——只记录日志，不改变、不拦截任何现有行为；已通过 `npm run build` 验证。
> **目的**：对机制链最后一环做直接观测（见 `07_起笔位置实验判读_2026-09-15.md` 第五节）。

---

## 一、操作步骤

1. 正常启动应用（`npm run dev`），进入阅读页；
2. 按 **Ctrl + Shift + L** 开始记录 —— 屏幕左上角出现红色 **● REC 选区探针** 标记；
3. 按之前的手感复现问题（「收藏一个词 → 划选紧邻的下一个词」），**直到发作一次**（可以试多次，日志会持续累积）；
4. 发作后再按 **Ctrl + Shift + L** 停止 —— 浏览器自动下载 `selection-probe-<时间戳>.json`；
5. 把该 JSON 文件交给我分析。

兜底：若下载失败，DevTools Console 里所有日志都有（前缀 `[probe]`），也可在 Console 执行 `copy(JSON.stringify(__selectionProbe.logs))` 复制。

---

## 二、日志格式速览

每条记录：`{ t: 相对毫秒, type, ... }`

| type | 含义 | 关键字段 |
|------|------|---------|
| `down` / `up` | 鼠标按下/抬起（capture 阶段，只读） | 坐标、`detail`（连击计数）、`up` 时选区长度与开头文本 |
| `sel` | selectionchange 快照 | `drag`（是否在拖选中）、`anchor`/`focus` 节点身份（类型/文本片段/所属段落/所属收藏/**connected**）与 offset |
| `mut` | DOM 变更 | `drag`、`zone`（paragraph/popup/other）、段落号、增删节点文本片段、characterData 旧值 |

---

## 三、判读规则（发作的那次拖选，即 `down`→`up` 区间）

| 日志表现 | 判读 |
|---------|------|
| 拖选途中（`drag:true`）锚点段落出现 `mut`，且后续 `sel` 中锚点 `connected:false` 或身份跳变到靠前段落 | ✅ M-render 实锤：DOM 变更移除锚点节点 → 机制链闭合，出修复方案 |
| 发作（`up` 时 len 异常大）但全程无 `mut` | ❌ DOM 变更说被推翻 → 转向浏览器原生选区行为方向，方案空间重估 |
| `down` 的 `detail ≥ 2` 伴随发作 | 连击误判残余可能复活（但换鼠标实验已排除硬件，需查软件层） |

---

## 四、注意事项

- 探针默认关闭，不影响正常使用；测试完可留着（无副作用），修复落地后再移除；
- 发作时请**顺手记下误选起点的位置**（上一段段首？文章开头？上一个已收藏词处？）——这是 07 报告第四节的待补信息；
- 仍请补录 04 / 06 两次实验的环境差异（是否登录云端、网络状况、预读/非预读模式），用于调和两次实验结果的矛盾。
