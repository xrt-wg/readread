# 延迟对照实验 — 测试清单与记录表

> **日期**：2026-09-15
> **目的**：验证 M-render 机制（拖选途中锚点文本节点被异步重渲染销毁）。
> **判别逻辑**：若问题由「收藏后的异步重渲染窗口与下一次拖选重叠」引起，则**等待窗口关闭后再划选应几乎不发作**，而**紧接着划选应高频发作**。两组复现率的显著差异即为竞态机制的确认证据。
> **前置文档**：`03_机制定位报告_2026-09-15.md` 第四节

## 二、A 组：延迟划选（对照组，预期几乎不发作）

每次迭代：

1. 划选一个未收藏的词，完成收藏（预读：划完即收藏；非预读：弹窗点收藏）。
2. **开始计时，等待 5 秒**（期间不碰鼠标键盘；此等待覆盖两波异步重渲染：保存回写 + 翻译完成回调）。
3. 紧接着划选**下一个词**（优先选与刚收藏词同句/同段、紧挨或邻近的词），完成收藏。
4. 观察并记录：本次划选是否出现「选区突然过扩 / 收藏列表出现大段误收藏」。
5. 若发作：额外记录误选内容的**起点**（是否为刚收藏词所在段的段首）、是否跨段。

重复 20 次。

## 三、B 组：紧接划选（实验组，预期高频发作）

每次迭代：

1. 划选一个未收藏的词，完成收藏。
2. **不等待**，以自然最快速度立刻划选下一个词（同样优先同句/同段邻近词），完成收藏。
3. 观察并记录：是否发作；若发作，记录误选起点、是否跨段。

重复 20 次。

> ⚠️ 注意：B 组若发作产生了大段误收藏，**先在收藏列表删除该误收藏条目**再进行下一次迭代，避免误收藏的大段高亮改变后续测试的 DOM 环境。

## 五、结果判读

| 结果 | 判读 |
|------|------|
| A ≈ 0 且 B 高频（≥5/20） | ✅ 竞态机制确认：发作依赖「异步重渲染窗口 × 拖选」的时间重叠。结合代码事实链，M-render 可定为结论 |
| A、B 均高频且相近 | ❌ 与竞态机制矛盾：发作不依赖等待时间 → 需重新审视（可能为确定性结构/手势因素，回到 H1 方向并用探针正面观测） |
| A、B 均 ≈ 0 | ⚠️ 本次环境未复现（窗口太窄/条件未命中）：改做第六节放大实验；仍不复现则说明触发还需未知条件，记录环境备查 |
| A 也发作但明显少于 B | 🔶 部分支持：可能存在第二条触发路径（如翻译完成的第二波重渲染滞后超过 5 秒）→ 把 A 组等待延长到 10 秒重测 |

**误选起点统计（两组汇总）**：起点为段首 ____ 次；非段首 ____ 次；跨段 ____ 次。
（起点恒为段首 → 与「锚点回落段首」吻合；起点不定 → 需重新审视机制细节。）

## 六、可选放大实验：Slow 3G 节流（A/B 差异不显著或均不复现时执行）

1. DevTools → Network → Throttling 选 **Slow 3G**（云端路径下异步窗口被拉宽至秒级）。
2. 只跑 B 组流程 ×20。
3. 判读：节流后 B 组复现率较未节流显著上升 → 强支持「异步窗口宽度决定发作概率」；无变化 → 削弱 M-render（窗口宽度应敏感）。
