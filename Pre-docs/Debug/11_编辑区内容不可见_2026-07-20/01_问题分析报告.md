# 编辑区「内容编辑」tab 看不到内容 — 问题分析报告

**日期**：2026-07-20
**分支**：`feat/unify-readings-model`
**现象**：在书架点击编辑，切换到「内容编辑」标签页，文章正文区域为空。

---

## 1. 调用链

```
书架 → 点击「编辑」→ setEditingItem(item)
  → ImportItemEditor item={editingItem}
    → sections = (item.sections || []).map(...)
    → item.sections = []  ← 空数组
    → 内容编辑 tab 为空
```

---

## 2. 根因

**书架列表查询故意不含 `sections` 列，但编辑器直接用列表数据初始化编辑区。**

`readings.js` 定义了两组查询列：

```js
// 列表列（不含 sections，避免 MB 级无效传输）
const READING_LIST_COLUMNS = 'id, user_id, title, author, ..., reading_status, ...'

// 详情列（含 sections 正文）
const READING_DETAIL_COLUMNS = READING_LIST_COLUMNS + ', sections'
```

各函数使用的列组：

| 函数 | 用途 | 列组 | 含 sections |
|------|------|------|:--:|
| `fetchImportItems` | 书架列表 | `READING_LIST_COLUMNS` | ❌ |
| `listShelfReadings` | 书架（新 API） | `READING_LIST_COLUMNS` | ❌ |
| `listReadingZone` | 阅读区列表 | `READING_LIST_COLUMNS` | ❌ |
| `getReading` | 详情（单条） | `READING_DETAIL_COLUMNS` | ✅ |

`fetchImportItems` 返回的 item 经 `mapReadingRow` → `sections: row.sections ?? []` → `undefined ?? []` → `[]`。

`ImportItemEditor` 打开时直接使用这条列表数据初始化：

```js
// ImportItemEditor.jsx:80
const [sections, setSections] = useState(() =>
    (item.sections || []).map((s) => ({
      id: s.id, heading: s.heading || '',
      bodyText: s.body?.text || '',
      bodyMarkdown: s.body?.markdown ?? null,
    }))
)
```

`item.sections = []` → `.map([])` → `[]` → 内容编辑区无任何段落。

---

## 3. 设计意图 vs 实际使用

列表不含 `sections` 是正确设计——书架可能包含数十本书，每本 sections 是几十 KB 的 JSONB，全量传输浪费带宽。

但编辑器只编辑**一个**条目，应该获取完整数据。当前编辑入口绕过了详情查询，直接复用了列表数据，形成了数据缺口。
