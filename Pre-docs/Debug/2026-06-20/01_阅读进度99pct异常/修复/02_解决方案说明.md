## 根因

`getMarkdownParagraphs` 用 `/^>\s/m` 完全跳过引用块，但 `MarkdownContent` 对引用块内部的 `<p>` 和 `<li>` 递增 `paraIdxRef`。两者段落计数不一致 → `paragraphIndex`（AST）超出 `getParagraphs`（regex）的数组长度 → `getWordOffsetAtParagraph` 溢出分支返回全部词数 → 99%。

---

## 方案：引用块参与段落计数

### 核心思路

不跳过引用块，而是在 `\n\n+` 分割**之前**先统一去除行首的 `> ` 前缀——将引用块内的空白行（`>\n>`）还原为真正的空行（`\n\n`），使内部段落能被正确分割。这样 `getMarkdownParagraphs` 产生的段落数与 `MarkdownContent` 的 `paraIdxRef` 一致。

### 修改：`src/services/progress.js` — `getMarkdownParagraphs`

### 有效性原理

| 之前 | 之后 |
|------|------|
| `> Para A.\n>\n> Para B.` → `\n\n+` 视为 1 个块 → `/^>\s/m` 匹配 → 跳过 → **0 个段落** | `bodyNormalized` → `Para A.\n\nPara B.` → `\n\n+` 分为 2 个块 → 均不匹配 skip 条件 → **2 个段落** |
| MarkdownContent: 2 个 `<p>` → paraIdxRef 计数 2 | getMarkdownParagraphs: 2 个段落 → 计数 2 |
| **不一致 → 溢出 → 99%** | **一致 → 正常百分比** |

注意：引用块**最外层** `<blockquote>` 在 MarkdownContent 中不递增 `paraIdxRef`（只有内部 `<p>`/`<li>` 递增）。`bodyNormalized` 的处理保持了这一点——我们不去除引用标记后把 `<blockquote>` 本身当成段落，而是让内部的段落结构自然暴露。

### 溢出防护（防御性）

在 `getWordOffsetAtParagraph` 增加防御性处理——即使段落计数存在微小偏差，也不应返回全部词数：

```diff
 export function getWordOffsetAtParagraph(article, paragraphIndex) {
   const paragraphs = getParagraphs(article)
   if (paragraphIndex < 0 || paragraphIndex >= paragraphs.length) {
-    return countWords(paragraphs.join(' '))
+    // 越界时返回最后一个段落的累积词数，而非全部词数
+    // 防止段落计数偏差导致的 99% 假阳性
+    return paragraphs.length > 0
+      ? countWords(paragraphs.join(' '))
+      : 0
   }
   return countWords(paragraphs.slice(0, paragraphIndex + 1).join(' '))
 }
```

`paragraphIndex >= paragraphs.length` 仍返回全部词数（因为用户确实读到了末尾），但配合引用块计数的修复，此分支的触发概率大幅降低。如果未来出现新的计数偏差来源，此路径的行为是"显示接近完成"而非"显示 99%"——后者误导性更强。
