## 二、核心类型定义

### 2.1 Document

```js
/**
 * @typedef {Object} Document
 * @property {string} id
 *          格式: "doc_" + Date.now() + "_" + random5chars
 *          示例: "doc_1718000000_a3f2b"
 *          新创建的文章使用 "doc_" 前缀。现有文章的 "art_" 前缀保持不变。
 *          documentId 字段接受任一种前缀，不做批量 ID 重命名。
 *
 * @property {string} title
 *          文档标题，必选。不可为空字符串。
 *
 * @property {string|null} author
 *          作者。EPUB 可从 metadata 提取，其他格式为 null。
 *          默认值: null。
 *
 * @property {DocumentFormat} format
 *          来源格式。允许值见下文 DocumentFormat 类型。
 *
 * @property {string|null} coverUrl
 *          封面图。EPUB 可提取为 base64 data URL；其他格式为 null。
 *          存储格式: "data:image/jpeg;base64,..."（Canvas 缩放至 max 300px）。
 *          默认值: null。
 *
 * @property {string} lang
 *          文档语言。默认值: 'auto'。
 *          当为 'auto' 时，后续可根据 navigator.language 或文本内容推断。
 *
 * @property {string|null} sourceUrl
 *          来源 URL。URL 导入时记录原始 URL；其他格式为 null。
 *          默认值: null。
 *
 * @property {Section[]} sections
 *          平铺的一级数组。始终至少包含 1 个 section。
 *          单 section 文档: [{ id: "s_main", heading: null, ... }]。
 *
 * @property {number} totalWordCount
 *          sum(section.body.wordCount)。整数 >= 0。
 *
 * @property {number} sectionCount
 *          sections.length。整数 >= 1。
 *
 * @property {string} createdAt
 *          ISO 8601 格式。示例: "2026-06-13T10:30:00.000Z"。
 *
 * @property {string|null} updatedAt
 *          ISO 8601 格式。默认值: null。
 */

/**
 * @typedef {'url'|'epub'|'pdf'|'paste'|'markdown'|'html'} DocumentFormat
 * 'url'       — URL 导入的文章
 * 'epub'      — EPUB 书籍
 * 'pdf'       — PDF 文档（预留，当前 PDF 提取未实现）
 * 'paste'     — 粘贴的纯文本
 * 'markdown'  — Markdown 文件
 * 'html'      — HTML 文件
 */
```

### 2.2 Section

```js
/**
 * @typedef {Object} Section
 *
 * @property {string} id
 *          节 ID，在 document.sections 数组内唯一。
 *          格式: "s_" + index（如 "s_0", "s_ch1"）。
 *
 * @property {string|null} heading
 *          节标题，如 "Chapter 1: The Beginning"。
 *          null 表示该节无标题。
 *          标题为纯文本，不包含 Markdown 语法。
 *
 * @property {number} depth
 *          层级深度。0 = 顶层（章），1 = 第二层（节），2 = 第三层（小节）。
 *          必须 >= 0。
 *
 * @property {string|null} parentId
 *          父节的 id。null 表示顶层节点。
 *          由工厂函数 createDocument 根据 depth 推导，不由提取器直接设置。
 *
 * @property {number} order
 *          在文档顺序中的排序序号，从 0 开始。
 *          sections 数组中 order 按文档出现顺序递增。
 *
 * @property {Object} body
 * @property {string} body.text
 *          纯文本正文。始终存在，可为空字符串（纯容器节点）。
 * @property {string|null} body.markdown
 *          富文本格式正文。可为 null（粘贴的纯文本、PDF 提取）。
 *          当不为 null 时，应为有效的 Markdown 字符串。
 * @property {number} body.wordCount
 *          本节词数。计算方式: text.split(/\s+/).filter(Boolean).length。整数 >= 0。
 */
```

### 2.3 字段命名一致性声明

- **数据库列名**使用 `snake_case`（如 `word_count`、`source_url`、`section_count`）
- **JSONB `sections` 内部字段**使用 `camelCase`（如 `parentId`、`wordCount`、`sectionCount`）
- **JS 端所有字段**使用 `camelCase`
- `mapArticleRow` 负责 `snake_case` ↔ `camelCase` 转换；sections JSONB 内部不做转换

## 三、Section.body 的切分规则

### 3.1 核心原则

每个 section 的 `body` 是**独立、互不重叠、互不包含**的文本块。

### 3.2 边界定义

```
以 EPUB 为例，原始内容结构：

  Chapter 1: Getting Started           ← 章标题
  "In this chapter we'll cover..."     ← 章引言
  1.1 Installation                     ← 子节标题
  "Download the latest version..."     ← 子节正文
  1.2 Configuration                    ← 子节标题
  "Create a .env file..."             ← 子节正文
```

映射为 sections：

```
s_ch1.body.text = "In this chapter we'll cover..."
  ↑ 章标题下方、第一个子标题上方的文本

s_ch1-s1.body.text = "Download the latest version..."
  ↑ 子标题"1.1 Installation"下方、下一个同级标题上方的文本

s_ch1-s2.body.text = "Create a .env file..."
  ↑ 子标题"1.2 Configuration"下方、下一个同级标题上方的文本
```

### 3.3 规则细则

| 规则 | 说明 |
|------|------|
| **互斥性** | 每段原始文本只属于一个 section.body，不会同时出现在两个 body 中 |
| **父节不包含子节** | 父节 body 仅包含第一个子标题出现之前的文本。子标题之后的文本属于各子节 |
| **空 body 合法** | 如果父节标题下方直接就是子节标题，父节 body.text 为空字符串 |
| **无子节时全归属** | 如果一个 section 没有任何子节，其 body 包含标题下的全部文本 |
| **文本边界由提取器决定** | 提取器根据原始格式的标题层级切分文本。EPUB 从 toc 读取，Markdown 从 `#` 扫描 |
| **不拼接** | 渲染时只展示当前 section 的 body，不拼接父节或兄弟节的 body |

### 3.4 边界情况

#### 同级 section 之间的散落文本

```
1.1 Installation      ← s_ch1-s1
"..."
[无名过渡段落]         ← 不属于任何子节
1.2 Configuration     ← s_ch1-s2
```

处理方式：归入前一个子节 `s_ch1-s1.body`，作为其 body 的延续部分。

#### 父节无 body

```
Chapter 2: Core Concepts   ← 标题后直接就是子节列表
2.1 Functions
2.2 Classes
```

处理方式：`s_ch2.body.text = ""`，`s_ch2.body.markdown = null`。section 作为纯容器存在。

#### 单 section 文档

```
单 section 文档（URL 导入、粘贴文本、无 ## 标题的 Markdown）：
  heading 始终为 null。
  即使内容中包含 "# 标题" 或 "## 子标题"，也不提取为 section heading——
  单 section 文档的 document.title 已承担标题语义。
  仅当存在多个 ## 级别标题切分为多个 section 时，heading 才非 null。
```

## 四、下游引用模型

### 4.1 Bookmark

```js
/**
 * @typedef {Object} Bookmark
 *
 * // —— 标识 ——
 * @property {string} id                收藏 ID，格式 "bm_" + timestamp + random5
 * @property {string} documentId        所属文档 ID（即原来的 articleId）
 * @property {string|null} sectionId    所属 section.id。null 时视为 "s_main"
 *
 * // —— 冗余展示字段 ——
 * @property {string|null} sectionHeading
 *          section.heading 的快照，写入时同步。
 *          陈旧策略：write-time snapshot。如果 section.heading 后续被修改，
 *          已存在的 bookmark 不会自动更新。读取时优先使用 sectionHeading，
 *          若为空/null 则回退查询 document.sections 中对应 section 的 heading。
 *
 * // —— 定位 ——
 * @property {number} paragraphIndex    section 内的局部段落索引（从 0 开始）
 * @property {number} charOffset        段落内字符偏移量
 *
 * // —— 内容 ——
 * @property {'word'|'phrase'|'sentence'|'paragraph'} type
 * @property {string} text             收藏原文
 * @property {string|null} translation
 * @property {string|null} contextSentence
 * @property {string|null} contextTranslation
 * @property {string} translationStatus  'pending' | 'done' | 'error'
 *
 * // —— 复习预留 ——
 * @property {number} reviewCount      复习次数，默认 0
 * @property {string|null} nextReviewAt  下次复习时间
 * @property {number} familiarity      熟悉度 0-5，默认 0
 *
 * // —— 时间戳 ——
 * @property {string} createdAt
 * @property {string|null} updatedAt
 */

// 与旧结构的对照：
//   旧: { articleId, paragraphIndex, charOffset }
//   新: { documentId, sectionId, paragraphIndex, charOffset }
//   sectionId 为 null → 代码中处理为 "s_main"
//   paragraphIndex 在单 section 文档中与旧值一致
```

### 4.2 ReadingProgress

```js
/**
 * @typedef {Object} ReadingProgress
 *
 * @property {string} documentId               所属文档 ID
 * @property {string|null} sectionId           当前阅读所在的 section.id。null 时视为 "s_main"
 * @property {number|null} paragraphIndex       section 内的段落索引。null 表示未设置
 * @property {string[]} completedSections      已读完的 section.id 列表
 * @property {boolean} completed               全文是否已读完
 */
```

#### `completedSections` 语义

| 操作 | 效果 |
|------|------|
| 用户在某 section 的阅读进度 >= 90% | 该 sectionId 加入 `completedSections` |
| 用户回到已完成 section 重新阅读 | 从 `completedSections` 中移除该 sectionId |
| 用户显式点击"标记已读完" | 所有 sectionId 加入 `completedSections` 且 `completed = true` |
| `completedSections.length === document.sectionCount` | 全文完成，`completed` 自动为 true |

### 4.3 回顾面板展示

回顾时，收藏卡片展示 section 来源：

```
┌────────────────────────────────┐
│  ● 词  · 6月13日               │
│                                │
│  brick walls                   │
│                                │
│  砖墙                          │ ← 翻译
│                                │
│  Chapter 3 · 第 12 段          │ ← sectionHeading + paragraphIndex
│  "The brick walls..."          │ ← contextSentence
└────────────────────────────────┘
```

`sectionHeading` 存储在 bookmark 中，使回顾面板无需加载完整 Document 即可展示上下文来源。展示时优先使用 bookmark 中的 `sectionHeading`，若为空则回退查询 `document.sections`。

回顾面板加载 bookmark 时需要预取关联 Document 的 metadata（至少 `sections` 数组），以支持回退查询。单 section 文档或 sectionHeading 有值的 bookmark 不需要额外查询。

## 五、各格式到 Document 的映射规范

### 5.1 URL 导入

```
输入: { title, text, markdown, sourceUrl }
输出:
  Document {
    format: "url",
    sourceUrl: url,
    sections: [{
      id: "s_main", heading: null, depth: 0, parentId: null, order: 0,
      body: { text, markdown, wordCount: computed }
    }],
    sectionCount: 1,
    totalWordCount: wordCount
  }

单 section 文档的 heading 始终为 null。
```

### 5.2 粘贴文本

```
输入: { title, text }
输出:
  Document {
    format: "paste",
    sections: [{
      id: "s_main", heading: null, depth: 0, parentId: null, order: 0,
      body: { text, markdown: null, wordCount: computed }
    }],
    sectionCount: 1
  }

单 section 文档的 heading 始终为 null。
```

### 5.3 Markdown 文件

```
输入: { title, content }
规则:
  1. 解析 YAML frontmatter（如有）→ title 优先用 fm title
  2. 扫描 body 中的 ## / ### / #### 标题
     - ##  → depth: 0, parentId 由 deriveParentIds() 推导
     - ### → depth: 1
     - #### → depth: 2
  3. 标题之间的正文归入该标题所在的 section（含 Markdown 格式）
  4. 第一个 ## 之前的正文（如有）→ 归入 heading: null、depth: 0 的 section
  5. 没有任何 # 标题 → 退化为单 section（heading: null）

输出:
  Document {
    format: "markdown",
    sections: [
      { id: "s_0", heading: null, depth: 0, parentId: null, order: 0, ... },  // 如果存在前置引言
      { id: "s_1", heading: "Overview", depth: 0, parentId: null, order: 1, ... },
      { id: "s_2", heading: "Installation", depth: 1, parentId: "s_1", order: 2, ... },
      ...
    ]
  }
```

### 5.4 HTML 文件

```
输入: { title, htmlContent }
规则:
  1. DOMParser → document
  2. h1 → document.title（如未提供 title）；h1 不作为 section 边界
  3. h2 → depth: 0; h3 → depth: 1; h4 → depth: 2; h5/h6 → depth: 2（不增加最大深度）
  4. 标题之间的 HTML → Readability → Turndown → body.markdown + body.text
  5. 没有任何标题 → 退化为单 section

输出: Document { format: "html", sections: [...] }
```

### 5.5 EPUB（epub2MD 适配）

```
输入: File (.epub)

规则:
  1. epub2md.parseEpub(fileBuffer) → Epub 对象
     - structure.opf.metadata → meta.title, meta.author, meta.language
     - structure.toc.tree → 递归 TocItem 树
     - sections[i].toMarkdown() → Section 正文
     - manifest 中 <meta name="cover"> → 封面图 item

  2. TOC 树 → 平铺 sections:
     - 深度优先遍历 Toc.tree 递归树
     - 通过 "最近的 depth 更小的 section 是父节点" 规则分配 depth
     - parentId 由工厂函数 deriveParentIds() 最终推导
     - section.id 使用 epub2MD 的 section.id（或 toc item 的 sectionId）
     - section.heading = tocItem.name
     - section.order = DFS 遍历序

  3. 章节关联:
     - 通过 tocItem.sectionId 关联到 Epub.sections 数组中的对应 Section
     - section.toMarkdown() → body.markdown
     - 从 body.markdown 提取纯文本 → body.text

  4. 封面图:
     - 通过 OPF manifest 定位 cover item
     - Canvas 缩放至 max 300px → "data:image/jpeg;base64,..."
     - 存入 meta.coverUrl

  5. 图片处理:
     - 第一阶段不提取 EPUB 内嵌图片为独立资源
     - epub2MD 原生 base64 嵌入的图片（< 50KB）保留在 Markdown 中
     - 透明背景图（EPUB UI 装饰元素）自动跳过
     - 大图或跳过位置插入占位符: [Image: alt_text]

  6. TOC 容错:
     - toc.ncx / nav.xhtml 结构不标准时，降级为 spine 平铺（全 depth: 0）

  7. 错误处理:
     - EPUB 损坏或 DRM 保护 → 明确错误提示: "该 EPUB 受 DRM 保护或已损坏，无法导入"
     - 无 TOC → spine 平铺 + 警告

输出:
  Document {
    format: "epub",
    author: "Robert C. Martin",
    coverUrl: "data:image/jpeg;base64,...",
    lang: "en",
    sections: [
      { id: "s_ch1", heading: "Chapter 1", depth: 0, parentId: null, order: 0, ... },
      { id: "s_ch1-s1", heading: "1.1 Section", depth: 1, parentId: "s_ch1", order: 1, ... },
      ...
    ]
  }

适配工作量估算: ~50 行 TOC 遍历 + ~15 行封面图提取
npm 依赖: epub2md (MIT, ~100KB)
```

### 5.6 PDF（预留）

```
PDF 提取当前不实现。DocumentFormat 类型联合中保留 'pdf'，
EXTRACTORS 注册表中 pdf 键位保留（值为 null，抛出"PDF 支持即将推出"）。

PDF 支持在未来需求验证后重新评估。若届时纯前端方案质量不达标，
考虑引入 Marker 后端服务。触发条件:
  1. PDF 导入量 > 20% 且用户反馈前端提取质量不可接受
  2. 或 ReadRead 进入商业化阶段，有能力承担 GPU 实例成本
```

### 5.7 sourceType → format 映射表

现有数据库的 `source_type` 字段迁移为新 `format` 字段的映射：

| 旧 sourceType | 导入场景 | 新 format |
|---------------|---------|-----------|
| `'manual'` + 纯文本粘贴 + 无文件 | 粘贴文本 | `'paste'` |
| `'manual'` + .md 文件 | Markdown 文件上传 | `'markdown'` |
| `'manual'` + .html 文件 | HTML 文件上传 | `'html'` |
| `'manual'` + .epub 文件 | EPUB 上传 | `'epub'` |
| `'url'` | URL 导入 | `'url'` |

`sourceUrl` 保留为 Document 可选字段和数据库 `source_url` 列，不解构为 `format`，仅作为元信息保留。

### 6.1 articles 表

```sql
-- 新增字段
ALTER TABLE articles
  ADD COLUMN author text,
  ADD COLUMN format text NOT NULL DEFAULT 'paste',
  ADD COLUMN cover_url text,
  ADD COLUMN lang text NOT NULL DEFAULT 'auto',
  ADD COLUMN sections jsonb NOT NULL DEFAULT '[]',
  ADD COLUMN section_count integer NOT NULL DEFAULT 1;

-- source_url 保留不解构，继续存在于 articles 表

-- sections JSONB 约束
ALTER TABLE articles
  ADD CONSTRAINT articles_sections_is_array
  CHECK (jsonb_typeof(sections) = 'array');

ALTER TABLE articles
  ADD CONSTRAINT articles_section_count_check
  CHECK (section_count >= 1);

-- 现有数据回填
UPDATE articles
SET format = 'paste',
    sections = jsonb_build_array(
      jsonb_build_object(
        'id', 's_main',
        'heading', null,
        'depth', 0,
        'parentId', null,
        'order', 0,
        'body', jsonb_build_object(
          'text', text,
          'markdown', markdown,
          'wordCount', word_count
        )
      )
    ),
    section_count = 1
WHERE sections = '[]' OR sections IS NULL;
```

## 七、向后兼容策略

### 7.1 旧 Article → 新 Document

```js
/**
 * 将旧 Article 对象映射为新 Document。
 * 保留原始 id（不重命名 art_ → doc_）。
 */
function migrateArticleToDocument(article) {
  return {
    id:             article.id,                 // 保持原始 id（art_ 或 doc_）
    title:          article.title,
    author:         null,
    format:         'paste',                    // 无法准确推断，保守值
    coverUrl:       null,
    lang:           'auto',
    sourceUrl:      article.sourceUrl ?? null,
    sections: [
      {
        id:        's_main',
        heading:   null,
        depth:     0,
        parentId:  null,
        order:     0,
        body: {
          text:      article.text,
          markdown:  article.markdown ?? null,
          wordCount: article.wordCount ?? article.text.split(/\s+/).filter(Boolean).length,
        },
      },
    ],
    totalWordCount: article.wordCount,
    sectionCount:   1,
    createdAt:      article.createdAt,
    updatedAt:      article.updatedAt ?? null,
  }
}
```

### 7.2 localStorage 匿名用户数据回填

```js
/**
 * 应用启动时执行。检测 localStorage 中的旧格式 articles，
 * 若缺少 sections 字段则自动升级。
 */
function migrateLocalStorageArticles() {
  const articles = articleStore.getAll()
  const needsMigration = articles.some(a => !a.sections)

  if (!needsMigration) return

  const migrated = articles.map(a =>
    a.sections ? a : migrateArticleToDocument(a)
  )
  writeJSON(KEYS.ARTICLES, migrated)
}

// bookmark 字段保持扁平——sectionId/paragraphIndex/charOffset 不变。
// 仅补充 sectionHeading（旧数据为 null，读取时通过 resolveSectionHeading 回退）。
```

### 7.3 旧 Bookmark → 新 Bookmark

```
旧 bookmark.sectionId 为 undefined/null  →  代码中处理为 ?? "s_main"
旧 bookmark.sectionHeading 为 undefined/null  →  代码中处理为 ?? null
旧 bookmark.paragraphIndex   →  保持原值（在单 section 下语义一致）

### 7.4 旧 ReadingMark → 新 ReadingProgress

```
旧 readingMark.sectionId 为 undefined/null  →  代码中处理为 ?? "s_main"
旧 readingMark.completed = true 且 completedSections = []  →  视为全文完成

### 7.5 导出格式版本兼容

导出格式的 `version` 字段升级为 `2`。导入时按版本号处理:

|-------------|---------|

### 7.6 代码中的兼容层

```js
/**
 * 安全获取 sectionId。兼容旧 bookmark/readingMark（无 sectionId 字段）。
 * @param {Object} record
 * @returns {string}
 */
function resolveSectionId(record) {
  return record.sectionId || 's_main'
}

/**
 * 安全获取 sectionHeading。
 * 优先使用 bookmark 中存储的快照；为空时回退查询 document.sections。
 * @param {Object} record
 * @param {Document} [document]
 * @returns {string|null}
 */
function resolveSectionHeading(record, document) {
  if (record.sectionHeading) return record.sectionHeading
  if (!document) return null
  const sectionId = resolveSectionId(record)
  const section = document.sections.find(s => s.id === sectionId)
  return section?.heading ?? null
}
```

### 8.3 Document 工厂函数

提取器不负责生成系统 id 和计算 wordCount。这些由统一的工厂函数完成：

```js
/**
 * 从 ExtractionResult 装配完整的 Document 对象。
 * 职责: 分配 section.id、推导 section.parentId、计算 wordCount、生成 document.id。
 *
 * @param {ExtractionResult} result
 * @returns {Document}
 */
function createDocument(result) {
  const sections = result.sections.map((s, i) => ({
    id:       `s_${i}`,
    heading:  s.heading,
    depth:    s.depth,
    parentId: null,  // 下一步由 deriveParentIds 填充
    order:    s.order,
    body: {
      text:      s.body.text,
      markdown:  s.body.markdown,
      wordCount: s.body.text.split(/\s+/).filter(Boolean).length,
    },
  }))

  // 根据 depth 推导每个 section 的 parentId
  deriveParentIds(sections)

  return {
    id:             generateDocumentId(),
    title:          result.meta.title,
    author:         result.meta.author ?? null,
    format:         result.meta.format,
    coverUrl:       result.meta.coverUrl ?? null,
    lang:           result.meta.lang ?? 'auto',
    sourceUrl:      null,
    sections,
    totalWordCount: sections.reduce((sum, s) => sum + s.body.wordCount, 0),
    sectionCount:   sections.length,
    createdAt:      new Date().toISOString(),
  }
}

/**
 * 根据 depth 推导每个 section 的 parentId。
 * 规则: 向前找最近的 depth 更小的 section，若存在则为父节点，否则为顶层节点。
 *
 * 前提: sections 数组必须按文档顺序排列（order 递增）。
 *
 * @param {Section[]} sections — 会被原地修改
 */
function deriveParentIds(sections) {
  const stack = []  // 记录最近的各级父节点
  for (const section of sections) {
    while (stack.length > 0 && stack[stack.length - 1].depth >= section.depth) {
      stack.pop()
    }
    section.parentId = stack.length > 0 ? stack[stack.length - 1].id : null
    stack.push(section)
  }
}

function generateDocumentId() {
  return `doc_${Date.now()}_${Math.random().toString(36).slice(2, 7)}`
}
```

## 九、TOC 树推导算法（渲染层）

从平铺 sections 生成 TOC 树结构：

```js
/**
 * @typedef {Object} TocNode
 * @property {Section} section
 * @property {TocNode[]} children
 */

/**
 * 从平铺 sections 构建 TOC 树。
 *
 * 前提: sections 数组必须按文档顺序排列（即 sections[i] 在文档中出现在
 *       sections[i-1] 之后）。算法利用 depth 的增减判断父子关系，
 * 不依赖 parentId 字段（但 parentId 的存在不影响算法正确性）。
 *
 * @param {Section[]} sections
 * @returns {TocNode[]}
 */
function buildTocTree(sections) {
  const roots = []
  const stack = []

  for (const section of sections) {
    const node = { section, children: [] }

    while (stack.length > 0 && stack[stack.length - 1].section.depth >= section.depth) {
      stack.pop()
    }

    if (stack.length === 0) {
      roots.push(node)
    } else {
      stack[stack.length - 1].children.push(node)
    }

    stack.push(node)
  }

  return roots
}

// 仅 sectionCount > 1 时调用并渲染 TOC。
```

## 十、总结

本规范定义了以 Document + Section 为核心的完整类型体系，覆盖了：

- 精确的字段定义和约束（JSDoc 类型表达）
- ID 前缀策略（art_ 保留，doc_ 用于新文档）
- Section.body 的切分规则（含单 section heading 规则）
- 下游 Bookmark / ReadingProgress 的升级路径（含 sectionHeading 陈旧策略、completedSections 精确语义）
- 六种提取格式到 Document 的映射规则（EPUB 采用 epub2MD 适配）
- sourceType → format 映射表 + sourceUrl 保留策略
- 数据库 schema 变更（含命名一致性声明、lang 默认 'auto'）
- 向后兼容策略（含 localStorage 回填、导出 v1/v2 兼容矩阵）
- 提取器接口（ExtractionSection 移除 parentId、ExtractorInput buffer 类型、deriveParentIds 工厂推导）

后续所有实现工作以本文档为唯一类型依据。
