## 一、审核说明

### 1.1 审核目标

对照设计与规范文档，逐项验证实施成果是否符合预期，确保：

- JSDoc 类型定义与规范一致
- 数据库变更正确且向后兼容
- localStorage 匿名用户路径正确升级
- 提取器输出符合 ExtractionResult 契约
- epub2MD 适配层正确映射 TOC 和 sections
- 渲染层正确支持多 section（单 section 行为不变）
- 下游系统正确适配
- 导出/导入 v1/v2 双版本兼容
- 所有现有功能未退化

### 1.2 审核方式

| 标记 | 含义 |
|------|------|
| ✅ 通过 | 实施完全符合规范，无遗留问题 |
| ⚠️ 有条件通过 | 实施基本符合规范，存在已知的、可接受的偏差 |
| ❌ 不通过 | 实施与规范存在实质性偏差，需修复后重新审核 |
| — 不适用 | 该项在当前阶段不适用 |

```
6. 备份导出 → JSON version 2 → 含 sections 字段
```

### A.2 多 section 验证

```
1. 上传含 ## 标题的 Markdown 文件

4. 不同 section 分别收藏 → 面板显示 section 来源
5. 阅读标记 → 切换 section 后正确恢复
```

```
1. 上传标准 EPUB（无 DRM 小说）
2. 文章库列表 → 章节数正确
3. 阅读页 → TOC 完整嵌套 → 封面图显示
4. 切换章节 → 内容正确
5. 多级嵌套 EPUB → depth 0/1/2 正确
```

### A.4 备份兼容验证

```
1. 导出含多 section 文档的备份 → JSON version 2
2. 导入旧版 v1 备份 → 自动升级成功

```
