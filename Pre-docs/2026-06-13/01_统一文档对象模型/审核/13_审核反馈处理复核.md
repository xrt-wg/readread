### BLK-01: EPUB TOC order 碰撞 (P0) — ✅ 通过

**处理记录声称**：将 `order` 改为共享累加器 `counter = { value: 0 }`

**实际代码**：[`parse-epub.cjs:17-31`](netlify/functions/parse-epub.cjs#L17-L31)
```js
function flattenTocTree(tocItems, depth = 0, counter = { value: 0 }) {
  const result = []
  for (const item of tocItems) {
    result.push({
      heading:    item.name || null,
      depth,
      order:      counter.value++,
      // ...
    })
    if (item.children && item.children.length > 0) {
      result.push(...flattenTocTree(item.children, depth + 1, counter))
    }
  }
  return result
}
```

**验证结论**：`counter` 对象在所有递归层级间共享，`counter.value++` 在所有子树间单调递增，不会再发生跨子树 order 碰撞。**与处理记录一致。**

### BLK-08: handleJumpToReadingMark setTimeout 竞态 (P1) — ✅ 通过

**处理记录声称**：改用 `useEffect` 监听 `currentSectionIdx`，通过 `pendingScrollRef` 传递滚动目标

**实际代码**：[`ReaderPage.jsx:394-405`](src/components/ReaderPage.jsx#L394-L405)
```js
const pendingScrollRef = useRef(null)

useEffect(() => {
  if (pendingScrollRef.current && currentSectionIdx === pendingScrollRef.current.targetIdx) {
    const timer = setTimeout(() => {
      const el = document.querySelector(`[data-para-index="${pendingScrollRef.current.paraIndex}"]`)
      if (el) el.scrollIntoView({ behavior: 'smooth', block: 'center' })
      pendingScrollRef.current = null
    }, 150)
    return () => clearTimeout(timer)
  }
}, [currentSectionIdx])

const handleJumpToReadingMark = useCallback(() => {
  if (!readingMark || readingMark.completed) return
  if (hasMultipleSections && readingMark.sectionId) {
    const idx = sections.findIndex(s => s.id === readingMark.sectionId)
    if (idx >= 0 && idx !== currentSectionIdx) {
      pendingScrollRef.current = { targetIdx: idx, paraIndex: readingMark.paragraphIndex }
      setCurrentSectionIdx(idx)
      return
    }
  }
  // 同 section 直接滚动
  const el = document.querySelector(`[data-para-index="${readingMark.paragraphIndex}"]`)
  if (el) el.scrollIntoView({ behavior: 'smooth', block: 'center' })
}, [readingMark, hasMultipleSections, sections, currentSectionIdx])
```

**验证结论**：改为 `useEffect` 事件驱动模型，等 React 确认 `currentSectionIdx` 变更且 DOM 重挂载后再滚动。比盲目的 100ms setTimeout 更可靠。**与处理记录一致。**

## 三、额外观察

在复核过程中发现的、处理记录未显式提及的连带改进：

### 3.1 createDocument(extractors) 新增 `text`/`markdown` 顶层字段

[`extractors/index.js:32-35`](src/services/extractors/index.js#L32-L35) 的 `createDocument` 新增了：
```js
const fullText = sections.map(s => s.body.text).filter(Boolean).join('\n\n')
const fullMarkdown = sections.some(s => s.body.markdown != null)
  ? sections.map(s => s.body.markdown ?? s.body.text).join('\n\n')
  : null
```

并在返回对象中加入了 `text: fullText` 和 `markdown: fullMarkdown`（行 40-41）。

**分析**：这是正向改进——`storage.js` 的 `createDocument`（用于单 section）已有 `text`/`markdown` 顶层字段，现在 `extractors/index.js`（用于多 section）也补充了。这解决了 `mapArticleRow` 返回的 `text` 字段需要从 sections 拼合的问题，确保下游代码（如 `ImportPage.jsx` 的 `calcProgress`）能正确读取全文字段。**属于合理的架构改进。**

### 3.2 handleJump 跨 section 跳转使用 200ms setTimeout

[`ReaderPage.jsx:348-351`](src/components/ReaderPage.jsx#L348-L351) 的 `handleJump`（来自 BLK-05）使用了 `setTimeout(..., 200)` 而非 `pendingScrollRef` 模式。

**分析**：这比 `handleJumpToReadingMark`（BLK-08，使用 `pendingScrollRef + useEffect`）的方案粗糙，但可以接受，因为 `handleJump` 需要在运行时动态决定目标 section（不像 readingMark 的场景是固定的），且 200ms 延迟在 React 17/18 的批量渲染周期内足够。**不构成功能缺陷。**
