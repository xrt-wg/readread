### P1 严重（7 个）

#### P1-01 【全局】键盘可访问性缺失 — 段落级书签按钮与焦点指示器

- **位置**：ReaderPage > SectionFlow > 段落左侧书签按钮（`left: -32px`）；全局所有可交互元素
- **现象**：
  1. 阅读正文每段左侧的「标记读到这里」按钮仅在鼠标悬停时可见（`opacity-0 group-hover:opacity-100`），键盘用户永远无法发现或触达
  2. 全局仅 `input/textarea/select` 有 `focus-visible` 样式（`outline: 2px solid var(--gold)`），按钮、链接等交互元素完全无焦点环
  3. 弹窗/面板（AuthPanel、BookmarkPanel、TranslationPopup）打开时未管理焦点陷阱（focus trap），Tab 键会跑到面板后方元素
- **违反标尺**：交互维度-灵活高效（键盘可达）；WCAG 2.4.7 Focus Visible
- **建议**：
  1. 段落书签按钮：始终可见（opacity 0.3 默认，hover/focus 时 opacity 1），或提供全局键盘快捷键（如 `Ctrl+Shift+M` 标记当前段落）
  2. 全局扩展 `focus-visible` 样式到所有交互元素：`button:focus-visible, a:focus-visible, [tabindex]:focus-visible { outline: 2px solid var(--gold); outline-offset: 2px; }`
  3. 面板/弹窗打开时设置焦点陷阱并将焦点移至面板内第一个可聚焦元素

#### P1-02 【全局】硬编码 `text-stone-*` / `bg-white` 等 Tailwind 颜色类在全局大量使用

- **位置**：AdminPage.jsx（大量 ~40 处）、ImportPage.jsx（多处）、App.jsx（多处）
- **现象**：`text-stone-600`、`text-stone-700`、`text-stone-800`、`bg-white/85`、`bg-stone-50` 等 Tailwind 内置颜色类直接出现在 JSX 中。这些颜色不受 `var(--*)` 主题系统管理，切换到夜间模式后这些元素不会变暗，形成大量视觉不一致。
- **证据**：
  - `AdminPage.jsx:93` — `text-stone-600`
  - `AdminPage.jsx:608` — `bg-white/85`
  - `AdminPage.jsx:631` — `color: '#fff'`（多处）
  - `ImportPage.jsx:748` — `text-stone-500`
  - `App.jsx:184` — `text-stone-600`
- **违反标尺**：视觉维度-色彩（深浅模式完整性）；用户规范 CLAUDE.md 第 1 条：「所有组件中的颜色必须通过 CSS 变量引用」
- **建议**：
  1. AdminPage 全面改造：将 `text-stone-*` 替换为 `color: 'var(--ink)'` / `'var(--ink-light)'` / `'var(--ink-muted)'`，将 `bg-white/*` 替换为 `background: 'var(--card-bg-warm)'` 或 `'var(--popup-bg)'`
  2. App.jsx 状态提示文字替换为 `var(--ink-muted)`
  3. ImportPage 加载和指导文字替换

#### P1-03 【全局】AdminPage 完全忽略深色模式

- **位置**：AdminPage.jsx 全文
- **现象**：AdminPage 中所有颜色均为硬编码（见 P1-02），无任何 `var(--*)` 引用或 `[data-theme="night"]` 适配。用户在深色模式下进入后台会看到大量亮色卡片和白色背景，与阅读前台的深色环境剧烈割裂。
- **违反标尺**：视觉维度-深浅模式；用户规范 CLAUDE.md 第 2 条：「新增变量需在 `:root` 和 `[data-theme="night"]` 中同时定义」
- **建议**：参照前台组件，将 AdminPage 全部颜色迁移到 CSS 变量体系。需注意 `bg-white/85` → `var(--card-bg-warm)` 或新增 `--admin-card-bg` 令牌。

#### P1-04 【全局】弹窗/面板均无 Escape 关闭 + 遮罩点击关闭的双重保障

- **位置**：BookmarkHoverCard、RecommendationDetailModal、SubmitRecommendationModal、ImportItemEditor
- **现象**：
  - `BookmarkHoverCard.jsx` — 仅靠鼠标移出（`onMouseLeave`）关闭，无 Escape 键或遮罩点击关闭；移动端无 hover 概念，卡片可能无法关闭
  - `RecommendationDetailModal` — 未提供 Escape 关闭
  - `ImportItemEditor` — 全屏模式无 Escape 关闭
  - `TranslationPopup` ✅ 已正确处理 Escape + 外部点击
  - `AuthPanel` ✅ 已正确处理 Escape + 外部点击
  - `BookmarkPanel` ✅ 有遮罩点击关闭
- **违反标尺**：交互维度-用户可控与自由（Nielsen #3）
- **建议**：建立统一的弹窗/面板关闭规范：所有浮层必须支持 (1) Escape 键关闭 (2) 遮罩/外部点击关闭 (3) 显式关闭按钮。创建一个 `useEscapeKey` hook 供全局复用。

#### P1-05 【全局】翻译失败无重试机制 — 静默失败

- **位置**：ReaderPage > TranslationPopup
- **现象**：划词翻译失败时（如网络断开、API 超限），`TranslationPopup` 显示红色错误文字（`var(--danger-text)`, 11px 字体），但没有「重试」按钮。用户必须重新划选才能再次触发翻译。对于整句/整段翻译（用户可能需要反复划选长文本），这个成本很高。
- **违反标尺**：交互维度-错误恢复（Nielsen #9：「报错信息是否说人话 + 怎么办」）
- **建议**：在 TranslationPopup 错误态添加「重试」按钮，点击后重新调用 `translate(selectedText)`。

#### P1-06 【全局】应用固定 720px tablet 布局 — 移动端完全不可用

- **位置**：`index.css` `.tablet` 规则；App.jsx ImportPage 渲染
- **现象**：`.tablet { width: 720px; height: 85vh; }` — 固定宽度意味着在屏幕宽度 < 720px 的设备上（大多数手机、小屏平板），内容会溢出或出现横向滚动。应用没有 `<meta name="viewport">` 之外的任何移动端适配。
- **违反标尺**：界面维度-响应式：「三档宽度（1440/768/375）下内容是否溢出、出现横向滚动条」
- **建议**：
  1. 短期：`.tablet` 添加 `max-width: 100vw` 和 `width: min(720px, 100vw)`
  2. 中期：为 375-767px 视口设计简化布局（阅读页自适应宽度，导入页去掉 tablet 外壳改为全屏）

#### P1-07 【全局】全局 grain 纹理覆盖所有浮层

- **位置**：`index.css:216-223` `body::before`
- **现象**：`body::before` 伪元素使用 `z-index: 9999` 的固定定位 SVG 噪点纹理。这意味着它渲染在**所有**弹窗、面板、模态框之上（TranslationPopup 最高 z-50，ImportItemEditor breakout z-100）。纹理层会微弱降低弹窗内容的对比度和可读性。
- **违反标尺**：视觉维度-色彩（对比度）；交互维度-简约设计
- **建议**：将 grain 纹理的 `z-index` 降至 1（或移除 `z-index` 依赖默认层叠），确保它位于 canvas 背景之上但所有内容面板之下。弹窗/面板自身设置 `z-index: 2` 或更高。

### P2 中等（15 个）

#### P2-01 【全局】两处独立的主题切换按钮

- **位置**：App.jsx:221（固定定位右下角）+ ReaderHeader.jsx:144（工具栏内）
- **现象**：同一功能有两个不同样式的入口。App.jsx 中是 40×40 圆形浮动按钮，ReaderHeader 中是 30×30 方形带边框按钮。在阅读页两个主题切换按钮**同时可见**（App.jsx 的浮动按钮在 view !== 'admin' 时渲染，而 ReaderPage 属于此条件）。用户可能困惑哪个是"正确的"切换方式。
- **违反标尺**：界面维度-一致性
- **建议**：在阅读页隐藏 App.jsx 的浮动主题按钮（或统一为 ReaderHeader 内的工具栏按钮），仅保留一个入口。

#### P2-02 【全局】AuthPanel 被渲染两次

- **位置**：App.jsx:219 + AdminPage.jsx:606
- **现象**：`App.jsx` 和 `AdminPage` 各自渲染一个 `AuthPanel` 实例（AdminPage 中为 `<AuthPanel showAdminEntry={false} />`）。两个实例具有不同的 props，可能导致状态不同步。
- **违反标尺**：交互维度-一致性与标准
- **建议**：将 AuthPanel 提升为 App 层级的单一实例，通过 props 控制不同页面下的行为差异。

#### P2-03 【全局】Google Fonts 加载无 `display=swap` — FOIT 风险

- **位置**：`index.html:10-13`
- **现象**：Google Fonts URL 中未包含 `&display=swap` 参数。网络较慢时，文字在字体下载完成前完全不可见（FOIT），影响首屏体验。
- **违反标尺**：界面维度-布局稳定性（与加载态相关）
- **建议**：在 URL 末尾追加 `&display=swap`，使浏览器在字体加载期间使用回退字体先渲染文本。

#### P2-04 ImportPage — 书架空态引导用词"策展"不够直白

- **位置**：ImportPage.jsx:661
- **现象**：空书架引导文案「导入你的第一篇英文内容，开始策展」中的"策展"（curation）是设计行业术语，普通用户可能不理解其含义。
- **违反标尺**：文案维度-清晰（贴近用户语言，Nielsen #2）
- **建议**：改为「导入你的第一篇英文内容，开始阅读和学习」或「建立你的英文阅读库」。

#### P2-05 ImportPage — 推荐卡片标题截断无 tooltip

- **位置**：ImportPage.jsx:579
- **现象**：推荐卡片标题使用 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` 截断，但没有 `title` 属性展示完整标题。用户无法看到被截断部分，除非点开详情弹窗。
- **违反标尺**：交互维度-识别优于回忆（Nielsen #6）
- **建议**：在标题 `<p>` 元素上添加 `title={rec.title}`。

#### P2-06 ImportPage — 素材编辑器 breakout 模式 z-index 低于 grain

- **位置**：ImportPage.jsx:394（`zIndex: editorBreakout ? 100 : undefined`）+ index.css `body::before { z-index: 9999 }`
- **现象**：ImportItemEditor 的全屏 breakout 模式 z-index 为 100，但 grain 纹理层 z-index 为 9999，编辑器会被纹理覆盖。**如果修复 P1-07，此问题自动消失。**
- **违反标尺**：交互维度-系统状态可见（遮盖内容）
- **建议**：修复 P1-07 降低 grain z-index 即可。

#### P2-07 ReaderPage — 章导航按钮禁用态对比度极低

- **位置**：ReaderPage.jsx:785, 797
- **现象**：书籍分页「上一章」「下一章」按钮禁用时，文字颜色设为 `var(--border-subtle)`（即与边框同色），在日间模式下约为 `rgba(28,25,23,0.07)` —— 几乎不可见。虽然禁用态不受 WCAG 对比度约束，但完全不可见的文字违背了「系统状态可见」原则。
- **违反标尺**：交互维度-系统状态可见（Nielsen #1）
- **建议**：禁用态文字使用 `var(--ink-muted)` 并配合 `opacity: 0.35`，确保可读但表意不可用。

#### P2-08 ReaderPage — 阅读进度环缺少说明文案

- **位置**：ReaderHeader.jsx:63-64
- **现象**：工具栏中 SVG 环形进度 + 百分比数字，无 tooltip 或标签说明。新用户可能不理解这个百分比代表什么（页面滚动进度？章节进度？全书进度？）。
- **违反标尺**：交互维度-帮助与引导（Nielsen #10）
- **建议**：为百分比文本添加 `title="阅读进度"` 属性；或在首次显示时给出简短说明。

#### P2-09 ReaderPage — 收藏面板删除按钮移动端不可达

- **位置**：BookmarkPanel.jsx:171-195
- **现象**：删除按钮仅在 `.group-hover:opacity-100` 时可见（`opacity-0 group-hover:opacity-100`）。在触摸设备上无 hover 态，删除按钮永远不可见。
- **违反标尺**：交互维度-灵活高效（Nielsen #7）
- **建议**：
  1. 在触摸设备上始终显示删除按钮（通过 `@media (hover: none)` 检测）
  2. 或提供长按/左滑删除手势

#### P2-10 ReaderPage — 预读模式缺少正文区域状态指示

- **位置**：ReaderPage.jsx:204-227（handleMouseUp 中 preReadMode 分支）
- **现象**：预读模式激活后，仅工具栏按钮变为金色。划词行为从"弹窗→确认收藏"变为"直接收藏"，但正文区域没有任何视觉提示表明当前处于不同的交互模式。用户可能误划词而创建大量意外书签。
- **违反标尺**：交互维度-系统状态可见（Nielsen #1）；错误预防（Nielsen #5）
- **建议**：在预读模式激活时，在正文区域顶部显示一条半透明的状态条（如「预读模式：划词即收藏」），或改变光标样式（`cursor: copy` 替代默认 `cursor: text`）。

#### P2-11 AuthPanel — 密码字段无显示/隐藏切换

- **位置**：AuthPanel.jsx:252-259
- **现象**：密码输入框为 `type="password"`，无「显示密码」👁 按钮。这是 2026 年登录表单的标准交互模式。
- **违反标尺**：交互维度-用户可控与自由（Nielsen #3）
- **建议**：在密码输入框右侧添加显示/隐藏切换图标按钮。

#### P2-12 AuthPanel — 无「忘记密码」流程

- **位置**：AuthPanel.jsx 整体
- **现象**：登录面板只有邮箱+密码+登录按钮，没有密码重置入口。用户忘记密码后将完全无法登录。
- **违反标尺**：交互维度-错误恢复（Nielsen #9）
- **建议**：在登录表单底部添加「忘记密码？」链接，后续对接 Supabase 的密码重置流程。

#### P2-13 ImportPanel — URL 导入无前端格式校验

- **位置**：ImportPanel.jsx:72-91
- **现象**：URL 导入仅检查输入是否为空，不做 URL 格式校验。用户输入 `not-a-url` 会被直接发送到后端提取器，等待网络超时后才知道失败。
- **违反标尺**：交互维度-错误预防（Nielsen #5）
- **建议**：提交前用 `try { new URL(input) }` 做基本格式校验，无效格式立即给出提示。

#### P2-14 ImportPanel — 粘贴模式缺少剪贴板一键读取

- **位置**：ImportPanel.jsx:142-153
- **现象**：「粘贴」Tab 要求用户手动 Ctrl+V 粘贴内容到 textarea。可以增加「从剪贴板读取」按钮，调用 `navigator.clipboard.readText()` 自动填充。
- **违反标尺**：交互维度-灵活高效（Nielsen #7）
- **建议**：在 textarea 上方添加「📋 从剪贴板读取」快捷按钮。

#### P2-15 ReaderPage — 字号调节缺少「恢复默认」快捷操作

- **位置**：ReaderHeader.jsx:155-185
- **现象**：字号调节范围为 14-28px，默认 18px。用户调整后无法一键恢复默认值，需要手动数点击次数回到 18。
- **违反标尺**：交互维度-用户可控与自由（Nielsen #3）
- **建议**：双击字号数字重置为默认值 18，或在调节器中添加小圆点标记默认位置。

### P3 细节（12 个）

#### P3-01 【全局】按钮圆角不统一
- **位置**：全局
- **现象**：按钮使用 `rounded-lg`(8px)、`rounded-xl`(12px)、`rounded-2xl`(16px)、`rounded-3xl`(24px)、`rounded-full` 等多种圆角。同一工具栏中，有的按钮 `rounded-lg`，有的无圆角类（仅 inline style 的 `borderRadius`）。
- **建议**：建立按钮圆角规范：主要操作按钮 `rounded-xl`(12px)，图标按钮 `rounded-lg`(8px)，卡片 `rounded-2xl`(16px)。

#### P3-02 【全局】图标尺寸不一致
- **位置**：全局
- **现象**：Lucide 图标在同一上下文中使用不同 size：工具栏按钮中有的 12px，有的 13px，有的 14px，有的 15px。
- **建议**：工具栏图标统一 14px，按钮内图标统一 14px，独立功能图标统一 16px。

#### P3-03 BookmarkPanel + BookmarkHoverCard 收藏卡片渲染逻辑重复
- **位置**：BookmarkPanel.jsx + BookmarkHoverCard.jsx
- **现象**：两个文件各自实现了近乎相同的书签卡片渲染（类型标签、彩色圆点、原文、翻译、语境句）。TYPE_LABEL、TYPE_DOT 常量各自定义一份。
- **建议**：抽取 `BookmarkCard` 共享组件，消除重复。TYPE_LABEL/TYPE_DOT 移到 `utils/reviewUtils.js` 统一导出。

#### P3-04 TranslationPopup 词模式 — 翻译字号 22px 与文章主标题竞争
- **位置**：TranslationPopup.jsx:135
- **现象**：单词翻译以 22px bold 显示，而文章标题为 26-38px，章节标题为 ~22px。翻译弹窗的内容不应在视觉权重上与阅读内容标题竞争。
- **建议**：单词翻译降为 18-20px，保持足够的可读性但不喧宾夺主。

#### P3-05 ReaderPage — 收藏面板 title 与 BookmarkHoverCard 的 dot 颜色不一致
- **位置**：BookmarkPanel.jsx:143 vs BookmarkHoverCard.jsx:79
- **现象**：BookmarkPanel 中彩色圆点为 6px，BookmarkHoverCard 中为 7px。同一视觉元素尺寸不同。
- **建议**：统一为 6px。

#### P3-06 ReviewPanel — 空态图标太大
- **位置**：ReviewPanel.jsx:142-146
- **现象**：未登录空态使用 `GraduationCap size={36}`，但在 560px 容器的空白中央显得过大和突兀。相比之下，ReviewPanel 完成态图标为内联字符 `✓`，书架空态图标为 `FileText size={32}`。
- **建议**：降为 28-32px，与其他空态图标保持一致。

#### P3-07 AdminPage — 导航项含已废弃的「推荐内容管理」
- **位置**：AdminPage.jsx:355-374
- **现象**：`navItems` 中 `articles` 导航项仍然存在，但点击后显示「推荐内容管理已迁移至社区众包推荐系统」的占位信息。废弃入口应移除或明确标注。
- **建议**：从 `navItems` 中移除 `articles` 项，或添加 `(已迁移)` 标注并置灰。

#### P3-08 AdminPage — Toast 通知无图标
- **位置**：AdminPage.jsx:1284-1288
- **现象**：Toast 仅为纯文字 + 深色背景，无成功 ✓ / 错误 ✕ / 警告 ⚠ 图标区分消息类型。
- **建议**：根据 `toastMessage` 的来源添加对应图标。

#### P3-09 书架筛选列表空结果无明确提示
- **位置**：ImportPage.jsx:730-738 → ImportItemList
- **现象**：当「未读」「未读完」「已读完」筛选条件下无匹配条目时，列表区域为空，无「该分类下暂无内容」的明确提示。这与书架完全为空有区别——用户可能以为功能故障。
- **建议**：在 `ImportItemList` 中，当 `items.length === 0` 且 `activeFilter !== 'all'` 时显示对应的空态提示。

#### P3-10 阅读页首次 hint 提示缺少手动关闭按钮
- **位置**：ReaderPage.jsx:738-758
- **现象**：首次使用的金色提示卡「划选单词获得词义…」仅在用户首次划词后自动消失（通过 `localStorage` 持久化）。用户如果不理解提示内容想保留、或想立即关闭，没有 X 关闭按钮。
- **建议**：添加可手动关闭的 X 按钮，同时在点击关闭时也写入 `localStorage`。

#### P3-11 书籍目录面板不跟踪当前阅读位置（无 scroll-spy）
- **位置**：SectionTocPanel.jsx
- **现象**：目录面板的高亮项基于 `currentIdx`（当前章序号），而不是用户实际滚动到的章节。如果用户在长章内滚动了很远，目录仍然高亮该章开头。
- **建议**：后续版本实现 IntersectionObserver 驱动的 scroll-spy，高亮当前视口内可见的章节。

#### P3-12 全文完标记装饰过简
- **位置**：ReaderPage.jsx:807-823
- **现象**：文章结尾为 `✦` 装饰线 +「— 全文完 —」。在深色模式下 `✦` 的 `opacity: 0.4` 可能过暗。此为纯主观的细节改进建议。
- **建议**：可考虑更精致的结尾装饰，或增加「返回书架」的快捷按钮在结尾处。

### 优先修复建议（Top 3）

1. **P1-07 + P1-02：修复 grain z-index + AdminPage 深色模式适配**
   — 理由：grain z-index 9999 覆盖所有弹窗是结构性缺陷，影响所有浮层交互；AdminPage 完全忽略深色模式是最大的主题一致性问题。两处修复涉及面广但为纯样式变更，批量替换即可。**且修复 grain z-index 可连带解决 P2-06。**

2. **P1-01 + P1-04：补全键盘可访问性与弹窗关闭机制**
   — 理由：段落书签按钮仅 hover 可见、全局无 focus-visible、弹窗无焦点陷阱和 Escape 关闭——这三者共同构成了「键盘用户完全无法使用核心功能」的系统性问题。修复后产品的可用性受众从鼠标用户扩展到全部用户。

3. **P1-06：tablet 布局响应式适配**
   — 理由：固定 720px 宽度使应用在占互联网流量 60%+ 的移动设备上不可用。改为 `min(720px, 100vw)` 仅需一行 CSS 即可实现基本可用性。

### 整体评价

ReadRead 作为个人英语阅读工具，在**视觉品质**和**氛围营造**上表现出色。parchment 纸色体系 + playfair/lora 字体搭配 + 噪点纹理建立了独特而有温度的品牌感，这在同类工具中属于上乘。CSS 变量体系的设计是成熟的——`:root` 和 `[data-theme="night"]` 的双主题覆盖完整，CLAUDE.md 的颜色使用规范也体现了良好的工程纪律。

但产品在以下三个维度存在系统性问题：

**1. 键盘可访问性空白。** 应用几乎完全为鼠标设计——段落标记、删除按钮、弹窗关闭等核心操作均依赖 hover 态。这不是局部的"忘了加 focus-visible"，而是一种设计范式缺陷：交互触发条件假定用户使用鼠标指针。如果要长期维护这个产品，需要在交互基线上建立键盘等价原则。

**2. 主题系统执行不彻底。** CSS 变量体系本身设计良好，但 AdminPage 是重灾区——整个后台使用了大量 `text-stone-*`、`bg-white/*` 等硬编码 Tailwind 类，完全绕过了主题系统。前台少量位置（App.jsx 状态提示、ImportPage 加载文字）也存在同类问题。整体上需要一次「颜色审计」——遍历所有 `style={{}}` 中的颜色值，确保都走变量通道。

**3. 移动端为空白地带。** 720px 固定 tablet 布局在桌面端是一种精致的选择，但没有为 < 720px 视口做任何降级。这不是技术难题——`min(720px, 100vw)` 就能解决基本的溢出问题——而是一个产品决策空白。

总体而言，ReadRead 在桌面端的阅读体验已经相当精致，核心任务流（导入→阅读→划词翻译→收藏→回顾）状态覆盖完整。上述问题中 P1 级别问题共 7 个，无一为功能阻断——更像是一个成熟度信号：产品已经从"能跑"进入了"需要打磨"的阶段。
