## 三、遇到的问题及处理

### 问题 1: React.lazy 代码分割导致循环依赖警告

**现象**: `npm run build` 成功后出现 8 条 Rollup 警告，提示 re-export 模块会产生跨 chunk 循环依赖，可能导致运行时执行顺序错乱。

**根因**: 以下文件通过 barrel 文件间接导入，代码分割后原模块和 barrel 文件被分到不同 chunk：

| 文件 | 原导入路径 | 问题 |
|------|-----------|------|
| `ImportPage.jsx` | `../services/supabase` → `recommendationService.js` | barrel re-export |
| `ImportPage.jsx` | `../services/importItems` → `readings.js` | barrel re-export |
| `ReaderPage.jsx` | `../services/supabase` → `recommendationService.js` | barrel re-export |
| `SubmitRecommendationModal.jsx` | `../services/supabase` → `recommendationService.js` | barrel re-export |
| `recommendationService.js` | `../importItems` → `readings.js` | barrel re-export |

**处理**: 全部改为直接从源模块导入，跳过 barrel 文件。7c2b600 提交中一并修复。

**教训**: 代码分割前应审计 barrel re-export 模式。barrel 文件在 eager-import 场景下无害，但在 lazy-import 场景下会产生跨 chunk 循环依赖。

### 问题 2: 打开书籍后无内容（回归缺陷）

**现象**: 书架列表正常显示，但点击任何书籍进入阅读页后，正文区域为空。

**根因**: 列表查询改用 `READING_LIST_COLUMNS`（不含 `sections`）后，书架列表数据直接传给了 `ReaderPage`。`ReaderPage` 依赖 `article.sections` 渲染正文，而列表数据中 `sections` 为 `undefined`。

**调用链追踪**:
```
ImportPage: 用户点击书籍
  → onOpen(art)                          // art 来自列表查询，无 sections
  → App.handleOpen(savedArticle)         // 直接 setState
  → ReaderPage article={article}         // article.sections === undefined
  → effectiveSections = []               // 空数组
  → 无内容渲染
```

**处理**: `handleOpen` 中补一次 `getReading(id)` 调用（使用 `READING_DETAIL_COLUMNS`，含 `sections`），获取完整数据后再传给 `ReaderPage`。

**教训**: 列拆分的优化策略中有一个隐含约束——**列表数据不能直接用于需要正文的详情视图**。所有从列表进入详情的入口都需要补一次详情查询。`handleOpen` 是唯一入口，但如果有其他路径（如直接 URL 跳转），也需要同样的处理。

### 问题 3: 方案 1.9（字体预加载）实为已有配置

**现象**: 方案计划在 `index.html` 添加字体 `preload` + `font-display: swap`。

**实际**: 检查 `index.html` 后发现：

**处理**: 跳过该项。现有字体加载策略已经是最佳实践（对 Google Fonts 而言，preconnect 优于 preload）。

**教训**: 实施前应逐项验证当前状态，避免重复劳动。分析报告中的发现可能基于不完整的代码审查。

### 问题 4: Supabase Migration 不支持 CREATE INDEX CONCURRENTLY

**现象**: 审核反馈建议使用 `CREATE INDEX CONCURRENTLY` 避免建索引期间的表锁。

**实际**: Supabase Migration 在事务块中执行 SQL，而 PostgreSQL 的 `CREATE INDEX CONCURRENTLY` 不能在事务块内运行，会直接报错：
```
ERROR: CREATE INDEX CONCURRENTLY cannot run inside a transaction block
```

**处理**: 改用普通 `CREATE INDEX IF NOT EXISTS`。ReadRead 的表规模（几千行）下，普通索引创建的表锁时间在 100ms-1s，完全可接受。

**教训**: Supabase 特有的约束需要在方案设计中提前考虑。`CONCURRENTLY` 在 Supabase 环境下只能通过 SQL Editor 手动执行，不能放入 migration 文件。

### 遇到的问题

#### 问题 5: React.memo 包裹后的语法错误链

**现象**: `npm run build` 报语法错误 "Expected ')' but found 'export'"

**根因**: 将 `export default function Name(...)` 改为 `const Name = memo(function Name(...)` 后, 函数定义末尾的 `}` 需要改为 `})` 来闭合 `memo(` 调用。4 个文件受到影响。

**处理**: 逐个文件在函数末尾添加 `)` 闭合 memo 调用。

#### 问题 6: ShelfTabs 移到模块级后 useMemo 不可用

**根因**: ShelfTabs 原定义在 ImportPage 组件函数内部, `TABS` 数组和 `counts` 计算每渲染重建。

**处理**: TABS 提升为模块常量 `SHELF_TABS`, counts 用 `useMemo` + 单次遍历替代 3 次 filter。
