## 1. 总体结论

- **发布判断**：有条件发布（修复指定问题后可以发布）
- **主要风险**：
  1. 一个已确认的越权（IDOR）——4 个 `SECURITY DEFINER` RPC 未校验 `auth.uid()`，任何登录用户可读写他人数据；

- **必须修复数量**：1 项 P0 核实 + 4 项 P1（其中 1 项含 4 个 RPC 的批量修复）。

## 2. 项目全局认知

### 项目结构
- **前端**：React 18 + Vite 5（SPA），入口 [src/main.jsx](src/main.jsx)，根组件 [src/App.jsx](src/App.jsx)，页面懒加载（`AdminPage` / `ImportPage` / `ReaderPage`）。
- **后端**：无独立服务，业务逻辑落在两类——
  - **Netlify Functions**：[netlify/functions/](netlify/functions/)（`translate` / `generate-recommendation` / `proxy` / `parse-epub`），共享适配层 [netlify/lib/aiProviders.cjs](netlify/lib/aiProviders.cjs)；
  - **Supabase**：Postgres + RLS + SECURITY DEFINER RPC，迁移脚本 [supabase/migrations/](supabase/migrations/)（58 个）。
- **配置**：[config/](config/)（`presetModels.json` / `recommendation.json` / `translation.js` / `directTranslation.json`）。
- **部署**：[netlify.toml](netlify.toml)（SPA + functions），SPA 回退在 [public/_redirects](public/_redirects)。
- **数据访问边界**：客户端 [src/services/supabase/client.js](src/services/supabase/client.js) 仅持 anon key；service_role key 仅存在于 Netlify 函数服务端。

### 核心模块
1. 身份与权限（`AuthProvider` / `useAuth` / `profile` / `admin_roles` + `is_current_user_admin`）；
2. 阅读库（`readings` 单表：书架区/阅读区/状态流转）；
3. 收藏与复习（`bookmarks` + `get_due_bookmarks` 服务端筛选 + 间隔复习）；
4. 翻译（AI 精译 `translate.js` LLM 路径 + 直译 youdao/deepl/myMemory）；
5. 社区众包推荐（提交审核 → 管理员策展 → 发布 → 上架发 Pro）；
6. 订阅与付费（Free/Pro 身份 + 额度杠杆 + 付费核对闭环）。

### 核心业务链路
「注册登录 → 导入内容（受导入额度闸门）→ 阅读中划词收藏 → AI/直译（受翻译限流）→ 间隔复习 → 推荐众包 / 付费开通 Pro」。**高风险区域**：鉴权边界（RPC 是否逐个校验 `auth.uid()`）、外部 API 成本与滥用面（未鉴权函数）、生产配置完整性（env/迁移）、私有数据跨用户暴露。

## 3. 发布阻断问题 P0

### P0-1 生产部署前置条件未在代码中可验证：Supabase 迁移落库 + Netlify 环境变量
- **涉及文件**：[netlify/functions/translate.js](netlify/functions/translate.js)、[supabase/migrations/](supabase/migrations/)（20260923000000 起订阅/付费/限流系列）、`Pre-docs/开发/28_…/05_实施后审核请求.md`
- **问题说明**：代码强依赖一批「部署后才存在」的资产，而仓库内文档明确记载其「尚未落库 / 尚未配置」：
  - **DB 对象**：`get_subscription_status`、`begin_payment_request`、`submit_payment_request`、`admin_confirm_payment`、`consume_translate_quota`、`start_reading`、`restart_reading`、`get_due_bookmarks` 等 RPC，及 `subscriptions`/`user_quotas`/`payment_requests`/`translate_rate_limits` 等表（记忆亦确认：本仓库无 Supabase CLI，须经 Dashboard SQL Editor 手动执行迁移）。
  - **Netlify 环境变量**：`SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、`SUPABASE_JWT_SECRET`、`PRESET_*`（DeepSeek/Kimi/Zhipu/Youdao 等 API key）。本地 `.env` 已 gitignore，**不等于**生产 Netlify 已配。
- **触发场景**：任一缺失时——
  - `translate.js` LLM 路径 `verifyJwt`（[translate.js:184](netlify/functions/translate.js#L184)）读不到 `SUPABASE_JWT_SECRET` → 返回 null → 所有已登录用户 AI 精译 **401**；`getRateLimitClient`（[translate.js:151](netlify/functions/translate.js#L151)）拿不到 URL/key → `consume_translate_quota` 抛错 → LLM 路径 **503**。
  - 订阅/付费/翻译限流相关 `.rpc()` 全部报 `function does not exist` → 付费开通、Free/Pro 额度闸门、翻译限流整体失效。
- **可能后果**：AI 精译不可用；付费/订阅机制不可用；额度闸门静默失效（`useSubscription` 捕获错误后 `setStatus(null)`，闸门形同虚设）。
- **修复建议**：发布前（1）按序在 Supabase Dashboard 执行全部未落库迁移并逐条校验 `notify pgrst` 生效；（2）在 Netlify 配齐上述环境变量（JWT Secret 须与 Supabase 项目一致）；（3）用真实账号走一遍「注册 → 导入 → 收藏 → AI 翻译 → 付费申请」冒烟验证。
- **是否阻断发布**：**是**（生产配置缺失，属 P0 定义中的「生产环境配置缺失或错误」）。此为「核实并完成」而非代码改动。

## 4. 严重风险问题 P1

### P1-1 越权（IDOR）：4 个 SECURITY DEFINER RPC 未校验 `auth.uid()`
- **涉及文件**：
  - [supabase/migrations/20260921000000_add_bookmark_status.sql:27](supabase/migrations/20260921000000_add_bookmark_status.sql#L27) `get_due_bookmarks(p_user_id, p_limit)`
  - [supabase/migrations/20260713000001_reading_mark_partial_upsert.sql](supabase/migrations/20260713000001_reading_mark_partial_upsert.sql) `upsert_reading_mark_position` / `clear_reading_mark_position` / `set_reading_mark_completed`（均含 `p_user_id` 参数）
- **问题说明**：四个函数均为 `SECURITY DEFINER`（绕过 RLS），但**接收 `p_user_id` 参数后直接使用，全程不校验 `p_user_id = auth.uid()`**。对比同期新写的 RPC（`start_reading`、`restart_reading`、`soft_delete_reading`、`check_reading_completed`）均已显式校验，说明这是「老函数未跟上新约定」的漏洞，而非有意为之。迁移注释还明确 `get_due_bookmarks`「依赖 PostgreSQL 默认 PUBLIC EXECUTE」。
- **触发场景**：任意登录用户（注册开放，见 P1-4 上下文）调用 `get_due_bookmarks(他人_user_id, 20)`，即可读取他人收藏（生词/短语原文 + 译文 + 语境句），构成**跨用户私有数据读取**；同理可向他人 `reading_marks` 写入/清空进度。攻击者可通过公开推荐流的 `submitter_user_id` 等渠道取得目标 UUID（推断）。
- **可能后果**：用户私有阅读笔记被任意第三方批量导出；他人阅读进度被篡改/清空。属「权限绕过 + 数据越权」。
- **修复建议**：在四个函数体首部加 `if p_user_id is null or p_user_id <> auth.uid() then raise exception '…' using errcode='42501'; end if;`（`get_due_bookmarks` 直接改用 `auth.uid()` 过滤即可）。发布前需在 Dashboard 重新执行这四段 `create or replace function`。
- **是否阻断发布**：**是**（最严重的安全问题，建议按 P0 优先修复）。

### P1-2 `generate-recommendation` 未鉴权、无限流（成本滥用 + 免费 LLM 代理）
- **涉及文件**：[netlify/functions/generate-recommendation.js:130](netlify/functions/generate-recommendation.js#L130)（`exports.handler` 全文无鉴权/限流）
- **问题说明**：与 `translate.js` 的 LLM 路径不同，该函数**没有任何 JWT 鉴权、没有限流**，任何人可 POST 任意 `articleText`；且内置「同 provider 重试 + 备选 provider 兜底」，单次请求最多触发 4 次上游 LLM 调用（[generate-recommendation.js:180-253](netlify/functions/generate-recommendation.js#L180)）。
- **触发场景**：未登录脚本直接 `POST /.netlify/functions/generate-recommendation` 批量提交，消耗服务端 DeepSeek/Gemini key。
- **可能后果**：AI 额度被刷爆产生账单；函数被当作免费大模型代理。属「成本滥用 / 未授权外部服务访问」。
- **修复建议**：对齐 `translate.js` 做法——加 `verifyJwt` 鉴权 + `consume_translate_quota`（或独立配额）限流，未登录直接 401。
- **是否阻断发布**：**是**（若 key 无硬性消费上限，影响是持续性的）。

### P1-3 `proxy` 未鉴权、未做 URL 校验（SSRF / 开放代理）
- **涉及文件**：[netlify/functions/proxy.js:2](netlify/functions/proxy.js#L2)
- **问题说明**：`event.queryStringParameters.url` 被直接 `fetch`，无鉴权、无协议/域名校验、无私网 IP 拦截。它本意是「URL 导入文章」的抓取代理，但作为公网可达的 Netlify 函数，等于一个开放代理。
- **触发场景**：任何人以 `?url=` 指向任意地址（含内网/回环地址、公网任意内容），借用该函数发起请求并读取响应。
- **可能后果**：SSRF 探测内网、被当作免费抓取代理消耗函数 egress/额度。
- **修复建议**：至少校验 `url` 必须是 `http(s)` 且目标为主流公网域名；更稳妥是加会话鉴权 + 域名白名单 + 私网网段拒绝。
- **是否阻断发布**：**是**（公网无鉴权 SSRF）。

### P1-4 AI 精译主力 provider 为「临时测试」配置，且 fallback 无效
- **涉及文件**：[config/translation.js:9](config/translation.js#L9)
- **问题说明**：`aiConfig.activePreset = 'kimi-preset'`，注释原文「临时：kimi 为主力测试（原 deepseek-preset），测完改回」；同时 `fallbackPreset` 也是 `kimi-preset`，**主备同源，备用形同虚设**（`useBookmarkAI` 的三级兜底里第②级等于重试第①级）。真正的兜底只剩第③级直译。
- **触发场景**：若生产未配 `PRESET_KIMI_API_KEY`，或 kimi 出问题，AI 精译（核心体验）整链静默降级到直译。
- **可能后果**：核心「AI 精译」能力与预期不一致 / 无真实容灾。
- **修复建议**：发布前确认 AI 精译最终 provider 并改回（或确认 kimi 为正式选择），同时把 `fallbackPreset` 设为与 active 不同的可用 provider。
- **是否阻断发布**：**是**（发布前必须确认的配置正确性，否则「临时测试」状态进入生产）。

## 5. 中等风险问题 P2

### P2-1 生产 bundle 含 17 处调试/性能日志
- **涉及文件**：`src/hooks/useBookmarkAI.js`、`src/services/aiProviders/index.js`、`src/services/aiProviders/recommendation.js`、`src/services/directTranslation/index.js`、`src/services/supabase/recommendationService.js`
- **说明**：`console.info('[AI_PERF_*]')`、`[DIRECT_PERF_*]`、`[BOOKMARK_FALLBACK]` 等会进入生产产物并刷满控制台。非敏感（无明文密钥/无用户数据），但影响体验且易与真实错误混淆。
- **建议**：按环境变量或构建开关 gating，或降为 `debug`。

### P2-2 构建警告：`@mozilla/readability` 静态+动态双导入
- **涉及文件**：[src/services/urlImport.js](src/services/urlImport.js)（动态 import）与 [src/services/extractors/htmlExtractor.js](src/services/extractors/htmlExtractor.js)（静态 import）
- **说明**：Vite 提示该模块同时被静态/动态引用，无法按预期独立分块，`readability` 会落入主包。不影响构建与运行，仅影响 chunk 拆分体积。
- **建议**：统一为一种导入方式。

### P2-3 仓库残留文件（非阻断，建议清理）
- **涉及文件**：`deno.lock`、根目录 `memory/`、`preview/`、`.tmp-first-reading-validation/`、`.tmp-modal-analysis/`、`vite.config.js.timestamp-*.mjs`
- **说明**：含临时代码/锁文件，易造成工程歧义（如 `deno.lock` 与 npm 生态并存）。
- **建议**：发布前清理或并入 `.gitignore`。

### P2-4 `increment_recommendation_add_count` 接受任意 `submission_id`（低危，幂等）
- **涉及文件**：[supabase/migrations/20260711000000_unify_readings_table.sql:326](supabase/migrations/20260711000000_unify_readings_table.sql#L326)
- **说明**：SECURITY DEFINER 且可被 authenticated 调用，`p_user_id` 参数被注释标注「兼容保留、函数内部不使用」，函数只按真实数据重算 `add_count`/`recommend_score`。**无任意写、无越权读**，仅可被反复触发无副作用重算。
- **建议**：加 `auth.uid()` 校验或改为仅 admin 可调，消除误用面（P3 亦可）。

## 10. 最终发布建议
