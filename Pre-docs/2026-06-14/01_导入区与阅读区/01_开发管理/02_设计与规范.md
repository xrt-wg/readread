# 导入区与阅读区 — 设计与规范

- **日期**：2026-06-14
- **状态**：设计中（待确认后进入实施）
- **英文命名**：Source Curation / 素材策展
- **讨论来源**：产品"双区"概念——导入区 + 阅读区 + 远期共享池

## 一、文档目的

定义 ReadRead 的**导入区（Import Zone）**与**阅读区（Reading Zone）**的完整规范，包括：

- 两区的概念定义与关系模型
- 新增表 `import_items` 的字段定义与约束
- 现有 `articles` 表的字段补充
- 核心操作流（导入 → 策展 → 移入阅读区）
- 与现有 Document/Section 模型的复用关系
- 引用链路与删除策略
- 共享池（Shared Pool）远期预留

本文档是后续所有实现工作的唯一设计依据。

## 二、概念定义

### 2.1 导入区（Import Zone）

```
所有内容导入后首先落地的 staging 区域。
用户可在此编辑：标题、作者、正文、格式、sections 结构等。
导入区内容独立于阅读区，不受阅读操作影响。
同一内容可多次移入阅读区（每次产生独立副本）。
```

### 2.2 阅读区（Reading Zone）

```
即当前的文章库（articles 表）。
承载阅读、收藏、进度跟踪、回顾等全部消费行为。
从导入区移入的内容为独立副本——后续编辑互不影响。
```

### 2.3 共享池（Shared Pool，远期）

```
导入区的逻辑子集——share_status ≠ 'private' 的内容。
用户可将自己的导入项标记为可共享，供他人拉取到其导入区。
拉取后形成独立副本，指向原始共享条目作为溯源。
```

### 2.4 核心原则

| 原则 | 说明 |
|------|------|
| **导入先落 staging** | 所有导入内容首先进入导入区，不直接进入阅读区 |
| **移入 = 复制，非移动** | 导入区源内容保留，阅读区获得独立副本 |
| **双向独立** | 导入区编辑不影响已移入副本；阅读区的阅读行为不影响源 |
| **可重复移入** | 同一导入项可多次移入阅读区，每次产生新的阅读副本 |
| **轻量引用** | 阅读副本指回导入源（可空），但非 FK 约束——不因上游删除而丢失数据 |

## 三、数据模型

### 3.1 新增表：`import_items`

```sql
CREATE TABLE import_items (
  id                text PRIMARY KEY,              -- "imp_" + timestamp + random5
  user_id           uuid NOT NULL REFERENCES profiles(user_id),

  -- 内容
  title             text NOT NULL,
  author            text,
  format            text NOT NULL,                  -- 'url'|'epub'|'pdf'|'paste'|'markdown'|'html'
  cover_url         text,
  lang              text NOT NULL DEFAULT 'auto',
  source_url        text,                           -- URL 导入的原始 URL
  sections          jsonb NOT NULL DEFAULT '[]',    -- 复用 Document.sections 结构
  total_word_count  integer NOT NULL DEFAULT 0,
  section_count     integer NOT NULL DEFAULT 1,

  -- 来源 + 共享
  origin            text NOT NULL DEFAULT 'imported',   -- 'imported' | 'shared'
  share_status      text NOT NULL DEFAULT 'private',    -- 'private' | 'shared' | 'public'
  share_source_id   text,                               -- origin='shared' 时指向共享池源条目

  -- 时间戳
  created_at        timestamptz NOT NULL,
  updated_at        timestamptz NOT NULL,
  deleted_at        timestamptz                     -- 软删除
);

-- 用户级唯一约束（防御跨用户 ID 碰撞）
ALTER TABLE import_items ADD CONSTRAINT import_items_user_id_id_unique UNIQUE (user_id, id);
```

#### `origin` 字段

| 值 | 含义 |
|----|------|
| `'imported'` | 用户自己导入（文件/URL/粘贴） |
| `'shared'` | 从共享池拉取 |

#### `share_status` 字段

| 值 | 含义 |
|----|------|
| `'private'` | 仅自己可见 |
| `'shared'` | 已分享到共享池，他人可拉取 |
| `'public'` | 全员可见（远期，可能用于精选内容） |

#### `share_source_id` 字段

当 `origin = 'shared'` 时非空，指向共享池中的源条目（即策展者设置了 `share_status ≠ 'private'` 的那条 import_items 行）。

### 3.2 现有表补充：`articles`

```sql
ALTER TABLE articles
  ADD COLUMN source_import_id text,          -- 指向 import_items.id，可空
  ADD COLUMN imported_at timestamptz;        -- 移入阅读区的时间，可空
```

**约束策略**：
- 无 FK 约束——纯应用层引用
- 兼容现有数据：旧文章的 `source_import_id` 为 null，不受影响
- 当 import_items 行被物理删除时，应用层负责将关联的 `articles.source_import_id` SET NULL

### 3.3 字段的职责分离

```
origin           ← "我从哪里得到的？"       （来源渠道）
share_status     ← "我正把它分享出去吗？"   （对外的分享状态）
share_source_id  ← "如果是共享来的，指向谁？"（溯源指针）
```

三者的正交关系：

| origin | share_status | share_source_id | 含义 |
|--------|-------------|-----------------|------|
| `'imported'` | `'private'` | null | 自己导入，不分享 |
| `'imported'` | `'shared'` | null | 自己导入，分享出去 |
| `'shared'` | `'private'` | imp_A_id | 从共享池拉取，不再二次分享 |
| `'shared'` | `'shared'` | imp_A_id | 从共享池拉取，再次分享（带溯源链） |

## 五、核心操作

### 5.1 导入 → 导入区（变化）

```
旧: 文件/URL → 提取器 → createDocument() → saveArticle() → 阅读区
新: 文件/URL → 提取器 → createImportItem() → saveImportItem() → 导入区
```

### 5.2 移入 → 阅读区（新增）

```
函数: copyToReadingZone(importItem)

步骤:
  1. 深拷贝 importItem.sections（structuredClone）
  2. 构造 ExtractionResult-like 对象
  3. createDocument() 生成新 Document（新 doc_xxx id）
  4. 设置 document.source_import_id = importItem.id
  5. 设置 document.imported_at = now()
  6. 写入 articles 表
  
  import_items 表不发生任何变化。sections 为深拷贝——后续两边独立编辑。
```

### 5.3 导入区编辑（新增）

```
导入区内容可编辑字段:
  · title
  · author
  · sections[].heading
  · sections[].body.text
  · sections[].body.markdown
  · cover_url

编辑操作仅影响 import_items 行，不影响已移入阅读区的任何文章。
```

### 5.4 删除导入项（新增）

```
函数: deleteImportItem(importItemId)

采用 SECURITY DEFINER RPC 函数，确保 SET NULL + 软删除在同一数据库事务中原子执行。

前端流程:
  1. 调用 countImportReferences(importItemId)
  2. 若有关联文章 → 弹窗提示（不展示具体数量）:
     "该素材已产生阅读副本。删除后：
      · 副本将保留在你的文章库中，可继续阅读
      · 副本不再显示「来源」信息
      确认删除？"
     [取消]  [确认删除]
  3. 用户确认后 → 调用 RPC delete_import_item(importItemId)
     RPC 内部原子执行:
       a. UPDATE articles SET source_import_id = NULL
          WHERE source_import_id = importItemId
            AND user_id = auth.uid()
            AND deleted_at IS NULL
       b. UPDATE import_items SET deleted_at = now()
          WHERE id = importItemId
            AND user_id = auth.uid()
            AND deleted_at IS NULL
  4. 无关联文章 → 直接调用 RPC（跳过弹窗）

原则: 不因导入区操作丢失阅读区的用户数据。
RPC 内 user_id = auth.uid() 双重校验，防止跨用户操作。
```

## 六、引用链路

### 6.1 完整链路

```
阅读区 article
  │
  └─ source_import_id → 导入区 import_item（用户自己的副本）
                            │
                            ├─ origin = 'imported'
                            │   → 完整链路止于此
                            │
                            └─ origin = 'shared'
                                 └─ share_source_id → 策展者的 import_item
                                                          │
                                                          └─ share_status = 'shared'/'public'
                                                             → 共享池源条目
```

每一层引用均为**可空**——链路在任一环节断开，数据不丢失，仅溯源能力衰减。

### 6.2 删除的传播

```
策展者删除自己的 import_item
  → 拉取者的 import_items.share_source_id 悬空
  → 拉取者的 import_item 仍存在（独立副本），文章也仍在
  → 溯源链路断裂，但数据无损

拉取者删除自己的 import_item
  → 关联的 articles.source_import_id = NULL
  → 文章仍存在于阅读区
  → 溯源链路断裂，但数据无损

阅读区删除文章
  → 正常的文章软删除流程，不影响 import_items
```

## 七、数据库约束与索引

### 7.1 约束

```sql
-- origin 取值约束
ALTER TABLE import_items
  ADD CONSTRAINT import_items_origin_check
  CHECK (origin IN ('imported', 'shared'));

-- share_status 取值约束
ALTER TABLE import_items
  ADD CONSTRAINT import_items_share_status_check
  CHECK (share_status IN ('private', 'shared', 'public'));

-- sections 必须是数组
ALTER TABLE import_items
  ADD CONSTRAINT import_items_sections_is_array
  CHECK (jsonb_typeof(sections) = 'array');

-- section_count 校验
ALTER TABLE import_items
  ADD CONSTRAINT import_items_section_count_check
  CHECK (section_count >= 1);

-- origin='shared' 时 share_source_id 不应为 null
-- （应用层校验，暂不加数据库 CHECK，因为 origin 可能在拉取时尚未确定）
```

### 7.2 索引

```sql
-- 用户素材列表（按创建时间倒序）
CREATE INDEX idx_import_items_user_created
  ON import_items (user_id, created_at DESC);

-- 用户素材列表（排除已删除）
CREATE INDEX idx_import_items_user_active
  ON import_items (user_id, deleted_at);

-- 共享池查询
CREATE INDEX idx_import_items_shared
  ON import_items (share_status, deleted_at)
  WHERE share_status IN ('shared', 'public');

-- 溯源查询
CREATE INDEX idx_import_items_share_source
  ON import_items (share_source_id)
  WHERE share_source_id IS NOT NULL;

-- 阅读区溯源查询
CREATE INDEX idx_articles_source_import
  ON articles (source_import_id)
  WHERE source_import_id IS NOT NULL;
```

### 7.3 RLS 策略

```sql
ALTER TABLE import_items ENABLE ROW LEVEL SECURITY;

-- 用户只能读写自己的素材
CREATE POLICY "Users can view own import items"
  ON import_items FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own import items"
  ON import_items FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update own import items"
  ON import_items FOR UPDATE
  USING (auth.uid() = user_id)
  WITH CHECK (auth.uid() = user_id);

-- 不授权 DELETE——软删除通过 RPC 函数 delete_import_item 原子执行
-- 与现有 articles 惯例一致（删除通过 soft_delete_article RPC）
```

### 7.4 权限授予

```sql
-- 仅授予 SELECT / INSERT / UPDATE，不授予 DELETE
GRANT SELECT, INSERT, UPDATE ON public.import_items TO authenticated;
```

### 7.5 自动触发器

```sql
-- updated_at 自动更新（与现有 articles 表模式一致）
CREATE TRIGGER trg_import_items_set_updated_at
  BEFORE UPDATE ON import_items
  FOR EACH ROW EXECUTE FUNCTION public.set_updated_at();
```

### 7.6 删除 RPC 函数

```sql
CREATE OR REPLACE FUNCTION public.delete_import_item(p_import_item_id text)
RETURNS integer  -- 返回受影响的 articles 数量（供日志记录）
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  affected_articles integer;
BEGIN
  -- 1. 解除已移入文章的溯源引用
  UPDATE public.articles
  SET source_import_id = NULL
  WHERE source_import_id = p_import_item_id
    AND user_id = auth.uid()
    AND deleted_at IS NULL;

  GET DIAGNOSTICS affected_articles = ROW_COUNT;

  -- 2. 软删除素材
  UPDATE public.import_items
  SET deleted_at = timezone('utc', now())
  WHERE id = p_import_item_id
    AND user_id = auth.uid()
    AND deleted_at IS NULL;

  RETURN affected_articles;
END;
$$;
```

## 十一、总结

本设计定义了导入区与阅读区的双区架构：

- **新增 `import_items` 表**作为导入区存储，完全复用 Document.sections 结构
- **articles 表补充 2 个可空字段**建立到导入区的轻量引用
- **origin / share_status / share_source_id 三个字段**为共享池远期预留
- **移入 = 复制，非移动**——导入区源内容保留，阅读区获得独立副本
- **引用链路可空**——上游删除不丢失下游数据
- **提取器完全复用**——导入流程改道，不进阅读区

后续所有实现工作以本文档为唯一设计依据。
