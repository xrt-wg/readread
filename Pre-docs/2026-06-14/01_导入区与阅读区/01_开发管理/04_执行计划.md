## 三、Phase 0：数据库层

### 阶段目标

在不改变任何现有功能的前提下，建立 `import_items` 表并补充 `articles` 表字段。

### 核心任务

#### 任务 0.1：Supabase migration — import_items 表

创建 migration 文件，包含：

- `CREATE TABLE import_items (...)` — 完整字段定义
- `ALTER TABLE import_items ADD CONSTRAINT ...` — CHECK 约束
- `CREATE INDEX ...` — 用户素材列表、共享池查询、溯源查询索引
- `ALTER TABLE import_items ENABLE ROW LEVEL SECURITY`
- `CREATE POLICY ...` — 四条 RLS 策略（SELECT / INSERT / UPDATE / DELETE）

**字段清单**：

| 字段 | 类型 | 约束 |
|------|------|------|
| `id` | `text` | PK |
| `user_id` | `uuid` | NOT NULL, FK → profiles |
| `title` | `text` | NOT NULL |
| `author` | `text` | |
| `format` | `text` | NOT NULL |
| `cover_url` | `text` | |
| `lang` | `text` | NOT NULL, DEFAULT 'auto' |
| `source_url` | `text` | |
| `sections` | `jsonb` | NOT NULL, DEFAULT '[]' |
| `total_word_count` | `integer` | NOT NULL, DEFAULT 0 |
| `section_count` | `integer` | NOT NULL, DEFAULT 1 |
| `origin` | `text` | NOT NULL, DEFAULT 'imported' |
| `share_status` | `text` | NOT NULL, DEFAULT 'private' |
| `share_source_id` | `text` | |
| `created_at` | `timestamptz` | NOT NULL |
| `updated_at` | `timestamptz` | NOT NULL |
| `deleted_at` | `timestamptz` | |

#### 任务 0.2：Supabase migration — articles 表补充

- `ALTER TABLE articles ADD COLUMN source_import_id text`
- `ALTER TABLE articles ADD COLUMN imported_at timestamptz`
- `CREATE INDEX idx_articles_source_import ON articles (source_import_id) WHERE source_import_id IS NOT NULL`

不添加 FK 约束。不执行回填（null 是合法状态）。

#### 任务 0.3：staging 环境验证

- 在 staging 分支执行 migration
- 插入测试数据，验证 CRUD 操作
- 验证 RLS 策略：用户 A 无法访问用户 B 的 import_items
- 验证现有 articles 查询不受新增字段影响

#### 任务 0.4：import_items 表附属对象

- `updated_at` 自动触发器 `trg_import_items_set_updated_at`（复用现有 `set_updated_at` 函数）
- `GRANT SELECT, INSERT, UPDATE ON public.import_items TO authenticated`（不授予 DELETE——软删除通过 RPC）
- `UNIQUE (user_id, id)` 约束（防御跨用户 ID 碰撞）

#### 任务 0.5：删除 RPC migration

创建独立 migration 文件，包含 `delete_import_item` 函数：

- `SECURITY DEFINER`，用户只能删除自己的素材（`WHERE user_id = auth.uid()`）
- 原子执行：先 SET NULL articles.source_import_id，再软删除 import_items
- 返回 `affected_articles` 计数（供日志记录）

### 本阶段不要求完成的事情

- 任何服务层代码
- 任何前端 UI
- 任何旧数据迁移

### 完成标志

- [ ] `import_items` 表在 staging 环境创建成功
- [ ] 所有约束（CHECK + UNIQUE）和索引生效
- [ ] `updated_at` 触发器生效（UPDATE 时自动更新）
- [ ] GRANT 权限正确（SELECT / INSERT / UPDATE 可用，DELETE 被拒）
- [ ] RLS 策略：跨用户隔离验证通过
- [ ] `delete_import_item` RPC 函数可用，原子性验证通过
- [ ] `articles` 表新增字段存在，旧数据 `source_import_id` / `imported_at` 为 null
- [ ] 现有功能（文章导入、阅读、收藏、回顾）未受影响

### 风险点

| 风险 | 应对 |
|------|------|
| RLS 策略配置错误导致用户数据泄露 | staging 先用两个测试用户验证跨用户隔离 |
| JSONB 约束语法错误 | 在 Supabase SQL Editor 中逐条测试后再写入 migration |
| migration 文件与现有 migration 冲突 | 按时间戳命名 migration 文件，确保顺序正确 |

### 回滚策略

- RPC migration：`DROP FUNCTION IF EXISTS public.delete_import_item`
- 建表 migration：`DROP TABLE IF EXISTS import_items CASCADE`（含触发器自动清理）
- articles 新增字段：`ALTER TABLE articles DROP COLUMN IF EXISTS source_import_id, DROP COLUMN IF EXISTS imported_at`
- 无旧数据回填 → 回滚零数据损失

## 四、Phase 1：服务层

### 阶段目标

建立导入区的完整服务层：CRUD 操作 + copyToReadingZone + 删除级联逻辑。articles 的 mapArticleRow 适配新字段。

### 核心任务

#### 任务 1.1：importItems.js 服务模块

创建 `src/services/importItems.js`：

```
export function createImportItem(extractionResult, options)  → ImportItem
export function fetchImportItems(userId)                      → ImportItem[]
export function fetchImportItemById(id)                       → ImportItem | null
export function fetchImportItemTitlesByIds(ids)               → Map<string, string>
export function updateImportItem(id, patch)                   → ImportItem
export function countImportReferences(importItemId)           → number
export function deleteImportItem(importItemId)                → void (调用 RPC)
export function copyToReadingZone(importItem)                 → Document
```

**实现要点**：

- **`createImportItem`**：
  - 调用 `assembleSections(result.sections)` + `deriveParentIds(sections)`（从 `extractors/index.js` 导入的共享函数）
  - 调用 `generateId('imp_')` 生成 ID
  - 其余字段从 `ExtractionResult.meta` 和 `options` 装配
- **`fetchImportItemTitlesByIds`**：批量查询，`SELECT id, title FROM import_items WHERE id IN (...)`，返回 `Map<string, string>`。为 Phase 4 文章卡片批量预取素材标题做准备
- **`deleteImportItem`**：调用 RPC `delete_import_item(id)`（单次原子操作，替代原两步 UPDATE 方案）
- **`copyToReadingZone`**：
  - `structuredClone(importItem.sections)` 深拷贝
  - 构造 `ExtractionResult`（含 `sourceUrl`）
  - `createDocument()` 生成 Document
  - 设置 `source_import_id`、`imported_at`、`sourceType = importItem.format`
  - `saveArticle()` 写入 articles
- 所有查询过滤 `deleted_at IS NULL`
- RPC 调用使用 `.rpc('delete_import_item', { p_import_item_id: id })`
- 错误处理统一使用 `isLibraryAccessError` / `resolveLibraryErrorMessage`（从公共模块导入）

#### 任务 1.2：library.js 适配

三处修改（均在 `src/services/library.js`）：

**a) `ARTICLE_COLUMNS` 常量**：添加 `source_import_id, imported_at`

```js
const ARTICLE_COLUMNS = [
  'id', 'user_id', 'title', 'text', 'markdown',
  'word_count', 'source_type', 'source_url',
  'author', 'format', 'cover_url', 'lang',
  'sections', 'section_count',
  'source_import_id', 'imported_at',  // 新增
  'created_at', 'updated_at', 'deleted_at',
].join(', ')
```

**b) `saveArticle` 的 upsert 对象**：添加两个字段的显式映射

```js
source_import_id: article.source_import_id ?? null,
imported_at: article.imported_at ?? null,
```

> **注意**：`saveArticle` 采用逐字段显式映射而非展开运算符——新增字段必须手动添加，否则会被静默丢弃。

**c) `mapArticleRow`**：添加 camelCase 映射

```js
source_import_id: row.source_import_id ?? null,
imported_at:      row.imported_at      ?? null,
```

#### 任务 1.4：sections 装配逻辑抽取

修改 `src/services/extractors/index.js`：

#### 任务 1.5：错误处理提取到公共模块

- 验证 structuredClone 深拷贝：修改源 sections 不影响已移入的 article
- 验证 `fetchImportItemTitlesByIds` 批量查询正确

### 本阶段不要求完成的事情

- 任何前端 UI
- 导入流程的实际改道

### 完成标志

- [ ] `createImportItem` 可正确生成并持久化 ImportItem（复用 `assembleSections` + `deriveParentIds` + `generateId`）
- [ ] `fetchImportItems` 可按 userId 过滤且排除已软删除
- [ ] `fetchImportItemTitlesByIds` 批量查询正确
- [ ] `updateImportItem` 可部分更新字段
- [ ] `deleteImportItem` 通过 RPC 原子执行：SET NULL + 软删除在同一事务中
- [ ] `copyToReadingZone` 生成独立副本：
  - [ ] `sourceUrl` 正确传递给 Document
  - [ ] `sourceType` 映射为 `importItem.format`
  - [ ] 修改源 sections 不影响副本
- [ ] `countImportReferences` 计数准确（仅未删除文章）
- [ ] `ARTICLE_COLUMNS` 包含 `source_import_id, imported_at`
- [ ] `saveArticle` 的 upsert 对象包含 `source_import_id, imported_at`
- [ ] `mapArticleRow` 返回 `source_import_id, imported_at`
- [ ] `isLibraryAccessError` / `resolveLibraryErrorMessage` 已提取到 `errorUtils.js`
- [ ] 现有文章功能不受影响（library.js 的旧路径未改变）

### 风险点

| 风险 | 应对 |
|------|------|
| structuredClone 在 Node 测试环境不可用 | 测试环境检查并 polyfill；浏览器环境已原生支持 |
| sections 深拷贝不彻底（引用残留） | 用 `structuredClone` 而非展开运算符，验证修改源不影响副本 |
| RPC 函数未被 Supabase JS 客户端正确调用 | 在 staging 环境先验证 `.rpc()` 调用路径 |
| ARTICLE_COLUMNS 遗漏新字段 → 写入但不返回 | 在 `saveArticle` 返回结果中验证新字段存在 |

### 回滚策略

- `importItems.js` 是纯新增模块，无依赖方 → 直接移除 imports 即可
- `mapArticleRow` 的新字段是可空的 → 移除后只是少两个字段，不影响现有功能

## 五、Phase 2：导入流程改道

### 阶段目标

将现有导入路径从"直接写入 articles"改为"写入 import_items"。现有提取器和 Document 模型完全不变。

### 核心任务

#### 任务 2.1：ImportPage 提交路径修改

现有流程（以 URL 导入为例）：

```js
// 旧
const result = await extractor(input, signal)
const document = createDocument(result)
await saveArticle(document, options)
await loadLibraryState()
```

改为：

```js
// 新
const result = await extractor(input, signal)
const importItem = await createImportItem(result, { userId, origin: 'imported' })
// 不再自动进入文章库
// 提示用户：素材已保存到导入区，可编辑后移入阅读区
```

三种导入方式（URL / 文件 / 粘贴）**全部改道**。

#### 任务 2.2：导入后行为

- 导入成功后 → 提示 toast: "已保存到素材区"
- 可选项：自动切换到素材区标签 → 定位到新创建的素材
- 不做自动跳转也可以——让用户自行切换到素材区

**第一阶段选择：toast 提示 + 不自动跳转。** 自动跳转可能让用户困惑"我的文章库怎么没更新"。toast 文案清晰传达"素材已保存"的信息。

#### 任务 2.3：回归验证

改道后验证所有现有导入路径：

- [ ] **登录用户** URL 导入 → 写入 import_items，不写入 articles
- [ ] **登录用户** Markdown 文件导入 → 写入 import_items
- [ ] **登录用户** HTML 文件导入 → 写入 import_items
- [ ] **登录用户** EPUB 文件导入 → 写入 import_items
- [ ] **登录用户** 粘贴文本 → 写入 import_items
- [ ] **匿名用户** 所有导入方式 → 保持旧路径（createDocument → saveArticle → localStorage）

#### 任务 2.4：匿名用户路径保留（新增）

> **实施后更新（2026-06-14）**：实际实施采用 `requireAuth` 门控——匿名用户点击导入时弹出注册提示，引导注册后使用。这与云端过渡计划的"门控引导注册"策略一致，而非设计文档中 P1-2 决议的"保留旧路径"选项。此偏差已记录在 `02_审核管理/05_实施后审核反馈处理记录.md`。

在 ImportPage 提交逻辑中添加 `isAuthenticated` 分支：

- 匿名用户：保持旧路径 `createDocument → saveArticle → localStorage → loadLibraryState`（与现有行为完全一致）
- 登录用户：新路径 `createImportItem → toast`（导入区）

补充测试用例：
- 匿名用户 URL 导入 → 文章库出现新文章，可正常阅读
- 匿名用户粘贴导入 → 文章库出现新文章
- 登录用户 URL 导入 → 素材区出现新素材，文章库无新增

> **注意**：Phase 2 与 Phase 3 应尽量在同一次发布中上线。Phase 2 单独部署后，登录用户导入的内容进入 `import_items` 但无 UI 可查看——从用户视角"消失了"。如果必须分开发布，需在 Phase 2 的 toast 和文档中明确告知测试者。

### 本阶段不要求完成的事情

- 导入区的编辑 UI
- "移入阅读区"按钮

### 完成标志

- [ ] 登录用户的五种导入方式全部改道至 import_items
- [ ] 导入后 articles 表无新增记录（登录用户）
- [ ] 匿名用户所有导入方式功能正常（旧路径不变）
- [ ] 匿名用户的导入门控行为不变
- [ ] 现有文章库不受影响（旧数据完好）

### 风险点

| 风险 | 应对 |
|------|------|
| 导入后用户找不到刚导入的内容（不知有素材区） | toast 包含"前往素材区查看"的链接 |
| 改道遗漏某条导入路径 | ImportPage 中 grep 所有 `saveArticle` 调用点，逐一确认改道 |
| 现有测试/调试依赖于导入→文章库行为 | 排查所有调用点，确保不遗留 |
| Phase 2 单独部署期间素材"消失" | Phase 2 与 Phase 3 同次发布；若分开发布，测试期需告知行为变化 |

### 回滚策略

- ImportPage 中的提交逻辑改回 `createDocument → saveArticle` 路径
- import_items 表中残留的测试数据可忽略（不影响阅读区）

## 六、Phase 3：导入区前端

### 阶段目标

用户可见的导入区功能：素材列表、编辑面板、"移入阅读区"按钮。这套 UI 与现有 ImportPage 在同一页面，通过标签切换。

### 核心任务

#### 任务 3.1：ImportPage 嵌套标签改造

将现有 ImportPage 重构为外层双标签 + 内层三标签：

```
外层标签（新增）:
  [素材区]  [文章库]

素材区 tab 内层（复用现有三标签）:
  [推荐阅读]  [URL导入]  [手动上传]
  └── 导入面板 UI
  └── ImportItemList（素材卡片列表）

文章库 tab:
  └── 现有文章库列表（Library）
```

**实现要点**：
- 外层标签状态管理（当前选中哪个外层标签）
- 内层标签仅在素材区选中时渲染（文章库选中时隐藏）
- 素材区空状态时引导文字 + 导入入口 CTA
- 标签切换时保持各自列表的滚动位置
- 现有 ImportPage 的推荐阅读 / URL 导入 / 手动上传三标签逻辑不变，仅被包裹在新的素材区标签内

#### 任务 3.2：ImportItemList 组件

创建 `src/components/ImportItemList.jsx`：

- 调用 `fetchImportItems(userId)` 获取素材列表
- 卡片展示：标题、格式图标、词数、节数、创建时间
- 每张卡片操作区：
  - `[编辑]` → 打开编辑面板
  - `[移入阅读区]` → 调用 `copyToReadingZone`
  - `[删除]` → 确认弹窗 → `deleteImportItem`
- "已移入 N 次" 徽标（当 count > 0 时显示）
- 空状态：引导文字 + 导入入口

#### 任务 3.3：ImportItemEditor 组件

创建 `src/components/ImportItemEditor.jsx`：

- 编辑字段：title, author
- Sections 列表：
  - 每节显示 heading + 词数
  - 点击展开 → 内联编辑 heading / body.text / body.markdown
- 保存：调用 `updateImportItem`
- 取消：丢弃修改
- 保存后自动关闭或 toast 提示

**交互细节**：
- 编辑模式：点击卡片上的 [编辑] → 模态框打开
- 第一阶段用模态框（实现简单），后续可改为侧边面板
- Markdown 编辑区使用 textarea（不做所见即所得，保持与现有风格一致）
- **`isDirty` 检测**：
  - 打开编辑面板时用 `useRef` 保存初始值的快照（浅层比较 `title` + `author` + `sections` 的 heading/body）
  - 关闭前（模态框 onClose / 点击遮罩 / 按 Escape）检测 `isDirty`
  - 若 `isDirty = true` → 弹窗确认："有未保存的修改，是否放弃？"
  - 保存成功后 `isDirty` 重置为 false

#### 任务 3.4：移入操作交互

- 素材卡片上 [移入阅读区] 按钮
- 点击 → 调用 `copyToReadingZone(importItem)`
- 等待完成 → toast: "已移入阅读区"
- 卡片上"已移入 N 次"更新
- 文章库标签自动刷新（或用户切换过去时刷新）

### 本阶段不要求完成的事情

- 阅读区文章卡片的来源标签
- 素材与文章之间的跳转链接

### 完成标志

- [ ] 导入区标签可见，素材列表正常加载
- [ ] 新建素材后列表实时更新
- [ ] 编辑面板可修改 title / author / sections 并保存
- [ ] [移入阅读区] 按钮功能正确，文章库出现新文章
- [ ] 删除素材的级联确认弹窗正常
- [ ] 空状态引导文案正确展示
- [ ] 现有文章库标签功能完全不受影响

### 风险点

| 风险 | 应对 |
|------|------|
| 编辑面板关闭时未保存 → 数据丢失 | `isDirty` 检测：关闭前比较当前值与快照，未保存时弹窗确认 |
| 嵌套标签层级过深用户困惑 | 外层标签用明显的视觉层级（大标签），内层标签用次级样式（小标签）；素材区为空时展示引导 CTA |
| 大量 sections 的素材编辑性能 | sections 列表使用虚拟滚动（如 > 50 节），第一阶段不做（实际不会超过 50 节） |
| 移入操作耗时（大 sections JSONB 深拷贝） | copyToReadingZone 内部操作同步（structuredClone + createDocument），网络写入是唯一的异步瓶颈，预计 < 1s |

### 回滚策略

- ImportItemList 和 ImportItemEditor 是纯新增组件——移除导入和标签即可恢复
- ImportPage 的标签改造通过条件分支控制——可通过 feature flag 关闭

## 七、Phase 4：阅读区适配

### 阶段目标

阅读区（文章库）展示来源标签，两区之间建立导航链接。

### 核心任务

#### 任务 4.1：文章卡片来源标签（含批量预取）

在现有文章卡片上（Library 列表），当 `article.source_import_id` 非空时：

- 展示灰色小字："来源：素材「{标题}」"
- **批量预取**：文章列表加载时，收集所有非空 `source_import_id` → 调用 `fetchImportItemTitlesByIds(ids)` → 一次性获取所有素材标题 Map
- 若素材已删除（deleted_at 非空且 source_import_id 无有效行）→ 不展示来源标签
- 点击来源标签 → 切换到素材区外层标签 → 定位到对应素材

#### 任务 4.2：两区导航衔接

- 素材区 → 文章库：点击"已移入 N 次"徽标 → 筛选文章库中来自该素材的文章
- 文章库 → 素材区：点击来源标签 → 切换到素材区并定位到对应素材

筛选逻辑：

```js
// 在文章库标签中，过滤来自特定素材的文章
fetchArticles({ source_import_id: importItemId })
```

#### 任务 4.3：素材区"已移入文章"列表（含移入时间戳）

点击素材卡片上的"已移入 N 次" → 展开或弹窗显示该素材产生的文章列表：

```
该素材已移入以下文章:
  · 经济学人·AI专题        — 2026-06-14 15:30 移入  [打开阅读]
  · 经济学人·AI专题        — 2026-06-15 09:12 移入  [打开阅读]
```

- 列表按 `imported_at` 倒序排列（最近移入在上）
- 每次移入显示时间戳（帮助用户区分多次移入的版本）
- `[打开阅读]` 链接跳转到该文章的 ReaderPage

### 本阶段不要求完成的事情

- 共享池功能
- 文章和素材的批量操作

### 完成标志

- [ ] 文章卡片正确展示来源标签
- [ ] 点击来源标签可跳转到对应素材
- [ ] 素材删除后，来源标签正确消失
- [ ] "已移入 N 次"可展开查看关联文章列表
- [ ] 两区导航流畅，无数据加载错误

### 风险点

| 风险 | 应对 |
|------|------|
| 源素材标题查询导致 N+1 问题 | 在文章列表加载时预取关联素材标题（一次批量查询） |
| 素材删除后来源标签的"闪烁"（先展示后消失） | 在文章加载时通过 JOIN 或子查询确认素材存在性 |

### 回滚策略

- 来源标签是纯展示层新增——移除标签渲染逻辑即可
- 不影响文章库核心功能

## 十一、延期与回退策略

### 延期原则

- Phase 0 延期 → 阻塞全部后续阶段，优先解决
- Phase 1 延期 → Phase 2/3 可使用 mock 数据做前端预研
- Phase 2 延期 → Phase 3 可用手动创建的素材数据做 UI 开发
- Phase 3 延期 → Phase 4 可提前做（来源标签逻辑独立于素材区 UI）
- Phase 4 延期 → 不影响核心功能，只是 UX 优化

### 回退原则

- **优先局部回退，不优先整体推翻**
- Phase 0 出问题 → 修补 migration 脚本，不推翻表设计
- Phase 1 出问题 → 修复单个函数，不推翻服务层架构
- Phase 2 出问题 → 单条导入路径恢复旧逻辑，其他路径保持新逻辑
- Phase 3 出问题 → 隐藏素材区标签，导入路径可临时恢复直接进文章库
- Phase 4 出问题 → 移除来源标签渲染，不影响阅读核心路径

### 最重要的回退底线

- **现有文章库的完整功能不被破坏**
- **旧文章（无 source_import_id）不受任何影响**
- **阅读、收藏、回顾链路完全不变**

## 十二、总结

执行计划的核心结论：

- 按 **"Phase 0（数据库）→ Phase 1（服务层）→ Phase 2（导入改道）→ Phase 3（导入区 UI）→ Phase 4（阅读区 UI）"** 的顺序推进
- Phase 0 新增 5 个任务（建表 + articles 字段 + staging 验证 + 触发器/GRANT/UNIQUE + RPC 函数）
- Phase 1 新增 6 个任务（importItems.js + library.js 三处修改 + mapImportItemRow + assembleSections 抽取 + errorUtils 提取 + 单元验证）
- Phase 2 新增匿名用户路径保留任务——**现有功能不退化**是关键底线（实施中采用 `requireAuth` 门控，见任务 2.4 偏差记录）
- ⚠ Phase 2 与 Phase 3 应同次发布——避免登录用户导入的素材在 Phase 2 单独部署期间"消失"
- Phase 3 是用户首次看到双区概念的时刻，嵌套标签交互需仔细打磨
- Phase 4 是两区联动优化——来源标签、批量预取、移入时间戳
- 删除使用 RPC 而非前端两步 UPDATE——与现有 `soft_delete_article` 模式一致，确保原子性
- 导入区不做本地存储——纯云端功能，与现有门控策略一致
