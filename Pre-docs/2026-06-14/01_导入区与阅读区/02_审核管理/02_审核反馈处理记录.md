## 二、逐项处理详情

### P0-1：`saveArticle` 显式字段映射 (P0)

**问题**：`saveArticle` 采用逐字段显式映射而非展开运算符。`source_import_id` 和 `imported_at` 未出现在 upsert 映射中——在 Document 上设置后调用 `saveArticle` 会被静默丢弃。`ARTICLE_COLUMNS` 同样遗漏，导致 select 不返回新字段。

**处理**：在 `04_执行计划.md` Phase 1 / 任务 1.2 中细化三处修改，列出具体代码位置和映射方式。同时在 Phase 1 完成标志和风险点中增加对应验证项。

**影响文档**：
- `04_执行计划.md` — Phase 1 / 任务 1.2（展开为 a/b/c 三处修改 + 代码示例）
- `04_执行计划.md` — Phase 1 完成标志（新增 3 项）
- `04_执行计划.md` — Phase 1 风险点（新增 `ARTICLE_COLUMNS` 遗漏风险）

---

### P0-2：`deleteImportItem` 竞态 → RPC (P0)

**问题**：删除流程分三步（COUNT → 弹窗确认 → UPDATE articles SET NULL + UPDATE import_items SET deleted_at），COUNT 和 UPDATE 之间存在竞态窗口。Supabase JS 客户端无法实现事务。项目已有 `soft_delete_article` RPC 模式可复用。

**处理**：
1. `02_设计与规范.md`：新增 §7.6 RPC 函数定义 + §7.3 移除 DELETE RLS 策略（软删除通过 RPC）+ §7.4 GRANT 不授权 DELETE
2. `03_实施方案.md`：重写 §5.1 删除流程，前端改为 `countImportReferences → 弹窗 → RPC delete_import_item`
3. `04_执行计划.md`：Phase 0 新增任务 0.5（RPC migration），Phase 1 任务 1.1 中 `deleteImportItem` 改为 RPC 调用
4. `01_决策记录.md`：删除策略从"应用层 SET NULL"改为"SECURITY DEFINER RPC 原子操作"
5. 弹窗文案不展示阅读副本数量——避免 COUNT 与 RPC 实际处理数之间的偏差导致用户困惑

**影响文档**：
- `02_设计与规范.md` — §5.4 重写 + §7.3/7.4/7.6 新增
- `03_实施方案.md` — §3.2.2 接口更新 + §5.1 重写
- `04_执行计划.md` — Phase 0 / 0.5 + Phase 1 / 1.1
- `01_决策记录.md` — 决策结论 + 决策范围

---

### P0-3：`copyToReadingZone` 缺少 `sourceUrl` (P0)

**问题**：`copyToReadingZone` 中构造 `ExtractionResult` 时 `meta` 未包含 `sourceUrl`。`import_items` 表有 `source_url` 字段，但移入时未被传递。URL 导入的素材移入阅读区后文章的 `source_url` 为 null。

**处理**：在 `03_实施方案.md` 的 `copyToReadingZone` 代码中补全 `sourceUrl: importItem.source_url ?? undefined`。同时补充 `sourceType: importItem.format` 映射（回应 P2-1），避免移入文章全部标记为 `source_type = 'manual'`。

**影响文档**：
- `03_实施方案.md` — §3.2.3 copyToReadingZone 代码（两行补全）
