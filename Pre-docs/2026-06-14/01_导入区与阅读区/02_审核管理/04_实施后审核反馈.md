### 4.2 匿名用户路径保留 — ❌ 未实现

| 编号 | 审核项 | 结果 |
|------|--------|------|
| A-001 | ImportPage 提交逻辑存在 `isAuthenticated` 分支 | ❌ |
| A-002 | 匿名用户 URL 导入 → 旧路径（`createDocument → saveArticle → localStorage`） | ❌ |
| A-003 | 匿名用户粘贴导入 → 旧路径 | ❌ |
| A-004 | 匿名用户导入后文章库正常出现新文章 | ❌ |
| A-005 | 匿名用户导入门控行为不变 | ❌ |

**详细分析**：

当前实现中，三个主要导入路径全部以 `requireAuth('导入文章')` 守卫：

- `handleSubmit`（粘贴/文件导入）L305：`if (!requireAuth('导入文章')) return`
- `handleUrlImport`（URL 导入）L333：`if (!requireAuth('导入文章')) return`
- `handleFile`（EPUB 分支）L262：`if (!requireAuth('导入文章')) return`

匿名用户触发任一路径时，`requireAuth` 返回 `false`，函数提前返回，仅显示 auth gate 提示消息。匿名用户**无法导入任何自有内容**——只能使用"立即体验"示例按钮（`handleSample`）。

**影响**：匿名用户的现有导入能力被移除。这是对 P1-2 "匿名用户导入路径保留" 的明确偏离。

**修正方案**：在各导入处理函数中添加 `isAuthenticated` 分支：

```js
// handleSubmit 示例修正
const handleSubmit = async () => {
  const trimmed = text.trim()
  if (!trimmed) { setError('请先输入或上传阅读内容'); return }
  if (!requireAuth('导入文章')) return  // ← 保留门控提示

  try {
    let result
    if (fileFormat && markdown) {
      result = await EXTRACTORS[fileFormat](...)
    } else {
      result = await EXTRACTORS.paste(...)
    }

    if (isAuthenticated) {
      // 登录用户 → 书架
      await createImportItem(result, { userId, origin: 'imported' })
      setSuccessMessage('已保存到书架')
      await loadImportItems()
    } else {
      // 匿名用户 → 旧路径（直接进阅读区 localStorage）
      const document = createDocument(result)  // 需从 extractors/index.js 导入
      await onImport(document)
    }
    handleClear()
  } catch (submitError) { ... }
}
```

> **注意**：`ImportPage` 当前未导入 `createDocument`（仅导入了 `EXTRACTORS`）。需要在文件头部补充：
> `import { EXTRACTORS, createDocument } from '../services/extractors/index'`

同样逻辑需应用于 `handleUrlImport` 和 `handleFile`（EPUB 分支）。
