## 二、逐条处理结果

### P1（中等）— D2 理由「调用点计数」与源码不符

**结论：采纳。** 独立复核确认：`saveBookmark` 实有 5 个调用点（`ReaderPage.jsx:249/303` 新建型，`ReviewPanel.jsx:76`、`useBookmarkAI.js:73`、`readings.js:971` 更新/回写/导入型）；`bookmarkStore.save` 仅 1 个调用点（`readings.js:785`，在 `saveBookmark` 内部）。原文「仅有两个调用点、都在 ReaderPage」错误，已更正前提陈述；结论（去重只放 `ReaderPage` 即可覆盖全部新建入口）不变。

**文档改动**（`01_讨论和决策记录.md` D2 理由首条）：

```diff
- 现有 `saveBookmark` / `bookmarkStore.save` 仅有两个调用点、都在 `ReaderPage`，在保存前判定即可覆盖全部路径，无需改数据层、无迁移风险。
+ 新建收藏的入口仅 `ReaderPage` 两处（预读分支 + `handleBookmark`）；`saveBookmark` 另有 `ReviewPanel`（复习回写）、`useBookmarkAI`（翻译回写）、`readings.js`（导入迁移）三处更新/回写型调用，均携带已有 `id` 经 `onConflict:'id'` upsert、不产生新 `id`。故去重只需落在 `ReaderPage` 的保存入口即可覆盖全部新建路径，无需改数据层、无迁移风险。
```

### P2（低）— 边界未覆盖 `paragraph_index` 为 null

**结论：采纳。** `isSameBookmarkLocation` 对 `paragraphIndex` 用严格相等、未归一化；历史云端书签 `paragraph_index` 可为 null，`null === 数值` 恒 false → 仅可能漏判重复（不误伤）。补一句与 `charOffset` 缺失同类的非破坏性边缘说明。

**文档改动**（`02_实施方案.md` §七 新增一条 bullet）：

```diff
 - **历史书签 `charOffset` 缺失**：判定用 `charOffset ?? null` 归一化，不误伤；……
+- **历史书签 `paragraphIndex` 缺失**：`paragraphIndex` 用严格相等、未归一化；历史云端书签若 `paragraph_index` 为 null，与任意新选区数值恒不等 → 仅可能漏判一条重复（不误伤），与 `charOffset` 缺失同属非破坏性边缘。
 - **预读高频划选**：……
```

### P3（低，确认项）— 去提示后重复收藏静默关闭无反馈

**结论：采纳（仅记录，不改方案）。** 这是 D3「已收藏状态由正文高亮 + 收藏列表承载」与 D4「点了就关」的直接推论，非缺陷。在 §四 显式记录该 UX 取舍及 `paragraphIndex === -1` 边缘，供测试/产品确认预期一致。

**文档改动**（`02_实施方案.md` §四 预期效果表格后新增说明段）：

```diff
 | 弹窗按钮文案 | 「收藏」/「已收藏」切换 | 恒为「收藏」 |
+
+ **UX 取舍（D3/D4 推论）**：同一位置同一词形重复收藏时，流程为「判定已存在 → 关闭弹窗 → 不保存」，**静默关闭、无 toast/文案提示**；已收藏状态由正文高亮 + 收藏列表承载。极端边界（`paragraphIndex === -1` 的标题/表格单元格选区不渲染高亮）下点「收藏」既无高亮又无提示，观感似「点了没反应」——此为已知取舍，若后续需要轻提示再作独立迭代。
```

### 验证清单补充（3 项）

**结论：采纳。** 追加至 `02_实施方案.md` §五：
