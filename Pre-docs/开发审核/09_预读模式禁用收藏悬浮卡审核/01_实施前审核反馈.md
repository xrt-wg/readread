## 七、问题清单（按严重程度排序）

### P1（中等，建议修复）— 切到预读模式时，已打开的悬浮卡不会即时关闭

**现象**：源头 gate 只能阻止**之后**的悬浮卡，但无法关闭**切换那一刻已经打开**的悬浮卡。

**根因**：

1. 渲染条件 [ReaderPage.jsx:932](src/components/ReaderPage.jsx#L932) 为 `hoverBookmark && !popup`，不含 `preReadMode`；
2. `handleTogglePreRead`（[ReaderPage.jsx:299-310](src/components/ReaderPage.jsx#L299-L310)）仅在关闭预读（`!newMode`）时做批量翻译，**未**在进入预读时清空 `hoverBookmark`；
3. 更隐蔽的是：预读模式下 `<span>` 的 `onMouseLeave` 会调 `showHoverCard(null, null)`，但该调用被 `if (preReadMode) return` 短路，**不会**清空残留的 `hoverBookmark`（除非鼠标恰好落在卡片的 `onMouseLeave` 上）。

**触发路径**（窄窗口）：普通模式悬浮某高亮 → 卡片弹出 → 快速点顶部「预读模式」按钮 → 卡片残留；此后即使移开鼠标，卡片也可能不消失（span 的 leave 被短路）。

**影响**：与 D1「预读模式下无悬浮卡」及 D2「避免陈旧卡」的初衷存在一个窄边角违背。实际触发概率低（需在卡片弹出且未移出高亮时切换），但一旦触发，卡片会「卡住」到下一次删除或回到普通模式。

**修复建议（任选其一，推荐 ①）**：

1. **渲染条件补 `!preReadMode`**（最省、最稳）：
   ```js
   {hoverBookmark && !popup && !preReadMode && ( ... )}
   ```
   这样无论 `hoverBookmark` 出于何种时序残留，预读模式下都绝不渲染。可与源头 gate 并存（gate 管「不产生」，条件管「不渲染」，双保险）。

2. 在 `handleTogglePreRead` 进入预读时主动清理：
   ```js
   if (newMode) {
     clearTimeout(hideTimerRef.current)
     setHoverBookmark(null)
   }
   ```

建议在 02 实施方案中同步补充一条验证项：「普通模式先悬浮出卡 → 切到预读模式 → 悬浮卡立即消失」。

### P2（低）— 「唯一入口」表述不够精确

02 实施方案 2.1 称「`showHoverCard` 是设置 `hoverBookmark` 的**唯一入口**」。实际 `setHoverBookmark(null)` 还出现在：

- [ReaderPage.jsx:324](src/components/ReaderPage.jsx#L324)（`handleDeleteBookmark`）
- [ReaderPage.jsx:936](src/components/ReaderPage.jsx#L936)（悬浮卡包装层的 `onMouseLeave`）

精确表述应为：「`showHoverCard` 是唯一把**收藏对象**写入 `hoverBookmark` 的入口（其余两处仅置 `null`）」。该表述不影响结论正确性，仅建议校准措辞，避免后续维护者误判。
