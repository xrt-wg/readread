## 二、逐条处理结果

### P1（中等）— 切到预读模式时已打开的悬浮卡不即时关闭

**结论：采纳，采用推荐方案 ①（渲染条件补 `!preReadMode`）。**

独立推演确认了残留窗口的存在：仅靠 `showHoverCard` 源头 gate 时，`hoverBookmark` 在模式切换瞬间可能残留，且预读模式下 span 的 `onMouseLeave` 被 gate 短路无法清空。方案 ① 把「预读模式下绝不渲染悬浮卡」升级为声明式不变量，零成本、零回归，是「gate 管不产生 + 条件管不渲染」的双保险。

**代码改动**（`src/components/ReaderPage.jsx`）：

```diff
-      {hoverBookmark && !popup && (
+      {hoverBookmark && !popup && !preReadMode && (
```

**文档同步**（`02_实施方案.md`）：

- 新增 `### 2.2 渲染条件补 !preReadMode（双保险）` 一节
- 修改总览更新为「2 处逻辑」
- 数据流图补「条件兜底」分支
- 验证清单追加 2 项：① 普通模式先悬浮出卡 → 切预读 → 卡立即消失；② 预读 OFF → ON → OFF 往返

### P2（低）— 「唯一入口」表述不够精确

**结论：采纳，措辞校准。**

原「`showHoverCard` 是设置 `hoverBookmark` 的**唯一入口**」改为「`showHoverCard` 是唯一把**收藏对象（非 null）**写入 `hoverBookmark` 的入口（其余两处 `setHoverBookmark(null)` 仅做清空）」。

**文档改动**：`02_实施方案.md` 2.1 说明。

### P3（低）— 根因分析「下划线不参与命中」措辞

**结论：采纳，措辞精化。**

原表述将 `text-decoration` 与 `border-bottom` 并列归为「不参与命中」，现收敛为：`text-decoration: underline` 纯装饰不参与命中；`border-bottom: 2px solid` 是真实边框、参与命中但仅 2px 细线。实质结论（句子/段落命中区远小于实色盒子）不变。

**文档改动**：`01_讨论和决策记录.md` 根因分析「可命中区域」表 + 关键点 1。
