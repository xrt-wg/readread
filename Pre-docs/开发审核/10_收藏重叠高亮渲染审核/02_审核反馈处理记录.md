## 二、逐条处理结果

### P1（中等）— 删除 `getCharOffset` 遗漏 import 同步移除

**结论：采纳。** 删除 `textUtils.js` 的 `getCharOffset` 导出时，`ReaderPage.jsx:24` 的 `import { ... getCharOffset }` 一并移除，三处联动（import / 使用处 / 导出）避免构建期「未导出命名导入」错误。

**代码改动**（`src/components/ReaderPage.jsx`）：

```diff
-import { detectSelectionType, findContainingSentence, getCharOffset } from '../utils/textUtils'
+import { detectSelectionType, findContainingSentence } from '../utils/textUtils'
```

**文档同步**（`02_实施方案.md`）：§2.3 说明 + §六 修改文件清单显式补充 import 移除。

### P2（中等）— `renderBgs` 在「短语完全包住句子 / 跨两条相邻句子」时重复 key

**结论：采纳。** 独立推演确认：同一 `bgRange` 被裁剪为多段后，落在**同一父节点**（外层容器）下的多个间隙片段 `key` 相同，触发 React 重复 key 警告。修复为 key 追加裁剪区段去重，`data-bookmark-id` 保持不变（hover/删除仍依赖它）。

**代码改动**（`src/components/ParagraphRenderer.jsx`）：

```diff
-      <span key={`bg-${r.bookmark.id}`} data-bookmark-id={r.bookmark.id} ...>
+      <span key={`bg-${r.bookmark.id}-${s}-${e}`} data-bookmark-id={r.bookmark.id} ...>
```

**文档同步**（`02_实施方案.md`）：§2.1「渲染规则」的「短语跨句边界」说明由「裁成两段」扩展为「可裁多段、key 按区段去重」。

### P3（低）— 01 失效链接

**结论：采纳。** `01_讨论和决策记录.md`「与既有设计的关系」中指向 `09_.../实施方案.md` 的链接改为实际存在的 `../09_预读模式禁用收藏悬浮卡/02_实施方案.md`。

### P4（低，预存）— `ulStyle` 沿用硬编码 indigo 与双下划线

**结论：采纳方案 A（单一 `border-bottom`）。** 该问题为预存（非本次引入），但本次重构 `ulStyle` 恰是收敛时机；Kaven 表示对该问题不熟悉，交由我方按分析取最佳方案。选 A 的理由：`HIGHLIGHT_STYLES` 本就声明 sentence/paragraph 用「`borderBottom` + `textDecoration:'none'`」，渲染处的 `textDecoration: underline` 覆盖属意外冗余——收敛为单一 `border-bottom` 是**恢复代码库自身声明的意图**，而非新设计；同时移除硬编码 `rgba(99,102,241,0.5)`（不在颜色规范允许例外内）、消除双下划线，且不新增任何变量。

**代码改动**（`src/components/ParagraphRenderer.jsx`）：`ulStyle` 只保留 `borderBottom: hs.borderBottom`，删除 `textDecoration` / `textDecorationColor` / `textDecorationThickness` / `textUnderlineOffset`。

**文档同步**：`01` 新增决策 D6；`02` §2.1 样式说明更新。

### P5（低）— `getSelectionStartOffset` 兜底返回段尾语义不佳

**结论：采纳。** 兜底值由「累加后的段尾偏移」改为 `0`（与旧 `indexOf` 的 `0` 兜底一致），并加注释说明交由 `buildLayers` 的 `slice === text` 校验过滤；helper 同时补 `!containerEl || !range` 空值守卫。

**代码改动**（`src/components/ReaderPage.jsx`）：

```js
function getSelectionStartOffset(containerEl, range) {
  if (!containerEl || !range) return 0
  ...
  return 0 // 兜底：startContainer 非文本节点等罕见情况（与旧 indexOf 的 0 兜底一致，交由 buildLayers 校验过滤）
}
```

### P6（低）— D1 措辞略窄

**结论：采纳。** D1 理由「改动集中在 `ParagraphRenderer`」收敛为「渲染改动集中在 `ParagraphRenderer`；另含 `ReaderPage` 的定位修正与 `textUtils` 的死代码清理」，避免「单文件改动」误读。

### 验证清单补充（3 项）

**结论：采纳。** 追加至 `02_实施方案.md` §五：① 短语跨句包住句子/跨两条相邻句子的重复 key 检查；② 改动后构建通过（import 已移除）；③ 复杂叠加无断线错位。
