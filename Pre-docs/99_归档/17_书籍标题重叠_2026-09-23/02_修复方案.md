# 书籍标题重叠 — 修复方案

- 日期：2026-09-23
- 前置文档：`01_问题分析报告.md`（根因 A：body 保留标题行；根因 B：同一 spine 全文重复填充进多个 TOC 节点）
- 验证工具：`scripts/debug-epub-headings.cjs`

---

## 一、修复目标

1. 消除标题重叠：任何 section 的 `body.markdown` 不再包含会被 SectionFlow 重建的标题文本（根因 A）。
2. 消除整章重复：共享同一 spine 文件的多个 TOC 节点，各自只拿到属于自己小节的内容切片（根因 B）。
3. 不破坏既有契约：Markdown 导入、URL 导入、无 TOC 书籍（fallback 路径）行为不变。

## 二、方案选型

| 方案 | 思路 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| 方案一：渲染层兜底 | SectionFlow 渲染 body 前跳过与 `section.heading` 重复的首个标题行 | 改动小；对存量坏数据即时生效 | 只解决根因 A，整章重复（根因 B）原样保留；启发式逻辑进渲染层，污染「body 不含标题」的契约 | ❌ 不单独采用 |
| 方案二：数据层修复（服务端解析时切分+剥离） | 在 `parse-epub.cjs` 中按 TOC 结构切分章节正文、剥离重复标题 | 同时解决根因 A+B；新导入数据干净；契约恢复 | 对存量已导入书籍无效，需配合阶段 2 | ✅ 主方案 |
| 方案三：方案二 + 渲染层轻量兜底 | 数据层修复为主，SectionFlow 加一道「首行标题与 heading 重复则跳过」的防御 | 存量坏数据的标题重叠也能缓解 | 多一处启发式 | ✅ 作为可选加固（见阶段 3） |

**推荐：方案二为主，方案三的渲染层兜底作为可选加固。**

## 三、主方案设计（数据层，改动集中在 `netlify/functions/parse-epub.cjs`）

### 3.1 整体流程

现有流程：`flattenTocTree` 平铺 TOC → 逐节点 `toMarkdown()` 填充全文。

新流程：

1. `flattenTocTree` 平铺时**保留 TOC 树上下文**：为每个节点记录 `_sectionId`、`_parentNames`（祖先名数组，用于剥离章标题）、`_siblings` 信息。
2. 按 `_sectionId` 分组：同一 spine 文件被几个节点引用，就在该文件的 markdown 内做一次**标题切分**。
3. 切分规则（核心）：
   - 在 markdown 中查找与**子节点名**匹配的 ATX 标题行（正则 `^#{1,6}\s*`，匹配前做归一化：去 `#`、空白、折行）；
   - 每个子节点的 body = 从其匹配标题行起、到下一个子节点标题行（或文末）止的内容，**且剥掉该小节自身的标题行**（SectionFlow 会重建）；
   - 实测依据：fixture 中 9 个 TOC 小节名与章节内 9 个 `<h3>`（转 `###`）逐一对应，归一化后可精确匹配。
4. 章标题剥离（根因 A 的另一半）：对每个 section 的 body 开头，若首个 ATX 标题块的归一化文本等于 `heading` 或任一 `_parentNames` 的归一化文本，则剥掉该标题块（注意处理 `<br>` 折行形成的跨行标题，如 `## 第1章  \n 审视自己`）。
5. 降级路径（找不到匹配标题时）：
   - 该 spine 的第一个引用节点保留全文（剥离章标题后），后续节点退化为 heading-only（`body.markdown = null`，`body.text = ''`）；
   - 保证任何情况下正文不重复、不丢失（第一个节点兜底持有全文）。

### 3.2 归一化函数（切分与剥离共用）

```
normalize(title) = title
  去除 markdown 标题符 ^#{1,6}\s*
  去除所有空白字符（含 \n、全角空格）
  去除 markdown 强调符 *、_
```

实测验证：`# 第一部分  \n 种子期` → `第一部分种子期` = normalize(`第一部分 种子期`) ✓；`## 第1章  \n 审视自己` → `第1章审视自己` = normalize(`第1章 审视自己`) ✓。

### 3.3 边界情况清单

| 情况 | 处理 |
| --- | --- |
| 无 TOC 书籍（wells.epub 型） | 走 fallbackSpineFlat，heading 全 null；只执行「首标题块剥离」的保守版：不剥（无 heading 可对照，保留原文最稳妥） |
| TOC 单层（无共享 sectionId） | 仅执行章标题剥离（3.1 第 4 步） |
| 小节标题是样式化 `<p>` 而非 `<h3>` | 匹配失败 → 降级路径（3.1 第 5 步） |
| 多个子节点同名 | 按出现顺序依次匹配第 N 个标题行 |
| 正文以图片/引言开头、章标题不在首行 | 剥离逻辑限定「body 首个非空行必须是标题块」才剥离，避免误删正文中的标题 |
| 章标题与子节标题相同 | 先剥章标题（对父名），再切子节（对子名），顺序保证不误切 |

### 3.4 同步影响检查

- `epubExtractor.js:48-50` 的 `applyImageThreshold` 在 body 填充之后执行，切片后照常生效，无需改动。
- `extractors/index.js:74-76` 汇总 fullText 用 `sections.map(s => s.body.text).join(...)`——切分后拼接结果与原文等价（去掉了重复），字数统计反而更准确。
- SectionFlow / ReaderPage / 收藏 charOffset：body 内容变化只影响**新导入**书籍，索引在新数据内自洽。

## 四、阶段划分

### 阶段 1（必做）：服务端解析修复

- 改动文件：`netlify/functions/parse-epub.cjs`（flattenTocTree 增强 + 切分 + 剥离 + 降级）。
- 验证：`scripts/debug-epub-headings.cjs` 扩展为断言式校验（见第六节）。

### 阶段 2（建议）：存量数据迁移

已导入书籍存于用户浏览器 localStorage（`rr_articles`），坏数据不会自动修复。两个选项：

- **选项 A（推荐）**：在 `storage.js` 的 `migrateArticlesIfNeeded` 旁加一次性迁移：对 `format==='epub'` 的书，重跑「剥离 + 切分」同款逻辑（切分逻辑抽到共享模块，客户端/服务端复用）；迁移后该书收藏的旧 charOffset 在正文变短处可能越界——已核实 `ParagraphRenderer.jsx:26-32` 的 `buildLayers` 会过滤越界或文本失配的收藏区间（`paraText.slice(r.start, r.end) === r.bookmark.text` 校验），表现为静默不高亮、不报错，属可接受的降级。
- **选项 B（保守）**：提示用户重新导入问题书籍，不做自动迁移。

### 阶段 3（可选加固）：渲染层兜底

SectionFlow 渲染 body 前，若首个非空行是 ATX 标题且归一化文本等于 `section.heading`，则跳过渲染该行。仅一行防御，缓解任何遗漏路径（含阶段 2 未覆盖的存量数据）的标题重叠。

## 五、不做的事

- 不改 epub2md 库本身（第三方依赖，且 TOC 无锚点属库的能力边界，绕开即可）。
- 不改 Markdown/URL/Paste 导入路径（无此问题，避免引入回归）。
- 不在渲染层做「正文去重」——数据问题在数据层解决。

## 六、验证计划

1. **fixture 断言**（扩展 `debug-epub-headings.cjs`）：
   - file-1.epub / zhihu.epub：断言每个 section 的 body 首行不再是与 heading 重复的标题；断言共享 sectionId 的 9 个小节 body 互不重复且拼接覆盖原章正文；断言切分起点正确——如「你为什么要创业？」节剥离自身 `###` 标题后，body 以该小节的第一个内容块（`#### ■ 创业是一种态度`，h4 未入 TOC、属正文）开头，而非整章的 `## 第1章 审视自己` 开头。
   - wells.epub（无 TOC）：断言输出与修复前逐字节一致。
   - file-2/3/4、online-imgs.epub：冒烟通过，无空 body 异常（除 heading-only 降级节点）。
2. **端到端**：导入 file-1.epub 到阅读区，分页翻阅第1章各小节——每页只出现一次标题（SectionFlow 重建的），正文不再整章重复。
3. **回归**：Markdown 导入（含 frontmatter）、URL 导入各一篇，确认标题/正文渲染与修复前一致。
4. **用户实测对照**：请用户对其问题书籍重新导入（或应用阶段 2 迁移后），确认标题重叠消失。
