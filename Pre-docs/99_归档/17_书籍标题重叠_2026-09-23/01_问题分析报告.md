# 书籍标题重叠 — 问题分析报告

- 日期：2026-09-23
- 现象：阅读区打开 EPUB 书籍时，小节顶部出现「标题重叠」——同一标题（或章标题）被渲染两次。
- 分析依据：`problem-analysis-guide.md`（区分结论与推测，重论据与推理）。
- 验证工具：`scripts/debug-epub-headings.cjs`（复刻 `parse-epub.cjs` 核心逻辑，对真实 EPUB fixture 实测）。

---

## 一、结论（有完备论证）

### 根因 A：章节正文保留了自身标题行，渲染层又重建了一个标题

渲染层 `SectionFlow` 的契约是「`section.body` 不含标题行」，它在每个 section 前用 `section.heading` 重建内联标题：

- `src/components/SectionFlow.jsx:212-236`：注释明示「每个 section 前按 heading + depth 重建内联标题（section.body 不含标题行）」，随后 `section.heading && <HeadingTag …>{section.heading}</HeadingTag>`，紧接着渲染 `section.body.markdown`。

但 EPUB 数据生产端违反了这个契约：

- `netlify/functions/parse-epub.cjs:17-32`：`flattenTocTree` 将 TOC 条目名写入 `heading: item.name`；
- `netlify/functions/parse-epub.cjs:94-107`：填充正文时 `rawMd = epubSection.toMarkdown()`，仅清理 XML/DOCTYPE 声明，**没有任何剥离正文开头标题行的逻辑**；
- `node_modules/epub2md/lib/parseSection.cjs:41-43`：`toMarkdown()` 是对该 spine 文件**整个 HTML** 的全量转换（converter 即 node-html-markdown），EPUB 章节 HTML 通常以 `<h1>/<h2>章节名</h2>` 开头，因此 `body.markdown` 首行就是 `#`/`##` 标题。

于是同一标题被渲染两次：SectionFlow 重建一次（article-h2/h3/h4），ReactMarkdown 渲染 body 内 `#` 行一次（article-h1/h2）。这就是「标题重叠」。

### 根因 B（实测新发现，比根因 A 更严重）：同一章节正文被重复填充进多个小节

EPUB 目录中「父章 + 若干小节锚点」常指向同一 spine 文件，而 `parse-epub.cjs` 给**每个 TOC 节点**都填充了该文件的**完整正文**。实测 `file-1.epub`（典型中文书）：

```
被多个 TOC 节点共用的 sectionId:
  id521 × 9, id531 × 10, id561 × 13, id571 × 6 …（共 11 个 spine 文件被复用）
```

即书籍分页模式下，「你为什么要创业？」「是否适合创业？」等 9 个小节页面，每一页渲染的都是同一整章（id521 正文 25 037 字符）。用户先注意到的是标题重叠，正文大规模重复是同一缺陷的另一面。

### 关键约束（决定修复方案的可行边界）

1. **epub2md 的 TOC 树不含锚点（hash）信息**：实测 TOC 节点字段仅 `name / sectionId / nodeId / path / playOrder / children`，无法按 TOC 锚点直接切分 spine 内容。
2. **但章节 HTML 内部有完整标题骨架**：实测 id521（第1章）内为 `<h2>第1章 审视自己</h2>` + 9 个 `<h3>`（与 9 个 TOC 小节名逐一对应）+ 34 个 `<h4>`（未入 TOC 的更细要点）。转 Markdown 后对应 `##`/`###`/`####` 行。**按标题文本切分是可行的**。
3. 章节标题常含 `<br>` 折行，转 Markdown 后标题跨两行（如 `## 第1章  \n 审视自己`），任何「剥离标题」逻辑都必须处理折行。

### 旁证

- `git log -S` 检索确认 `parse-epub.cjs` 从未存在过「剥离首个标题」的逻辑——不是回归，而是管线自建立以来的契约缺口。
- Markdown 导入无此问题：`src/services/extractors/markdownExtractor.js:83-101` 切分时把 `##/###/####` 标题行消耗进 heading、不进 body，body 天然干净。EPUB 管线缺少等价处理。
- 阅读页无其他标题来源：`ReaderPage.jsx:830-831` 页面级大标题仅非书籍渲染（`{!isBook && …}`）。

## 二、实测数据（推测 → 已证实）

| 原推测 | 实测结果 |
| --- | --- |
| 推测 1：父子 TOC 节点共用 sectionId 导致整章重复 | ✅ 证实。11 个 spine 文件被 5~13 个 TOC 节点复用，每节点均填充全文 |
| 推测 2：重复标题存在「完全一致」与「部分一致」两形态 | ✅ 证实。完全一致：TOC「目录」 vs 正文 `## 目录`；部分一致：TOC「第一部分 种子期」 vs 正文 `# 第一部分  \n 种子期`；9 个共用 id521 的小节标题各异，正文标题均为 `## 第1章 审视自己` |

### 「是否所有书都出现」

取决于书的结构：**有 TOC 且章节 HTML 内含标题行的书必然重叠**（中文出版 EPUB 的典型结构）；无 TOC 的书（如 wells.epub）走 fallback 路径、heading 全为 null，不重叠。属普遍性问题，非个别文件损坏。

## 三、尚存的次要未知（不阻塞修复）

- 用户问题书籍的实际存储数据未直接核验（书籍存于浏览器 localStorage `rr_articles`，分析环境无法访问）。但 fixture 复现的证据链已闭合，该项仅用于最终回归对照。
- 个别 EPUB 的小节标题可能是样式化 `<p>` 而非 `<h3>`（本 fixture 恰好是 `<h3>`），切分方案需对「找不到匹配标题」有降级路径（见修复方案）。

## 四、影响面评估

- **阅读体验**：标题重叠；分页模式下多个小节页面内容完全相同（整章重复），翻页计数虚高。
- **收藏/阅读标记**：同一正文在多小节重复，charOffset 相同但 sectionId 不同，收藏会归属到不同小节、互相不可见；修复后新导入书籍恢复正常。
- **存量数据**：已导入用户 localStorage 的书籍仍是坏数据，需要迁移或重新导入（见修复方案阶段 2）。
