### 4.3 多章节进度计算

```js
function calcMultiSectionProgressAtMark(article, currentSection, sectionScrollPercent, readingMark) {
  const totalWords = article.sections.reduce((sum, s) => sum + s.body.wordCount, 0)
  if (totalWords === 0) return sectionScrollPercent

  const completedIds = new Set(readingMark?.completedSections ?? [])
  let cumulativeWords = 0

  for (const section of article.sections) {
    if (completedIds.has(section.id)) {
      cumulativeWords += section.body.wordCount
    } else if (section.id === currentSection.id) {
      cumulativeWords += section.body.wordCount * (sectionScrollPercent / 100)
      break
    }
  }

  return Math.round((cumulativeWords / totalWords) * 100)
}
```

调用处：

```js
const progressPercent = hasMultipleSections
  ? calcMultiSectionProgressAtMark(article, currentSection, scrollPercent, readingMark)
  : scrollPercent
```

## 七、有效性原理

```
                   之前                              之后
           ┌─────────┴─────────┐            ┌─────────┴─────────┐
     标记时                    列表时         标记时              列表时
        │                        │              │                  │
  存 paragraphIndex        getParagraphs   存 scroll%        读 scroll%
  (AST 段落索引)           → 重新解析      (顶部栏快照)       → 直接展示
        │                  → calcProgress      │                  │
        │                  → 算出百分比         │                  │
        │                        │              │                  │
        └──── 两次计算 ──────────┘              └── 零计算，同一值 ──┘
        不同数据源，不同算法                   记录即展示
```

**为什么根除了不一致**：

- 不再在列表端解析 markdown → CRLF / 引用块 / AST vs regex 全部不再参与
- 进度值的唯一来源是 `window.scrollY / scrollable`——浏览器原生 API，与阅读器顶部栏完全同源
- 多章节部分仅依赖 `section.body.wordCount`——导入时已算好，无需实时解析

## 八、预期效果

| 指标 | 之前（段落模型简化后） | 之后（scroll 快照） |
|------|---------------------|-------------------|
| 单章节：列表 vs 顶部栏 | **相同**（段落模型 + clamp） | **相同**（同一 scroll 值） |
| 多章节：列表 vs 实际 | 仅反映当前 section 内进度 | 反映全书词数加权进度 |
| 99% 假阳性 | 可能残留（段落计数仍有微小偏差时） | **不可能**——不存段落索引作为进度 |
| progress.js 行数 | 127 | ~85 |
| ImportPage 计算逻辑 | `calcProgress(article, mark)` | `mark.progressPercent` |
| 崩溃风险（undefined 等） | 无（已加防护） | 无（纯数字读写） |
| 精度 | 1%（段落比例） | 1%（scroll 百分比） |
| 字体大小变化后 | 段落索引仍正确，进度依段落位置 | scroll% 是标记时刻的快照——**不随字体变化而更新**（D1 已明确接受） |
