## 2. 关键问题处理

### P1：`#2d2926` → `#3d3934` 违反设计令牌原则 🔴

**审核意见**：替换方案用一个新硬编码替代旧硬编码，违反方案自身原则。应新增 `--btn-hover-bg` CSS 变量。

**处理**：✅ 完全接受。

**具体动作**：
- 在 `index.css` 新增 `--btn-hover-bg` 变量（日间 `#2d2926`、夜间 `#3d3934`）
- 修复方案 §1.1.1 新增 `#2d2926` 全局影响清单（6 处出现位置）
- 修复方案 §5 变量清单扩展
- 修复方案 §2.2.3 / §2.3.3 / §3.1.7 所有 `#3d3934` → `var(--btn-hover-bg)`
- 执行计划 Phase 0 变量数 9→11
- 执行计划 Phase 1.2.3 / 1.3.3 / 2.1.7 步骤更新
- 执行计划 §风险 3 更新为 `var(--btn-hover-bg)` 说明
- 分析报告 §6.0 新增 `#2d2926` 横切关注点

### P2：验证计划严重不足 🔴

**审核意见**：缺乏量化成功标准、用户测试计划、回滚方案、上线门槛。

**讨论**：实施方提出以"任务完成率 checklist + 用户走查"替代数据指标，因项目无埋点基础设施。审核方接受。

**处理**：✅ 讨论后达成共识。

**具体动作**：
- 执行计划 §5.1 新增结构化成功标准（6 维度 × 判定条件）
- 执行计划 §5.3 新增用户测试计划（2-3 人 × 30 分钟）
- 执行计划 §5.6 新增回滚方案（Per-Phase 独立 revert）
- 执行计划新增「上线门槛」节：P0+P1 可上线，P2 跟进迭代

### P3：存在未覆盖的硬编码阴影 🟡

**审核意见**：修复方案中 hover 阴影（`rgba(0,0,0,0.12)` 等）仍是硬编码，建议新增 `--card-shadow-hover`。

**讨论**：实施方同意新增变量，但对变量范围有不同意见 —— 审核建议的值包含金色描边，实施方认为金色描边是推荐卡片专属的语义化设计，不应纳入通用阴影变量。审核方完全接受实施方的方案。

**处理**：✅ 讨论后达成共识。

**具体动作**：
- 新增 `--card-shadow-hover` 变量（纯阴影，不含金色描边）
- 金色描边保留在组件内联样式：`var(--card-shadow-hover), 0 0 0 1px rgba(196,154,60,0.12)`
- 修复方案 §1.3 补充设计说明
- 修复方案 §3.1.3 / §3.2.10 / §3.2.7 hover 阴影统一使用变量
- 执行计划 Phase 0 变量清单扩展
