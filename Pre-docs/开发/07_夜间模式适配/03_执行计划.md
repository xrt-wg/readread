- 浏览器默认深色模式偏好（`prefers-color-scheme`）→ 当前未实现，本次不改

### 5.6 回滚方案

每 Phase 独立 commit。如果某个 Phase 引入回归：

1. `git revert <phase-commit>` 回退该 Phase
2. 其他 Phase 不受影响
3. 修复后在新的 commit 中重新提交

### 5.7 编码规范沉淀

在 `CLAUDE.md` 中新增颜色使用规范：

```markdown
## 颜色使用规范

所有组件中的颜色必须通过 CSS 变量（`var(--*)`）引用，定义于 `src/index.css`。
- 需要新增颜色变量时，必须在 `:root` 和 `[data-theme="night"]` 中**同步定义**
- 允许硬编码的例外：语义色（红/绿/琥珀反馈按钮、金色品牌强调色）
- 阴影在日间模式使用 `rgba(28,25,23,...)`、夜间模式使用 `rgba(0,0,0,...)`
- 禁止在组件中新增 `#xxxxxx` 或 `rgba(...)` 硬编码颜色值（例外除外）
```

## 风险与注意事项

1. **不能并行修改同一文件** — Phase 1-3 涉及的文件互不重叠（ReviewCard / ImportPage / ReaderPage 各自独立），Phase 4 与 Phase 2 共享 ImportPage 但修改区域不同（已完成的 vs 未完成的）。建议严格按 Phase 顺序执行，每完成一个 Phase 就 commit。

2. **CSS 变量引用必须在 style 属性中** — `var(--card-bg-warm)` 只能工作在内联 `style={{}}` 或 `<style>` / CSS 文件中，不能用于 Tailwind 的 `className`（除非配合 `bg-[var(--card-bg-warm)]` 语法，但本项目风格不一致，统一用内联 `style`）。

3. **`var(--btn-hover-bg)` 的取值逻辑** — 日间模式使用 `#2d2926`（与原值一致），夜间模式使用 `#3d3934`（比背景 `#1a1814` 浅半度，保持 hover 可辨识）。两个值在 CSS 变量中分别定义，如果视觉验收不满意，只需在 `index.css` 中微调变量值即可，组件代码不受影响。

4. **阴影对比度** — Phase 0 中 `--card-shadow` 的夜间值（`rgba(0,0,0,0.28)`）是初始建议值。实际效果可能需在真实设备上微调（±0.05）。

5. **不要改结构** — 本次修复只改颜色值。不调整 JSX 结构、不改变组件逻辑、不重构 props。保持 diff 最小化，降低回归风险。
