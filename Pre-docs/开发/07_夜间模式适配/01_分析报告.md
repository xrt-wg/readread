# 夜间模式适配 — 分析报告

> 日期：2026-07-14
> 分支：`perf/global-optimization`
> 范围：阅读区 / 回顾区 / 推荐区

---

## 1. 背景与目标

用户反馈：在阅读过程中将模式切换为夜间模式后，阅读区、回顾区、推荐区的设计未与该模式适配。本报告从产品设计师的视角出发，对三个区域进行逐组件审计，评估夜间模式适配的完备程度、对功能与业务的影响，并追溯根本原因。

---

## 2. 主题系统架构梳理

### 2.1 机制概述

| 层次 | 文件 | 职责 |
|---|---|---|
| 状态管理 | [useTheme.jsx](../../src/hooks/useTheme.jsx) | React Context，管理 `parchment` / `night` 两态，持久化到 localStorage |
| DOM 标记 | 同上 | `setAttribute('data-theme', theme)` 设置在 `<html>` 上 |
| 设计令牌 | [index.css](../../src/index.css) `:root`（L5-41） | 亮色主题下约 30 个 CSS 自定义属性 |
| 暗色覆盖 | [index.css](../../src/index.css) `[data-theme="night"]`（L43-78） | 暗色主题下覆写全部 30 个属性 |

### 2.2 设计令牌清单

亮色主题定义了以下语义化令牌（暗色主题全部覆写）：

| 类别 | 令牌 | 用途 |
|---|---|---|
| 基础 | `--parchment`, `--parchment-50`, `--parchment-dark` | 页面/区域背景 |
| 基础 | `--ink`, `--ink-light`, `--ink-muted` | 三级文字色阶 |
| 强调 | `--gold`, `--gold-light`, `--gold-dark` | 品牌金色系 |
| 表面 | `--header-bg`, `--surface-bg`, `--surface-border` | 半透明表面 |
| 表面 | `--card-bg-warm`, `--border-subtle`, `--hover-bg` | 卡片/边框/hover |
| 弹窗 | `--popup-bg`, `--popup-border`, `--popup-shadow` | 弹窗容器 |
| 弹窗 | `--popup-divider`, `--popup-surface`, `--popup-surface-hover` | 弹窗内部 |
| 语义 | `--teal`, `--teal-border`, `--teal-bg` | 蓝绿色点缀 |
| 语义 | `--danger-bg`, `--danger-text` | 危险操作色 |
| 其他 | `--meta-sep-color` | 元数据分隔符 |

**结论：令牌体系覆盖面完整，基础设施正确。**

### 2.3 样式架构

所有组件采用 **Tailwind（布局）+ 内联 style（视觉属性）** 的混合方案。颜色应当通过 `var(--*)` 引用，但大量组件中出现了硬编码 hex/rgba 值。

| # | 文件 | 行号 | 用途 |
|---|---|---|---|

## 7. 业务与产品影响分析

### 7.1 用户体验断崖

```
用户阅读正文（适配良好）
  ↓ 建立"夜间模式可用"的认知
切换到回顾 Tab（亮色卡片）
  ↓ 体验断崖：刺眼的白色方块
信任感下降 → 切回日间模式或放弃使用
```

### 7.2 功能闭环受损

ReadRead 的核心价值主张是「阅读 → 收藏 → 回顾」的英语学习闭环：

- **阅读**：正文适配尚可 ✅
- **收藏**：弹窗层适配良好 ✅
- **回顾**：闪卡核心视觉完全硬编码 🔴

→ 夜间模式下用户要么手动切回日间模式做回顾，要么**放弃回顾**。闭环断裂。

### 7.3 推荐区冷启动受损

推荐区是内容发现和社区增长的关键入口。如果推荐列表在夜间模式下显示为刺眼白块：
- 新用户（尤其是夜间浏览用户）会直接跳过该区域
- 影响推荐内容消费率和社区贡献意愿
- 推荐评分、添加人数等社交信号被视觉噪音掩盖

### 7.4 品牌调性不一致

应用品牌定位：「羊皮纸 + 墨水」的沉浸式阅读体验。夜间模式应有「烛光下读书」的氛围感。硬编码的白色卡片完全违背了这种品牌承诺，使用户感知到产品的不成熟。

## 8. 根本原因

**不是设计问题，是工程执行问题。** 设计令牌体系（`index.css` 中的 `var(--*)`）已经完整定义了夜间模式所需的所有颜色。但：

1. 组件中约有 **60+ 处硬编码颜色值**绕过了设计令牌
2. 硬编码集中在三种类型：
   - **白色/亮色背景**：`#ffffff`、`#fdfaf5`、`#fefdfb` → 应使用 `var(--card-bg-warm)` / `var(--popup-bg)` / `var(--surface-bg)`
   - **亮主题 ink 色用于边框/阴影**：`rgba(28,25,23,0.06~0.12)` → 应使用 `var(--border-subtle)` / `var(--surface-border)`
   - **阴影中的 ink**：`rgba(28,25,23,0.xx)` → 夜间模式需要 `rgba(0,0,0,0.xx)`（已在 popup 阴影中示范：`--popup-shadow` 在夜间模式使用纯黑）
3. `ReviewCard.jsx` 的 `CARD_BG` 作为**文件级常量**被定义，是最典型的反模式
4. 品牌 Slogan 区域的文字渐变在亮色模式写死为深色系，夜间模式下与深色背景融为一体

**对比范例**：`BookmarkPanel`、`TranslationPopup`、`BookmarkHoverCard` 三个组件全部使用 `var(--popup-*)` 令牌，夜间适配完善，证明采用相同的工程方法即可解决所有问题。
