## 一、总体思路

引入一个复用的渲染原语 **`SectionFlow`**（分节堆叠渲染），并按 `kind` 决定其使用方式：

- **`article`**：把**全部 sections** 交给一个 `SectionFlow`，一条连续滚动流，底部**唯一**"全文完 / 标记已读完"。
- **`book`（顶层章 > 1）**：先按 `depth 0` 把 sections 分组为"章"，用现有分页器逐章翻页；**每一章页**用一个 `SectionFlow` 渲染该章的 section 子集（章内子节内联堆叠）；章底为**章节导航**，仅最后一章保留完成区块。

关键点：`SectionFlow` 内**每个 section 各自一个 `MarkdownContent`**，段落索引 `paraIdx` 逐节从 0 计数——**与现有 `sectionId + paraIndex` 三级索引完全一致**，历史书签零迁移。

## 二、核心数据推导

### 2.1 章分组（chapters）

新增纯函数（`ReaderPage` 内或 `utils`）：

```
groupIntoChapters(sections):
  按 order 升序遍历，每遇到 depth===0 的 section 起一个新章，
  其后 depth>0 的 section 归入当前章，直到下一个 depth===0。
  返回 Chapter[] = [{ lead: Section(depth0), children: Section[] , all: Section[] }]
```

- `article`：忽略分章，直接 `flow = sections`。
- `book`：`chapters = groupIntoChapters(sections)`；分页单元 = `chapters[currentChapterIdx]`；该页 `flow = chapter.all`。

### 2.2 分流判据（替换 P1/P3 根因）

```
现有：const hasMultipleSections = sectionCount > 1 && sections.length > 1
改为：
  const isBook = (article.kind === 'book')
  const paginated = isBook && groupIntoChapters(sections).length > 1
```

`paginated` 取代原 `hasMultipleSections` 作为"是否分页"的唯一开关。`article` 恒不分页。

## 三、`SectionFlow` 渲染原语（新增）

输入：`sections: Section[]`、`bookmarks`、`fontSize`、`readingMark`、回调等。

对每个 section 依次渲染：

1. **内联标题**（当 `section.heading` 非空）：按 `depth` 映射 `<h2>/<h3>/<h4>`，复用现有 `article-h2/h3/h4` 样式类。
   > 必要性：`section.body` **不含标题行**（`parseMarkdownSections` 将标题单独存入 `section.heading`），故须在此重建，否则连续流会丢失全部小标题。
2. **正文**：复用 `MarkdownContent`，`key = section.id`；bookmark 传入按 `b.sectionId === section.id` 过滤（沿用 [ReaderPage.jsx:1002](../../../src/components/ReaderPage.jsx#L1002) 现逻辑）。
3. **`readingMark` 传入**：仅当 `readingMark.sectionId === section.id` 时透传，保证标记高亮落在正确节。
4. **DOM 锚点**：block 外层加 `data-section-id={section.id}`，供跨节位置恢复消歧（不同节的 `data-para-index` 会重复）。

`SectionFlow` **不含**结尾区块——"全文完/导航"由外层按形态决定。

## 四、`ReaderPage` 呈现改造

### 4.1 内容区

```
{paginated
  ? <SectionFlow sections={currentChapter.all} ... />   // book：当前章的子集
  : <SectionFlow sections={sections} ... />}            // article：全部节
```

单节退化内容（无 heading、单 section）仍走 `SectionFlow`（单元素、无标题）——等价于旧的单节渲染，行为不变。

> 说明：现有"非 markdown 文本"分支（`currentBody.markdown == null` 时的 `parseText` 渲染，[ReaderPage.jsx:1008-1053](../../../src/components/ReaderPage.jsx#L1008-L1053)）需一并纳入 `SectionFlow` 的降级路径，保持 paste/纯文本内容可读。

### 4.2 结尾区块（修复 P2）

```
{paginated ? (
  <ChapterNav
     hasPrev={idx>0} hasNext={idx<chapters.length-1}
     onPrev/onNext={setCurrentChapterIdx}
     showComplete={idx === chapters.length-1} />   // 仅最后一章显示完成区块
) : (
  <EndMark + 标记已读完 />                          // article：唯一结尾
)}
```

- "— 全文完 —" 仅在 `article` 或 `book` 最后一章出现，消除"每节重复"。
- 完成按钮仍调 `setReadingMarkCompleted(articleId)`（D4 不变）。
- 推荐评分区块（[ReaderPage.jsx:1094-1116](../../../src/components/ReaderPage.jsx#L1094-L1116)）跟随完成区块一同迁移。

### 4.3 顶部"目录 N/M"

- `article`：隐藏章节指示与目录入口（无分页概念）。
- `book`：`N/M` 改为**章序 / 章总数**（`currentChapterIdx+1 / chapters.length`），而非 section 下标；`SectionTocPanel` 传入 chapters 的 lead sections，点击跳转到对应章页（子节仍在 TOC 树内展示但滚动到章页内该节）。

## 五、进度与位置恢复

### 5.1 进度计算

| 形态 | 进度取值 | 说明 |
|---|---|---|
| `article` | `scrollPercent`（整页滚动比例） | 与单节路径一致（2026-06-20 D3）；一次连续滚动即一个进度域 |
| `book` | `calcMultiSectionProgressAtMark` 复用，但**以"章"为单位** | 累计已完成章 wordCount + 当前章 wordCount×scroll%；当前章 wordCount = 该章 `all` 子节词数之和 |

`handleSetReadingMark`（[ReaderPage.jsx:450-486](../../../src/components/ReaderPage.jsx#L450-L486)）中 `hasMultipleSections` 分支判据改为 `paginated`；`currentSection` 在 article 下取"被点击段落所属 section"（由 `SectionFlow` 回调带出 `sectionId`），book 下取当前章 lead。

保存的 mark 仍是 `{ sectionId, paraIndex, progressPercent }` —— 结构不变。

### 5.2 位置恢复

- `article`：所有节都在 DOM，按 `[data-section-id="X"] [data-para-index="Y"]` 定位滚动。
- `book`：现有逻辑（[ReaderPage.jsx:504-514](../../../src/components/ReaderPage.jsx#L504-L514)）——先把 `readingMark.sectionId` 映射到所属**章**并翻页，再在该章页内滚动到目标节/段。需新增"section → chapterIdx"映射。

## 七、兼容性与风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 历史 article 书签定位 | 若段落索引口径变化会错位 | `SectionFlow` 保持"每节 paraIdx 从 0" → 与旧 `sectionId+paraIndex` 一致；无迁移 |
| `article.markdown` 拼接不含标题 | 直接渲染整份 markdown 会丢标题 | **不走整份渲染**；`SectionFlow` 从 `heading+depth` 重建内联标题 |
| `kind` 缺失的旧数据 | 分流判据取不到值 | `article.kind ?? 'article'`（library 已如此，[library.js:205](../../../src/services/library.js#L205)）→ 默认连续流，安全 |
| 纯文本/paste（markdown=null） | 需保持可读 | `SectionFlow` 内 `MarkdownContent` 降级到 `parseText` 分支 |
| book 进度语义变化（section→章） | 已读章的 wordCount 归属 | 章 wordCount = 子节词数和；`completedSections` 语义保持（仍按 section 记，聚合到章展示） |

## 八、测试检查清单

**article（多标题 MD）**
1. 连续滚动，无"目录 N/M"，无翻页。
2. `##/###` 内联为可见小标题（层级正确）。
3. 底部仅一处"— 全文完 — / 标记已读完"。
4. 划词收藏、`readingMark` 标记、位置恢复、进度与顶部栏一致。
5. 历史 article 的既有书签仍正确高亮定位。

**book（多章 EPUB / 构造多章 MD 手动置 kind=book）**
6. 按顶层章分页；`### 子节`在本章页内内联，非独立页。
7. 顶部显示"章序/章总数"；目录以章为跳转单元。
8. 章间导航正常；仅最后一章出现完成区块与评分。
9. 跨章进度加权正确；跨章位置恢复（先翻到章、再滚到节）。

**退化 / 回归**
10. 无 H2+ 的单节内容：行为与改动前一致。
11. paste 纯文本（markdown=null）：可读、可收藏、可标记。
12. 推荐区来源文章读完后评分入口正常。
