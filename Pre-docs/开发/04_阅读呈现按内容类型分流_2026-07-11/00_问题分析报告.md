# 问题分析报告 — 阅读呈现按内容类型分流

- **日期**：2026-07-11
- **参与者**：Kaven, Claude
- **状态**：已定位
- **触发来源**：内部测试（`Pre-docs/ReadRead-内部测试和迭代.md`）
- **原始问题**：
  1. 为什么导入单个 MD 文件会依据标题拆分成章节？
  2. 为什么每个章节底部都有"读完标记"，有意为之还是 BUG？

---

## 一、背景

ReadRead 于 2026-06-13 落地**统一文档模型（UDM）**：所有格式导入后收敛为同一份 `sections[]`（平铺数组 + `depth` + `parentId`），下游以 `documentId + sectionId + paragraphIndex` 三级索引引用。模型层由 `kind` 字段区分内容形态（`epub → book`、其余 → `article`）。

书架的 MD 导入经 `extractFromMarkdownFile` → `parseMarkdownSections` 拆分为 sections，移入阅读区后由 `ReaderPage` 呈现。本次测试暴露的现象集中在**阅读呈现层**。

---

## 二、现象与根因定位

### P1 — 单篇 MD 被拆成"章节"并逐页阅读

**性质：既定设计行为（拆分本身正确），但呈现判据错配。**

数据流证据链：

1. 上传 `.md` → [ImportPanel.jsx:59-63](../../../src/components/ImportPanel.jsx#L59-L63)：`fileFormat='markdown'`、`markdown=content`。
2. 保存 → [ImportPanel.jsx:99-102](../../../src/components/ImportPanel.jsx#L99-L102)：走 `EXTRACTORS.markdown`。
3. [markdownExtractor.js:28](../../../src/services/extractors/markdownExtractor.js#L28) → `parseMarkdownSections(body)` 无条件按标题切分。
4. [markdownExtractor.js:83-103](../../../src/services/extractors/markdownExtractor.js#L83-L103)：`##`/`###`/`####` 均 `flushSection()` 切出平级 section（`#` 当 title、`#####+` 当正文）。
5. [importItems.js:60-61](../../../src/services/importItems.js#L60-L61)：`assembleSections` 分配 `s_0…s_n`。
6. [ReaderPage.jsx:182](../../../src/components/ReaderPage.jsx#L182)：`hasMultipleSections = sectionCount > 1`。
7. [ReaderPage.jsx:209](../../../src/components/ReaderPage.jsx#L209)：按 `currentSectionIdx` **逐节分页**，顶部显示"目录 N/M"。

**根因**：呈现层的分页判据是 `sectionCount > 1`，**完全无视 `kind`**。带小标题的**文章**（`kind='article'`）因此被当作**书**逐页呈现。UDM 决策记录明确否决"丢结构降级"（[决策记录 99-106](../../2026-06-13/01_统一文档对象模型/01_决策记录.md#L99-L106)），故拆分与保存结构是对的；问题在于呈现方式没有按内容形态分流。

**边界事实（避免误判触发条件）**：
- 只切 `##/###/####`；`#`（H1）不切、`#####+` 不切。→ 仅当 MD 含 H2+ 标题时才分页。
- 无 H2+ 标题时走退化单节路径 [markdownExtractor.js:31-46](../../../src/services/extractors/markdownExtractor.js#L31-L46)。

### P2 — 每个章节底部都有"全文完 / 标记已读完"

**性质：缺陷（未处理多节场景）。**

1. [ReaderPage.jsx:1056-1144](../../../src/components/ReaderPage.jsx#L1056-L1144)："— 全文完 —"分隔符 + "标记已读完"按钮，位于内容区之后。
2. 内容区 [ReaderPage.jsx:998-1054](../../../src/components/ReaderPage.jsx#L998-L1054) 渲染的是 `currentBody` = **当前单个 section**（[ReaderPage.jsx:210-212](../../../src/components/ReaderPage.jsx#L210-L212)）。
3. 该完成区块**无"仅末节显示"的条件判断** → 逐节分页时**每节底部都出现**。
4. "全文完"在非末节上是**事实错误**的文案。
5. 完成动作 [ReaderPage.jsx:520](../../../src/components/ReaderPage.jsx#L520) `setReadingMarkCompleted(articleId)` **以整篇为键**、不带 sectionId → 任意节点击都标记整篇完成，逐节重复即**冗余 + 语义误导**。

**根因**：文末完成区块沿用"单篇文章"时代的 UI，多节分页引入后未收口。旁证：同文件的进度/书签逻辑均已 section 化（[ReaderPage.jsx:352-353](../../../src/components/ReaderPage.jsx#L352-L353)、[476](../../../src/components/ReaderPage.jsx#L476)、[1002](../../../src/components/ReaderPage.jsx#L1002)），唯独完成区块遗漏——典型的"改造覆盖不全"。

### P3 — `###` 子节被拉平成与 `##` 同级的独立页

**性质：缺陷（呈现层丢弃 `depth` 从属关系）。**

1. `parseMarkdownSections` 将 `##/###/####` 切成**平级** section，仅以 `depth`(0/1/2) 记录层级，无嵌套。
2. 阅读器按数组下标 `currentSectionIdx` 翻页（[ReaderPage.jsx:209](../../../src/components/ReaderPage.jsx#L209)），**未使用 `depth`**。
3. 结果：`## A / ### A.1 / ### A.2` 呈现为 3 个平级页（目录 1/3、2/3、3/3），而非"1 章含 2 子节"。
4. 仅 `SectionTocPanel` 用 depth 还原了缩进树（[SectionTocPanel.jsx:6-22](../../../src/components/SectionTocPanel.jsx#L6-L22)），阅读主区未用。

**根因**：存储层按 UDM 正确保留了 `depth` 层级，呈现层却把层级与分页一并拍平。

---

## 三、共同根因

三个现象共享同一条数据流与同一根因：

> **存储层已按 UDM 统一并保留完整结构（sections + depth），但呈现层用错了分流判据——只看 `sectionCount > 1`，既没看 `kind`，也没用 `depth`。**

因此修复方向应锁定在**呈现层**，不回退存储/拆分层。P1 的用户直觉（文章应连续阅读）与 UDM 的结构保留（B 意图）并不冲突——二者分属**呈现层**与**数据层**，各自成立。

---

## 四、结论

| 问题 | 性质 | 归因层 |
|---|---|---|
| P1 单篇被拆章节逐页读 | 判据错配（非拆分错误） | 呈现层 |
| P2 每节重复"全文完/读完" | 缺陷（多节未收口） | 呈现层 |
| P3 `###` 子节平级独立页 | 缺陷（丢弃 depth） | 呈现层 |

存储层保留 `sections[]` 与 `depth` 正确且既定，**不回退**。修复统一收敛为一条主线：**阅读呈现按内容类型（`kind`）分流，并让分页尊重 `depth`。**
