## 四、实施方案 — 合理性与有效性审核

### 4.1 SectionFlow 设计（§3）

**核心设计**：每个 section 各自一个 `MarkdownContent`，段落索引逐节从 0 计数，与现有三级索引完全一致。

| 审核维度 | 分析 | 结论 |
|---------|------|------|
| 三级索引兼容 | 现有 bookmark 存 `{sectionId, paragraphIndex}`；SectionFlow 每节独立 `MarkdownContent`、paraIdx 从 0 → 完全一致 | ✅ |
| 内联标题必要性 | `section.body.markdown` **不含标题行**（markdownExtractor.js L83-103 将标题单独存入 `heading`）→ 必须重建 | ✅ 必要 |
| `data-section-id` 锚点 | 供跨节位置恢复消歧（不同节的 `[data-para-index]` 会重复） | ✅ 必要 |
| 纯文本降级路径 | 计划提及 `parseText` fallback 需纳入 SectionFlow，与现有 L1008-1053 的降级分支语义一致 | ✅ |
| readingMark 透传 | 仅当 `readingMark.sectionId === section.id` 时传入 → 标记高亮落在正确节 | ✅ |

### 4.2 分流判据（§2.2）

```js
const isBook = (article.kind === 'book')
const paginated = isBook && groupIntoChapters(sections).length > 1
```

**边界分析**：

| 场景 | sections | isBook | chapters | paginated | 呈现方式 |
|------|---------|--------|----------|-----------|---------|
| MD 文章含 `##` | 5 个 section | false | — | false | 连续流 ✅ |
| 单章书 | 1 个 depth0 section | true | 1 | false | 连续流（无非导航必要）✅ |
| 多章书 | 8 个 section, 3 个 depth0 | true | 3 | true | 分章翻页 ✅ |
| 旧数据无 kind | 任意 | `?? 'article'` | — | false | 连续流（安全默认）✅ |
| sections=[] | 空 | false | 0 | false | 降级渲染 ✅ |

所有边界行为正确。**设计合理。**

### 4.3 groupIntoChapters（§2.1）

> 按 order 升序遍历，每遇到 depth===0 起新章，depth>0 归入当前章

与 markdownExtractor.js 中 `## → depth 0` / `### → depth 1` / `#### → depth 2` 的赋值语义一致。`##` 即为章边界，`###`/`####` 即为子节。**算法正确。**

### 4.4 展示改造（§4）

**内容区**：

```
{paginated
  ? <SectionFlow sections={currentChapter.all} />
  : <SectionFlow sections={sections} />}
```

单节退化内容（无 heading、单 section）经 `SectionFlow` 单元素、无标题渲染，等价于旧的单节渲染。✅

**结尾区块**：

```
{paginated
  ? <ChapterNav showComplete={isLastChapter} />
  : <EndMark + 标记已读完 />}
```

- `book`：仅最后一章出现完成区块，非末章为章节导航 → 从根上消除 P2 重复 ✅
- `article`：唯一结尾 → 消除 P2 重复 ✅
- 评分区块（L1094-1116）跟随完成区块一同迁移 ✅

**顶部"目录 N/M"**：

- `article`：`paginated=false` → 顶部 `目录` 按钮和 TOC 面板不渲染（L740-754 和 L1181-1189 均受 `paginated` 控制）✅
- `book`：`N/M` 改为章序/章总数 ✅

### 4.5 进度与位置恢复（§5）

| 形态 | 进度方案 | 与现有逻辑的兼容性 |
|------|---------|-----------------|
| article | `scrollPercent`（整页滚动比例） | ✅ 与 2026-06-20 单节路径一致 |

## 五、发现的问题与建议

### 5.1 ⚠️ P1 数据流第 6 步表述不精确

**问题**：分析报告声称 `hasMultipleSections = sectionCount > 1`（L182），但实际代码为：
```js
const hasMultipleSections = sectionCount > 1 && Array.isArray(sections) && sections.length > 1
```
遗漏了 `Array.isArray(sections)` 和 `sections.length > 1` 两个守卫。

**影响**：不影响根因结论（多 section 时必满足）。**

**建议**：修正分析报告中的代码引用以精确匹配源码。

### 5.2 ⚠️ 实施方案 SectionTocPanel 改造描述偏简

**问题**：实施方案 §4.3 对 `SectionTocPanel` 的改造描述为：
> "book 下以'章'为跳转单元（子节滚动到章页内）"

目前 `SectionTocPanel` 的 `onSelect` 接受 `section.order`（L26-31），调用方（L1186）将其传给 `setCurrentSectionIdx`。改造后 book 模式下需改为：点击 → 映射到 chapterIdx → 翻章 → 章页内滚动到子节。

**建议**：S2 实施时明确 `SectionTocPanel` 的接口变更——是否为 book 模式新增 `chapters` prop 替代 `sections`，或保留 `sections` 但由外层重新解释 `onSelect` 语义。

### 5.3 💡 建议：S1 交付后可做最小回归验证

S1 交付即可验证的核心路径（不等 S2）：
1. 导入含 `##` 标题的 MD → 确认连续滚动、无"目录 N/M"、标题内联可见
2. 旧单节文章 → 确认行为不变
3. 旧多节文章的书签 → 确认仍能正确定位高亮
4. paste 纯文本 → 确认可读、可标记

建议在 S1 完成后立即跑这 4 条，作为 S2 进入前的质量门。
