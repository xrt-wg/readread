## 一、目标

1. 移除「登录时把本地试用数据同步到云端」的静默导入逻辑（`migrateTrialSnapshot`）。
2. 登录时丢弃本地试用快照，保持试用数据的瞬时性，不再进入用户数据。
3. 「首次阅读选文」onboarding 不再被试用数据同步所压制。

## 三、逐文件改动

### 1. `src/store/storage.js` — 新增 `clearTrialData()`

```js
export function clearTrialData() {
  _articlesCache = null
  _bookmarksCache = null
  _marksCache = null
  localStorage.removeItem(KEYS.ARTICLES)
  localStorage.removeItem(KEYS.BOOKMARKS)
  localStorage.removeItem(KEYS.READING_MARKS)
  // 以下两个 key 由已删除的静默导入/旧「首次迁移」写入，作防御性清理
  localStorage.removeItem('rr_trial_migration_owner')
  localStorage.removeItem('rr_local_migration_meta')
}
```

> 必须在 `storage.js` 内实现（而非 `App.jsx` 裸 `removeItem`），因为要同时复位模块级缓存 `_articlesCache`/`_bookmarksCache`/`_marksCache`（复位为 `null` 与 `importData` 惯例一致，并强制下次 getter 重读），否则登录后再登出会从内存缓存「复活」已丢弃的试用数据。

## 五、验收标准

1. 静态：`grep -rn "migrateTrialSnapshot\|readTrialSnapshot\|firstReadingMigration\|toReadingDbRow\|firstReadingReady\|silentImporting\|migrationRetry" src/ scripts/` → **无结果**。
2. 构建：`npm run build` 通过，无未用 import 告警。
3. 运行时（登录流转）：
   - 匿名态点「示例文章」→ 本地出现文章/收藏 → 登录 → **不再出现**「正在同步阅读数据…」卡屏，也**不再出现**「部分本地文章尚未同步」报错。
   - 登录后 `localStorage` 中 `rr_articles`/`rr_bookmarks`/`rr_reading_marks` 被清除；云端书架只有既有数据，**不含示例文**。
   - 退出登录回到匿名态，书架**不再出现**旧的试用示例文。
4. 运行时（onboarding）：新用户（无云端 readings/bookmarks/marks）登录后，「首次阅读选文」弹窗能正常出现（前提：后台 `first_reading_config` 已启用并配置两篇选文）。
5. 回归：备份导入/导出当前为**未接线死代码**（`handleExport`/`handleImportFile` 无 UI 绑定），本次不触碰；`migrateLocalStorageArticles`（本地格式升级）不受影响。

## 六、风险与回滚

| 风险 | 应对 |
|---|---|
| 「匿名态只产生示例文章」依赖备份导入为死代码 | `handleImportFile` 现无 UI 绑定（`ImportPage.jsx:357`）；若未来为匿名开放备份导入，`clearTrialData` 需收紧为只清已知试用数据或加 `requireAuth`（见 `01` §二.1） |
| 误删 `toReadingDbRow` 仍有隐藏调用方 | 已 grep 全仓确认仅 `App.jsx:46` 调用；构建 + 验收 #1 兜底 |
| 丢弃与弹窗的竞态 | 弹窗不再本地判断试用数据，直接调后端 `get_first_reading_offer`，由后端判定 |
| StrictMode 双调用 effect | `clearTrialData()` 幂等（重复 `removeItem` 无害） |
| `rr_trial_migration_owner` 残留导致后续误判 | 已纳入 `clearTrialData` 一并清除 |

回滚：`git revert` 对应提交即可（无 DB 变更、无迁移文件）。
