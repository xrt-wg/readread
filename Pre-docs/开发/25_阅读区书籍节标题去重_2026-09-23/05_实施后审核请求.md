# 实施后审核请求 — 阅读区书籍节标题去重

> 日期：2026-09-23
> 审核对象：`src/components/ReaderPage.jsx` · `src/components/SectionFlow.jsx`
> 审核依据：[01 讨论和决策记录](01_讨论和决策记录.md) · [02 实施方案](02_实施方案.md) · [04 实施前审核反馈处理记录](04_实施前审核反馈处理记录.md)

## 一、请求说明

本次实施修复 EPUB 书籍在阅读区的节标题重复：根因是 EPUB 导入时正文 `body.markdown` 已含节标题行（`# 标题`），而 SectionFlow 又额外渲染了来自 TOC 的 `section.heading`，同一标题出现两次。

修复方式（决策 D1/D2）：**按 `format === 'epub'` 区分**——EPUB 书籍跳过内联 `section.heading`、只渲染完整 body（标题已在正文里）；其它格式（markdown/html/url/paste）维持渲染 `section.heading` + body。

请审核方在实施完成后，**对照本文档 §三「对照点」逐项核验代码与预期是否一致**，重点确认「一致性红线」无违例。

### 3.3 一致性红线（审核必须确认，违反即不通过）

- 判别键必须是 **`article.format === 'epub'`**，**不得**写成 `kind === 'book'`（`kind` 用户可改，Markdown/HTML 文件也可被标为书籍，否则会丢节标题）。
- `headingsInBody` 默认值必须为 `false`（未传 prop 的既有调用点行为不变）。
- **不得**改动 `netlify/functions/parse-epub.cjs`（EPUB body 含标题行是决策 D2 明确保留的现状）。
- `headingsInBody` **只作用于 SectionFlow 自身 JSX 的门控（L234）**，不得传入 `MarkdownContent`（其为 `memo`，依赖 `[sectionId]`；传入会破坏 memo 依赖、有整树重挂风险）。
- 不新增硬编码颜色；本次为纯布尔门控，不新增任何颜色/阴影值（CLAUDE.md 颜色规范）。

## 四、验收标准

（同步自 [02 §五](02_实施方案.md)，含 5.4 补的回归样本清单）

1. **EPUB 书籍**：阅读区每节只出现一次标题（正文首行的 `# 标题`），不再有 `section.heading` 重复。
2. **Markdown/HTML 文件（含被标为书籍者）**：节标题仍由 `section.heading` 正常渲染，不丢失。
3. **URL/粘贴文章**：行为与现状一致（单节、`heading: null`，不受影响）。
4. **目录侧栏**：仍基于 `section.heading` 全量建树，不受正文渲染影响。
5. **层级**：EPUB 节标题按正文自然 h1/h2/h3 显示（章标题变大，属已接受 D3）。
6. **无硬编码颜色**：本次纯逻辑改动，不新增颜色。
7. **最小回归样本清单**：至少覆盖——
   - 含 TOC 的 EPUB（验证每节标题只出现一次、层级为自然 h1/h2/h3）；
   - 一个 Markdown 书籍 + 一个 HTML 书籍（验证 `section.heading` 仍渲染、不丢失）；
   - 一个 URL/粘贴文章（验证行为不变）；
   - 一个「有正文父节(B1)且正文首行不带标题」的 EPUB（显式观察并接受「该节无标题」的已声明场景）。

## 五、风险与回滚

- **历史缺失 `format` 的 EPUB（已知不回填、非回归）**：回读经 `mapReadingRow` 归一为 `'paste'`（`headingsInBody = false`），不触发去重；修复仅对 `format` 已持久化为 `'epub'` 的文档生效。
- **编辑破坏不变式**：本方案依赖「EPUB body 含标题」不变式；正文策展/编辑若手动剥离 body 首行标题而保留 `heading` 字段，阅读区将因 `format === 'epub'` 跳过 `heading` 且 body 无标题而丢失该节标题。属已声明的已知边界，非本次缺陷。
- **回滚**：纯前端改动，回退 `ReaderPage.jsx` / `SectionFlow.jsx` 两处即可，无数据/迁移副作用。
