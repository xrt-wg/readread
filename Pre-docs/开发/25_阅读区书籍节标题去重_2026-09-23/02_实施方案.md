# 阅读区书籍节标题去重 — 实施方案

> 日期：2026-09-23
> 前置：[01_讨论和决策记录](01_讨论和决策记录.md)

## 一、目标

1. EPUB 书籍在阅读区不再重复显示节标题：`format === 'epub'` 时跳过内联 `section.heading`，直接渲染完整 body（标题已在正文里）；
2. 其它格式（markdown/html/url/paste）维持现状，渲染 `section.heading` + body，节标题不丢失；
3. 接受 EPUB 节标题改用正文自然 h1/h2/h3 层级（D3）。

**性质：纯前端渲染层改动，无数据库迁移，已导入书籍立即生效。**

> **范围边界**：本次仅改阅读区（ReaderPage + SectionFlow）；后台只读预览 `SectionPreview`（推荐审核/正文策展）及编辑态不纳入本次范围，后台预览对 EPUB 的节标题重复属既有行为、另立需求。

## 二、模型说明

无新表、无新字段。核心是一个文档级布尔 flag：

```
headingsInBody = article.format === 'epub'
```

- `article.format` 为 Document 自带字段（[document.js](../../../src/types/document.js) `DocumentFormat`），来源格式由导入链路确定，可靠。
- `format === 'epub'` ⇔ 每节 `body.markdown` 自带节标题（EPUB 提取器保留整段 HTML→markdown），故跳过 `section.heading`；其它格式提取时已把标题剥到 `section.heading`，须继续渲染。
- 判别是文档级的（每篇一次），非逐节判断、无文本匹配（D1）。

## 三、分层实施

改动两处：[ReaderPage.jsx](../../../src/components/ReaderPage.jsx) 派生并下传 flag；[SectionFlow.jsx](../../../src/components/SectionFlow.jsx) 门控内联标题。

### 3.1 ReaderPage 派生 flag 并下传

[ReaderPage.jsx](../../../src/components/ReaderPage.jsx) 在 `isBook` 附近（约 L87）新增派生值：

```js
// 正文自带节标题的格式（仅 EPUB 提取器保留整段 markdown 含标题行）→ 渲染层跳过内联 section.heading
const headingsInBody = article.format === 'epub'
```

随后在 `<SectionFlow ... />`（约 L904）下传：

```jsx
<SectionFlow
  key={paginated ? currentSection?.id : 'flow'}
  sections={flowSections}
  headingsInBody={headingsInBody}
  sectionScoped={sectionScoped}
  ...
/>
```

### 3.2 SectionFlow 门控内联标题

[SectionFlow.jsx](../../../src/components/SectionFlow.jsx) 组件签名（L223）新增 `headingsInBody` prop，并把 L234 的内联标题渲染改为受该 flag 门控：

```jsx
export default function SectionFlow({ sections, headingsInBody = false, sectionScoped, ... }) {
  ...
  {!headingsInBody && section.heading && (
    <HeadingTag className={headingClassForDepth(section.depth)}>{section.heading}</HeadingTag>
  )}
  ...
}
```

- 默认值 `false` 保证任何未下传该 prop 的既有调用点行为不变（安全兜底）。
- `body.markdown` / `body.text` 渲染路径不变；EPUB 的 `# 标题` 由 ReactMarkdown 自然渲染为 `article-h1`。

## 五、验收标准

1. **EPUB 书籍**：阅读区每节只出现一次标题（正文首行的 `# 标题`），不再有 `section.heading` 重复。
2. **Markdown/HTML 文件（含被标为书籍者）**：节标题仍由 `section.heading` 正常渲染，不丢失。
3. **URL/粘贴文章**：行为与现状一致（单节、`heading: null`，不受影响）。
4. **目录侧栏**：仍基于 `section.heading` 全量建树，不受正文渲染影响。
5. **层级**：EPUB 节标题按正文自然 h1/h2/h3 显示（章标题变大，属已接受 D3）。
6. **无硬编码颜色**：本次纯逻辑改动，不新增颜色。
7. **最小回归样本清单**：至少覆盖——
   - 含 TOC 的 EPUB（验证每节标题只出现一次、层级为自然 h1/h2/h3）；
   - 一个 Markdown 书籍 + 一个 HTML 书籍（验证 `section.heading` 仍渲染、不丢失）；
   - 一个 URL/粘贴文章（验证行为不变）；
   - 一个「有正文父节(B1)且正文首行不带标题」的 EPUB（显式观察并接受「该节无标题」的已声明场景）。

## 六、风险与回滚

- **历史缺失 `format` 的 EPUB（已知不回填、非回归）**：回读经 `mapReadingRow` 归一为 `'paste'`（`headingsInBody = false`），不触发去重；修复仅对 `format` 已持久化为 `'epub'` 的文档生效，历史缺失 format 的 EPUB 不回填、不修复。
- **父正文节无标题**：EPUB 有正文的父节若 body 首行不带标题，则该节无标题显示；属 EPUB 数据形态，可接受（与 Markdown/HTML 同理）。
- **编辑破坏不变式**：正文策展/编辑若手动剥离 body 首行标题而保留 `heading` 字段，阅读区将因 `format === 'epub'` 跳过 `heading` 且 body 无标题而丢失该节标题；策展编辑剥离标题行时须同步维护「EPUB body 含标题」不变式。
- **回滚**：纯前端改动，回退 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx) / [SectionFlow.jsx](../../../src/components/SectionFlow.jsx) 两处即可，无数据/迁移副作用。
