# 阅读区书籍节标题去重 — 讨论和决策记录

> 日期：2026-09-23
> 关联：[02_实施方案](02_实施方案.md)

## 一、背景与需求

阅读区书籍「按节分页」（24）落地后，每节独立成一页，节标题重复的问题变得显眼：一页顶部先出现一个标题，紧接着正文首行又是同一个标题。

根因不在渲染逻辑「多画」了一个标题，而是**数据里标题存了两份**，渲染层各画一遍：

1. EPUB 导入链 [parse-epub.cjs](../../../netlify/functions/parse-epub.cjs) 里，`flattenTocTree` 从目录树把节名写入 `section.heading`（如「第一章」）；随后填充正文时 `es.body.markdown = epubSection.toMarkdown()`，把该片段**整段 HTML 转成的 markdown 原样塞进 body**——里面本就带着开头那个 `<h1>第一章</h1>` → `# 第一章`，没有剥掉。
2. [SectionFlow.jsx](../../../src/components/SectionFlow.jsx#L234-L246) 渲染时，先画 `section.heading`（按 `depth` 成 h2/h3/h4），再把 `body.markdown` 交给 ReactMarkdown，后者把正文里的 `# 第一章` 又画成一个 `article-h1`。两者都显示 → 标题重叠。

而 Markdown / HTML 文件导入时，提取器（[markdownExtractor.js](../../../src/services/extractors/markdownExtractor.js)、[htmlExtractor.js](../../../src/services/extractors/htmlExtractor.js)）在切分时就**把标题剥到了 `section.heading`、body 不含标题行**，所以只有 EPUB 受影响。

> 说明：这不是「按节分页」改动引入的回归，是 EPUB 导入数据一直如此；分页后每节独立成页，重复才显眼。

## 二、现状调查结论

| 导入格式 | `body.markdown` 是否含节标题 | 节标题还存在哪里 |
|---|---|---|
| EPUB | ✅ 含 `# 标题`（[parse-epub.cjs](../../../netlify/functions/parse-epub.cjs#L98-L103) 未剥） | `section.heading`（来自 TOC） |
| Markdown 文件 | ⚠️ 节标题(h2-h4)已剥、`#`(h1)未剥 | 只有 `section.heading` |
| HTML 文件 | ⚠️ 节标题(h2-h4)已剥、`<h1>`作文档 title | 只有 `section.heading` |
| URL / 粘贴 | 单节、`heading: null` | 文档级 title |

> 注：「已剥」严格指 **h2-h4 节标题**；正文中残留的 `#`（Markdown）/ `<h1>`（HTML）仍会渲染为 `article-h1`，但因 `section.heading` 仅由 h2-h4 切分，不会产生重复，不影响本方案正确性。

关键结论：

1. 「节标题是否融合在正文里」由 **`format`**（epub / markdown / html / url / paste）决定，与 `kind`（文章/书籍）无必然绑定——`kind` 是用户可改的分类，Markdown/HTML 文件也能被标为「书籍」。
2. 因此「按类型渲染」的判别键必须是 `format === 'epub'`，而不是 `kind === 'book'`。若按 `kind` 走「书籍只渲染 body」，Markdown/HTML 书籍的节标题（只存在 `section.heading` 里）会整个消失。
3. EPUB 正文里的 `#` 会被渲染成 `article-h1`（1.75em），层级（1.4/1.15/1.0）改由 EPUB 自身 HTML 的 h1/h2/h3 决定——这是「自然渲染」的固有结果，与「书籍隐藏书名」的设计一致（书籍无可见 h1 文档标题，节标题用 h1 不冲突）。

## 三、决策记录

### D1 判别键 → `format === 'epub'`（而非 `kind === 'book'`）

- 备选：按 `kind === 'book'` 渲染；按「body 首行是否含标题」逐节判断；源头归一化（改 `parse-epub.cjs` 剥标题）。
- **决策：按 `format === 'epub'` 区分。** 理由：① `format` 才真正决定「标题是否融合在正文里」；② 文档级常量、每篇只判一次，无逐节判断、无文本匹配；③ 源头归一化会破坏「书籍节标题与正文融合」的自然性，且只能影响新导入、已导入书籍仍重复。
- **代价（已接受）**：Markdown/HTML 被标为「书籍」时仍渲染 `section.heading`（因其 body 不含标题），与其「标题分离」的数据形态一致，不丢标题。

### D2 EPUB 渲染 → 只渲染 body，跳过 `section.heading`

- **决策：`format === 'epub'` 时，SectionFlow 不再额外渲染 `section.heading`，直接渲染完整 body（标题已在正文里）；其它格式维持现状（渲染 `section.heading` + body）。**
- 理由：保留「书籍节标题与正文融合」的自然性，正文里已含标题，无需再加。

### D3 层级变化 → 接受自然 h1

- **决策：接受 EPUB 节标题由「`depth` 映射的 h2/h3/h4」改为「正文自然的 h1/h2/h3」。** 章标题从 `article-h2`（1.4em）变为 `article-h1`（1.75em），层级随原书 HTML 走。
- 理由：与「书籍隐藏书名」设计自洽——文章把 h1 留给可见文档标题、节标题从 h2 起；书籍无可见 h1 文档标题，节标题用 h1 不冲突，且更贴合原书自然层级。

### D4 实现性质 → 纯前端渲染层

- **决策：改动集中在 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx)（派生并下传 flag）+ [SectionFlow.jsx](../../../src/components/SectionFlow.jsx)（门控内联标题）。** 不动数据、无迁移，已导入书籍立即生效。

## 四、最终方案要点

| 维度 | 决策 |
|---|---|
| 判别键 | `article.format === 'epub'`（D1） |
| EPUB 渲染 | 跳过 `section.heading`，只渲染 body（D2） |
| 其它格式渲染 | 维持 `section.heading` + body（D2） |
| 层级 | EPUB 节标题改用正文自然 h1/h2/h3（D3） |
| 迁移 | 无（纯前端渲染层）（D4） |

> **范围边界**：本次仅改阅读区（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx) + [SectionFlow.jsx](../../../src/components/SectionFlow.jsx)）。后台只读预览 `SectionPreview`（[SectionContentEditor.jsx](../../../src/components/SectionContentEditor.jsx#L114-L134)，用于推荐审核/正文策展 [RecommendationModerationPanel.jsx](../../../src/components/RecommendationModerationPanel.jsx#L381)）与编辑态不纳入本次范围——后台预览对 EPUB 同样存在节标题重复，属既有行为，另立需求再处理。

## 五、风险与注意点

1. **历史缺失 `format` 的 EPUB（已知不回填、非回归）**：数据库回读经 `mapReadingRow` 把缺失的 `format` 归一为 `'paste'`（[readings.js](../../../src/services/readings.js#L58)），故 `headingsInBody = false`、不会去重。修复仅对 `format` 已持久化为 `'epub'` 的文档生效，历史缺失 format 的 EPUB 不回填、不修复，属已知不回填、非回归。
2. **容器节 / 父正文节**：EPUB 纯容器节（无正文）本就不进正文页（24 方案 A2），跳过 `section.heading` 对它们无影响；有正文的父节（B1）若正文首行不带标题，则该节无标题——属 EPUB 数据自身形态，与 Markdown/HTML 同理，可接受。
3. **颜色/阴影规范**：本次为纯逻辑改动，不新增颜色；若后续调整标题样式，须走 `var(--*)`（CLAUDE.md 颜色规范）。
4. **编辑破坏不变式**：本方案依赖「EPUB body 含标题」不变式。正文策展/编辑若手动剥离 body 首行标题而保留 `heading` 字段，阅读区将因 `format === 'epub'` 跳过 `heading`、body 又无标题而丢失该节标题；策展编辑剥离标题行时须同步维护该不变式。
