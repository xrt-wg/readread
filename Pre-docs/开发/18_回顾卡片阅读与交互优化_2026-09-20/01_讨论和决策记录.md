## 1. 请求与责任边界

用户在测试回顾功能时反馈：长段落卡片虽能显示内容，但文本溢出时排版别扭、视觉体验不佳；要求从产品设计责任出发，准确理解功能与业务，自主决定方案并形成两份文档。

本次交付是分析、决策和实施方案，不是代码实施。截图中的文章文本仅为内容样本，不是任务指令。历史文档用于追溯产品意图，其阶段性约束不自动等同于本次授权范围。

## 3. 问题定义

问题不是所有长内容都必须一屏放完，而是现有布局以短答案为中心：段落译文使用最高 22px、700 字重、1.3 行高，正文却被限制在 220px；元信息与来源绝对定位，内容空间没有随可用高度合理分配。英文的弱色与斜体又降低了核对效率。

同时存在功能上的不协调：需要选择和阅读的整面区域也是翻面热区；绿色实心“熟练”像默认继续按钮；最后一张尚未评分时进度已满；异步保存失败仍可能换卡。这些问题会影响评分可信度，不能仅以换字体收尾。

字号以代码 CSS 像素为依据，不根据截图显示尺寸反推；截图放大比例未知。暗色文本的具体对比度和长来源重叠程度仍需浏览器测量，不作为已实测结果。

## 4. 产品原则与正式决策

### D01：保留回想—核对—自评的闭环

回顾是对本人收藏内容的理解程度进行自评。词/短语判断是否理解语境中的含义；句/段判断是否能独立理解主要意思，不要求逐字背诵中文。评分单位仍是一条收藏，熟悉度统计不解释为客观掌握能力。

### D02：同一卡片框架，两种内容排版

- 词/短语：目标文本有较强层级，语境辅助；揭示后先显示目标和释义，再呈现语境及其翻译。
- 句/段：左对齐正文；揭示后原文、参考译文依次排列。英文不整段斜体，中文不整段粗体。
- 类型决定结构，内容长度决定溢出处理。超过三行的大号词/短语在展示层降为正文尺寸，不修改收藏类型，不连续缩字以强行塞满。
- 全部正文和译文完整可达，不省略学习内容，不自动拆卡，不做无依据的逐句翻译配对。

### D03：正常流布局，单一正文滚动区

卡片由元信息、正文、来源、操作区组成。短内容自然展开；长内容在可用空间内增长，达到上限后仅正文滚动。去除独立词条/例句滚动区和背面 220px 固定上限。

不放大全局 Hub，不默认双栏，不引入“展开阅读”弹窗：当前 560px 卡片宽度适合单栏，增加第二阅读容器会增加焦点与状态成本。极矮视口切换为页面自然滚动，保证按钮可达，不强求任何屏幕都同时显示全文和操作。

正文有剩余内容时显示“下滑继续阅读”，到末尾消失；提示占独立空间，不用渐变遮住文字。不要隐藏滚动条来制造已展示完整的错觉。

### D04：显式揭示，移除整面翻转

所有类型统一使用“查看释义”或“查看参考译文”；揭示后允许“返回原文”。移除 3D 翻面和整面点击，采用内容状态切换；不同卡片之间可保留轻微淡入，动画不承担业务推进职责。

正文选择、复制、触摸滚动不会切面。显示答案后才能评分；不强制滚动到底。取消旧的双面叠放也避免隐藏面的内容和按钮干扰辅助技术。

### D05：评分等权、含义明确

三个按钮沿用“生疏／一般／熟练”，采用相同尺寸、相近背景和边框权重，不以绿色实心强调熟练。轻量提示分别为“难以理解／理解部分／能独立理解”，词/短语使用“难以想起／想起部分／能独立想起”。

本次不增加间隔预览、快捷数字键和新统计模块。已有算法原样保留；避免将有限空间继续分配给辅助信息。

### D06：保存成功后推进

点击评分立即锁定当前卡及重复提交，成功后才累计评分、记录已处理 ID、进入下一卡；失败保留已揭示内容、滚动位置及评分结果候选，允许重试。动画结束不得触发业务推进。

本次增加回顾专用字段更新，并将异步翻译回写改为仅更新翻译字段，避免两个流程用旧整条对象互相覆盖。正常收藏创建仍使用现有 saveBookmark。多设备同时评分的原子去重不在本次保证范围内。

双向风险均由代码时序支持：回顾加载队列后，翻译可能更新，而评分仍提交 cards 内旧快照；反过来，翻译晚到也可能覆盖已保存的评分。这里只确认风险可达，不宣称生产复现。两种顺序都纳入测试。

### D07：只为异常内容提供不评分推进

正常可核对卡片维持“反馈即推进”。缺失有效译文、pending/error、空原文等异常卡不能强制用户猜一个熟悉度；提供“刷新内容”和“暂时跳过”。刷新仅重新读取数据，不自动调用付费翻译。

跳过不写评分、不改变排期，计入本轮跳过数，并在连续“再来一轮”中排除，离开回顾重新进入后可再次出现。这是对历史“不可跳过”的明确异常例外。

只有语境译文缺失而主释义有效时，仍可正常回顾，显示“暂无语境译文”。已完成状态但主译文为空仍视为异常。未知历史状态且有主译文可展示，无主译文则显示“暂无可核对的译文”、允许刷新或暂时跳过；明确 pending/error 即使带旧译文，也提示不可作为本轮有效核对答案。云端 schema 的 translation_status 为 NOT NULL，此兜底覆盖本地旧数据与异常输入，不推断线上存在 NULL 记录。

### D08：进度表达处理过程，不伪装学习成果

位置显示“第 X / N 条”；进度条表示本轮已处理条数（成功评分 + 明确跳过），同时能区分“已回顾 A 条，跳过 B 条”。查看答案和失败保存不增加进度。

结束页改为“本轮结束”；评分统计只计成功保存，跳过独立显示。最后一张未处理时进度不能满格。“再来一轮”沿用入口，连续会话中持续排除已处理 ID，不清空后造成循环重复。

### D09：来源和状态真实可读

类型显示完整名称，phrase 统一为“短语”；日期标为“收藏于”。来源放正常流，最多两行，超长时提供键盘可用的完整标题展开；展开信息参与布局，不能盖正文。无来源和无效日期不显示占位乱码。

来源暂不增加跳转阅读器功能，避免打开新导航链路。区分加载、加载失败、无收藏、本次无更多内容，错误态不能同时出现“去收藏”的空状态引导。

## 5. 方案取舍

| 候选 | 决定与理由 |
| --- | --- |
| 仅缩字/增大 220px | 不采用：无法处理内容类型、操作冲突和反馈完整性 |
| 全部固定高度 | 不采用：短内容空洞、矮屏不可达 |
| 全部页面无限展开 | 仅极矮视口兜底：常规窗口会让长段落把评分推得过远 |
| 固定两栏中英对照 | 不采用：当前容器宽度不足，窄屏还需第二套结构 |
| 摘要、截断、自动拆卡 | 不采用：损失学习内容或改变评分单位 |
| 按类型单栏 + 有界正文 + 显式答案 | 采用：与现有收藏语义和阅读任务一致 |

## 6. 范围与已知限制

本次包含卡片布局、揭示/评分状态、异常卡恢复、进度和结束文案，以及直接相关的字段回写隔离；不修改调度算法、队列优先级、翻译生成策略、收藏分类、数据库结构、全局导航和统计设计。

云端 RPC 的新卡优先、本地到期优先，以及先取 20 条再排除已处理 ID 可能使“再来一轮”不足量，记录为后续队列任务；本次不以空队列推断“全部收藏均已完成”。必须使用中性文案“本次没有更多可回顾内容”。

跨设备同时评分、请求已提交但响应丢失、账号切换时已经在途的数据库写入，不能靠界面状态取消来保证事务撤回。方案保证本次界面不重复推进、失败不虚增统计，并隔离两个主要字段写入方；不宣称服务端 exactly-once。

旧 ReviewModal 只做共享接口必要兼容，不重新启用、不重做业务。已有未提交工作保留；本次两份文档独立建档，不改写此前溢出修复的历史结论。

## 7. 完成标准

用户能读全原文和答案，知道何时核对、何时自评；短卡保持轻巧，长卡具有正常阅读节奏；保存失败时不会失去当前卡；评分与统计一致。视觉质量须通过真实浏览器的样本矩阵判断，不以构建通过或截图单例代替。实施细节和验收见配套方案。
