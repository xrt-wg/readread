## 二、核心改动

### 2.1 位置去重判定 helper（`ReaderPage.jsx` 模块级）

新增模块级 helper，与 `buildLayers` 的定位模型（`charOffset + text`）一致：

```js
/**
 * 判断两个收藏是否指向「同一位置同一词语」。
 * 位置 = paragraphIndex + sectionId + charOffset，词语 = text。
 * 同一词形在不同位置（不同语境）是不同学习对象，不去重；
 * 同一词形在同一位置才是同一处，不重复收藏。
 */
function isSameBookmarkLocation(a, b) {
  return a.text === b.text
    && a.paragraphIndex === b.paragraphIndex
    && (a.sectionId ?? null) === (b.sectionId ?? null)
    && (a.charOffset ?? null) === (b.charOffset ?? null)
}
```

`charOffset ?? null` 用于兼容极少数历史书签可能缺失 `charOffset` 的情况（与 `sectionId` 的 `?? null` 归一化一致）；新收藏的 `charOffset` 恒为数字，不会被误判。

### 2.2 预读分支：保存前位置去重（`ReaderPage.jsx` `handleMouseUp`）

**现状**（第 236–259 行）：预读分支 `removeAllRanges()` 后直接 `createBookmark` + `saveBookmark`，无去重。

**改动**：`removeAllRanges()` 后、`createBookmark` 前，先按位置四元组判断是否已收藏，已收藏则直接 `return`（不重复保存）：

```js
if (preReadMode) {
  window.getSelection()?.removeAllRanges()
  // 位置去重：同一位置同一词语已收藏则跳过（不重复保存）
  const alreadyBookmarked = bookmarks.some((b) =>
    isSameBookmarkLocation(b, { text: selected, paragraphIndex: paraIndex, sectionId, charOffset }))
  if (alreadyBookmarked) return
  try {
    const bm = createBookmark({ /* 原参数不变 */ })
    const savedBookmark = await saveBookmark(bm, { canUseCloudLibrary, userId })
    await loadReaderState()
    translateBookmark(savedBookmark, async () => { await loadReaderState() })
  } catch (e) {
    if (isLibraryAccessError(e)) refreshAuthState()
    setLibraryError(resolveLibraryErrorMessage(e, '收藏失败'))
  }
  return
}
```

**依赖更新**：`handleMouseUp` 的 `useCallback` 依赖数组新增 `bookmarks`（判定需读取最新收藏状态）。

### 2.3 非预读 `handleBookmark`：位置去重 + 同步关闭弹窗

**现状**（第 283–315 行）：无去重、不关弹窗；保存期间弹窗仍在，可连点制造重复。

**改动**：先按位置判定，再**同步关闭弹窗**，已收藏则返回，否则异步保存：

```js
const handleBookmark = useCallback(async () => {
  if (!popup) return
  const { text, selectionType, contextSentence, paragraphIndex, charOffset, sectionId } = popup

  // 位置去重：同一位置同一词语已收藏则不再保存
  const alreadyBookmarked = bookmarks.some((b) =>
    isSameBookmarkLocation(b, { text, paragraphIndex, sectionId, charOffset }))

  // 收藏后同步关闭弹窗，避免连点（按钮随弹窗一并移除）
  closePopup()

  if (alreadyBookmarked) return

  try {
    setLibraryError('')
    const bm = createBookmark({
      type: selectionType,
      text,
      contextSentence: contextSentence ?? null,
      articleId,
      paragraphIndex,
      charOffset,
      sectionId: sectionId ?? null,
      sectionHeading: (sectionId ? effectiveSections.find((s) => s.id === sectionId)?.heading : null) ?? null,
    })
    const options = { canUseCloudLibrary, userId }
    const savedBookmark = await saveBookmark(bm, options)
    await loadReaderState()
    translateBookmark(savedBookmark, async () => { await loadReaderState() })
  } catch (bookmarkError) {
    if (isLibraryAccessError(bookmarkError)) refreshAuthState()
    setLibraryError(resolveLibraryErrorMessage(bookmarkError, '保存收藏失败，请稍后重试'))
  }
}, [popup, bookmarks, closePopup, articleId, canUseCloudLibrary, loadReaderState, refreshAuthState, translateBookmark, userId, effectiveSections])
```

**说明**：

- 先解构 `popup` 再 `closePopup`：`closePopup` 的 `setPopup(null)` 是异步状态更新，当前闭包里的 `popup`/解构值在保存时仍有效；同步读取避免顺序歧义。
- `closePopup`（第 516–520 行）内部 `clear()` + `removeAllRanges()` 的语义保留不变，正好完成「关弹窗 + 清选区 + 清直译」。
- 依赖数组新增 `bookmarks`、`closePopup`。

## 三、数据流示意

```
非预读：划选 → 弹窗「收藏」→ 点按
  → 位置四元组判定
      ├─ 已存在 → closePopup（不保存）
      └─ 不存在 → closePopup + createBookmark + saveBookmark + loadReaderState

预读：划选
  → removeAllRanges → 位置四元组判定
      ├─ 已存在 → return（不保存）
      └─ 不存在 → createBookmark + saveBookmark + loadReaderState
```

两路径共用 `isSameBookmarkLocation`，行为一致：**同一处不重复，不同处自由收藏**。

## 四、预期效果

| 场景 | 之前 | 之后 |
|------|------|------|
| 非预读：同一词同一位置划选两次 | 第二次显示「已收藏」禁用 | 第二次点「收藏」→ 弹窗关闭，不新增重复 |
| 非预读：同一词不同位置各收藏 | 被文本去重误拦截 | 各自独立收藏 |
| 非预读：点「收藏」 | 弹窗停留，可连点重复 | 弹窗立即关闭，无连点重复 |
| 预读：同一词同一位置划选两次 | 新增重复收藏 | 不重复 |
| 预读：同一词不同位置各收藏 | 各自收藏 | 各自收藏（不变） |
| 弹窗按钮文案 | 「收藏」/「已收藏」切换 | 恒为「收藏」 |

**UX 取舍（D3/D4 推论）**：同一位置同一词形重复收藏时，流程为「判定已存在 → 关闭弹窗 → 不保存」，**静默关闭、无 toast/文案提示**；已收藏状态由正文高亮 + 收藏列表承载。极端边界（`paragraphIndex === -1` 的标题/表格单元格选区不渲染高亮）下点「收藏」既无高亮又无提示，观感似「点了没反应」——此为已知取舍，若后续需要轻提示再作独立迭代。

## 七、边界与已知限制

- **历史书签 `charOffset` 缺失**：判定用 `charOffset ?? null` 归一化，不误伤；个别旧书签若 `charOffset` 为空且与新选区同位置，仍可能产生一条重复（罕见、非破坏性，可手动删除）。
- **历史书签 `paragraphIndex` 缺失**：`paragraphIndex` 用严格相等、未归一化；历史云端书签若 `paragraph_index` 为 null，与任意新选区数值恒不等 → 仅可能漏判一条重复（不误伤），与 `charOffset` 缺失同属非破坏性边缘。
- **预读高频划选**：去重依赖 `bookmarks` 状态，`loadReaderState()` 在每次保存后刷新；若在刷新完成前以极高频率连划同一处，存在极小概率重复（离散 mouseup 事件下可忽略）。
- **跨设备/多端**：判定在本地 UI 态完成，与云端 schema 无关；两设备分别首次收藏同一处时仍可能各存一条（现状即如此，本次不改云端约束）。
