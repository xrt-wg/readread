# 收藏去重按位置 — 讨论和决策记录

> 日期：2026-09-14
> 参与者：Kaven, Claude
> 状态：已确认
> 关联：无（针对「重复收藏去重不一致」首次立项）

---

## 背景

验证测试中报告了一个去重不一致问题：

- **非预读模式**：再次划选同一个词，弹窗显示「已收藏」并禁用收藏按钮（被拦截）。
- **预读模式**：再次划选同一个词，能正常划选收藏（直接新建一条重复收藏）。

两个模式对「重复收藏」的处理**不一致**，且两条路径各自的语义都有问题。

---

## 根因分析

问题分两层：

1. **去重只存在于 UI 层，且只覆盖一条路径。** `ReaderPage.jsx` 的 `isPopupBookmarked`（第 508–514 行）按 `text + paragraphIndex + sectionId` 判断「已收藏」，仅用于非预读弹窗按钮的禁用态。预读分支（`handleMouseUp` 第 236–259 行）直接 `createBookmark` + `saveBookmark`，数据层（`bookmarkStore.save` / `saveBookmark`）也均无去重。→ 于是「非预读拦截、预读放行」的不一致。

2. **去重谓词漏了 `charOffset`，是「按文本去重」。** `isPopupBookmarked` 只比较 `text + paragraphIndex + sectionId`，不含 `charOffset`。同一个词形在同一段落的不同位置（不同语境），`text/paragraphIndex/sectionId` 完全相同，会被误判为「同一处」而拦截。

第 2 点是业务认知错误的核心：**同一个词形在不同语句里有不同用法/语义，是两个独立的学习对象**，不应用文本相同去强行合并。

---

## 业务认知对齐（Kaven 明确）

> 「不应该按文本去重，因为很多场景下，同一个词可能在不同的语句中有不同的使用方法，应该把这个自由交给用户，而不是强制引入去重机制。」

对齐后的模型：

1. **去重按「位置」，不按「文本」。** 判定「是否同一处」的键是四元组 `(text, paragraphIndex, sectionId, charOffset)`，四者全等才算同一处：
   - 同一词形、**不同位置**（不同句子/语境）→ 各自独立收藏，**不拦截** ← 交给用户的自由。
   - 同一词形、**同一位置** → 就是同一处，**不重复收藏** ← 「同一个位置的同一个词语，不能重复收藏」。
2. **去掉弹窗「已收藏」提示**：是否已收藏靠正文高亮 + 收藏列表判断，不在弹窗里做禁用/提示。
3. **收藏成功后弹窗自动关闭**，避免连点产生重复。
4. **两条路径对齐为同一行为**：预读与非预读共用同一位置判定。

---

## 方案演进

### 起点：给 `isPopupBookmarked` 补 `charOffset`

最初考虑把 `charOffset` 加进现有 `isPopupBookmarked`，让非预读的「已收藏」判定更精确。

### 分析：真正的问题是「按文本去重」本身错了

补 `charOffset` 只能让「已收藏」少误伤，但「按文本拦截同一词」的语义仍错——同一词形在不同位置本就该自由收藏。且该去重只覆盖非预读，预读仍会重复。

### 最终决策：去重统一改为「按位置」，并收敛两条路径

把去重从「弹窗禁用态」移到「保存前的判定」，用位置四元组统一预读与非预读两条路径；同时去掉「已收藏」提示、收藏后自动关弹窗。

## 决策记录

### D1：去重键由「文本」改为「位置」

**决策：是。** 判定「同一处」的键为四元组 `(text, paragraphIndex, sectionId, charOffset)`，四者全等才算重复。

**理由：**
- 同一词形在不同位置是不同学习对象，按文本去重会误伤用户的自由收藏。
- `paragraphIndex + sectionId + charOffset` 唯一确定「位置」，`text` 唯一确定「词形与选区长度」（区分同起点不同长度的选区，如 `apple` vs `apple pie`），二者合起来精确刻画「同一个位置的同一个词语」。

### D2：去重统一落到「保存前」判定，预读与非预读共用

**决策：是。** 在 `ReaderPage` 的保存入口处（预读分支 + `handleBookmark`）统一做位置去重：同一处已存在则跳过保存，不同处则新建。两条路径共用同一 `isSameBookmarkLocation` 判定。

**理由：**
- 新建收藏的入口仅 `ReaderPage` 两处（预读分支 + `handleBookmark`）；`saveBookmark` 另有 `ReviewPanel`（复习回写）、`useBookmarkAI`（翻译回写）、`readings.js`（导入迁移）三处更新/回写型调用，均携带已有 `id` 经 `onConflict:'id'` upsert、不产生新 `id`。故去重只需落在 `ReaderPage` 的保存入口即可覆盖全部新建路径，无需改数据层、无迁移风险。
- 消除「非预读拦截、预读放行」的不一致：两模式从此行为一致。

### D3：去掉弹窗「已收藏」提示

**决策：是。** 移除 `TranslationPopup` 的 `isBookmarked` prop 与「已收藏」禁用态，收藏按钮恒为「收藏」、恒可点。

**理由：** 是否已收藏由正文高亮 + 收藏列表呈现，弹窗内再做禁用提示是与「按文本去重」绑定的旧 UI，语义已失效；去掉后配合 D4 的自动关闭，连点问题由位置去重兜底。

### D4：收藏成功后自动关闭弹窗

**决策：是。** `handleBookmark` 在点按「收藏」时**同步先关闭弹窗**（`closePopup`），再异步保存。

**理由：** 关闭弹窗移除按钮，从源头杜绝「连点」在异步保存完成前再次触发（旧实现中保存期间弹窗仍在，可连点制造重复）。同步关闭、异步保存，两者解耦。

## 放弃的方案

| 方案 | 放弃原因 |
|------|---------|
| 完全不去重 | 同一位置的同一词语不能重复收藏（Kaven 明确），会污染收藏列表与复习队列 |
| 仅给 `isPopupBookmarked` 补 `charOffset` | 治标不治本：仍按文本拦截不同位置的同一词，且只覆盖非预读，不一致仍在 |
| 在数据层/云端加唯一约束（如 `(reading_id, paragraph_index, char_offset)` 唯一索引） | 需数据迁移 + 云端 schema 变更，且对历史重复数据无妥善收敛方案，成本高、收益低 |

## 与既有设计的关系

- **收藏重叠高亮渲染**（[10_收藏重叠高亮渲染](../10_收藏重叠高亮渲染/01_讨论和决策记录.md)）：本次改动与 `buildLayers` 的 `charOffset + text` 定位模型一致——`charOffset` 已是书签的位置身份，本次只是把这一身份补进「去重」判定。
- **预读模式**（[08_预读模式](../08_预读模式/实施方案.md)、[09_预读模式禁用收藏悬浮卡](../09_预读模式禁用收藏悬浮卡/02_实施方案.md)）：预读「划词即收藏」从「无去重」变为「按位置去重」，与「零打扰但标注完整」的定位自洽；不改变预读禁用悬浮卡的行为。
- **复习系统**：词/句各自独立复习，位置去重保证「同一处不重复进入复习队列」，正是复习语义所需；不同位置的同一词仍各自成复习项，符合「不同用法独立学习」。
- **颜色规范**：本次仅移除一处按 `isBookmarked` 切换的按钮样式，不新增任何颜色；保留的收藏按钮继续沿用现有 `--popup-*` 变量与金色 accent。
