## 1. 目标与范围

### 1.1 目标

在「尽快跑通产品」前提下，落地两身份（Free/Pro）与两个额度杠杆（导入终身、收藏每周）的服务端强制 + 前端呈现，**不接入任何支付**（验证期新增一条「扫码支付 + 人工确认」的临时发放路径，见 [12_付费发放_验证期闭环](12_付费发放_验证期闭环.md)）。

### 1.2 范围

**In scope**
- 数据模型：`subscriptions` / `pro_grants` / `user_quotas` / `subscription_config` 四张新表；`readings` 与 `bookmarks` 各加一个 `quota_consumed` 判别列。
- 服务端强制：导入额度、收藏额度在 `guard_reading_user_write` 触发器内原子扣减（复用 `lock_reading_user` advisory lock）。
- 社区激励：`admin_publish_recommendation` 首次上架时发 N 天 Pro（幂等 + 月上限 M）。
- 前端：身份/额度呈现、撞墙提示、升级占位；`isQuotaError` 错误识别。

**Out of scope（明确不做）**
- 支付渠道、Pro 价格（后置清单）。
- 同时在读可配化 / Pro「更多同时在读」（A6）。
- 未来钩子实现：PDF 导入、学习统计报告、连续打卡（仅留数据钩子，见 §3.1）。
- 生词本↔书架解耦（本次仅记录、不拆，见 §10）。
- `translate` 函数层的 JWT 鉴权（接支付前再做；本次仅加匿名 IP 限流兜底，见 §5.5）。

## 2. 核心设计原则

### 2.1 身份 = 派生值，不存枚举列

`is_pro = (subscriptions.pro_expires_at is not null and pro_expires_at > now())`。
不设 `plan` 枚举列，杜绝「plan=pro 但时间已过」的漂移。免费档 = `pro_expires_at is null` 或已过期，永久不过期。

「叠加到到期日之后」用一条列表达：
```
pro_expires_at = GREATEST(now(), coalesce(pro_expires_at, now())) + N 天
```
无需后台任务 / cron。

### 2.2 额度判别键 = `quota_consumed` 布尔列（而非 origin）

`origin` 不足以判别——「加入上架内容」与「首次阅读 offer」同为 `origin='featured'` 且 `share_source_id` 非空，但前者计（A1）、后者不计。判别必须落在「动作路径」上，用显式布尔列自文档化：

| 写入 readings 的路径 | origin | quota_consumed |
|---|---|---|
| 导入（URL/粘贴/文件/EPUB）`ImportPanel→createReading` | imported | **true** |
| 加入上架内容 `addRecommendationToBookshelf→createReading` | featured | **true** |
| 首次阅读 offer `choose_first_reading_offer` RPC | featured | false（缺省） |
| 备份恢复 `importLibraryData→saveReading` | 保留原值 | false（缺省） |

`bookmarks` 同理：新建收藏（ReaderPage 划词/预读）`quota_consumed=true`；备份恢复 `quota_consumed=false`；翻译回写/复习更新/归档恢复通过「`quota_consumed` 不 round-trip + 触发器 `not exists` 真新增判定」不重复计（见 §4.1）。

> 安全边界：该列随客户端 INSERT 写入，理论上可被技术型用户直接调 Supabase API 置 false 绕过。**接受此风险**——无支付、无财务欺诈，其危害等价于「注册新账号」；待接入支付时再把计额度路径收敛进 security definer RPC（见 §10）。

### 2.3 服务端原子强制，额度门先于 AI

- 所有额度扣减在 `guard_reading_user_write` 触发器内、`lock_reading_user` 已持有的用户级 advisory lock 保护下完成，INSERT 与计数同事务，失败即回滚。
- **收藏额度是成本闸门**：真实代码链路为「`saveBookmark`(pending) → `translateBookmark`(AI 精译 → 回写 done/error)」。额度在 INSERT 时扣减，INSERT 失败则 `translateBookmark` 不会执行 → 天然拦住 AI，不白烧钱。
- 触发器函数为 `security definer`，可读被 `revoke all` 的 `subscriptions`/`user_quotas`/`subscription_config`，客户端不可篡改。

### 2.4 时区锚定

- 收藏「每周」起点：`date_trunc('week', now() at time zone 'Asia/Shanghai') at time zone 'Asia/Shanghai'`（ISO 周一 0 点，与现有 `recommendation_submission_config` 的 `date_trunc('day', now() at time zone 'Asia/Shanghai')` 写法同源）。
- 社区月上限「本月」：`date_trunc('month', ... at time zone 'Asia/Shanghai')`。
- Pro 计时：`+ N × interval '1 day'` 滑动窗口（非自然日切分）。

### 2.5 额度错误码独立于 auth 错误

现有 `isLibraryAccessError` 匹配 401/403/42501/jwt/session/unauthorized/forbidden/permission denied/row-level security。额度错误必须**不命中**这些关键词，否则会被误判为「会话失效」触发 `refreshAuthState`。

约定：额度超限 `raise exception ... using errcode = 'Q0001'`（导入）/ `'Q0002'`（收藏），消息用中文额度文案（不含上述关键词）。前端新增 `isQuotaError` 在 `isLibraryAccessError` **之前**判断。

## 3. 数据模型变更

单条迁移 `20260923000000_subscription_mechanism.sql`（沿用 Dashboard SQL Editor 手动执行，无 CLI），分节如下。

### 3.1 新表

```sql
-- 订阅状态（权威）：身份由 pro_expires_at 派生
create table public.subscriptions (
  user_id         uuid primary key references auth.users(id) on delete cascade,
  pro_expires_at  timestamptz,
  pro_source      text,           -- 'paid' | 'contribution' | 'admin'（最近一次来源，仅展示）
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now()
);

-- 只增账本：社区贡献幂等 + 月度上限求和 + 审计（未来付费的 entitlement 来源）
create table public.pro_grants (
  id             bigint generated always as identity primary key,
  user_id        uuid not null references auth.users(id) on delete cascade,
  source         text not null check (source in ('paid','contribution','admin')),
  days           integer not null check (days > 0),
  granted_at     timestamptz not null default now(),
  submission_id  text,            -- 贡献幂等键（同一篇上架只奖一次）
  external_ref   text,            -- 支付幂等键（未来 webhook 防重放，预留）
  granted_by     uuid
);
-- 幂等：一篇 submission 至多奖励一次
create unique index uq_pro_grants_submission
  on public.pro_grants(submission_id) where submission_id is not null;

-- 额度计数器（单调）：导入终身 + 收藏每周
create table public.user_quotas (
  user_id               uuid primary key references auth.users(id) on delete cascade,
  import_lifetime_count integer not null default 0,
  bookmark_week_start   timestamptz,      -- 当前计费周起点（Asia/Shanghai 周一 0 点）
  bookmark_week_count   integer not null default 0,
  updated_at            timestamptz not null default now()
);

-- 单行配置：B 档参数后台可调（默认值见 §6）
create table public.subscription_config (
  id                            boolean primary key default true check (id),
  import_free_limit             integer not null default 30,
  bookmark_week_limit           integer not null default 30,
  contribution_days_per_publish integer not null default 30,
  contribution_monthly_cap_days integer not null default 60,
  pro_weekly_limit              integer,           -- 预留：Pro 公平使用上限，null=无限（防滥用，本次不启用）
  updated_at                    timestamptz not null default now()
);
insert into public.subscription_config(id) values (true) on conflict do nothing;
```

未来钩子（不建表，仅留位）：`readings.format` 无 CHECK 约束可容纳 `'pdf'`；学习统计纯聚合无需新 schema；连续打卡未来建 `user_streaks`。

### 3.2 加列（判别键）

```sql
alter table public.readings  add column quota_consumed boolean not null default false;
alter table public.bookmarks add column quota_consumed boolean not null default false;
```

> `quota_consumed` **仅对新增写路径有意义**（触发器只读 `new.quota_consumed`）；存量行该列为 false，其额度语义由 §3.4 回填计数承载，二者双轨、不冲突。

### 3.3 RLS 与授权

四张新表全部：
```sql
alter table public.subscriptions      enable row level security;
alter table public.pro_grants         enable row level security;
alter table public.user_quotas        enable row level security;
alter table public.subscription_config enable row level security;

revoke all on public.subscriptions      from anon, authenticated;
revoke all on public.pro_grants         from anon, authenticated;
revoke all on public.user_quotas        from anon, authenticated;
revoke all on public.subscription_config from anon, authenticated;

grant select on public.subscriptions to authenticated;
grant select on public.user_quotas   to authenticated;
-- 各自 own policy：
--   subscriptions/user_quotas：select using (user_id = auth.uid())
--   pro_grants：不开放 select（仅服务端/管理员可见），或 own select 视审计需要
--   subscription_config：不开放 select，经 admin RPC 读写
```

写路径全部 security definer：触发器（额度消耗）、`admin_publish_recommendation`（发 Pro）、未来付费 webhook（service_role）。

### 3.4 存量回填

```sql
-- 订阅：全员 Free（无到期）
insert into public.subscriptions(user_id)
select id from auth.users on conflict do nothing;

-- 导入终身计数：自导入 + 推荐加入（排除首次阅读 offer），含软删行（A2 不释放）
insert into public.user_quotas(user_id, import_lifetime_count)
select u.id, count(r.id)
from auth.users u
left join public.readings r on r.user_id = u.id
  and (
    r.origin = 'imported'
    or (r.origin in ('featured','featured_legacy') and r.share_source_id is not null
        and r.id not in (select selected_reading_id from public.user_first_reading_states
                          where selected_reading_id is not null))
  )
group by u.id
on conflict (user_id) do update set import_lifetime_count = excluded.import_lifetime_count;
```

> 首次阅读 offer 行通过 `user_first_reading_states.selected_reading_id` 识别排除；若精确排除过繁，可退化为「imported + featured 全计」，N=30 的余量足够吸收少量 offer 行。
>
> 当前仅有测试用户、无存量老用户，回溯不会造成「上线即撞墙」；未来接入真实存量用户时再评估「从 0 起算 vs 回溯」。
>
> `origin='manual'`（历史迁移残留）/`origin='shared'`（已废弃、无写路径）**不计入**导入额度；未来若新增写路径需同步更新口径。

## 4. 后端变更

### 4.1 扩展 `guard_reading_user_write` 触发器

在现有触发器内追加两段，**插入位置固定在 reading-limit（`>=5`）检查之后、`user_first_reading_states` 抑制插入之前**（`lock → 级联检查 → reading-limit → consume → 抑制插入 → return`）。

> `saveBookmark` 是 `INSERT ... ON CONFLICT (id) DO UPDATE`，翻译回写/重试即使最终落 UPDATE，也会先触发 `tg_op='INSERT'` 的 BEFORE INSERT 分支。因此不能只靠 `tg_op='INSERT'` 判「新建」，必须叠加 **`not exists` 真新增判定**，否则正常回写会静默多计。

```sql
if tg_table_name = 'readings' and tg_op = 'INSERT' and coalesce(new.quota_consumed, false)
   and not exists (select 1 from public.readings where id = new.id) then
  perform public.consume_import_quota(v_user);
end if;
if tg_table_name = 'bookmarks' and tg_op = 'INSERT' and coalesce(new.quota_consumed, false)
   and not exists (select 1 from public.bookmarks where id = new.id) then
  perform public.consume_bookmark_quota(v_user);
end if;
```

### 4.2 两个消耗辅助函数（security definer，`revoke all` 仅内部调用）

```sql
-- 导入额度（终身单调；Pro 期间不递增——见 §0 补充决策）
create function public.consume_import_quota(p_user uuid) returns void
language plpgsql security definer set search_path = public as $$
declare v_limit integer;
begin
  -- Pro 不占额度
  if exists (select 1 from public.subscriptions where user_id = p_user and pro_expires_at > now()) then return; end if;
  -- coalesce 兜底：配置行被误删时回退默认值，防额度静默失效
  select coalesce(import_free_limit, 30) into v_limit from public.subscription_config where id = true;
  insert into public.user_quotas(user_id) values (p_user) on conflict (user_id) do nothing;
  if (select import_lifetime_count from public.user_quotas where user_id = p_user) >= v_limit then
    raise exception '导入额度已用完（终身累计 % 篇），Pro 即将开放', v_limit using errcode = 'Q0001';
  end if;
  update public.user_quotas set import_lifetime_count = import_lifetime_count + 1 where user_id = p_user;
end; $$;

-- 收藏额度（每周，Asia/Shanghai 周一 0 点重置）
create function public.consume_bookmark_quota(p_user uuid) returns void
language plpgsql security definer set search_path = public as $$
declare
  v_limit integer;
  v_week  timestamptz;
  v_count integer;
begin
  -- Pro 不占额度
  if exists (select 1 from public.subscriptions where user_id = p_user and pro_expires_at > now()) then return; end if;
  -- coalesce 兜底：配置行被误删时回退默认值，防额度静默失效
  select coalesce(bookmark_week_limit, 30) into v_limit from public.subscription_config where id = true;
  v_week := date_trunc('week', now() at time zone 'Asia/Shanghai') at time zone 'Asia/Shanghai';
  insert into public.user_quotas(user_id, bookmark_week_start, bookmark_week_count)
    values (p_user, v_week, 0) on conflict (user_id) do nothing;
  -- 同周递增、跨周置 1；同步更新周起点（漏改周起点会导致后续误判「仍在旧周」）
  update public.user_quotas
     set bookmark_week_count = case when bookmark_week_start = v_week then bookmark_week_count + 1 else 1 end,
         bookmark_week_start = v_week,
         updated_at = now()
   where user_id = p_user
   returning bookmark_week_count into v_count;
  if v_count > v_limit then
    raise exception '本周收藏额度已用完（每周 % 条，北京时间周一 0 点重置），Pro 即将开放', v_limit using errcode = 'Q0002';
  end if;
end; $$;
```

### 4.3 社区贡献发 Pro（`admin_publish_recommendation` 内扩展）

> 首次上架判定：现有 RPC 的 `first_published_at = coalesce(first_published_at, now()) returning` **恒非 NULL**，同事务内无法据此区分「首次 / 重新上架」。发放前先 `SELECT first_published_at FROM recommendation_submissions WHERE id = ... FOR UPDATE` 判是否为 NULL。

仅当 `first_published_at` 此前为 NULL（首次上架）时，与上架同事务：
1. 读 `subscription_config` 取 `contribution_days_per_publish`、`contribution_monthly_cap_days`。
2. 月上限校验：`sum(days) from pro_grants where user_id=提交者 and source='contribution' and granted_at >= 北京本月 1 日`。已达 M 则**只上架、不发奖励，且作废、不顺延，记 audit_logs**（A4：撞月上限的首次上架也作废）。
3. 发放：`update subscriptions set pro_expires_at = GREATEST(now(), coalesce(pro_expires_at, now())) + N天, pro_source='contribution', updated_at=now() where user_id=提交者`；`insert pro_grants(source='contribution', days=N, submission_id=..., granted_by=...)`。
4. 幂等：`pro_grants.submission_id` 唯一索引，重上架（removed→approved→active）insert 冲突 `do nothing`。

### 4.4 新增 RPC

- `get_subscription_status()` → 返回 `{ plan: 'free'|'pro', proExpiresAt, importUsed, importLimit, bookmarkUsed, bookmarkLimit, bookmarkWeekStart }`。前端统一消费。**用 LEFT JOIN 兜底无 `subscriptions`/`user_quotas` 行的新注册用户**（plan 缺省 'free'、额度 0、limit 取配置默认值）。
- `admin_get_subscription_config()` / `admin_save_subscription_config(...)`：仿 `recommendation_submission_config` 的乐观并发 + `audit_logs` 审计（可后置到 Phase 3）。
- `admin_grant_pro(p_user_id, p_days, p_note)`：管理员人工授予 Pro 时长（`GREATEST` 累加 + `pro_source='admin'` + `updated_at=now()` + `audit_logs`）。**支付接入前的唯一 Pro 发放路径，Phase 1 必需**。

## 5. 前端变更

### 5.1 订阅状态读取

- 新增 `src/services/subscription.js`：`getSubscriptionStatus()` 调 RPC。
- 新增 `useSubscription()` hook 或并入 AuthProvider：暴露 `{ plan, proExpiresAt, importUsed, importLimit, bookmarkUsed, bookmarkLimit }` + `refresh()`。建议独立 hook 以降低 AuthProvider 中枢改动面。

### 5.2 错误识别

`src/services/errorUtils.js` 新增：
```js
export function isQuotaError(error) {
  return ['Q0001','Q0002'].includes(String(error?.code || '').toUpperCase())
}
```
所有相关 catch 链在 `isLibraryAccessError` **之前**先判 `isQuotaError`，撞墙时展示额度文案 + 升级占位，不触发 `refreshAuthState`。

**需插入 `isQuotaError` 的位置（本次穷举）**：
- `Q0001`（导入）：`ImportPanel`（URL/文件/粘贴导入）、`ImportPage`（`addRecommendationToBookshelf` 加入书架）的 catch。
- `Q0002`（收藏）：`ReaderPage` 划词收藏、预读模式收藏两处 `saveBookmark` 新建路径的 catch。
- 复习反馈（`ReviewPanel`）/归档恢复（`BookmarkManager`）的收藏写是 UPDATE、不触发扣额，**无需**插入（仍走原有 `isLibraryAccessError`）。

### 5.3 写入点标记判别键

- `createReading`（`readings.js`）：云端 INSERT 的 reading 对象加 `quota_consumed: true`（该函数仅被导入流程与推荐加入调用，二者均计额度）。
- `saveBookmark`（`readings.js`）：upsert payload 加 `quota_consumed: bookmark.quotaConsumed ?? false`；新建收藏构造处（ReaderPage 划词/预读的 `createBookmark`）置 `quotaConsumed=true`；备份恢复 `importLibraryData` 不置（缺省 false）。
- **关键不变式**：`BOOKMARK_COLUMNS` / `mapBookmarkRow` **不得映射 `quota_consumed`**——该字段只进不出、不 round-trip，否则翻译回写经 upsert 泄漏 `quotaConsumed=true` 会静默多计（触发器已用 `not exists` 兜底，前端也须同步遵守）。

### 5.4 呈现与撞墙（轻量）

- **身份徽标**：AuthPanel 已登录卡片加 Free/Pro 小徽标（Pro 金、Free 中性），只写事实不写「解锁/尊享」营销词。
- **导入额度**：书架/导入入口一行弱化文案「累计已导入 x / 30 篇（Free）」，剩余 ≤3 加强色；撞墙在 ImportPanel 错误区提示，与「收藏周重置」明确区分（导入撞墙是永久性）。
- **收藏额度**：BookmarkManager 统计卡旁「本周剩余 N 条」小标签；撞墙时**划词弹窗收藏按钮不变灰**（划词翻译永远在线），点击给轻提示「本周收藏额度已用完，周一重置；划词翻译不受影响」。可选：收藏动作前用 `getSubscriptionStatus` 预检，撞墙直接提示不发请求（服务端触发器兜底）。
- **升级占位**：统一文案「Pro 权益即将开放」，出现在账号面板额度区块 + 三个撞墙提示的次级链接；不放价格/套餐/支付按钮。
- **Pro 在读权益**：本次（A6）Pro 不差异化同时在读，触发器仍硬限 5 本。前端**不得**展示「Pro 更多在读」，与 02 权益表「Pro 更多（待定）」同步标注「本次不生效」。

### 5.5 未登录路径

`useCloudSource=false`（匿名/localStorage）完全跳过额度逻辑，避免「登录反而更差」的行为跳变。

> 匿名用户仍会触发 `translate`（AI 精译/直译），而该函数无鉴权。本次在 `netlify/functions/translate.js` 加**匿名 IP 级限流**兜底（挡脚本/滥用，不挡正常使用；**限流以不破坏「划词直译永远在线」为前提**）；函数层 JWT 鉴权留待接支付时（见 §10）。

## 7. 成本观测（C 档，Phase 3 可选）

在 `admin_get_growth_stats` 基础上新增成本口径，输出：每周收藏条数（按 `translation_status='done'`）、精译成功率、**provider 分布**（主力/备用/直译兜底占比，读 `translation_provider` 字段）、单 provider 字符量估算。这是把「额度 N」调到成本平衡点的唯一现成抓手。

成本估算口径：1 条收藏按「三级降级最坏 3 次、常态 ≈1.2~1.5 次」调用估算，N=30 据此 sanity check。

**附带发现（非本次必须，但建议一并处理）**：`config/translation.js` 的 `activePreset` 与 `fallbackPreset` 当前都是 kimi-preset（备用形同虚设）；直译 `activeProvider='youdao'` 有成本。验证期建议备用错开 provider、直译兜底切免费 myMemory（**切换前先评估可用性，以不破坏「划词直译永远在线」铁律为前提**），否则按 N 算出的成本预算失真。

## 9. 边界与语义核对表

| 场景 | 行为 |
|---|---|
| 加入上架内容 | 计导入额度（A1） |
| 首次阅读 offer | 不计（RPC 路径，quota_consumed 缺省 false） |

| 删书 | 不释放导入额度（A2）；软删行仍计入终身计数 |
| 收藏翻译失败（三段全挂） | INSERT 已计、不退款（成本已发生；见 §10 说明） |

| 直译兜底成功 | 占额度（A3） |
| Pro 到期超额存量 | 存量保留、冻结新增、不删不降级（A5） |

## 10. 风险与回归清单

1. **触发器回归（最高风险）**：扩展 `guard_reading_user_write` 触及 readings/bookmarks/reading_marks 全部写路径。必须在改动前为「导入 / 收藏 / 阅读区取还书 / 推荐加入 / 首次阅读 offer」建立冒烟清单，Phase 0 落库后逐条回归。
2. **「翻译失败不占额度」与共识的偏差**：原讨论「error 不占」在本代码真实流程（先存 pending 再译）下无法在不破坏成本闸门的前提下实现——额度须在 INSERT 预留以拦住 AI，且三段兜底几乎不会全失败。最终收敛为「INSERT 即计、失败不退款」。**已按此写入方案，若坚持「error 不占」需改为「done 首度过渡」计数并接受成本闸门后移，请知会。**
3. **三处「5」漂移**：`start_reading` RPC 已不读 `p_max_limit`、触发器写死 `>=5`、前端 `MAX_ACTIVE_READINGS=5`，且两处文案不一致。本次（A6）不动，但需在本方案 §1.2 明确记录，避免未来只改一处。
4. **`quota_consumed` 被篡改的风险（两面）**：① 绕过少计——可被直接 API 置 false，接受（§2.2）；② 泄漏多计——翻译回写经 upsert 泄漏 true 会静默多计，已用「触发器 `not exists` + `mapBookmarkRow` 不映射」双保险（§4.1/§5.3）。接支付时计额度路径收敛进 security definer RPC，两面一并消除。
5. **RLS 漏 `revoke all`**：新建表默认 PUBLIC 权限，忘 `revoke all` 会让用户自插自改额度。迁移必须逐表显式 revoke。
6. **触发器内 `now()` 周边界**：统一用 `now()`（事务内恒定，同用户 advisory lock 串行下无「两处求值不一致」问题），周归属判定稳定。
7. **备份恢复误触额度**：`saveBookmark` 是 upsert 且被 `importLibraryData` 复用，必须靠 `quota_consumed` 显式分流，不能挂在「每次 saveBookmark」。
8. **AI 主备同 provider**（§7 附带发现）：影响成本账真实度，建议验证期错开。
9. **删书毁生词（未来）**：`delete_reading` 级联软删 bookmarks，与「生词本独立于书架」未来诉求冲突。本次不拆，仅保留软删（`deleted_at` 非物理删）+ 删除交互明确「删内容」与「删学习积累」的区分文案，并记录为待办钩子。
10. **`translate` 函数无鉴权（成本闸门的函数层缺口）**：AI 成本发生在无鉴权的 `/.netlify/functions/translate`，技术用户可跳过收藏直接调用。本次仅加匿名 IP 限流兜底（§5.5）；**接支付前必须在函数层加 Supabase token 校验**，这是成本闸门从「设计成立」到「实现成立」的关键一环。

## 11. 验收标准

1. Free 用户导入第 31 篇时被服务端拒绝，错误码 `Q0001`，前端提示「导入额度已用完」，且不触发 `refreshAuthState`。
2. Free 用户本周收藏第 31 条时被拒绝（`Q0002`），划词翻译弹窗仍正常直译。
3. 删除已导入内容后，导入计数不回退。
4. 备份恢复不占用导入/收藏额度。
5. 管理员首次上架一篇推荐，提交者 Pro 到期时间 +30 天（幂等，重上架不重复加）；同月第 3 篇起只上架不发奖励。
6. Pro 到期后自动回 Free：Pro 期间导入/收藏的存量全部保留、且不消耗 Free 额度（到期从升级前继续）；回 Free 后再新增导入/收藏重新受 Free 额度约束（额度口径见 [11_设计备忘_Pro期间额度口径](11_设计备忘_Pro期间额度口径.md)）。
7. 未登录用户全流程无额度提示、行为不变。
8. 核心闭环（划词直译、收藏+精译、SRS 复习）在两身份下能力一致，永不降级。
9. 周边界：北京时间周日 23:59:59 与周一 00:00:01 的两次收藏，归属不同计费周（前一计入上周、后一计入本周）。
10. 翻译回写 / 复习反馈 / 归档恢复后，本周已用收藏数不增加——一条新收藏仅计 1 次，无「双计」。
11. 管理员 `admin_grant_pro` 授予 N 天 Pro → 用户 `get_subscription_status` 返回 plan='pro'、`proExpiresAt` 增加 → 到期后自动回 free，可再授予。
