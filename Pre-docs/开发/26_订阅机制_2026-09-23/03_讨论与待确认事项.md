## 3. 待确认事项清单

### A 组 — 机制语义（动笔前必须定）

#### A1 导入计数口径 —— 哪些写入 `readings` 的动作算「一次导入」？

**背景**：`readings` 有 4 类 INSERT 路径——自导入（URL/粘贴/文件/EPUB）、推荐区「加入上架内容」、首次阅读 offer、备份恢复。「导入额度」封的是「燃料」（把新内容带进来），这 4 类里哪些算燃料需逐一界定。

| 选项 | 含义 | 评估 |
|---|---|---|
| 只算自导入 | 推荐加入 / 首次阅读 / 备份均不计 | 免费用户可靠推荐区无限补燃料，额度形同虚设 |
| 自导入 + 加入上架内容 | 推荐内容是真实燃料，计入；首次阅读 offer 保留为不计额的新手引导 | **推荐** |
| 全部计 | 首次阅读 offer 也计 | 掐死新手引导，与「给足探索」相悖 |

**决策（A1 算）**：自导入 + 加入上架内容均计终身导入额度；首次阅读 offer 不计；备份恢复不计。

#### A2 删书是否释放导入额度？

**背景**：导入额度是「终身累计」。若删书回退计数，用户可「导入→读完→删→再导入」无限绕过累计墙。

| 选项 | 评估 |
|---|---|
| 释放（删书回退） | 可被「删了重导」绕过，终身累计失效 |
| 不释放（终身单调） | 删书只释放「同时在读」槽位，不释放导入额度 | **推荐** |

**决策（A2 不释放）**：不释放，终身单调计数。

#### A3 收藏计费边界 —— 一条收藏到底怎么算「计 1」？

**背景**：真实链路是「`saveBookmark`(pending) → `translateBookmark`(AI 精译 → 回写 done/error)」。一条收藏生命周期内有多次写库（pending 创建、翻译回写、复习反馈、归档恢复），且精译有三级降级（主力→备用→直译），可能 1~3 次付费调用，也可能彻底失败。

**关键张力**：讨论初始共识倾向「翻译失败不占额度」，但若额度在「精译成功时」才扣，则 INSERT(pending) 时无法拦截 AI，成本闸门失效（AI 在收藏创建**之后**异步执行）。

| 选项 | 评估 |
|---|---|
| 创建时扣（INSERT 即计） | 闸门在动作入口，天然拦 AI；代价：失败不退款 | **推荐** |
| 精译成功时扣 | 成本准确，但闸门后置、AI 白烧 |
| 创建时扣 + 失败返还 | 需补偿逻辑，复杂度高、收益低 |

**决策（A3 算）**：新建收藏计 1（INSERT 即计、无论精译成败、失败不退款）；重试 / 编辑 / 复习走 UPDATE 不重复计。

#### A4 上架奖励触发时机与幂等

**背景**：01/02 说「上架才计」。但存在 `removed→approved→active` 重新上架路径，且同一内容可被多人「加入上架内容」。「奖励发给谁、发几次」需定。

| 选项 | 评估 |
|---|---|
| 每次上架都发 | 重上架重复发，可刷 |
| 仅首次上架发（`first_published_at` NULL→非 NULL 那刻） | 幂等，字段已备好 | **推荐** |

**决策（A4 接受）**：`status→active` 那刻发 N 天给提交者一次；多人加入不重复；每月 M 触发后内容照常上架、奖励不发。

#### A5 Pro 到期后超额存量处置

**背景**：Pro 期间导入无限、可能 >5 本在读；到期回 Free 后这些超额存量怎么办。01 说「到期自动回 Free，无惩罚」。

| 选项 | 评估 |
|---|---|
| 删 / 降级超额 | 有惩罚感，违背「无惩罚」 |
| 存量保留、冻结新增 | 已导入的不删、超额在读的不强制取回，但不能再新增 | **推荐** |

**决策（A5 接受）**：存量保留、冻结新增、不删不降级、无宽限期。

#### A6 同时在读可配化是否纳入本次

**背景**：01 说「顺手时改、非必须」。但 Pro 权益表有「同时在读：更多」，本次不做则 Pro 少一条差异化；且「5」已硬编码三处漂移（前端常量 / RPC / 触发器）。

| 选项 | 评估 |
|---|---|
| 纳入本次 | 改动面（前端常量 + RPC + 触发器）+ 配置表按身份分档，工作量上升 |
| 本次不纳入 | 保持硬编码 5，三处漂移留待「Pro 更多同时在读」一并处理 | **推荐** |

**决策（A6 暂时不纳入）**：本次不纳入。

### B 组 — 参数数值（验证期默认）

| 参数 | 默认值 | 调法提示 |
|---|---|---|
| 导入累计 N | 30 | 给足额度，别在验证期卡死探索者 |
| 收藏每周 N | 30 | LLM 成本承受力，配成本观测再调 |
| 上架奖励天数 | 30 天/篇 | 激励强度 vs 审核人力 |
| 每月赚取上限 M | 60 天 | 防刷（最多 2 篇有效贡献） |
| Pro 同时在读 | 暂不差异化 | 待 A6 一并处理 |

**决策（B 接受）**：采纳上述验证期默认值。

### C 组 — 实现约定

| 约定 | 内容 |
|---|---|
| 时区锚 | `Asia/Shanghai`（收藏周 = 周一 0 点、社区月 = 本月 1 日） |
| Pro 计时 | `+N×24h` 滑动窗口（非自然日切分），`GREATEST(now(), coalesce(pro_expires_at, now())) + N天` |
| 状态 RPC | 新增 `get_subscription_status()`，前端统一消费身份 + 额度 |
| 额度写路径 | 全走 security definer（触发器 + 发奖励 RPC） |
| 新表权限 | `subscriptions` / `user_quotas` / `pro_grants` 全 `revoke all`，只留 own SELECT |

**决策（C 接受）**：采纳上述实现约定。

| 编号 | 拍板 | 结论 |
|---|---|---|

| A2 | 不释放 | 删书不回退导入额度 |

| A4 | 接受 | 上架即发 N 天一次、幂等、月上限 M 后只上架不发奖 |

## 5. 遗留偏差与已知风险

1. **A3「翻译失败不占额度」的实质转向（最重要）**：讨论初始共识「error 不占」，但真实代码流程（先存 pending 再译）下，额度须在 INSERT 预留才能拦住 AI，故收敛为「INSERT 即计、失败不退款」。三段兜底几乎不会全失败，实际影响极小；但这是对原始共识的一处**修正**，已在 [04 §10.2](04_实施方案.md) 明示——若坚持「error 不占」需改为「done 首度过渡」计数并接受成本闸门后移。
2. **`quota_consumed` 可被直接 API 置 false 绕过**：该列随客户端 INSERT 写入，技术型用户可绕过。**接受**——无支付、无财务欺诈，危害等价于「注册新账号」；接支付时收敛进 security definer RPC。
3. **未登录用户完全跳过额度**：匿名走 localStorage 本地数据源，服务端不可见，无法计数；额度机制整体定位为**仅登录用户**。验证期接受此行为（对应 Kimi 审核 4.1 的 C 选项），风险记录在案。

**两处需产品侧知晓的差异**：
