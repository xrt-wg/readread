## 结论（TL;DR）

M2 的结构校验（`admin_update_recommendation_content` 逐元素校验）在**方向正确但实现有 SQL 三值逻辑漏洞**：`jsonb_typeof(v_section->'body') <> 'object'` 在 `body` 键缺失时求值为 `NULL` 而非 `TRUE`，`IF` 对 `NULL` 不进入分支，导致「缺 body 的对象」「空 body 对象」「text 错型且 markdown 缺失」等坏结构**静默通过校验**。这恰好落在 05 §五自述「结构校验错误分支未用坏数据直接触发过，可采信代码审查」的盲区里——静态审查发现该分支实际失效。好消息是读路径（`addRecommendationToBookshelf` 的 `s.body?.text || ''`）已兜底，无崩溃、仅产生退化空 section，且正常 UI 路径（editor 恒产出合法 body）不会触发，故定级为中。

## 一、中（结构校验失效，与 04 M2「把脏数据挡在写入前」的承诺不符）

### M1　`jsonb_typeof(v_section->'body') <> 'object'` 在键缺失时得 `NULL` 而非 `TRUE`，坏结构静默通过

**证据链：**

1. [20260922000000_recommendation_content_curation.sql:42-49](../../../supabase/migrations/20260922000000_recommendation_content_curation.sql#L42-L49) 的结构校验写为：

   ```sql
   for v_section in select jsonb_array_elements(p_sections) loop
     if jsonb_typeof(v_section) <> 'object'
        or jsonb_typeof(v_section->'body') <> 'object'
        or (jsonb_typeof(v_section->'body'->'text') <> 'string'
            and jsonb_typeof(v_section->'body'->'markdown') <> 'string') then
       raise exception '正文结构不合法：每节须含 body.text 或 body.markdown 字符串';
     end if;
   end loop;
   ```

2. 关键在 SQL 三值逻辑：`v_section->'body'` 对「无 body 键」的元素返回 SQL `NULL`；`jsonb_typeof(NULL::jsonb)` 返回 `NULL`；于是 `NULL <> 'object'` 求值为 `NULL`（未知），而 `IF` 条件把 `NULL` 当作「非真」处理，**不进入分支**。
3. 逐例推演（均不触发 `raise`，即**校验失效**）：
   - `{"heading":"x"}`（缺 body）：`false OR NULL OR NULL = NULL` → 通过。
   - `{"body":{}}`（空 body）：`false OR false OR (NULL AND NULL) = NULL` → 通过。
   - `{"body":{"text":123}}`（text 错型、markdown 缺失）：`false OR false OR (true AND NULL) = NULL` → 通过。
4. 与 [04_实施前审核反馈处理记录.md:28-29](../../../Pre-docs/开发/22_推荐区正文策展与上架排版保障_2026-09-22/04_实施前审核反馈处理记录.md#L28-L29) 承诺的「逐元素校验每节须含 body 对象且 body.text/body.markdown 至少其一为字符串」、[05 §三 #2](../../../Pre-docs/开发/22_推荐区正文策展与上架排版保障_2026-09-22/05_实施后审核请求.md) 验收项「结构校验」相悖——承诺校验，实际对「缺失」类坏结构是空转。

**影响评估（为何定中而非高）：**

- 正常 UI 路径**不可达**：`SectionContentEditor` 的 `editingToFull` 恒产出含 `body` 的 section（[SectionContentEditor.jsx:153-165](../../../src/components/SectionContentEditor.jsx#L153-L165)），面板与书架两条编辑路径都不会产出缺 body 的结构。
- 读路径已兜底：`addRecommendationToBookshelf` 映射用 `s.body?.text || ''`（可选链），缺 body 不会崩，仅产生一段空正文 section。
- 触发面：仅管理员经 PostgREST 直调 RPC、或未来某处 bug 产出坏结构时才会把脏数据写入 `curated_sections`。

**修复建议（NULL 安全的比较，一处改动）：**

```sql
if jsonb_typeof(v_section) <> 'object'
   or jsonb_typeof(v_section->'body') is distinct from 'object'
   or (jsonb_typeof(v_section->'body'->'text') is distinct from 'string'
       and jsonb_typeof(v_section->'body'->'markdown') is distinct from 'string') then
```

`IS DISTINCT FROM` 把「键缺失（NULL）」与「错型」都判为「非目标类型」，`NULL is distinct from 'string'` 为 `TRUE`，三个坏结构案例均会被拦截。修复后建议补一条 SQL 断言（`set_config('request.jwt.claims', …)` 模拟管理员）对 `[{"heading":"x"}]`、`[{"body":{}}]`、`[{"body":{"text":123}}]` 分别断言 `raise`。

## 二、低（稳健性 / 一致性）

### L1　数组类型检查与空数组检查同处一个 `OR`，错误信息不确定

[20260922000000_recommendation_content_curation.sql:38-40](../../../supabase/migrations/20260922000000_recommendation_content_curation.sql#L38-L40)：

```sql
if p_sections is null or jsonb_typeof(p_sections) <> 'array'
   or jsonb_array_length(p_sections) = 0 then
```

`jsonb_typeof(p_sections) <> 'array'`（判非数组）与 `jsonb_array_length(p_sections) = 0`（判空数组）在同一 `OR` 内。PostgreSQL 不保证 `OR` 短路求值顺序；若对非数组 jsonb（如 `'{}'::jsonb`）先求值 `jsonb_array_length`，会抛出「cannot get array length of a non-array」而非约定的「正文结构不合法：须为非空数组」。两种情况下写入都被拦截（安全性无影响），仅错误文案可能漂移。建议拆成两个 `if`（先判类型、再判空），保证报错文案确定。

### L2　编辑回写丢弃 `parentId`（当前无下游消费，属信息性记录）

`fullToEditing` / `editingToFull` 只保留 `id/heading/depth/order/body`，丢弃 `parentId`（[SectionContentEditor.jsx:142-165](../../../src/components/SectionContentEditor.jsx#L142-L165)），而 `Section` 类型含 `parentId`（[document.js:99](../../../src/types/document.js#L99)）。经全仓检索，`parentId` 仅由 `deriveParentIds` 在创建时推导、无任何渲染/查询消费，且「加入书架」路径本就重新 `assembleSections`+`deriveParentIds`（[extractors/index.js:18-31](../../../src/services/extractors/index.js#L18-L31)），故**当前无功能影响**。此处仅提示：若未来有功能消费 `section.parentId`（如目录树），编辑保存后的书架上内容将缺失该字段。可在 `editingToFull` 携带 `parentId: s.parentId ?? null` 一次性抹平，或在 D6 中注明「parentId 为派生字段、编辑后由创建链路重推导」。
