## 二、逐条处理

### H1（高）共享组件抽取契约未定 → 已定稿并落地

- **立场**：认同。§3.3/§3.4 确为两套互斥的状态所有权方案。
- **定稿**：采用方案 A——`SectionContentEditor` 受控于完整态 `Section[]`（`{id, heading, depth, order, body:{text, markdown, wordCount}}`），`onChange(fullSections)` 回写；组件内部派生编辑态 `{id, heading, depth, order, bodyText, bodyMarkdown}`，`id/depth/order` 原样携带/写回，`wordCount` 按 `bodyText` 重算。已写入 [02_实施方案 §3.3/§3.4](02_实施方案.md)。
- **附带发现**：原 `ImportItemEditor.handleSave` 用 `...item.sections[i]` 取 id/depth/order，而书架列表项 `item.sections=[]`（列表列不含 sections），每次编辑保存都**静默丢弃 id/depth/order**——多章节/深层标题内容编辑后退化为 h2。改为完整态 state 后一并消除。已写入 [01 D6](01_讨论和决策记录.md)。
- **落地**：`ImportItemEditor.jsx` 的 `sections` state 改完整态，`handleSave` 删 `...item.sections[i]`，`isDirty`/`snapshot` 改比较完整态；`SectionContentEditor.jsx` 用 `lastEmittedRef` 区分「外部数据源变化」与「自身 onChange 回显」，避免按键光标回跳。

### M1（中）`coalesce(s.author, x.author)` 复活清空值 → 已修复

- **立场**：认同。`join` 保证 `s` 恒存在，`coalesce(s.x, x.x)` 对可空字段反而吞掉「清空」语义。
- **落地**：`get_recommendation_snapshot` 的 title/author/source_url 改为直取 `s.title/s.author/s.source_url`；`sections` 的 `coalesce(curated_sections, sections)` 保留。已写入 [02 §3.1 Step 3](02_实施方案.md) 与 [01 D4](01_讨论和决策记录.md)。

### M2（中）RPC 只校验顶层 array，坏结构流入 `s.body.text.split` → 已修复（A 为主）

- **立场**：认同 A（RPC 逐元素结构校验）。
- **补充修正**：反馈的 M2-B 崩溃链已追到底——`addRecommendationToBookshelf` 映射用 `s.body?.text || ''` 把 `body.text` 归一为字符串，且 `wordCount` 由 `assembleSections` 重算，故 `s.body.text.split` 崩溃风险**已基本被覆盖**；剩余风险仅「非字符串 text」，由 A 的源头校验挡掉即可。故以 A 为主，不再额外改读路径。
- **落地**：`admin_update_recommendation_content` 逐元素校验「每节须含 body 对象且 body.text/body.markdown 至少其一为字符串」，不合法即 `raise exception`。已写入 [02 §3.1 Step 2](02_实施方案.md)。

### L1（低）`detail.snapshot.curated_sections ?? …` 缺空守卫 → 已补

- **落地**：面板改为 `detail?.snapshot?.curated_sections ?? detail?.snapshot?.sections`，并对 `!Array.isArray(displaySections)` 渲染「正在加载正文快照…」空态。已写入 [02 §3.5](02_实施方案.md)。

### L2（低）策展审计无 payload → 已补

- **落地**：审计 insert 增加 `payload = jsonb_build_object('content_hash', v_content_hash, 'first_curation', v_prev_curated_at is null)`，记录提交指纹与是否首次策展。已写入 [02 §3.1 Step 2](02_实施方案.md)。

### L3（低）空数组 `[]` 不被拒绝 → 已补

- **落地**：RPC 校验改为「非空数组」（`jsonb_array_length(p_sections) = 0` 即报错），把「空正文」退化态挡在写入前。已写入 [02 §3.1 Step 2](02_实施方案.md)。

### L4（低）纯文本 section 编辑后被转 markdown → 记录不修复

- **立场**：认同按「记录而非修复」处理。只读 `SectionPreview` 仍按 `body.markdown != null` 分流渲染（未编辑的纯文本 section 不受影响）；仅**编辑**路径触发转换。
- **落地**：在 [01 D7](01_讨论和决策记录.md) 明确「策展后统一按 markdown 交付、纯文本语义不再保留」，并说明日后如需保留纯文本语义再另立 RPC。
