# 推荐区正文策展与上架排版保障 — 实施方案

> 日期：2026-09-22
> 前置：[01_讨论和决策记录](01_讨论和决策记录.md)

## 一、目标

让管理员在推荐审核后台能**像书架区那样「编辑 + 预览」正文**，在上架前把正文排版修正到位，并修复「卡片标题 vs 加入书架标题」不一致。

1. 快照表新增策展层 `curated_sections`/`curated_at`，保留提交原样 `sections`/`content_hash` 不变；
2. 新增 `admin_update_recommendation_content` RPC，管理员在上架前可修正正文；
3. `get_recommendation_snapshot`（加入书架）优先返回策展正文，标题/作者/来源取提交表现行值；
4. 抽取共享「内容编辑 + 预览」组件，后台审核面板以排版后的形态渲染/编辑正文。

## 二、数据模型

`recommendation_submission_snapshots` 新增两列：

| 字段 | 类型 | 约束 | 含义 |
|---|---|---|---|
| `curated_sections` | jsonb | 可空 | 管理员策展正文，非空时覆盖 `sections` 供加入书架 |
| `curated_at` | timestamptz | 可空 | 最近一次策展时间 |

- `sections` 保持提交时冻结原样（不可变）；`content_hash` 保持提交指纹（去重基线），策展不重算。
- 语义：`coalesce(curated_sections, sections)` 即「上架时实际交付给用户」的正文。

## 三、分层实施

### 3.1 数据层（迁移脚本）

新建 `supabase/migrations/20260922000000_recommendation_content_curation.sql`：

> **执行顺序（H1）**：本迁移经 Dashboard SQL Editor 手工执行、与前端发布不同步。必须**先执行迁移、确认新 RPC 可调用，再发布前端**。

```sql
-- ============================================================================
-- Migration: 推荐区正文策展（上架前排版保障）
-- 日期: 2026-09-22
-- 说明: 为推荐快照新增「管理员策展正文」层 curated_sections/curated_at，
--       保留提交时的 sections/content_hash 不变（不可变 + 去重基线）；
--       新增 admin_update_recommendation_content 供管理员在上架前修正正文排版；
--       改写 get_recommendation_snapshot（加入书架）优先返回策展正文，
--       并让标题/作者/来源取提交表现行值，修复「卡片显示 vs 导入内容」不一致；
--       扩展 admin_get_recommendation_submission_detail 返回策展信息。
-- 执行方式: Dashboard SQL Editor 手动执行（无本地 CLI）
-- ============================================================================

begin;

-- Step 1: 快照表新增策展层
alter table public.recommendation_submission_snapshots
  add column if not exists curated_sections jsonb,
  add column if not exists curated_at timestamptz;

-- Step 2: 管理员策展正文（仅待审核/已通过/已下架；已发布需先下架）
-- 校验：非空数组 + 逐元素含 body 对象且 body.text/body.markdown 至少其一为字符串
--   （结构比较用 IS DISTINCT FROM 做 NULL 安全比较，避免键缺失时 SQL 三值逻辑漏判——实施后审核 M1）
-- 审计：payload 记录提交指纹 content_hash 与是否首次策展（L2）
create or replace function public.admin_update_recommendation_content(
  p_submission_id text,
  p_sections jsonb
)
returns jsonb
language plpgsql security definer set search_path = public as $$
declare
  v_status text;
  v_prev_curated_at timestamptz;
  v_content_hash text;
  v_section jsonb;
begin
  if not public.is_current_user_admin() then
    raise exception '无管理员权限';
  end if;
  if p_sections is null or jsonb_typeof(p_sections) <> 'array' then
    raise exception '正文结构不合法：须为非空数组';
  end if;
  if jsonb_array_length(p_sections) = 0 then
    raise exception '正文结构不合法：须为非空数组';
  end if;
  for v_section in select jsonb_array_elements(p_sections) loop
    if jsonb_typeof(v_section) is distinct from 'object'
       or jsonb_typeof(v_section->'body') is distinct from 'object'
       or (jsonb_typeof(v_section->'body'->'text') is distinct from 'string'
           and jsonb_typeof(v_section->'body'->'markdown') is distinct from 'string') then
      raise exception '正文结构不合法：每节须含 body.text 或 body.markdown 字符串';
    end if;
  end loop;
  select status into v_status from public.recommendation_submissions where id = p_submission_id;
  if v_status is null then
    raise exception '推荐提交不存在';
  end if;
  if v_status not in ('pending', 'approved', 'removed') then
    raise exception '仅待审核、已通过或已下架内容可编辑正文；已发布内容请先下架';
  end if;
  select curated_at, content_hash into v_prev_curated_at, v_content_hash
    from public.recommendation_submission_snapshots where submission_id = p_submission_id;
  if not found then
    raise exception '该提交没有正文快照，无法编辑';
  end if;
  update public.recommendation_submission_snapshots
    set curated_sections = p_sections, curated_at = now()
    where submission_id = p_submission_id;
  insert into public.audit_logs (actor_user_id, actor_role, action, target_type, target_id, payload)
    values (auth.uid(), 'admin', 'recommendation.content_curated', 'recommendation_submission', p_submission_id,
      jsonb_build_object('content_hash', v_content_hash, 'first_curation', v_prev_curated_at is null));
  return jsonb_build_object('submission_id', p_submission_id);
end;
$$;

-- Step 3: 加入书架 → 策展正文优先 + 标题/作者/来源取提交表现行值
-- 注（M1）：author/source_url 取发布态列 s.author/s.source_url，不做 coalesce——
--   管理员清空作者/来源后应回退为空，而非「复活」提交时冻结值。
--   sections 的 coalesce(curated_sections, sections) 仍必须保留（无策展回退提交原样）。
create or replace function public.get_recommendation_snapshot(p_submission_id text)
returns jsonb
language sql security definer set search_path = public as $$
  select jsonb_build_object(
    'title', s.title, 'author', s.author, 'source_url', s.source_url,
    'sections', coalesce(x.curated_sections, x.sections),
    'format', x.format, 'cover_url', x.cover_url, 'lang', x.lang, 'kind', x.kind)
  from public.recommendation_submission_snapshots x
  join public.recommendation_submissions s on s.id = x.submission_id
  where x.submission_id = p_submission_id and s.status = 'active'
$$;

-- Step 4: 管理员详情 → 附带策展信息（面板据此渲染 + 显示「已策展」）
create or replace function public.admin_get_recommendation_submission_detail(p_submission_id text)
returns jsonb language sql security definer set search_path = public as $$
  select case when public.is_current_user_admin() then jsonb_build_object(
    'submission', to_jsonb(s), 'internal_note', r.internal_note, 'reviewed_at', r.reviewed_at,
    'snapshot', case when x.submission_id is null then null else jsonb_build_object(
      'content_hash', x.content_hash, 'sections', x.sections,
      'curated_sections', x.curated_sections, 'curated_at', x.curated_at,
      'created_at', x.created_at, 'title', x.title, 'author', x.author, 'source_url', x.source_url)
    end
  ) else null end
  from public.recommendation_submissions s
  left join public.recommendation_submission_admin_reviews r on r.submission_id = s.id
  left join public.recommendation_submission_snapshots x on x.submission_id = s.id
  where s.id = p_submission_id
$$;

revoke all on function public.admin_update_recommendation_content(text, jsonb)
  from public, anon, authenticated;
grant execute on function public.admin_update_recommendation_content(text, jsonb) to authenticated;
notify pgrst, 'reload schema';

commit;
```

> 关键点：
> - **`create or replace` 保留 grant**：`get_recommendation_snapshot`、`admin_get_recommendation_submission_detail` 签名不变，原 `grant execute` 依然有效；仅新增 `admin_update_recommendation_content` 需 grant。
> - **`content_hash` 不重算**：始终是提交指纹；策展只写 `curated_sections`/`curated_at`。
> - **状态门（D5）**：`pending/approved/removed` 可策展，`active` 报「请先下架」；对齐 `admin_update_recommendation_editorial`。
> - **快照缺失防御**：`update ... where submission_id` 未命中时 `if not found` 报错，历史无快照记录不可编辑正文。

### 3.2 服务层（`src/services/supabase/recommendationService.js`）

新增一个函数：

```js
/** 管理员策展正文（上架前修正排版）；已发布内容须先下架。 */
export async function updateRecommendationContent(submissionId, sections) {
  const client = getClient()
  const { data, error } = await client.rpc('admin_update_recommendation_content', {
    p_submission_id: submissionId,
    p_sections: sections,
  })
  if (error) throw error
  return data
}
```

`getRecommendationModerationDetail` 无需改动——`admin_get_recommendation_submission_detail` 返回的 `snapshot.curated_sections`/`curated_at` 经 RPC 已是 JS 值。

### 3.3 抽取共享「内容编辑 + 预览」组件（新增 `src/components/SectionContentEditor.jsx`）

从 [ImportItemEditor.jsx](../../../src/components/ImportItemEditor.jsx) 把内容编辑核心**迁出**：`ToolbarButton`/`insertAtCursor`/`FormatToolbar` 原样移动为 `MarkdownToolbar`，`MarkdownPreview` 保持导出，`SectionContentEditor`/`SectionPreview` 为新增封装。

**契约（H1 定稿，唯一对外形态为「完整态 Section[]」）：**

完整态 Section：`{ id, heading, depth, order, body: { text, markdown, wordCount } }`。

```jsx
<SectionContentEditor
  sections={fullSections}   // 完整态 Section[]
  onChange={(next) => {}}   // (Section[]) => void，每次编辑即时回写完整态
/>
```

- **组件受控于完整态**：`sections`（完整态）由父组件持有并传入，`onChange` 由父组件回写；组件内部把完整态派生为编辑态 `{id, heading, depth, order, bodyText, bodyMarkdown}` 供表单使用，任何改动即时映射回完整态并 `onChange`。
- **保留规则**：`id/depth/order` 由完整态→编辑态原样携带、编辑态→完整态原样写回（不再用 `...item.sections[i]`，顺带修复「编辑保存丢失 id/depth/order」隐患）；`wordCount` 按 `bodyText` 重算；`heading` 空串归一为 `null`。
- **派生规则（L4 记录）**：`bodyMarkdown = body.markdown ?? body.text ?? null`、`bodyText = body.text ?? ''`，与现有 ImportItemEditor 完全一致；「编辑纯文本 section 会转成 markdown 交付、纯文本语义不再保留」为既有行为，保留并记录。
- **不内嵌保存按钮、不用 ref**：保存由父组件头部按钮统一触发（父组件持完整态，直接提交）。
- **光标稳定**：组件仅在 `sections` 引用相对自身最近一次 emit 发生变化（外部懒加载/重新拉取）时重建编辑态，自身 onChange 的回显不重建，避免每次按键光标回跳。

- 新增 **`SectionPreview`**（只读排版预览）：`sections.map` → `heading + depth → 标题标签` + `MarkdownPreview(body.markdown)` 或纯文本降级，等价于去掉交互的 `SectionFlow`。供审核面板默认态使用。

## 五、验收标准

1. 迁移后，`recommendation_submission_snapshots` 存在 `curated_sections`/`curated_at`，既有行两列为 NULL，`sections`/`content_hash` 未变；`admin_update_recommendation_content` 已 `revoke all ... from public`，`anon` 调用被拒。
2. 权限/状态门/结构校验：非管理员报「无管理员权限」；`active` 报「已发布内容请先下架」；无快照报「没有正文快照」；`p_sections` 非数组或空数组 `[]` 报「正文结构不合法：须为非空数组」；元素缺 `body` 或 `body.text`/`body.markdown` 均非字符串报「每节须含 body.text 或 body.markdown 字符串」。
3. 策展生效：对 `pending` 提交编辑正文保存后，`curated_sections`/`curated_at` 落库，`audit_logs` 出现 `recommendation.content_curated` 且 `payload` 含 `content_hash` 与 `first_curation`；`get_recommendation_snapshot` 返回策展正文。
4. 加入书架一致性：正文 = 策展正文（无策展 = 提交原样）；标题 = 卡片当前标题（D4）；**作者/来源被管理员清空后导入为 null，不复活提交时冻结值（M1）**。
5. 后台渲染：正文区以排版后只读预览呈现（标题层级 + markdown 渲染）；「编辑正文」可编辑并保存，保存后回预览态且出现「已策展」徽标；快照缺失时保持「需运营补录」且无编辑入口；加载期不崩（L1）。
6. 回归：ImportItemEditor 的编辑→预览→保存→「加入书架」全链路行为不变；**多章节/深层标题内容编辑保存后 `id/depth/order` 保留（H1 附带修复）**；推荐发布约束（`intro + 1~5 摘录`）、去重、状态机不受影响。
7. 颜色规范：新增 UI 全部走 `var(--*)`，无硬编码颜色（金色 accent 例外）。

## 六、风险与回滚

- **ImportItemEditor 抽取回归**：抽共享组件会动阅读主线；采用「只移动、不改行为」+ 验收 #6 全链路回归。若回归出问题，优先在共享组件内修正而非复制逻辑。
- **部署顺序（H1）**：迁移先行；前端在 `detail.snapshot.curated_sections` 为 `undefined` 时（迁移未到位）按 `undefined ?? sections` 回退到提交原样，不报错。
- **content_hash 语义**：策展不重算指纹，去重与面板指纹显示不受影响。
- **回滚**：`ALTER TABLE ... DROP COLUMN curated_sections, DROP COLUMN curated_at;` + `DROP FUNCTION admin_update_recommendation_content(text, jsonb);` + 还原 `get_recommendation_snapshot`/`admin_get_recommendation_submission_detail`（`20260917000000`/`20260917000002` 版本函数体）。回滚会丢失已策展正文，回滚前先导出 `curated_sections`。
