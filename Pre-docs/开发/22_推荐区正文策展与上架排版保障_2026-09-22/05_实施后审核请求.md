## 四、实施偏差与补充说明（请审核者重点复核）

1. **H1 附带发现（比反馈更深的隐患）**：原 `ImportItemEditor.handleSave` 用 `...item.sections[i]` 取 `id/depth/order`，而书架列表项 `item.sections=[]`（列表列不含 sections），每次编辑保存都**静默丢弃 id/depth/order**，多章节/深层标题内容编辑后退化为 h2。已按 D6 改为完整态 state 一并消除。审核者可对照 `ImportItemEditor.jsx` 的 `handleSave` 确认不再有 `...item.sections[i]` 展开。

2. **H1 契约定稿（方案 A）**：`SectionContentEditor` 受控于完整态 `Section[]`（`{id, heading, depth, order, body:{text, markdown, wordCount}}`），`onChange(fullSections)` 回写；内部派生编辑态，`id/depth/order` 原样携带/写回，`wordCount` 按 `bodyText` 重算。光标稳定用 `lastEmittedRef` 区分「外部数据源变化」与「自身 onChange 回显」。

3. **M1 修正**：`get_recommendation_snapshot` 的 `title/author/source_url` 直取发布态列 `s.title/s.author/s.source_url`，**去掉可空字段的 coalesce**，清空即空；`sections` 的 `coalesce(curated_sections, sections)` 保留（无策展回退提交原样）。

4. **M2 落地（A 为主）**：`admin_update_recommendation_content` 逐元素校验「每节须含 body 对象且 `body.text`/`body.markdown` 至少其一为字符串」，不合法 `raise exception`。M2-B 的读路径崩溃风险经追溯已由 `addRecommendationToBookshelf` 的 `s.body?.text || ''` 归一覆盖，故未额外改读路径。

5. **L1 空守卫**：`displaySections = detail?.snapshot?.curated_sections ?? detail?.snapshot?.sections`，并对 `!Array.isArray(displaySections)` 渲染「正在加载正文快照…」空态。

6. **L2 审计 payload**：`payload = jsonb_build_object('content_hash', v_content_hash, 'first_curation', v_prev_curated_at is null)`，记录提交指纹与是否首次策展。

7. **L3 拒空数组**：RPC 校验改为「非空数组」（`jsonb_array_length(p_sections) = 0` 即报错）。

8. **L4 记录不修复**：纯文本 section 一经编辑保存即转 markdown 交付，为 ImportItemEditor 既有行为，共享组件原样继承；已在 D7 明确「策展后统一按 markdown 交付、纯文本语义不再保留」，审核者知悉即可。
