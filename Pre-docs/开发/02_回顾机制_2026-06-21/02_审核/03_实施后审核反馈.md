## 二、发现的问题与建议

### P1（High）：`handleFeedback` 未停止语音播放

**位置**：[ReviewPanel.jsx:61-79](src/components/ReviewPanel.jsx#L61-L79)

**问题**：`handleFeedback` 在推进到下一张卡片前未调用 `stop()`。旧版 `handleNext` 在推进前会停止语音：

```js
// 旧版 handleNext（已删除）
const handleNext = useCallback(() => {
  stop()                              // ← 停止语音
  if (index + 1 >= cards.length) ...
}, [index, cards.length, stop])

// 新版 handleFeedback
const handleFeedback = useCallback(async (feedback) => {
  // ... stop() 未被调用
  setSaving(false)
  advanceToNext()                     // 推进时语音可能仍在播放
}, [...])
```

**影响**：用户在卡片背面点击反馈按钮时，如果之前点击了正面的发音按钮，语音会在下一张卡片上继续播放。

**修正**：
```js
const handleFeedback = useCallback(async (feedback) => {
  if (saving) return
  const bookmark = cards[index]
  if (!bookmark) return

  stop()  // ← 添加：停止语音
  setSaving(true)
  // ...
}, [cards, index, saving, canUseCloudLibrary, refreshAuthState, userId, advanceToNext, stop])
```

### P2（High）：`handleRestart` 重复查询书签数据

**位置**：[ReviewPanel.jsx:81-109](src/components/ReviewPanel.jsx#L81-L109)

**问题**：`handleRestart` 分别调用 `listAllBookmarks()` 和 `listDueBookmarks()`，而后者内部又调用 `listAllBookmarks()`。一次"再来一轮"触发了 **3 次** `listAllBookmarks()` 查询（listDueBookmarks 内部 1 次 + 显式 listAllBookmarks 1 次 + 可能的重渲染触发）。加上手动过滤/补齐逻辑，整个函数约 25 行，逻辑分散。

**当前实现**：
```js
const all = await listAllBookmarks({ ... })          // 查询 1
const fresh = all.filter(b => !reviewedThisSession.current.has(b.id))
const due = await listDueBookmarks({ ... })           // 查询 2（内部再次 listAllBookmarks）
const freshIds = new Set(fresh.map(b => b.id))
const newSession = due.filter(b => freshIds.has(b.id))
// 手动补齐...
```

**建议简化**：为 `listDueBookmarks` 增加可选的 `excludeIds` 参数：
```js
// library.js
export async function listDueBookmarks(options, excludeIds = new Set()) {
  const all = await listAllBookmarks(options)
  const filtered = all.filter(b => !excludeIds.has(b.id))
  // ... 对 filtered 进行分类和组卷
}

// ReviewPanel.jsx
const handleRestart = useCallback(async () => {
  stop()
  setLoadError('')
  try {
    const session = await listDueBookmarks(
      { canUseCloudLibrary, userId },
      reviewedThisSession.current
    )
    setCards(session)
    // ...
  }
}, [...])
```

这样消除了双重查询和手动过滤逻辑，`handleRestart` 缩减至 ~15 行。

### P3（Medium）：空状态下统计指标不展示

**位置**：[ReviewPanel.jsx:116](src/components/ReviewPanel.jsx#L116)

**问题**：统计指标行的渲染条件为 `{stats && cards.length > 0 && (...)}`。当 `cards.length === 0`（空状态）时指标被隐藏，但实施方案 §6.2 和 §8.2 明确要求「三个指标在空状态下均显示 `0 / 尚无数据 / 0`」：

```
当前行为：空状态 → 统计数据行不渲染
期望行为：空状态 → 显示 "0 / 尚无数据 / 0"
```

**影响**：用户首次打开回顾 Tab（无书签）时看不到任何统计信息，与设计意图不符。

**修正**：
```jsx
{/* Stats row — 始终展示（含空状态） */}
{stats && (
  <div className="flex gap-3 mb-4">
    {/* ... 三个指标卡片 ... */}
  </div>
)}
```

当 `cards.length === 0` 时 stats 为 `{due:0, mastered:'尚无数据', total:0}`，各项均为 0，展示无副作用。需要确保初始化时 stats 在空书签情况下也被正确设置——当前 `init()` 在 `listAllBookmarks` 成功但 `listDueBookmarks` 返回空数组时，stats 仍会被设置（第 36-37 行在 `listDueBookmarks` 成功后执行）。
