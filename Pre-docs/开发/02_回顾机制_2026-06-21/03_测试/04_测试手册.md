# 回顾机制优化 — 测试手册

- **日期**：2026-06-21
- **测试范围**：调度算法 / 组卷逻辑 / 交互反馈 / 统计指标 / 功能无退化

---

## Test 1：首次回顾 — 新收藏的调度初始化

### 测试背景
所有现有书签的 `reviewCount=0, familiarity=0, nextReviewAt=null`。需验证首次反馈后三个字段正确写入。

### 测试目标
验证首次反馈 special mapping（生疏→1 / 一般→2 / 熟练→3）及 `saveBookmark` 持久化。

### 测试链路
1. 阅读器 → 划选一个单词 → 点击收藏
2. 切换到回顾 Tab → 确认该词出现在卡片中
3. 翻到背面 → 点击 [一般]

### 核心检测点
- [ ] 点击 [一般] 后推进到下一张（或完成），无报错
- [ ] 打开 Supabase Dashboard → bookmarks 表 → 该行 `review_count=1`, `familiarity=2`, `next_review_at` 为 3 天后的 ISO 时间
- [ ] 再次打开回顾 Tab → 该词不出现在本轮（已排期到 3 天后）

## Test 2：三种反馈的效果差异

### 测试背景
同一张卡片，不同反馈应对应不同的 familiarity 和间隔。

### 测试目标
验证 hard/ok/easy 三档产生不同调度结果。

### 测试链路
1. 准备 3 张从未复习的卡片（或在 Supabase 中手动重置 `review_count=0, familiarity=0`）
2. 逐一给反馈：卡片 A → [生疏] / 卡片 B → [一般] / 卡片 C → [熟练]
3. 检查数据库

### 核心检测点
- [ ] A: `familiarity=1`, `next_review_at` = +1 天
- [ ] B: `familiarity=2`, `next_review_at` = +3 天
- [ ] C: `familiarity=3`, `next_review_at` = +7 天

---

## Test 3：后续复习 — delta 递增与钳制

### 测试背景
非首次复习时，familiarity 按 delta 变化，需验证上下限钳制。

### 测试目标
验证 familiarity=5 不越界（easy→仍5）、familiarity=1 不越界（hard→仍1）。

### 测试链路
1. 在 Supabase 中手动设置：卡片 A `familiarity=5, review_count=2`；卡片 B `familiarity=1, review_count=1`；`next_review_at` 改为过期时间（如昨天）
2. 回顾 Tab → 给 A [熟练] / 给 B [生疏]
3. 检查数据库

### 核心检测点
- [ ] A: `familiarity=5`（未超过上限），`next_review_at` = +30 天
- [ ] B: `familiarity=1`（未跌破下限），`next_review_at` = +1 天
- [ ] 两者的 `review_count` 均 +1

---

## Test 4：到期优先 + 新卡补足

### 测试背景
书签池中包含到期卡片、新卡片、未来卡片三种。到期卡片应优先进入 session。

### 测试目标
验证 `listDueBookmarks` 组卷顺序：到期优先 → 新卡补足 → 未来兜底。

### 测试链路
1. 准备 8 张过期卡片（`review_count>0, next_review_at` = 昨天）+ 5 张新卡片（`review_count=0`）+ 若干未来卡片（`next_review_at` = 下周）
2. 打开回顾 Tab

### 核心检测点
- [ ] Session 共 10 张卡片
- [ ] 前 8 张全部是到期卡片（可从 `nextReviewAt` 在数据库确认）
- [ ] 后 2 张是新卡片
- [ ] 未来卡片未出现（不足 10 张也不需要补齐）

## Test 5：防重复点击

### 测试背景
用户快速双击反馈按钮应被 `saving` 锁阻止。

### 测试目标
验证第二次点击被忽略，不会对下一张卡片误评价。

### 测试链路
1. 打开回顾 Tab
2. 翻到背面 → 快速双击 [熟练]
3. 观察推进行为

### 核心检测点
- [ ] 只推进了一次（到下一张正面）
- [ ] 下一张卡片未被意外评价（仍是正面，可见原文）
- [ ] 双击期间无报错、无白屏

## Test 6：「再来一轮」排除本轮卡片

### 测试背景
完成一轮 10 张后点击"再来一轮"，本轮刚评价的卡片不应立即出现。

### 测试目标
验证 `reviewedThisSession` Set 过滤生效。

### 测试链路
1. 回顾 Tab → 完成全部 10 张卡片的反馈 → 看到"回顾完成 ✓"
2. 点击 [再来一轮]

### 核心检测点
- [ ] 第二轮中不出现第一轮评价过的卡片
- [ ] 如果书签总数 ≤ 10，第二轮 session 为空或仅含未到期卡片 → 不报错
- [ ] 如果再打开新一次回顾（切换 Tab 再回来），已排期的卡片按 `nextReviewAt` 正常到期才出现

## Test 7：统计指标 — 正常状态

### 测试背景
回顾 Tab 顶部应展示三个统计卡片。

### 测试目标
验证统计数值与数据库一致。

### 测试链路
1. 准备已知状态的书签：数据库确认 N 张 `review_count=0`, M 张 `familiarity≥4`
2. 打开回顾 Tab

### 核心检测点
- [ ] 待复习 = N +（到期卡片数）
- [ ] 已掌握 = "M / 有复习记录的卡片数 · 百分比"
- [ ] 总收藏 = 全部 bookmark 数量
- [ ] 数值与 Supabase 查询结果一致

## Test 10：功能无退化

### 测试背景
回顾机制改动不应影响其他功能模块。

### 测试目标
验证书架、阅读、收藏、导入四个模块不受影响。

### 测试链路
1. 书架 Tab → 导入素材 → 编辑 → 移入阅读区
2. 阅读 Tab → 打开文章 → 划选收藏 → 标注阅读进度 → 标记读完
3. 导入 Tab → 导入新文章
4. 回到回顾 Tab → 确认新增收藏在统计中体现

### 核心检测点
- [ ] 书架：CRUD 正常
- [ ] 阅读：划选收藏弹窗正常、BookmarkPanel 正常、段落跳转正常
- [ ] 导入：导入流程正常
- [ ] 回顾：新收藏出现在指标和 session 中
