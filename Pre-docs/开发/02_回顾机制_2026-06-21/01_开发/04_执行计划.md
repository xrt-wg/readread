重写 `src/components/ReviewPanel.jsx`：

- 正面的 `[下一张]` 按钮 → 不再需要

**关键改动** — handleFeedback 实现：

```js
const handleFeedback = useCallback(async (feedback) => {
  try {
    const updated = computeNextReview(current, feedback)
    const saved = { ...current, ...updated }
    await saveBookmark(saved, { canUseCloudLibrary, userId })
  } catch (e) {
    if (isLibraryAccessError(e)) refreshAuthState()
    setLoadError(resolveLibraryErrorMessage(e, '保存复习进度失败，请稍后重试'))
  }
  // 无论保存成功与否，均推进
  if (index + 1 >= cards.length) setFinished(true)
  else { setIndex(i => i + 1); setFlipped(false) }
}, [current, index, cards.length, canUseCloudLibrary, refreshAuthState, userId])
```

## 十一、延期与回退策略

### 延期原则

- Phase 0 延期 → 阻塞全部后续阶段，优先解决
- Phase 1 延期 → Phase 2/3 可用 mock 组件做集成预研
- Phase 2 延期 → Phase 3 不受影响（独立组件）
- Phase 3 延期 → 不影响 ReviewPanel 的使用（用户通过回顾 Tab 访问）；ReviewModal 本身尚未启用
- Phase 4 延期 → 不影响功能（仅代码整洁度）

### 回退原则

**优先局部回退，不优先整体推翻。**

- Phase 0 出问题 → 修复单个函数，不推翻整体设计
- Phase 1 出问题 → 修复 ReviewCard 组件
- Phase 2 出问题 → ReviewPanel 回到旧版本（保留 git 历史），ReviewCard 不受影响
- Phase 3 出问题 → ReviewModal 回到旧版本
- Phase 4 出问题 → 不影响功能（仅清理）

### 最重要的回退底线

1. **现有回顾功能（随机翻阅）不被破坏**——若新调度逻辑有问题，应能快速切回旧 ReviewPanel
2. **书签数据不被破坏**——saveBookmark 仅更新三个字段，不修改 text/translation 等核心数据
3. **阅读、收藏、导入功能完全不变**——回顾机制改动隔离在回顾面板内

### 具体回退操作

```bash
# 回退 ReviewPanel
git checkout HEAD~1 -- src/components/ReviewPanel.jsx

# 回退 ReviewModal
git checkout HEAD~1 -- src/components/ReviewModal.jsx

# 移除新增文件
rm src/components/ReviewCard.jsx
rm src/utils/reviewUtils.js

# library.js 回退（移除 listDueBookmarks）
git checkout HEAD~1 -- src/services/library.js
```

所有改动都是文件级操作，无数据库 migration 需要回滚。
