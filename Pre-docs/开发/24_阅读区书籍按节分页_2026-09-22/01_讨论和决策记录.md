# 阅读区书籍按节分页 — 讨论和决策记录

> 日期：2026-09-22
> 关联：[02_实施方案](02_实施方案.md)

## 一、背景与需求

EPUB 书籍导入后，在阅读区的「分页粒度」由 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx) 的 `groupIntoChapters` 决定：它只认 `depth === 0`（目录顶层）作为翻页边界，把「一个 depth 0 节 + 其后所有更深节」合并成「一章 / 一页」。

由此产生两个体验问题：

1. **分页粒度随书漂移**：`depth 0` 到底对应「章」还是「部」，取决于这本书 EPUB 目录的顶层是什么。顶层是「第一部/第二部」时按「部」翻页、真正的章和节全挤在一页；顶层是「章」时才按章翻页。目录顶层语义不由系统控制，导致同类书籍的分页体验不一致。
2. **节 / 小节不分页**：depth 1 的「节」、depth 2 的「小节」永远被并进父节所在的页，同一页内靠 h2/h3/h4 字号区分层级，翻页单位太粗。

同时，书架编辑器的左侧目录是**平铺呈现**的（[SectionContentEditor.jsx](../../../src/components/SectionContentEditor.jsx) 直接 `editing.map` 渲染，未用 `depth`），层级关系看不出来。

经多轮澄清，需求收敛为两点：

1. **书架编辑器目录**：按 `depth` 缩进呈现层级（最小改动方案）；
2. **阅读区分页粒度**：不再用「章 / 部」这类语义标签决定分页，改为按「该书的最深层级」——即**目录树里的叶子节（每一个有实际正文、不再包含子节的最小单元）独立成一页**。

## 二、现状调查结论

### 2.1 阅读区分页机制

- `groupIntoChapters`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L44-L56)）：按 `depth === 0` 切章，一章 = 一个顶层节 + 其后所有 `depth > 0` 的节。
- `paginated = isBook && chapters.length > 1`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L100-L101)）：仅「书籍且多章」才逐章分页。
- 翻页状态 `currentChapterIdx`，一页渲染 `currentChapter.all`（当前章的全部节，[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L105-L108)）。
- 连带逻辑：`chapterIdxOfSection`（节 → 章定位）、`calcBookProgressAtMark`（按章 wordCount 加权进度）、`handleJump` / `handleJumpToReadingMark` / 阅读标记恢复（切章 + `pendingScrollRef` 延迟滚动）、目录面板 `SectionTocPanel` 的点击跳转与高亮。

### 2.2 目录呈现的两处不一致

| 位置 | 实现 | 是否按层级 |
|---|---|---|
| 阅读区目录侧栏 | [SectionTocPanel.jsx](../../../src/components/SectionTocPanel.jsx#L6-L22) 的 `buildTocTree` 用栈算法重建树、按 depth 缩进 | ✅ 有层级 |
| 书架编辑器左侧目录 | [SectionContentEditor.jsx](../../../src/components/SectionContentEditor.jsx#L229-L245) 直接 `editing.map` 平铺 | ❌ 平铺 |

数据层面 `sections` 里每节都带 `depth` / `parentId`，层级信息充足，编辑器平铺纯属「呈现层未用 depth」，非数据缺失。

### 2.3 关键结论（技术判断依据）

1. **分页单位可取「有正文的 section」**：EPUB 目录经 `flattenTocTree` 平铺后，`sections` 数组已是深度优先顺序（父在前、子在后）。每一节要么是「有正文的内容单元」，要么是「无正文的纯容器节（如『第一部』）」。用 `hasContent`（text-or-markdown 双保险，见 §五风险2）区分。
2. **B1 天然满足**：因为 sections 保序，`filter(有正文)` 后父正文自动排在它的子节之前——「中间节点父正文独立成页、排在首个子节前」无需额外排序逻辑。
3. **容器节无正文 → 阅读标记/进度不可能落在其上**，把容器节从正文页剔除是安全的。
4. **纯前端改动，无数据迁移**：分页是渲染层概念，不动 `readings.sections` 存储结构、不动数据库。

## 三、决策记录

### D1 书架编辑器目录 → 按 depth 缩进（已实施）

- 备选：保持平铺；树形 + 折叠。
- **决策：保持平铺列表，按 `depth` 加左侧缩进，最深 clamp 到 2 级。** 理由：改动最小、风险低，立即看出父子；clamp 到 2 与阅读区标题「`depth≥2` 都当 h4」的约定对齐，避免 EPUB 深层目录把 200px 侧栏挤爆。
- **状态：已实施**（[SectionContentEditor.jsx](../../../src/components/SectionContentEditor.jsx) 目录按钮 `paddingLeft: ${16 + Math.min(depth, 2) * 16}px`）。对 markdown 文章的多级标题同样生效，是统一收益。

### D2 阅读区分页粒度 → 从「章（depth 0）」改为「有正文节」

- 备选：维持按章分页；按「全局最大 depth 的那一层」分页。
- **决策：分页单位 = 每一个「有正文的 section」独立成一页（即叶子节，含父正文）**。理由：① 分页粒度不再绑定目录顶层的章/部语义，全书统一；② 更贴近 EPUB 阅读器行业通行做法（按 spine 内容单元分页，spine 单元 ≈ 有正文的 TOC 叶子节）；③ 字面「全局最大 depth」有歧义——若全书最深 depth 2，但某条「第一章」（depth 1）无子节、自己就是叶子，无法归类，故落地为「叶子节」。
- **代价（已接受）**：翻页次数变多，章/部的聚合感消失。

### D3 纯容器节（无正文，如「第一部」）→ A2

- 备选：A1（作为下一页顶部的层级标题）；A2（只在目录侧栏显示，正文页不出现）。
- **决策：A2**。理由：容器节无正文、不独立成页；只在目录侧栏保留层级定位，正文页干净。
- **适用范围（实施前审核 P1 定稿）**：A2 为全场景不变式——分页态剔除容器节之外，**非分页（有正文节数 ≤ 1）书籍连续流同样过滤容器节**（正文流 = 有正文节序列），杜绝「删到只剩一节时容器标题又冒出」的内容数漂移。为此接受对现状单章书的一次性行为纠正：单章书若含空容器标题，改后不再显示。

### D4 中间节点父正文（有正文 + 有子节，如「第三章」有章引言 + 3.1）→ B1

- 备选：B1（父正文独立成页，排在首个子节前）；B2（父正文合并进首个子节）。
- **决策：B1**。理由：规则最统一、可预期。**实现上由「有正文节保序 filter」自动满足，无额外代码。**

### D5 目录点击容器节 → 跳到其后第一个有正文节

- **决策：目录侧栏点击任意条目，跳到「以该节为起点、向后第一个有正文的 section（含自身）」**。理由：容器节无正文、不成页，点击它跳向它的第一个有正文后代，保证目录里每一项都能点、都有落点。正常数据下「其后第一个有正文节」即它的第一个后代。

## 四、最终方案要点

| 维度 | 决策 |
|---|---|
| 编辑器目录 | 按 depth 缩进，clamp 到 2（D1，已实施） |
| 分页单位 | 「有正文节」（按 `hasContent`），每节一页 |
| 分页序列 | sections 按 order 过滤出「有正文节」子序列，保序 |
| 翻页 | 上一节 / 下一节，`paginated = isBook && 有正文节数 > 1` |
| 容器节 | 不出现在正文页（含非分页单有正文节书），只进目录侧栏（A2，全场景统一） |
| 父正文 | 独立成页、排首个子节前（B1，filter 保序自动满足） |
| 目录点击 | 跳到该节起向后第一个有正文节（D5） |
| 进度 | 按「有正文节」wordCount 加权（替代按章加权） |
| 迁移 | 无（纯前端渲染层改动） |

## 五、风险与注意点

1. **翻页变碎**：一本书几十上百节时翻页次数明显增多；这是「一致性」换「粒度」，已接受。
2. **「有正文」判定（唯一规则）**：`hasContent(s) = (s.body.text || '').trim() 非空 || (s.body.markdown || '').trim() 非空`。EPUB 回填时 text 由 markdown 剥离而来，纯图片节（text 被剥空、markdown 非空）不能被误判为容器节，故必须双保险；方案各处 `filter(有正文)` 一律使用此判定。
3. **索引单位全面切换**：`chapterIdxOfSection` 及所有调用点（进度、跳转、位置恢复、目录高亮）的定位单位从「章」换成「有正文节序列」，遗漏任何一处会导致跳转/进度错位，实施时须全量排查 `currentChapterIdx` / `chapters` 引用。
4. **目录点击容器节的简化**：正常数据下「其后第一个有正文节」即容器节第一个后代；若遇「容器节无后代」的异常数据，会跳到下一个无关节，属数据异常、可接受。
5. **颜色/阴影规范**：本次为纯逻辑 + 文案改动，不新增颜色；若后续调整翻页 UI 样式，须走 `var(--*)`（CLAUDE.md 颜色规范）。
