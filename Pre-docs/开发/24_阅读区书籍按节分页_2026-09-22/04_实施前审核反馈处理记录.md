## 二、逐条处理记录

### P1 — A2 容器节在非分页路径未收口（唯一需决策项）

- **反馈**：`flowSections = paginated ? [currentSection] : effectiveSections`，当 `contentSequence.length <= 1` 时非分页流含容器节，`SectionFlow` 仍渲染容器 `heading`，与验收 #2 冲突。审核给出二选一：(a) 收敛措辞；(b) 非分页书流也过滤容器节。
- **独立核验**：属实。`SectionFlow.jsx` L234-236 对 `section.heading` 无正文节照常渲染；现状单章书（`chapters.length === 1`）同样有此行为（非回归，但属缺陷）。
- **处理**：**采纳 (b) 统一语义**。理由：选项 (a) 会留下「同一本书删到只剩一节时容器标题又冒出」的内容数漂移，恰是本次要消灭的「分页语义随内容漂移」老毛病；(b) 让 A2 成为全场景不变式，且对现状单章书仅是「去掉空容器标题」的纠正。落地公式：
  ```js
  const currentSection = paginated ? (contentSequence[currentSectionIdx] ?? contentSequence[0]) : null
  const flowSections = isBook ? (paginated ? [currentSection] : contentSequence) : effectiveSections
  ```
- **落点**：01 D3 增补「适用范围」段、01 §四「容器节」行、02 §3.1、02 §五 #2、02 §六新增「P1(b) 行为变化」风险。

### P2 — `currentSection` 遗漏兜底

- **反馈**：现有 `currentChapter = paginated ? (chapters[currentChapterIdx] ?? chapters[0]) : null`；方案示意无兜底，数据刷新窗口内索引越界会致 `currentSection` 为 `undefined` 崩溃。
- **独立核验**：属实，ReaderPage L106 确有 `?? chapters[0]` 与 `: null` 两段语义。
- **处理**：`currentSection = paginated ? (contentSequence[currentSectionIdx] ?? contentSequence[0]) : null`，与现有语义对齐。
- **落点**：02 §3.1。

### P3 — 「有正文」判定表述不一致

- **反馈**：§二/§3.1 只写 text-only，风险节写 text-or-markdown，存在二义；纯图片节（`text` 被剥空、`markdown` 非空）会被 text-only 误判为容器节剔除。
- **独立核验**：属实，纯图片节属真实可能（EPUB 图片章）。取双保险更正确、成本为零。
- **处理**：固化 `hasContent(s) = (s.body?.text || '').trim().length > 0 || (s.body?.markdown || '').trim().length > 0` 为唯一判定，§二/§3.1/§3.4/§六 与 01 §五风险2 全部统一。
- **落点**：01 §五风险2、02 §二、02 §3.1、02 §六。

### P4 — L949 结尾「全文完」条件未显式列入

- **反馈**：L949 `(!paginated || currentChapterIdx === chapters.length - 1)` 是唯一未被 §3.2 枚举的 `chapters.length` 引用点。
- **独立核验**：属实，已定位 L949。
- **处理**：§3.2 显式补列，改为 `contentSequence.length - 1`。
- **落点**：02 §3.2。

### P5 — 行号 ±1 偏差

- **反馈**：02 §3.7 `#L229-L246` → L245；02 §3.3 `L545-L562` → L561。
- **独立核验**：属实；另发现 01 §2.2 `#L229-L242` 同源偏差一并修正为 `#L229-L245`。
- **处理**：行号修正（仅导航用，不阻塞实施）。
- **落点**：01 §2.2、02 §3.3、02 §3.7。

## 三、变更后的关键要点

2. **唯一「有正文」判定**：`hasContent` = text-or-markdown 双保险（P3）。
3. **兜底保留**：`currentSection` 带 `?? contentSequence[0]`（P2）。
4. **改动面补齐**：L949 结尾条件显式列入（P4）。

### 5.2 逻辑一致性复核（P1(b) + P2 的连带影响）

- **P1(b) 公式** `flowSections = isBook ? (paginated ? [currentSection] : contentSequence) : effectiveSections` 与源码核对无冲突：书籍全状态过滤容器节，文章（无容器节语义）保持全量连续流，`sectionScoped = effectiveSections.length > 1` 不受影响（书签/标记仍按 section.id 关联）。
- **`currentSection = ... : null`（非分页态为 null）** 不产生副作用：目录高亮 `currentSection?.order` 仅当 `paginated`（目录面板此时才渲染）才被使用；`calcBookProgressAtMark` 仅当 `paginated` 才被调用，非分页态 `currentSectionIdx` 不被读取。
- 结论：P1(b) 与 P2 的组合在源码语境下自洽，无新逻辑缺陷。

### 5.3 复核发现（残留项）

1. ⚠️ **P3 未完全收口**——`hasContent`（text-or-markdown 双保险）已固化为主判定，但仍有 2 处保留旧的「body.text 非空」表述，与「全篇一致」的结论不符：
   - 01 §四「分页单位」行：`「有正文节」（body.text 非空），每节一页`
   - 02 §一目标 #2：`每一个 body.text 非空的 section 独立成一页`
   - （次）01 §2.3.1「用 `body.text` 是否非空即可区分」属现状调查语境，纯图片节下不成立，建议加「纯图片节除外，见 §五风险2」或直接指向唯一判定。
   
   建议：将上述「body.text 非空」统一改为「有正文节（按 `hasContent`）」或引用 02 §二/§五 的唯一判定，使「全篇一致」名副其实。

2. 💡 **02 §3.6 的 SectionFlow `key` 三元未完整表述**——原文 `key={paginated ? currentChapter?.lead?.id : 'flow'}`，方案写作「key 改为 `currentSection?.id`」，未明示保留 `: 'flow'` 分支。建议补全为 `key={paginated ? currentSection?.id : 'flow'}`，避免实施时误删三元、非分页态 key 退化为 `undefined`（单子元素下虽可容忍，但与现有 `'flow'` 稳定键语义有偏差）。
