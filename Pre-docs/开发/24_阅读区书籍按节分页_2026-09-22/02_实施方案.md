# 阅读区书籍按节分页 — 实施方案

> 日期：2026-09-22
> 前置：[01_讨论和决策记录](01_讨论和决策记录.md)

## 一、目标

1. 书架编辑器左侧目录按 `depth` 缩进（D1，**已实施**，本文档 §3.4 回顾）；
2. 阅读区书籍分页粒度从「章（depth 0 + 子树合并）」改为「有正文节」——**每一个有正文（按 `hasContent`）的 section 独立成一页**；
3. 纯容器节（无正文，如「第一部」）不出现在正文页、只进目录侧栏（A2）；
4. 中间节点父正文独立成页、排在首个子节前（B1，由保序 filter 自动满足）；
5. 目录点击任意条目跳到「该节起向后第一个有正文节」（D5）。

**性质：纯前端渲染层改动，无数据库迁移。**

## 二、模型说明

无新表、无新字段。核心是一个新概念「分页序列」：

```
分页序列 = sections.filter(hasContent)   // 按 order 保序
hasContent(s) = (s.body?.text || '').trim() 非空  ||  (s.body?.markdown || '').trim() 非空
```

- sections 数组本就是深度优先顺序（父在前、子在后），`filter` 保序后**父正文天然排在子节前**，B1 自动满足，无需排序。
- 容器节被 filter 剔除 → 不进正文页（A2），但仍保留在 `effectiveSections` 里供目录侧栏 `buildTocTree` 展示层级。
- 纯图片节（`text` 被剥空、`markdown` 非空）应视为有正文，故 `hasContent` 取 text-or-markdown 双保险，作为本方案全篇唯一判定。

示例（沿用讨论用书）：

```
sections（order 序）          分页序列（每项一页）
序(d0, 有正文)        ──►  页1：序
第一部(d0, 空)         ✗ 跳过（A2）
第一章(d1, 有正文)    ──►  页2：第一章
第二章(d1, 有正文)    ──►  页3：第二章
第二部(d0, 空)         ✗ 跳过（A2）
第三章(d1, 有正文)    ──►  页4：第三章父正文（B1）
3.1(d2, 有正文)       ──►  页5：3.1 在车站
```

## 三、分层实施

改动集中在 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx)，辅以 [ReaderHeader.jsx](../../../src/components/ReaderHeader.jsx) 文案、[SectionTocPanel.jsx](../../../src/components/SectionTocPanel.jsx) 高亮与点击。

### 3.1 分页序列构建（替代 `groupIntoChapters`）

新增「有正文节序列」派生值，替换现有 `chapters` 的核心用途：

```js
// 示意：唯一「有正文」判定（text-or-markdown 双保险，纯图片节不被误判为容器）
const hasContent = (s) =>
  (s.body?.text || '').trim().length > 0 || (s.body?.markdown || '').trim().length > 0

// 替代 groupIntoChapters 作为分页单位
const contentSequence = useMemo(
  () => effectiveSections.filter(hasContent),
  [effectiveSections]
)
```

- `isBook = kind === 'book'`（不变）。
- `paginated = isBook && contentSequence.length > 1`（由「章数 > 1」改为「有正文节数 > 1」）。
- `currentSectionIdx` 取代 `currentChapterIdx`；`currentSection = paginated ? (contentSequence[currentSectionIdx] ?? contentSequence[0]) : null`（保留现有 `?? chapters[0]` 兜底，防御数据刷新窗口内索引越界）。
- `flowSections = isBook ? (contentSequence.length > 0 ? (paginated ? [currentSection] : contentSequence) : effectiveSections) : effectiveSections`——书籍无论是否分页都过滤容器节（A2 全场景统一，采纳实施前审核 P1(b)），文章（无容器节）保持全量连续流；`contentSequence.length === 0`（全书无正文的病态数据）回退 `effectiveSections`，避免正文区空渲染。

### 3.2 翻页状态与 UI 文案

- 状态 `currentChapterIdx` → `currentSectionIdx`（0 起，界于 `[0, contentSequence.length - 1]`）。
- 底部章节导航（现 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L923-L946)）：`上一章/下一章` → `上一节/下一节`；页码 `x / y` 用 `currentSectionIdx + 1 / contentSequence.length`；边界 disabled 逻辑不变。
- [ReaderHeader.jsx](../../../src/components/ReaderHeader.jsx)：仅两处消费——L6 prop 声明 `currentChapterIdx`/`chapters` 重命名为 `currentSectionIdx`/`contentSequence`，L52 `目录 · {currentChapterIdx + 1}/{chapters.length}` 改为 `{currentSectionIdx + 1}/{contentSequence.length}`（节序号/节总数）。
- **结尾「全文完」条件**（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L949)）：`(!paginated || currentChapterIdx === chapters.length - 1)` 的 `chapters.length - 1` 改为 `contentSequence.length - 1`（实施前审核 P4 显式补列，防逐项替换漏改）。

### 3.3 节定位（替代 `chapterIdxOfSection`）

```js
// 示意：替代 chapterIdxOfSection —— 定位 section 在分页序列中的索引
const sectionIndexInSequence = useCallback((sectionId) => {
  return contentSequence.findIndex((s) => s.id === sectionId)
}, [contentSequence])
```

调用点全面替换：

| 现有 | 改为 |
|---|---|
| `chapterIdxOfSection(sectionId)`（跳转/恢复 3 处 + 目录 1 处） | `sectionIndexInSequence(sectionId)` |
| `setCurrentChapterIdx(chIdx)` | `setCurrentSectionIdx(idx)` |
| `pendingScrollRef.targetIdx = chIdx` | `targetIdx = idx` |
| `useEffect(() => { if (paginated) window.scrollTo({top:0}) }, [currentChapterIdx, paginated])` | 依赖改 `currentSectionIdx` |

- `handleJump`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L445-L462)）、`handleJumpToReadingMark`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L545-L561)）、阅读标记恢复 useEffect（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L744-L774)）三处的「切章 + `pendingScrollRef` 延迟滚动」结构**不变**，仅索引单位从章换节。
- 注意：`sectionIndexInSequence` 返回 `-1` 表示该 section 无正文（容器节）。容器节无段落、阅读标记不可能落在其上，正常流程不会走到 `-1` 分支；若出现，按「不跳转」兜底即可。

### 3.4 进度计算（按节加权，替代按章加权）

`calcBookProgressAtMark`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L479-L486)）改为按 `contentSequence` 加权：

```js
// 示意：book 分页进度 = 已翻过节的全词数 + 当前节 scroll% × 当前节词数
function calcBookProgressAtMark(scrollPercent) {
  const totalWords = contentSequence.reduce((sum, s) => sum + (s.body?.wordCount ?? 0), 0)
  if (totalWords === 0) return scrollPercent
  let cumulative = 0
  for (let i = 0; i < currentSectionIdx; i++) cumulative += contentSequence[i].body?.wordCount ?? 0
  cumulative += (contentSequence[currentSectionIdx]?.body?.wordCount ?? 0) * (scrollPercent / 100)
  return Math.round((cumulative / totalWords) * 100)
}
```

`handleSetReadingMark`（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L488-L523)）中 `paginated ? calcBookProgressAtMark(scrollPercent) : scrollPercent` 分支不变，依赖数组 `chapters, currentChapterIdx` 换 `contentSequence, currentSectionIdx`。

### 3.5 目录侧栏（SectionTocPanel）高亮与点击

- **高亮**：`currentIdx` 由 `currentChapter?.lead?.order` 改为 `currentSection?.order`（精确高亮当前节，而非当前章 lead）。
- **点击跳转**（[ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L1093-L1116) 的 `onSelect`）：

```js
// 示意：点目录条目 → 跳到「该节起向后第一个有正文节」（含自身，D5）
// order 严格递增且数组按 order 有序，故 find(s.order >= sec.order) 天然覆盖两种情形：
//   sec 有正文 → 命中自身（order 相等）
//   sec 是容器节 → 命中其后第一个有正文后代（order 更大）
const target = contentSequence.find((s) => s.order >= sec.order)
if (!target) return
const targetIdx = contentSequence.indexOf(target)
const scrollToSec = () =>
  document.querySelector(`[data-section-id="${target.id}"]`)?.scrollIntoView({ behavior: 'smooth', block: 'start' })
if (targetIdx !== currentSectionIdx) {
  setCurrentSectionIdx(targetIdx)
  setTimeout(scrollToSec, 200)
} else {
  scrollToSec()
}
```

- [SectionTocPanel.jsx](../../../src/components/SectionTocPanel.jsx) 本身**无需改动**：它仍基于 `effectiveSections` 全量建树、渲染全部节（含容器节，满足 A2「容器只进目录」），点击与高亮逻辑全在 ReaderPage 侧。

### 3.6 SectionFlow 渲染（key 与单节）

- [ReaderPage.jsx](../../../src/components/ReaderPage.jsx#L911-L920)：`<SectionFlow key={...} sections={flowSections} ... />` 的 key 由 `currentChapter?.lead?.id` 改为 `currentSection?.id`，保留三元 `key={paginated ? currentSection?.id : 'flow'}`（分页态用 `currentSection.id`，非分页态仍用稳定键 `'flow'`）。
- `sectionScoped = effectiveSections.length > 1`（不变）：书签/阅读标记仍按 `section.id` 关联，与单节渲染无关。

### 3.7 书架编辑器目录缩进（D1，已完成，回顾）

[SectionContentEditor.jsx](../../../src/components/SectionContentEditor.jsx#L229-L245) 目录按钮已加 `paddingLeft: ${16 + Math.min(s.depth ?? 0, 2) * 16}px`，选中金边仍贴最左。本次方案不重复改动，仅在此记录为已完成项。

## 五、验收标准

1. **分页单位**：多节书籍按「有正文节」逐节分页；`上一节/下一节` 顺序正确、边界禁用正确；页码 = 节序号 / 有正文节总数。
2. **容器节剔除（全场景）**：「第一部」这类无正文节不出现在正文页（**含非分页单有正文节书**），但出现在目录侧栏；点击容器节跳向其第一个有正文后代。
3. **父正文独立页**：中间节点父正文（如「第三章」章引言）单独成页，且排在其首个子节（3.1）之前。
4. **单节书**：有正文节数 = 1 时 `paginated=false`，连续流、不出现翻页与目录侧栏（与现状单章书行为一致）。
5. **进度/跳转/恢复**：进度条按节加权；「跳到阅读标记」「跳转段落」「目录点击」均定位到正确节并正确滚动。
6. **目录高亮**：侧栏高亮当前节（精确到节，非章 lead）。
7. **编辑器目录**：D1 缩进已生效（无回归）。
8. **无硬编码颜色**：若调整翻页 UI 样式，全部走 `var(--*)`。

## 六、风险与回滚

- **索引单位遗漏**：`currentChapterIdx` / `chapters` 相关引用若漏改，会导致跳转/进度错位。实施后须逐条验收 §五 1/5 项。
- **翻页变碎**：节数多的书翻页次数增加，属已接受的产品决策，非缺陷。
- **目录点击容器节的简化**：依赖「其后第一个有正文节 = 其第一个后代」，异常数据（容器无后代）会跳到下一个无关节，可接受。
- **「有正文」唯一判定**：`hasContent(s) = (text || '').trim() || (markdown || '').trim()`（text-or-markdown 双保险），全篇一致。
- **P1(b) 行为变化**：非分页单章书若含空容器标题（如「第一部」），改后不再显示该标题，属纠正而非回归；如在意，可回退为审核选项 (a)（仅收敛措辞、保留容器标题）。
- **空正文书边界**：`contentSequence.length === 0`（全书无正文的病态数据）时回退 `effectiveSections` 渲染容器标题，避免空页；正常数据不触发。
- **回滚**：纯前端改动，回退 [ReaderPage.jsx](../../../src/components/ReaderPage.jsx) / [ReaderHeader.jsx](../../../src/components/ReaderHeader.jsx) 即可，无数据/迁移副作用；D1 编辑器缩进独立于本方案，单独可回退。
