## 四、审核重点（请审核者优先复核，按风险排序）

1. **累计用户窗口求和物化（P0）**：`v_baseline + sum(new_users) over (order by bucket)` 必须先物化到 `cum` CTE 再 `jsonb_agg`——窗口函数不能出现在聚合函数参数内，否则首次调用即报 `aggregate function calls cannot contain window function calls`。重点确认最终 `select jsonb_agg(...) from cum` 而非 `from joined`，且 `cumulative_users` 列直接取自 `cum`、未再套窗口函数。
2. **权限门与 revoke 作用域**：函数首行 `IF NOT public.is_current_user_admin() THEN RAISE EXCEPTION ... USING ERRCODE = '42501'`；新函数默认授 PUBLIC，必须 `REVOKE ALL ... FROM public, anon, authenticated` 后仅 `GRANT ... TO authenticated`（此函数为全新函数，非 `create or replace`，无既有 grant 可保留）。
3. **产出口径（P1-2 + P2-5）**：`activity` / `reading_started` / `reading_finished` / `new_readings` 四个 CTE **均不得**含 `deleted_at is null`；`bookmarks` 不得过滤 `status`。这是「可回溯全部历史」立论的一致性根因——漏掉任意一处都会让历史曲线被后续删除/归档追溯性擦除。
4. **时区（P1-1，经 05 P2-1 细化）**：函数级 `SET timezone = 'Asia/Shanghai'`（与 `SET search_path = public` 并列，进入函数生效、退出恢复，不依赖事务上下文）；`today_new_users` 与 `v_axis_*` 的 `date_trunc` 均依赖该时区，缺了则「今日新增」按 UTC 翻页、与管理员本地错位。
5. **cohort 窗口与留存语义（P2-2 + P2-3）**：留存区两处下界均为 `make_interval(days => h.d + 7)`（7 天窗口、非 6 天）；判定 `a.created_at < p.created_at + make_interval(days => h.d)` 是「N 日内累计仍有产出」而非「第 N 天当日」，UI 文案「累计留存」。
6. **前端措辞与复用（P2-4 + P2-6）**：顶部卡「DAU（打开应用）」与图表「活跃用户（有产出 · 近似）」口径不同、措辞显式区分；`StatCard` 抽为 `AdminStatCard.jsx`（AdminPage 与 GrowthStatsPanel 共用，无视觉漂移）；错误处理统一走 `errorUtils.isLibraryAccessError` + `resolveLibraryErrorMessage`，**不**跨文件复用 AdminPage 私有的 `resolveAdminErrorMessage`。
7. **次要一致性（P3-1/P3-2/P3-3）**：计数变量 `bigint`（对齐 `count(*)` 返回类型）；迁移关键字大小写（`CREATE OR REPLACE`/`REVOKE`/`GRANT` 大写，事务起止 `begin`/`commit`/`notify` 小写，对齐既有迁移）；§3.1 关键点已注明「周/月粒度首桶可能含窗口外前置天数」。
