# 后台数据统计（用户增长与使用） — 实施方案

> 日期：2026-09-22
> 前置：[01_讨论和决策记录](01_讨论和决策记录.md)

## 一、目标

在后台新增「数据统计」独立子页，让管理员能看用户增长与使用情况：

1. 顶部 5 张快照卡：用户总量 / 今日新增 / DAU / WAU / MAU；
2. 4 张时间趋势图（可切日/周/月）：新增注册 / 累计用户 / 活跃用户（近似）/ 阅读活跃（开始读 · 读完 · 新增阅读）；
3. 留存区：d1 / d7 / d30 三个数（产出近似口径，与粒度无关）；
4. 聚合经 `SECURITY DEFINER` RPC 一次返回（快照 + 序列 + 留存），前端自绘 SVG 图表，颜色走 `var(--*)`。

## 二、数据模型

**无新表**，仅新增一个 RPC。依赖的既有字段：

| 字段 | 用途 |
|---|---|
| `profiles.created_at` | 新增注册 / 今日新增 / 累计用户 |
| `profiles.last_seen_at` | DAU / WAU / MAU 快照 |
| `readings.created_at` / `reading_started_at` / `reading_finished_at` | 新增阅读 / 开始读 / 读完 |
| `readings.created_at` + `bookmarks.created_at`（去重 user_id） | 活跃（近似）与留存（近似） |

- 活跃口径（D2）：某窗「有产出行为」= 当天 `readings` 或 `bookmarks` 新增的去重 `user_id`。**产出=发生过即计入**：只认不可变 `created_at`，不因后续删除（`deleted_at`）或归档（`status='archived'`）排除。
- 留存口径（D3）：`dN`（N 日内累计留存）= 注册时间落在 `[now-(N+7)天, now-N天)` 的用户中，注册后 N 天内仍有产出的比例。
- 时区口径：RPC 函数级 `SET timezone = 'Asia/Shanghai'`（进入函数生效、退出恢复），使「今日/本周/本月」对齐管理员本地日历。

## 三、分层实施

### 3.1 数据层（迁移脚本）

新建 `supabase/migrations/20260922000001_admin_growth_stats.sql`：

> **执行顺序（H1）**：经 Dashboard SQL Editor 手工执行、与前端发布不同步。必须**先执行迁移、确认 `admin_get_growth_stats` 可调用，再发布前端**。

```sql
-- ============================================================================
-- Migration: 后台数据统计（用户增长与使用）
-- 日期: 2026-09-22
-- 说明: 新增 admin_get_growth_stats RPC，为后台「数据统计」页提供：
--         - snapshot: 用户总量 / 今日新增 / DAU / WAU / MAU
--         - series:   新增注册 / 累计用户 / 活跃用户(近似) / 阅读活跃三线，按日/周/月
--         - retention: d1 / d7 / d30（产出近似 + 滚动 cohort）
--       活跃与留存采用「有产出行为（新增阅读或收藏）」近似口径，
--       因 profiles.last_seen_at 为覆盖式时间戳、无法回溯历史；
--       「有产出」按「是否发生过」计：不因后续删除（deleted_at）或归档（status='archived'）排除。
--       聚合走 SECURITY DEFINER（readings/bookmarks 无 admin select 策略）。
--       时区：函数级 SET timezone = 'Asia/Shanghai'（进入函数生效、退出恢复），使今日/本周/本月对齐管理员本地日历。
-- 执行方式: Dashboard SQL Editor 手动执行（无本地 CLI）
-- ============================================================================

begin;

CREATE OR REPLACE FUNCTION public.admin_get_growth_stats(
  p_granularity text DEFAULT 'day',
  p_window_days int DEFAULT 90
)
RETURNS jsonb
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
SET timezone = 'Asia/Shanghai'
AS $$
DECLARE
  v_granularity text := p_granularity;
  v_interval interval;
  v_axis_start timestamptz;
  v_axis_end timestamptz;
  v_baseline bigint;
  v_total_users bigint;
  v_today_new bigint;
  v_dau bigint;
  v_wau bigint;
  v_mau bigint;
  v_series jsonb;
  v_retention jsonb;
BEGIN
  IF NOT public.is_current_user_admin() THEN
    RAISE EXCEPTION '无管理员权限' USING ERRCODE = '42501';
  END IF;

  IF v_granularity NOT IN ('day', 'week', 'month') THEN
    RAISE EXCEPTION 'granularity 须为 day/week/month';
  END IF;

  v_interval := CASE v_granularity
    WHEN 'day' THEN INTERVAL '1 day'
    WHEN 'week' THEN INTERVAL '1 week'
    WHEN 'month' THEN INTERVAL '1 month'
  END;

  v_axis_end := date_trunc(v_granularity, now());
  v_axis_start := date_trunc(v_granularity, now() - make_interval(days => greatest(p_window_days - 1, 1)));

  -- ── 快照 ──────────────────────────────────────────────
  SELECT count(*) INTO v_total_users FROM public.profiles;

  SELECT count(*) INTO v_today_new
  FROM public.profiles
  WHERE created_at >= date_trunc('day', now());

  SELECT count(*) INTO v_dau
  FROM public.profiles
  WHERE last_seen_at >= now() - INTERVAL '1 day';

  SELECT count(*) INTO v_wau
  FROM public.profiles
  WHERE last_seen_at >= now() - INTERVAL '7 days';

  SELECT count(*) INTO v_mau
  FROM public.profiles
  WHERE last_seen_at >= now() - INTERVAL '30 days';

  -- ── 序列（时间轴 + 各桶聚合 + 累计）────────────────────
  -- 累计用户 = 窗口前的存量 + 窗口内逐桶累加
  SELECT count(*) INTO v_baseline
  FROM public.profiles
  WHERE created_at < v_axis_start;

  WITH axis AS (
    SELECT generate_series(v_axis_start, v_axis_end, v_interval)::date AS bucket
  ),
  new_users AS (
    SELECT date_trunc(v_granularity, created_at)::date AS bucket, count(*) AS n
    FROM public.profiles
    WHERE created_at >= v_axis_start
    GROUP BY 1
  ),
  activity AS (
    SELECT user_id, created_at FROM public.readings
    UNION ALL
    SELECT user_id, created_at FROM public.bookmarks
  ),
  active_users AS (
    SELECT date_trunc(v_granularity, created_at)::date AS bucket, count(DISTINCT user_id) AS n
    FROM activity
    WHERE created_at >= v_axis_start
    GROUP BY 1
  ),
  reading_started AS (
    SELECT date_trunc(v_granularity, reading_started_at)::date AS bucket, count(*) AS n
    FROM public.readings
    WHERE reading_started_at IS NOT NULL AND reading_started_at >= v_axis_start
    GROUP BY 1
  ),
  reading_finished AS (
    SELECT date_trunc(v_granularity, reading_finished_at)::date AS bucket, count(*) AS n
    FROM public.readings
    WHERE reading_finished_at IS NOT NULL AND reading_finished_at >= v_axis_start
    GROUP BY 1
  ),
  new_readings AS (
    SELECT date_trunc(v_granularity, created_at)::date AS bucket, count(*) AS n
    FROM public.readings
    WHERE created_at >= v_axis_start
    GROUP BY 1
  ),
  joined AS (
    SELECT
      a.bucket,
      coalesce(nu.n, 0) AS new_users,
      coalesce(au.n, 0) AS active_users,
      coalesce(rs.n, 0) AS reading_started,
      coalesce(rf.n, 0) AS reading_finished,
      coalesce(nr.n, 0) AS new_readings
    FROM axis a
    LEFT JOIN new_users nu ON nu.bucket = a.bucket
    LEFT JOIN active_users au ON au.bucket = a.bucket
    LEFT JOIN reading_started rs ON rs.bucket = a.bucket
    LEFT JOIN reading_finished rf ON rf.bucket = a.bucket
    LEFT JOIN new_readings nr ON nr.bucket = a.bucket
  ),
  cum AS (
    SELECT j.*,
           v_baseline + sum(j.new_users) OVER (ORDER BY j.bucket) AS cumulative_users
    FROM joined j
  )
  SELECT jsonb_agg(
    jsonb_build_object(
      'bucket', bucket,
      'new_users', new_users,
      'cumulative_users', cumulative_users,
      'active_users', active_users,
      'reading_started', reading_started,
      'reading_finished', reading_finished,
      'new_readings', new_readings
    ) ORDER BY bucket
  )
  INTO v_series
  FROM cum;

  -- ── 留存（d1/d7/d30，产出近似 + 滚动 cohort）───────────
  WITH horizons(d) AS (VALUES (1), (7), (30)),
  activity AS (
    SELECT user_id, created_at FROM public.readings
    UNION ALL
    SELECT user_id, created_at FROM public.bookmarks
  ),
  rows AS (
    SELECT
      h.d,
      (SELECT count(*) FROM public.profiles p
        WHERE p.created_at >= now() - make_interval(days => h.d + 7)
          AND p.created_at <  now() - make_interval(days => h.d)) AS cohort_size,
      (SELECT count(DISTINCT p.user_id)
        FROM public.profiles p
        JOIN activity a ON a.user_id = p.user_id
        WHERE p.created_at >= now() - make_interval(days => h.d + 7)
          AND p.created_at <  now() - make_interval(days => h.d)
          AND a.created_at >= p.created_at
          AND a.created_at <  p.created_at + make_interval(days => h.d)) AS retained
    FROM horizons h
  )
  SELECT jsonb_object_agg(
    'd' || d::text,
    CASE WHEN cohort_size = 0 THEN 0
         ELSE round(100.0 * retained / cohort_size, 1) END
  )
  INTO v_retention
  FROM rows;

  RETURN jsonb_build_object(
    'snapshot', jsonb_build_object(
      'total_users', v_total_users,
      'today_new_users', v_today_new,
      'dau', v_dau,
      'wau', v_wau,
      'mau', v_mau
    ),
    'series', coalesce(v_series, '[]'::jsonb),
    'retention', v_retention
  );
END;
$$;

REVOKE ALL ON FUNCTION public.admin_get_growth_stats(text, int) FROM public, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.admin_get_growth_stats(text, int) TO authenticated;

notify pgrst, 'reload schema';

commit;
```

> 关键点：
> - **权限门**：函数首行 `is_current_user_admin()`，非管理员报 `42501`；`REVOKE ALL ... FROM public/anon/authenticated` 后仅 `GRANT ... TO authenticated`（新函数默认授 PUBLIC，必须显式 revoke）。
> - **时区**：函数级 `SET timezone = 'Asia/Shanghai'`（进入函数生效、退出恢复），使「今日新增」与所有日/周/月桶对齐管理员本地日历（否则默认 UTC，本地 07:59 的注册会算进「昨天」）。
> - **累计用户（P0 修复）**：窗口求和先物化到 `cum` CTE（`v_baseline + sum(new_users) over (order by bucket)`），再 `jsonb_agg`——窗口函数不能出现在聚合函数参数内，否则运行期报 `aggregate function calls cannot contain window function calls`。`v_baseline`（窗口前存量）+ 窗口内累加，保证曲线从「真实总用户数」起点开始、而非窗口内从 0 起。
> - **产出口径（发生即计入）**：`activity` / `reading_started` / `reading_finished` / `new_readings` 均**不加 `deleted_at is null`**，`bookmarks` 也不过滤 `status`——产出时间戳不可变，后续删除/归档不改变「当天曾产出」的事实，保证历史曲线不被追溯性擦除。
> - **粒度语义**：`date_trunc('week'/'month', ...)` —— 周按 ISO 周一、月按自然月；`v_axis_start` 先 `date_trunc` 再 `generate_series`，保证桶边界对齐（避免「每月 22 号」这类错位）。**注意：周/月粒度下首桶可能回退到窗口外的前置天数（如 week 粒度 now-364天 落在周三、首桶回退到周一），属预期、对趋势无影响。**
> - **留存 cohort**：窗口 `[now-(N+7), now-N)` 覆盖整整 7 个注册日、保证 cohort 内用户均已「满 N 天」；`activity` 与 `profiles` 按 user 关联、`a.created_at ∈ [created_at, created_at+N)` 判定「N 日内是否仍有产出」；`cohort_size = 0` 时留存记 0，避免除零。

### 3.2 服务层（新增 `src/services/supabase/adminStats.js`）

```js
import { getSupabaseClient } from './client'

/** 后台数据统计：快照 + 序列 + 留存（近似口径）。 */
export async function getGrowthStats({ granularity = 'day', windowDays = 90 } = {}) {
  const { data, error } = await getSupabaseClient().rpc('admin_get_growth_stats', {
    p_granularity: granularity,
    p_window_days: windowDays,
  })

  if (error) throw error
  return data
}
```

### 3.3 组件层（新增 `src/components/GrowthStatsPanel.jsx`）

数据形状（来自 RPC）：

```js
{
  snapshot: { total_users, today_new_users, dau, wau, mau },
  series: [
    { bucket: '2026-09-22', new_users, cumulative_users, active_users,
      reading_started, reading_finished, new_readings },
    // ...按时间升序
  ],
  retention: { d1, d7, d30 },
}
```

**结构：**

1. **顶部快照**：5 张卡（用户总量 / 今日新增 / DAU（打开应用）/ WAU / MAU），卡片复用抽取后的共享 `StatCard`（见 §3.5）。**顶部「DAU（打开应用）」与图表「活跃用户（有产出 · 近似）」口径不同，措辞显式区分，避免同屏两个「活跃」数值混淆。**
2. **粒度切换**：`日 / 周 / 月` 三态按钮；切换时以 `windowDays` 适配——day→90、week→365、month→730，重新 `getGrowthStats({ granularity, windowDays })`。
3. **趋势图 × 4**（受粒度切换影响）：
   - 新增注册趋势（柱/线）
   - 累计用户增长（单调上升面积/线）
   - 活跃用户趋势（有产出 · 近似，线，附「近似」标注）
   - 阅读活跃趋势（三线：开始读 / 读完 / 新增阅读，附图例）
4. **留存区**：d1 / d7 / d30 三个数 + 「累计留存（注册后 N 天内仍有产出，近似）」说明；**不受粒度切换影响**。

**图表实现约定：**

- **自绘 SVG**（项目未引图表库），抽一个极简 `<TrendChart data={...} />`：算 x/y 刻度、`<polyline>` 折线 + 可选面积填充、y 轴刻度与 hover 提示；不引第三方依赖。
- **配色**：全部走 `var(--*)` 令牌；多系列用「同一语义色系 + 明度/饱和度梯度」区分，亮暗双主题一致。图表绘制前遵循 dataviz 规范（可读、可访问、无障碍）。
- **空态**：`series` 为空或 `snapshot.total_users === 0` 时显示占位，与后台其余子页空态风格一致。
- **错误**：复用 [errorUtils.js](../../../src/services/errorUtils.js) 的 `isLibraryAccessError` + `resolveLibraryErrorMessage`（`resolveAdminErrorMessage` 是 AdminPage 模块私有、不跨文件复用；`isLibraryAccessError` 已识别 `42501`），权限失效时 `refreshAuthState()`。

## 五、验收标准

1. **权限**：迁移后 `anon` 调用 `admin_get_growth_stats` 被拒；非管理员 `authenticated` 调用报「无管理员权限」（`42501`）；管理员调用正常返回 jsonb。
2. **快照**：`snapshot.total_users` = `profiles` 行数；`today_new_users` = 今日注册（按 Asia/Shanghai 日历）；`dau/wau/mau` = `last_seen_at` 落在 1/7/30 天内的去重人数；`last_seen_at` 为 NULL 者不计入。
3. **序列**：`series` 按 `bucket` 升序、无缺桶（`generate_series` 补零）；`cumulative_users` 单调不减且首桶 ≈ 历史存量 + 首桶新增（不凭空从 0 起）；`active_users` 为「新增阅读或收藏」去重用户数，且**不含 `deleted_at is null` / `status` 过滤（已删除/已归档仍计入，产出=发生过即计入）**。
4. **留存**：`retention.d1/d7/d30` 为 `0` 或 `0–100` 的一位小数；`cohort_size = 0` 时该档为 0 不报错。
5. **前端渲染**：粒度切换日/周/月正确重查并重绘；4 图与留存区正常展示；顶部 DAU 卡标「打开应用」、图表「活跃用户（有产出 · 近似）」、留存「累计留存（近似）」措辞区分；空数据与错误态不崩；权限失效触发 `refreshAuthState`。
6. **颜色规范**：新增 UI 全部 `var(--*)`，无硬编码颜色；亮暗主题一致。

## 六、风险与回滚

- **近似口径误读**：活跃/留存是「使用活跃」近似，UI 必须标注「近似」；若后续需要严格登录 DAU/留存，另立「活跃事件表」埋点（本次不做）。
- **时区口径**：函数级 `SET timezone = 'Asia/Shanghai'` 已定；若日后管理员跨时区使用，需改为可配置或回退 UTC + UI 标注。
- **时间戳重置**：`reading_started_at` / `reading_finished_at` 在「重新阅读」时重置/清空，反映「最近一次」；已接受，不另做事件表。
- **部署顺序（H1）**：迁移先行；前端在 RPC 返回字段缺失（空数据）时降级显示空态，RPC 未部署（404）时走错误态、诚实提示——两种状态区分，避免验收时按空态标准误判。
- **性能**：留存 cohort 用相关子查询，`profiles`/`readings`/`bookmarks` 数据量增长后可能变慢；当前小规模无碍，后续可加 `(created_at)` 索引优化（`readings`/`bookmarks` 已有 `user_id` 索引，`created_at` 覆盖可后补）。
- **回滚**：`DROP FUNCTION public.admin_get_growth_stats(text, int);`（无表结构变更、无数据写入，回滚零成本）。
