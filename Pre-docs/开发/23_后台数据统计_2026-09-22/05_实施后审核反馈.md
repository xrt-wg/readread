## 三、问题清单（按严重程度）

### P2-1　`SET LOCAL timezone` 依赖事务块上下文，建议改为函数级 `SET timezone`

迁移函数体第 50 行：

```sql
SET LOCAL timezone TO 'Asia/Shanghai';
```

`SET LOCAL` 仅在**事务块内**有效；在 autocommit 上下文（典型如 Dashboard SQL Editor 直接 `select public.admin_get_growth_stats('day', 30);` 做验收，见 04 §三 #1/#2 的核验方式）存在报 `SET LOCAL can only be used in transaction blocks` 的风险，会使验收测试本身报错、而非返回期望的三态结果。生产路径（supabase-js `.rpc()` → PostgREST 事务）大概率正常，故此风险集中暴露在「人工验收」环节。

**修正建议**：把时区放到**函数级 `SET` 子句**（与既有 `SET search_path = public` 并列，进入函数生效、退出恢复，不依赖事务上下文）：

```sql
CREATE OR REPLACE FUNCTION public.admin_get_growth_stats(...)
RETURNS jsonb
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = public
SET timezone TO 'Asia/Shanghai'
AS $$
...
-- 删除函数体内的 SET LOCAL timezone TO 'Asia/Shanghai';
```

此写法与本库既有 `SET search_path = public` 惯例一致（`ensure_profile`/`is_current_user_admin`/`restart_reading` 均已如此），语义等价但无上下文依赖。

### P3-1　02 §3.1 内嵌 SQL 片段的事务关键字大小写与实际迁移不一致

02 §3.1 内嵌 SQL 显示 `BEGIN;`（:54）/ `NOTIFY pgrst, ...;`（:243）/ `COMMIT;`（:245）**大写**；实际迁移文件为 `begin;`（:16）/ `notify pgrst, ...;`（:205）/ `commit;`（:207）**小写**。

### P3-2　`TrendChart` 的 `preserveAspectRatio="none"` 会横向拉伸文字

`GrowthStatsPanel.jsx` 的 `<svg viewBox="0 0 720 220" preserveAspectRatio="none" style={{ width: '100%', height }}>` 使 SVG 随容器宽度**非等比拉伸**：当内容区宽度偏离 720px 时，y 轴刻度文字、x 轴日期标签与折线会被横向拉宽变形。

**修正建议**（非功能性、低优先级）：改为 `preserveAspectRatio="xMidYMid meet"` 并接受左右留白，或将刻度文字抽为独立 HTML 层、仅折线用 SVG。属轻微视觉瑕疵，不影响数据正确性。

### P3-3　「迁移未到位」实际表现为错误态而非空态，与 02 §六 措辞不一致

02 §六 风险称「前端在 RPC 返回字段缺失时（迁移未到位）降级显示空态，不报错」。但实际：RPC 完全不存在时，PostgREST 返回 404（`Could not find the function ...`），前端 catch 后走**错误态**（显示 error 文案），而非空态。

**说明**：当前行为可接受（比静默空态更诚实），且 H1「迁移先行」部署顺序下此状态不应出现。仅建议将 02 §六 措辞澄清为「RPC 字段缺失时降级空态；RPC 未部署时表现为错误态」，避免验收时按空态标准误判。
