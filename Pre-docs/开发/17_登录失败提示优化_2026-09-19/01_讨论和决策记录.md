# 登录失败提示体验优化 — 讨论和决策记录

> 日期：2026-09-19
> 状态：**已确认**（本文件记录对「登录/注册失败提示体验差」的调查结论与方案决策；结论进入 `02_实施方案.md`）
> 关联：`src/components/AuthPanel.jsx`（悬浮登录面板）、`src/services/supabase/auth.js`（认证协议）、`src/services/errorUtils.js`（既有错误分类范式）

---

## 一、背景与问题

- 测试反馈：登录失败时的提示体验很差。
- **结论先行：登录/注册失败时，UI 直接把 Supabase 返回的原始英文技术错误展示给中文用户**（如 `Invalid login credentials`），用户既看不懂、也得不到「该改哪个字段、下一步怎么办」的引导；叠加错误提示视觉弱、错误生命周期与输入脱节，形成「差」的整体体验。

---

## 二、问题定位（根因）

### 1. 原始英文错误直接透传（核心）

`AuthPanel.jsx:107-109` 的 catch：

```js
catch (submitError) {
  setError(submitError.message || '认证请求失败，请稍后重试')
```

而 `auth.js:19-21` 的 `signInWithPassword` 直接 `throw error`，故 `submitError.message` 即 supabase-js 的英文文案。唯一兜底 `'认证请求失败，请稍后重试'` 仅在 `message` 为空时生效，绝大多数情况走不到。

| 失败原因 | 用户实际看到 |
|---|---|
| 邮箱/密码错误 | `Invalid login credentials` |
| 邮箱未确认 | `Email not confirmed` |
| 请求过于频繁 | `Email rate limit exceeded` |
| 邮箱格式非法 | `Unable to validate email address: invalid format` |
| 邮箱已注册 | `User already registered` |
| 密码过短 | `Password should be at least 6 characters` |
| 网络异常 | `Failed to fetch` / `Request Failed` |

### 2. 失败原因无分类，无针对性引导

所有失败共用同一条 catch，未按 `code` / `status` / `message` 分类。项目已有成熟分类范式 `errorUtils.js:28-34`（`resolveLibraryErrorMessage` 按关键字映射中文），但登录链路未沿用该思路。

### 3. 视觉与交互反馈弱

- 错误块是 `text-xs` 小块（`AuthPanel.jsx:248`），夹在密码框与提交按钮之间，不醒目。
- 无 `aria-invalid`，用户不知道错在邮箱还是密码字段。
- 无 `role="alert"` / `aria-live`，屏幕阅读器不播报，无障碍性差（项目内 `FirstReadingChoiceModal.jsx:133`、`FirstReadingAdminPanel.jsx:58` 已有 `role="alert"` 先例）。

### 4. 错误生命周期与输入脱节

输入框 `onChange`（`AuthPanel.jsx:231、242`）不清除 `error`，用户改正输入后旧错误仍停留，直到下次提交才刷新。

---

## 三、影响范围与表现

1. **登录失败（sign_in）—— 主缺陷**：英文提示、无字段定位、无下一步引导。
2. **注册失败（sign_up）—— 同一链路**：「邮箱已注册」「邮箱格式错」「密码过短」等同样展示英文。
3. **网络异常 —— 尤差**：`Failed to fetch` 这类技术文案对普通用户完全无意义。

---

## 四、方案对比与选择

| 方案 | 评价 |
|---|---|
| **A｜新增 `resolveAuthErrorMessage` 分类映射中文** | ✅ 根因修复；对标 `errorUtils.js`，可复用、可单测 |
| B｜引入全局 toast 通知系统 | ❌ 超出范围，新增基建；面板内联提示已够用 |
| C｜仅改兜底文案 | ❌ 治标；兜底几乎不生效，仍无分类 |
| **D｜字段级高亮（`aria-invalid` + 边框）** | ✅ 引导用户定位出错字段，成本低 |
| **E｜错误随输入清除** | ✅ 对齐「反馈」与「用户动作」 |

**选择 A + D + E。** 原则：**成功路径逐像素零回归；失败路径把「看不懂的英文」升级为「中文、可区分、有引导」**。

---

## 五、决策记录

| # | 决策点 | 决定 |
|---|---|---|
| D1 | 映射函数位置 | 新建 `src/services/supabase/authError.js`，导出 `resolveAuthErrorMessage`；直接 import（对标 `errorUtils.js` 的「顶层服务文件 + 直接 import」范式，不进 barrel） |
| D2 | 映射策略 | 按 `error.message`（不区分大小写）关键字 + `error.status` 分类，返回 `{ message, field }`；顺序敏感，先匹配更具体场景 |
| D3 | 字段定位 | `field ∈ email / password / null`；`null`（如「邮箱或密码不正确」「网络异常」）不标字段 |
| D4 | 呈现增强 | 错误块加 `role="alert"` + `CircleAlert` 图标，用 `--danger-bg` / `--danger-text` 令牌 |
| D5 | 生命周期 | 输入框 `onChange` 时清除错误；提交开始/退出登录/切换模式处 `errorField` 与 `error` 成对清空 |
| D6 | 原始错误留痕 | catch 内 `console.error('[auth]', submitError)` 记录原始英文，不上屏 |
| D7 | signOut 失败提示 | 本期**不改**（范围=登录/注册；signOut 失败罕见，另有独立问题） |
| D8 | 全局 toast / 忘记密码流程 | 均**不做**（前者超范围、后者属功能新增需单独决策） |

---

## 六、明确边界

- 只新增 `authError.js`、修改 `AuthPanel.jsx`；不动数据模型、不改 `auth.js` 的 `throw` 行为、不新增依赖。
- 不引入全局 toast、不加「忘记密码」流程。
- 不改注册成功提示、不改 signOut 错误处理、不改 AuthProvider 状态机。

---

*本文件确认：登录失败提示差的根因为「原始英文错误直接透传 + 无分类 + 视觉/交互弱 + 生命周期脱节」；采用 A + D + E 组合（新增错误映射 + 字段高亮 + 随输入清除），明确不做 toast 与忘记密码；具体变更见 `02_实施方案.md`。*
