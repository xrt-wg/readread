# 登录失败提示体验优化 — 实施方案

> 日期：2026-09-19
> 状态：**待实施**（依据 `01_讨论和决策记录.md` 结论；D1–D8 已定）
> 关联：`01_讨论和决策记录.md`

---

## 一、目标

1. 登录/注册失败时展示**中文、可区分原因、有下一步引导**的提示。
2. 错误**定位到字段**（`aria-invalid` + 边框高亮），用户知道该改哪里。
3. 错误提示**醒目且无障碍**（`role="alert"` + 图标）。
4. 错误**随输入消失**，反馈与用户动作一致。
5. 成功路径（登录成功关面板、注册成功提示、退出登录）**零回归**。

## 三、逐文件改动

### 1. 新增 `src/services/supabase/authError.js`

```js
/**
 * 认证错误 → 用户友好的中文提示
 *
 * 按 error.message（不区分大小写）关键字与 error.status 分类，
 * 返回 { message, field }：field 指向出错输入框（email | password | null）。
 *
 * AuthPanel.jsx 登录/注册失败时调用，替代「直接展示原始英文 message」。
 */
export function resolveAuthErrorMessage(error) {
  const message = String(error?.message || '').toLowerCase()
  const status = error?.status

  // 顺序敏感：先匹配更具体的场景
  if (message.includes('email not confirmed') || message.includes('not confirmed')) {
    return { message: '邮箱尚未验证，请先查收确认邮件后再登录', field: 'email' }
  }

  if (message.includes('rate limit') || message.includes('too many requests') || status === 429) {
    return { message: '操作过于频繁，请稍后再试', field: null }
  }

  if (message.includes('already registered') || message.includes('already exists') || message.includes('user already')) {
    return { message: '该邮箱已注册，可直接登录', field: 'email' }
  }

  if (message.includes('password should be') || message.includes('at least 6')) {
    return { message: '密码需至少 6 位', field: 'password' }
  }

  if (message.includes('unable to validate email') || message.includes('invalid format') || message.includes('invalid email')) {
    return { message: '邮箱格式不正确', field: 'email' }
  }

  if (message.includes('invalid login credentials') || message.includes('invalid credentials')) {
    return { message: '邮箱或密码不正确', field: null }
  }

  if (message.includes('failed to fetch') || message.includes('request failed') || message.includes('network') || message.includes('timeout')) {
    return { message: '网络异常，请检查连接后重试', field: null }
  }

  return { message: '认证失败，请稍后重试', field: null }
}
```

> 「邮箱或密码不正确」无法确定是邮箱还是密码，`field: null` 不标字段；「邮箱未确认」「邮箱已注册」「邮箱格式」「密码过短」可定位，分别标 `email` / `password`。

### 2. `src/components/AuthPanel.jsx`

**① 引入依赖（:1-8）**

```jsx
import { CircleAlert, LogIn, LogOut, Mail, ShieldCheck, UserPlus } from 'lucide-react'
```

**② 新增 `errorField` 状态（:20-22 附近）**

```jsx
const [message, setMessage] = useState('')
const [error, setError] = useState('')
const [errorField, setErrorField] = useState(null)   // 'email' | 'password' | null
```

**③ catch 分支改写（:107-109）**

```jsx
} catch (submitError) {
  console.error('[auth] 认证失败', submitError)
  const { message: friendlyMessage, field } = resolveAuthErrorMessage(submitError)
  setError(friendlyMessage)
  setErrorField(field)
  setPanelOpen(true)
}
```

**④ 邮箱输入框：`aria-invalid` + 边框 + onChange 清错（:227-234）**

```jsx
<input
  type="email"
  autoComplete="email"
  value={email}
  onChange={(event) => { setEmail(event.target.value); if (error) { setError(''); setErrorField(null) } }}
  aria-invalid={errorField === 'email'}
  className="w-full rounded-2xl border px-3 py-3 text-sm outline-none transition focus:border-amber-600"
  style={{ borderColor: errorField === 'email' ? 'var(--danger-text)' : 'var(--popup-border)', background: 'var(--popup-surface)', color: 'var(--ink)' }}
  placeholder="you@example.com"
/>
```

**⑤ 密码输入框：同上（:238-245）**

```jsx
<input
  type="password"
  autoComplete={mode === 'sign_in' ? 'current-password' : 'new-password'}
  value={password}
  onChange={(event) => { setPassword(event.target.value); if (error) { setError(''); setErrorField(null) } }}
  aria-invalid={errorField === 'password'}
  className="w-full rounded-2xl border px-3 py-3 text-sm outline-none transition focus:border-amber-600"
  style={{ borderColor: errorField === 'password' ? 'var(--danger-text)' : 'var(--popup-border)', background: 'var(--popup-surface)', color: 'var(--ink)' }}
  placeholder="至少 6 位"
/>
```

**⑥ 错误块加 `role="alert"` + 图标（:248）**

```jsx
{error ? (
  <div role="alert" className="flex items-start gap-2 rounded-2xl px-4 py-3 text-xs" style={{ background: 'var(--danger-bg)', color: 'var(--danger-text)' }}>
    <CircleAlert size={14} className="mt-0.5 shrink-0" />
    <span>{error}</span>
  </div>
) : null}
```

> 仅改**匿名分支（登录/注册表单）**的错误块；认证后分支（signOut 失败）错误块保持现状（D7）。

**⑦ 同步清理 `errorField`（提交开始 / 退出登录 / 切换模式）**

`errorField` 需与 `error` 成对清空，否则会出现「错误已清空、边框仍红」的残留态（边框高亮只依赖 `errorField`）。在以下三处 `setError('')` 后补 `setErrorField(null)`：

- 提交开始（`handleSubmit`，:82）
- 退出登录（`handleSignOut`，:117）
- 切换登录/注册（:211）

```jsx
setError('')
setErrorField(null)
setMessage('')
```

## 五、验收标准

1. 静态：`authError.js` 存在且导出 `resolveAuthErrorMessage`；`AuthPanel.jsx` 错误块含 `role="alert"`，邮箱/密码输入框含 `aria-invalid`。
2. 构建：`npm run build` 通过，无告警。
3. 运行时（各失败场景，逐一触发）：
   - 密码错 → 「邮箱或密码不正确」（不标字段）
   - 未确认邮箱登录 → 「邮箱尚未验证，请先查收确认邮件后再登录」（标邮箱）
   - 频繁提交 → 「操作过于频繁，请稍后再试」
   - 注册已存在邮箱 → 「该邮箱已注册，可直接登录」（标邮箱）
   - 密码不足 6 位 → 「密码需至少 6 位」（标密码）
   - 断网 → 「网络异常，请检查连接后重试」
4. 交互：出错字段边框变红；修改任一输入后错误消失；切换登录/注册错误清空。
5. 回归：登录成功自动关面板、注册成功提示「请检查邮箱完成确认」、退出登录，均与改动前一致。

## 六、风险与回滚

| 风险 | 应对 |
|---|---|
| 关键字匹配漏配某类 Supabase 文案 | 兜底「认证失败，请稍后重试」保证不裸显英文；`console.error` 留原始错误便于补配 |
| 错误误标字段 | `field: null` 仅在可确定时标字段；验收 #3 逐场景核对 |
| `aria-invalid` 触发浏览器原生校验样式冲突 | 输入框 `type="email"` 的浏览器校验与自定义边框可共存；若冲突，改用自定义 class 标记 |
| 误伤成功路径 | 仅改 catch 与错误展示分支；验收 #5 兜底 |

回滚：`git revert` 对应提交即可（纯前端、无数据与协议变更）。
