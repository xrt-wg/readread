# 迁移功能遗留代码分析报告

> 日期：2026-09-18
> 范围：针对已关闭的「首次迁移」功能（本地 localStorage 数据 → Supabase 云端）在全代码库中的历史遗留代码与功能做全面检索与判定。
> 性质：本报告仅做分析与检索，不包含任何代码改动。

---

## 1. 背景与结论

### 1.1 「迁移功能」指的是什么

「迁移功能」= **首次迁移（initial migration）**：把早期纯本地（localStorage）的阅读资产（文章 / 收藏 / 阅读进度）同步到 Supabase 云端。

其生命周期经历了两个阶段：

| 阶段 | 实现 | 状态 |
|---|---|---|
| 旧（已关闭） | `MigrationPanel` 迁移 UI + `localMigration.js` / `remoteMigration.js` 显式迁移流程，配合 `pending_migration` 认证态与 `has_completed_initial_migration` 标记 | **已停用** |
| 新（当前） | `App.jsx` 中的静默导入（silentImport），即 `migrateTrialSnapshot()`（`services/migration/firstReadingMigration.js`） | **活跃** |

代码中的权威关闭声明：
- `App.jsx:25`：「MigrationPanel 导入已移除，迁移功能入口已关闭，组件文件保留在磁盘上以备后续需要。」
- `AuthProvider.jsx:20`：「迁移功能已关闭：不再产生 pending_migration 状态，直接进入 authenticated」
- `AuthPanel.jsx:131`：「pending_migration 状态已于 2026-06 关闭」
- `localMigration.js:123` / `remoteMigration.js:35`：「迁移 UI 已停用（silentImport 替代）」

### 1.2 核心结论

1. **迁移 UI 及其整套执行逻辑已成孤儿代码**：`MigrationPanel` + `localMigration` + `remoteMigration` 三个文件已无任何活跃引用，可整体删除。
2. **`has_completed_initial_migration` 标记已冻结**：当前唯一写入口 `markInitialMigrationCompleted()` 属于死代码；`ensure_profile()` RPC 不写该字段。因此该标记对新用户永远是 `false`，后台「待迁移用户 / 已完成首次迁移」统计已失真。
3. **后台管理（`AdminPage.jsx`）是遗留最集中的地方**，且叠加了另一处独立遗留——「推荐内容管理」（featured articles，2026-06-16 已迁移到社区众包推荐系统）的大量死代码。
4. **存在一个潜在运行期隐患**：`AdminPage` 中未渲染的死块引用了**未导入**的函数（`updateFeaturedArticle` 等），一旦该块被误触发渲染会直接抛 `ReferenceError`（详见 §5）。

### 3.6 F 类：数据库 schema 遗留

[supabase/migrations/20260509164000_create_profiles.sql:6-7](../../supabase/migrations/20260509164000_create_profiles.sql#L6-L7)：

```sql
has_completed_initial_migration boolean not null default false,
initial_migrated_at timestamptz,
```

关键事实链：
- `ensure_profile()`（同文件 :91-122）**只更新 `last_seen_at`，不写这两个字段**；但因其定义为 `returns public.profiles` 且内部 `select * into`，当前会**返回**这两列（供 AuthProvider 读取）。DROP 后返回类型随复合类型自动收窄，不再包含该两列，无报错风险。
- 唯一写这两个字段的 `markInitialMigrationCompleted()`（profile.js:63-95）是死代码。
- 结论：这两个字段已无活跃写入口，处于「冻结」状态，只被后台读取展示。

## 5. 关键风险点

1. **`AdminPage._removed` 块引用未导入函数**（G.1）：当前被 `display:none` 包裹、`currentPage` 又永远不等于 `_removed`，故安全；但属于「一碰就炸」的隐患，清理时应整块删除而非「修好 import」。
2. **`has_completed_initial_migration` 已冻结**（F）：后台「待迁移用户」统计恒等于「用户总量」，具有误导性；需在清理 UI 与决策字段去留之间做权衡。
3. **误删风险**（§6）：`firstReadingMigration.js`、`exportData`/`importData`、`createAuditLog` 等与「迁移」字面相关但实际活跃，必须排除在删除范围外。
