## 2. 清理原则

1. **删除优先于注释**：已确认无引用的死代码直接删除，不保留「以备后用」注释。
2. **小步提交**：按 Phase 拆分成独立提交，每个 Phase 可独立验证、独立回滚。
3. **先断引用再删定义**：先清理调用方（UI/组件），再删被引用方（service/函数），避免中间态出现未定义引用。
4. **DB 改动单独成 Phase 并显式评审**：schema 变更需独立迁移文件，不与其他代码混入同一提交。
5. **每 Phase 跑构建/静态检查**，确保无 `ReferenceError`、无残留 import。
6. **行号仅作定位参考**：本方案所有行号以 `develop` HEAD `4fdd324` 为基准，删除前必须 `grep` 按符号名重新定位，不得按行号直接删。

### Phase 6：DROP 数据库迁移字段（F 类，D1=删 已确认）

**目标**：新增迁移文件 DROP `profiles` 两字段。

```sql
-- supabase/migrations/<timestamp>_drop_initial_migration_columns.sql
alter table public.profiles
  drop column if exists has_completed_initial_migration,
  drop column if exists initial_migrated_at;
```

**执行前提**：
1. 确认生产库 `profiles` 两字段无任何 RPC / 视图 / 策略依赖。
2. `profile.js` 的 `ADMIN_PROFILE_COLUMNS`、`mapAdminProfileRow` 已移除对应列（Phase 3）。
3. AdminPage 已无任何引用（Phase 5）。
4. 确认 `ensure_profile()` 定义为 `returns public.profiles` 且 `select * into`，DROP 后返回类型随复合类型自动收窄、不再包含该两列，无报错风险；在 DROP 迁移文件注释中说明此点。
5. 迁移文件命名遵循既有时间戳约定，放 `supabase/migrations/`。
6. 备好回滚 SQL：
   ```sql
   alter table public.profiles
     add column has_completed_initial_migration boolean not null default false,
     add column initial_migrated_at timestamptz;
   ```
