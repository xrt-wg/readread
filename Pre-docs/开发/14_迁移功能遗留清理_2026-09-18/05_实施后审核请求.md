## 四、实施偏差与补充说明（请审核者重点复核）

1. **P3-1「`loading`/`error` 连带核查」结论与方案假设相反，已删除而非保留。**
   方案 §7.1 假设 `loading`/`error` 仍被 dashboard / users 加载逻辑使用、需保留。实际核查发现：dashboard / users 加载使用的是 `profilesLoading`/`profilesError`/`auditLoading`/`auditError`，而裸 `loading`/`error` 仅被 featured 代码（`reloadFeaturedArticles` 及 featured JSX）使用。故在 P7 中**一并删除** `loading`/`error` 声明及 `setLoading`/`setError` 调用。当前 `AdminPage.jsx` 仅保留 `profilesLoading`/`profilesError`/`auditLoading`/`auditError`（已 grep 复核）。审核者可确认：dashboard / users 卡片的加载态仍正常驱动。

2. **`FileText` import 保留，改删 `X`。**
   方案 §7.1 注明「`FileText` 若不再使用则移除」。核查后 `FileText` 仍被导航项（推荐审核 / 首次阅读）使用，**予以保留**；实际随编辑器弹窗删除的是仅被该弹窗使用的 `X`（关闭图标）import。

3. **E 类（提交 5）触碰了一处位于 `_removed` 死块内的展示行。**
   提交 5 删除的「`首次迁移：{profile?.has_completed_initial_migration ? ...}`」一行，位于 `AdminPage` 的 `_removed` 死块（`display:none`）内、属 G 类范围；该行已在提交 5 删除、其所在整块又在提交 7 删除。净效果正确（无残留），但存在「E 类提交先删了 G 类区块内一行」的跨边界细节，审核者知悉即可，无需回改。

4. **DROP 迁移文件命名**：`20260918000001_drop_initial_migration_columns.sql`，遵循 `<YYYYMMDDHHMMSS>_<snake_case>.sql` 约定；`000001` 序号用于在既有 `20260509164000_create_profiles.sql` 之后保持单调递增。

5. **`rr_local_migration_meta` 行号由 :78 漂移至 :79**：因按 P2-1 决策在 :78 插入一行注释，属预期漂移。

6. **审计筛选项未补充推荐系统 action/target**：方案 §7.3 将「补充推荐系统筛选项」标为可选。本次按最小改动原则，仅删除 `featured_article.*` 死筛选项，未新增推荐系统筛选项（推荐审核页自身已有完整操作入口）。如需补充可另立任务。
