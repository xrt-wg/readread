## 1. 修复总则

### 1.1 核心原则

1. **优先使用现有 CSS 变量** — 不新建变量，`index.css` 的 `[data-theme="night"]` 已覆盖全部所需颜色
2. **阴影改用纯黑系** — 亮色模式的 `rgba(28,25,23,...)` 阴影在夜间模式必须转为 `rgba(0,0,0,...)`（`popup-shadow` 已有示范）
3. **语义色保持硬编码但需验证** — 红/绿/琥珀反馈按钮颜色在两种模式下应分别验证对比度
4. **不改变组件结构** — 只替换颜色值，不改 JSX 结构或逻辑

### 1.2 设计令牌速查表

将硬编码值替换为以下对应变量：

| 当前硬编码（典型） | 替换为 | 说明 |
|---|---|---|
| `#ffffff` | `var(--card-bg-warm)` 或 `var(--popup-surface)` | 卡片/面板背景 |
| `#fdfaf5` | `var(--popup-bg)` | 弹窗/面板背景 |
| `#fefdfb` | `var(--card-bg-warm)` | 卡片内部背景 |
| `rgba(28,25,23,0.06~0.12)` | `var(--border-subtle)` 或 `var(--surface-border)` | 边框 |
| `rgba(28,25,23,0.04~0.08)` 背景 | `var(--hover-bg)` | hover / 浅背景 |
| `rgba(28,25,23,0.04~0.12)` 阴影 | 见下方阴影方案 | 阴影需特殊处理 |
| `rgba(255,255,255,0.6)` | `var(--surface-bg)` | 半透明白色表面 |
| `#2d2926` | `#3d3934` | 暗色 hover（需在夜间保持可辨识） |
| `rgba(28,25,23,0.15~0.20)` 遮罩 | `rgba(0,0,0,0.35)` | 模态遮罩 |
| `linear-gradient(175deg, #1c1917 10%, #3d2b1e 100%)` | 使用 `var(--ink)` 渐变 | 品牌文字 |

### 1.3 阴影处理方案

阴影在两种模式下需要不同的颜色：

**方案 A（推荐）**：为阴影新建一个 CSS 变量。

在 `index.css`  `:root` 中新增：
```css
--card-shadow: 0 2px 16px rgba(28,25,23,0.06), 0 1px 4px rgba(28,25,23,0.04);
```

在 `[data-theme="night"]` 中覆写：
```css
--card-shadow: 0 2px 16px rgba(0,0,0,0.25), 0 1px 4px rgba(0,0,0,0.15);
```

**方案 B（备选）**：如果阴影不需要精细区分，代码中直接使用 `var(--popup-shadow)` 复用已有的弹窗阴影变量。

采用**方案 A**，新增一个 `--card-shadow` 变量，因为卡片阴影与弹窗阴影的视觉需求不同（卡片阴影更轻）。

## 6. HIGHLIGHT_STYLES 修复方案（P1）

**文件**：[src/utils/textUtils.js](../../src/utils/textUtils.js)

### 6.1 问题分析

当前高亮颜色的设计假设是亮色背景（`#faf4e8`）。在夜间模式（背景 `#1a1814`）下，半透明颜色叠加在深色背景上会**显著变暗**，尤其是低不透明度的值。

| 类型 | 当前值 | 夜间模式问题 |
|---|---|---|
| word | `rgba(251,191,36,0.35)` | 金色变暗，但与深色背景对比度尚可 |
| phrase | `rgba(52,211,153,0.28)` | 绿色在深色背景上不够突出 |
| sentence | `rgba(99,102,241,0.6)` 底线 | 靛蓝底线在深色背景上辨识度降低 |
| paragraph | 同上 | 同上 |

### 6.2 方案选择
