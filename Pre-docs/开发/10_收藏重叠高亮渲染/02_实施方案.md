## 二、核心改动

### 2.1 `ParagraphRenderer`：双层叠加渲染

**现状**：`buildSegments` 把所有收藏当一条扁平区间，贪心去重叠后返回 `{ text, bookmark }` 片段；重叠的旧收藏被直接丢弃。

**目标**：词/短语走「背景层」、句/段走「下划线层」，两层各自独立消解后**嵌套**渲染，两层可同时可见。

**新结构**：

```js
const BG_TYPES = new Set(['word', 'phrase'])
const UL_TYPES = new Set(['sentence', 'paragraph'])

function resolveRanges(ranges) {
  // 同层内最新优先，贪心去重叠，返回按 start 升序
  ranges.sort((a, b) => new Date(b.bookmark.createdAt) - new Date(a.bookmark.createdAt))
  const resolved = []
  for (const r of ranges) {
    if (!resolved.some((o) => r.start < o.end && r.end > o.start)) resolved.push(r)
  }
  return resolved.sort((a, b) => a.start - b.start)
}

function buildLayers(paraText, bookmarks) {
  // 沿用现有校验：越界过滤 + 原文 slice 匹配
  const ranges = bookmarks
    .map((bm) => ({ start: bm.charOffset, end: bm.charOffset + bm.text.length, bookmark: bm }))
    .filter((r) =>
      r.start >= 0 && r.end <= paraText.length && r.start < r.end &&
      paraText.slice(r.start, r.end) === r.bookmark.text
    )
  return {
    bgRanges: resolveRanges(ranges.filter((r) => BG_TYPES.has(r.bookmark.type))),
    ulRanges: resolveRanges(ranges.filter((r) => UL_TYPES.has(r.bookmark.type))),
  }
}
```

**渲染规则**：

- `ulRanges` 是外层连续 span（下划线），**每个是一整段 span，不在词处切开**——保证下划线/`border-bottom` 连续，不因嵌套而断裂。
- 每个下划线 span 内部，递归渲染与之相交的 `bgRanges`（背景 span，按 ul 边界裁剪）。
- 下划线区间之间的「间隙」，只渲染纯文本 + 背景 span（无外层下划线）。
- 短语跨句边界（罕见）时，同一背景 span 会被裁剪为**多段**（句中 + 相邻间隙），因此 key 需按裁剪区段去重（`bg-${id}-${s}-${e}`），避免同一父节点下重复 key；视觉上仅多极细断点，可接受。

```jsx
function renderBgs(text, from, to, bgRanges) {
  const nodes = []
  let cursor = from
  for (const r of bgRanges) {
    const s = Math.max(r.start, from), e = Math.min(r.end, to)
    if (e <= s) continue
    if (s > cursor) nodes.push(text.slice(cursor, s))
    nodes.push(<span key={`bg-${r.bookmark.id}-${s}-${e}`} data-bookmark-id={r.bookmark.id} style={bgStyle(r.bookmark)}>{text.slice(s, e)}</span>)
    cursor = e
  }
  if (cursor < to) nodes.push(text.slice(cursor, to))
  return nodes
}

function render() {
  const { bgRanges, ulRanges } = buildLayers(text, bookmarks)
  const nodes = []
  let cursor = 0
  for (const r of ulRanges) {
    if (r.start > cursor) nodes.push(...renderBgs(text, cursor, r.start, bgRanges))
    nodes.push(
      <span key={`ul-${r.bookmark.id}`} data-bookmark-id={r.bookmark.id} style={ulStyle(r.bookmark)}>
        {renderBgs(text, r.start, r.end, bgRanges)}
      </span>
    )
    cursor = r.end
  }
  if (cursor < text.length) nodes.push(...renderBgs(text, cursor, text.length, bgRanges))
  return <span onMouseOver={handleOver} onMouseLeave={handleLeave}>{nodes}</span>
}
```

`bgStyle` 复用现有背景样式；`ulStyle` 收敛为单一 `border-bottom`（`var(--hl-sentence-border)` / `var(--hl-paragraph-border)`），移除冗余 `text-decoration: underline` 与硬编码 `textDecorationColor`（审核 P4，见 D6）。不新增任何颜色/变量。

### 2.2 hover 委托化

**现状**：每个高亮 span 各自挂 `onMouseEnter` / `onMouseLeave`。

**嵌套后的问题**：词从词上移出到句子的非词部分时，内层 `onMouseLeave` 会清空 hover，而外层句子的 `onMouseEnter` 不会重新触发（鼠标已在句内）→ 悬浮卡**消失而非切换到句卡**。这是逐 span 模型在嵌套下的固有缺陷。

**改动**：`ParagraphRenderer` 返回一个 `<span>` 容器，挂**委托式** `onMouseOver`（取最内层收藏）与 `onMouseLeave`（移出段落清空）：

```jsx
const bookmarkMap = useMemo(() => new Map(bookmarks.map((b) => [b.id, b])), [bookmarks])

const handleOver = (e) => {
  const el = e.target instanceof Element ? e.target.closest('[data-bookmark-id]') : null
  if (el) {
    const bm = bookmarkMap.get(el.dataset.bookmarkId)
    if (bm) onHoverBookmark?.(bm, el)
  } else {
    onHoverBookmark?.(null, null) // 移到非高亮文本 → 走隐藏计时器（等价原逐 span 的 onMouseLeave）
  }
}
const handleLeave = () => onHoverBookmark?.(null, null)
```

**行为**：

- 鼠标停在词上 → `e.target.closest` 命中词 span → 词卡（最内层优先，天然满足 D3）。
- 从词移出到句子的非词部分 → `mouseover` 目标变为句 span → 句卡（修复了逐 span 模型的切换断层）。
- 移到非高亮文本 → `handleOver` 的 `else` 分支清空（走 150ms 隐藏计时器），不残留卡。
- 移出整个段落 → `onMouseLeave` 清空。

**说明**：`mouseover` 仅在跨越元素边界时触发、不随像素连续触发，与现状 `mouseenter` 频率相当，无性能回归；`onHoverBookmark` 签名（`(bookmark, el)`）不变。

### 2.3 `ReaderPage`：`charOffset` 精确定位

**现状**：`getCharOffset(paraText, selectedText)` 用 `indexOf` 只取第一次出现，段落内重复词会导致定位错位（叠加关系错误）。

**改动**：在 `ReaderPage.jsx` 新增模块级 helper，用 DOM Range 起点相对段落文本节点累加求偏移：

```js
function getSelectionStartOffset(containerEl, range) {
  const walker = document.createTreeWalker(containerEl, NodeFilter.SHOW_TEXT)
  let offset = 0, node
  while ((node = walker.nextNode())) {
    if (node === range.startContainer) return offset + range.startOffset
    offset += node.textContent.length
  }
  return 0 // 兜底：startContainer 非文本节点等罕见情况（与旧 indexOf 的 0 兜底一致，交由 buildLayers 校验过滤）
}
```

`handleMouseUp` 内替换 `charOffset` 计算（原 `src/components/ReaderPage.jsx` 第 214 行，同时覆盖预读路径与弹窗路径）：

```js
const rawSelection = selection.toString()          // 未 trim 的原始选中文本
const charOffset =
  getSelectionStartOffset(anchorEl, range)          // range 起点在段落 textContent 中的偏移
  + (rawSelection.length - rawSelection.trimStart().length) // 修正被 trim 掉的前导空白
```

**说明**：

- `selected = selection.toString().trim()` 是保存的 `text`；`charOffset` 必须指向 trim 后文本的起点，故加前导空白修正；尾随空白不影响起点。
- `anchorEl` 即 `<p data-para-index>`（或 frontmatter 容器 / `li`），其 `textContent` 与传入 `ParagraphRenderer` 的 `rawText` 一致，TreeWalker 累加长度等于 `textContent.length`。
- `textUtils.getCharOffset` 改为无引用后删除（`textUtils.js` 第 45–48 行）；同时移除 `ReaderPage.jsx` 第 24 行 import 中的 `getCharOffset`（三处联动，缺一会构建失败）。

## 三、数据流 / 渲染示意

```
词先藏 + 句后藏（D1 场景）：
  数据：word「apple」+ sentence「I ate an apple.」 两条都在
  渲染：<span 下划线> I ate an <span 背景>apple</span>. </span>
        → 整句下划线 + 词背景色块 同时可见

句先藏 + 词后藏（反向）：
  数据：sentence 先行 + word 后行
  渲染：同上，两样都在（不再因 createdAt 吞掉句下划线）

同类重叠（词套词 / 句套句）：
  同层内最新优先，旧者不可见（与现状一致）
```

## 七、边界与已知限制

- **旧书签的 `charOffset` 不迁移**：本次为前瞻修复；历史书签中「重复词错位」的个别数据不追溯（罕见、非破坏性）。

- **段落级收藏（paragraph）**：下划线贯穿整段、视觉偏重，本次不额外处理（维持现状）。
