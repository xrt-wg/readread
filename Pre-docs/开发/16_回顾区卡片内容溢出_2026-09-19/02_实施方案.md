## 一、目标

1. 封住 `ReviewCard.jsx:54` 正面短类型大字的无上限区，超长 `bookmark.text` 在卡片内部滚动，卡片不再被无限撑高。
2. 弹窗在矮视口（视口高度 < ~533px）下内部可滚动，反馈按钮与翻页控件始终可达。
3. 正常长度内容的渲染与现在完全一致（零回归）。
4. 不触碰三处滚动容器（`:58`/`:65`/`:98`，本已正常滚动）。

## 三、逐文件改动

### 1. `src/components/ReviewCard.jsx` — 正面短类型大字（:54）

补 `maxHeight` + `overflowY` + `scrollbarWidth`：

```jsx
<p style={{ ...TEXT_WRAP, fontFamily: '"Playfair Display", Georgia, serif', fontSize: 'clamp(28px, 5vw, 42px)', fontWeight: 700, color: 'var(--ink)', textAlign: 'center', lineHeight: 1.2, letterSpacing: '-0.01em', maxHeight: '3.6em', overflowY: 'auto', scrollbarWidth: 'thin' }}>{bookmark.text}</p>
```

> `fontSize` 为 `clamp(28px, 5vw, 42px)`、`lineHeight: 1.2` → 每行 1.2em，`3.6em` ≈ 3 行。正常词/短语绝大多数 1–2 行；较长 phrase（8–10 词）偶触 3 行上限、属可接受（如确需放宽改 `4.8em`，见 §六）。

### 2. `src/components/ReviewModal.jsx` — 外层容器（:123）

补 `overflowY: 'auto'`：

```jsx
style={{
  width: '100%',
  maxWidth: '560px',
  maxHeight: '90vh',
  overflowY: 'auto',   // 新增：矮视口兜底
  margin: '0 16px',
}}
```

> `maxHeight: '90vh'` 已存在。弹窗最小高度 ≈ 480px（头 48 + 进度 19 + 卡片 360 + 控制 52），视口高度 < ~533px 时即便内容正常也超 90vh；补 `overflowY: 'auto'` 后内部滚动、按钮可达。子元素被 cap 在 90vh 内，不会触发 `items-center` 的「顶部裁切不可滚」问题。

## 五、验收标准

1. 静态：`ReviewCard.jsx:54` 含 `maxHeight` + `overflowY`；`ReviewModal.jsx:123` 含 `overflowY`。
2. 构建：`npm run build` 通过，无告警。
3. 运行时（正常内容）：词/短语/句/段各一条，卡片渲染与改动前一致——无滚动条、内容居中、卡片约 360px。
4. 运行时（超长 phrase）：给 word/phrase 注入超长 `bookmark.text`，确认 `:54` 在卡片内部滚动、卡片高度不无限增长、footer 常驻可见；同时给长句/段注入超长原文，回归确认 `:65`、`:98` **本就**在容器内滚动、卡片高度不增长（本项不改动，仅为回归确认）。
5. 运行时（矮视口）：将视口高度缩至 < 约 550px，确认弹窗内部可滚动、「下一张 / 完成」始终可达（即便内容正常）。
6. 回归：翻面动画、滑动反馈、发音按钮、进度条均不受影响。

## 六、风险与回滚

| 风险 | 应对 |
|---|---|
| `3.6em` 误伤正常长 phrase | 3 行上限远大于正常短语；确需放宽时改 `4.8em`（4 行） |
| 弹窗滚动与 `items-center` 的顶部裁切 | 子元素 cap 在 90vh 内，不触发；验收 #5 兜底 |
| `scrollbarWidth: 'thin'` 仅 Firefox 生效 | 属既有行为，非本次引入；Chrome 细样式列为可选后续（D6） |

回滚：`git revert` 对应提交即可（纯样式改动，无逻辑与数据变更）。
