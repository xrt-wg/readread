核心结论三点：

1. **分析准确性有重大瑕疵**：`01` §二.1 的「flex 子项 `min-height: auto` 覆盖 `max-height`」只对 `overflow: visible` 的 flex 子项成立；三处滚动容器均设了 `overflow-y: auto`（scroll container），自动最小尺寸为 0，`max-height`（8.5em / 10.5em / 180px）是硬约束，内容超长时应在容器内滚动，而非撑高卡片。

## 三、问题清单（按严重程度）

### P1-1　核心根因判断错误：三处滚动容器是 scroll container，`min-height: auto` 解析为 0，`max-height` 并未被覆盖

`01` §二.1 断言：「三处滚动容器都用了 `overflow-y: auto` + `maxHeight`，但它们所在的父容器都是 `flex flex-col`。flex 子项默认 `min-height: auto`，解析为『内容的最小高度』；当 `min-height` 计算值大于 `max-height` 时，`max-height` 被忽略。于是内容一旦超过上限，元素不会被裁剪、不出现滚动条，而是直接长到内容高度。」

经核，该推理**缺失一个关键例外**：

- 三处容器 `ReviewCard.jsx:58`（例句 `8.5em`）、`:65`（长内容原文 `10.5em`）、`:98`（背面主体 `180px`）**自身均设置了 `overflowY: 'auto'`**（代码已核实）。
- 按 CSS Overflow 规范，`overflow-y: auto` 使该元素成为 **scroll container**；按 CSS Flexbox §4.5「Automatic Minimum Size of Flex Items」，**scroll container 的自动最小尺寸为 0，而非内容最小高度**。只有 `overflow: visible` 的 flex 子项，其 `min-height: auto` 才解析为内容最小高度。
- 因此对这三处容器，`min-height: auto` → 0，`max-height`（8.5em / 10.5em / 180px）是硬约束，内容超长时**在容器内部滚动**（`overflow-y: auto` 有内容可滚），并不会「把卡片无限撑高」。

**影响**：

1. `01` §二.1 的「核心根因」不成立，§一「根因是 `min-height: auto` 覆盖 `max-height`」的结论指向错误。
2. 由此推出**方案 A（`TEXT_WRAP` 补 `minHeight: 0`）是 no-op**：三处滚动容器本就滚动，补不补 `minHeight: 0` 行为不变；其余 5 处非滚动元素在无收缩压力（祖先无固定高度）下亦不受影响。详见 P2-1。
3. 真正无上限的溢出点只有 `ReviewCard.jsx:54`（正面短类型大字，无 `maxHeight`、无 `overflow`，且 `overflow` 为 visible）——这才是「卡片被无限撑高」的唯一（或主要）来源，而它被文档列为「附加隐患 E」。
4. 由错误根因推出的「方案 C 必要性」（卡片撑高超过 90vh）也随之脱钩，见 P2-2。

**修正建议**：

- 重写 `01` §二.1 与 §一结论：真实根因是「正面短类型大字（:54）无上限」，而非「三处滚动容器 `min-height: auto` 失效」。
- 若实施方对本判断存疑，建议先做一次 5 分钟实证：浏览器中给一条「句/段」收藏注入超长原文，观察 `:65` 是否已在 10.5em 内滚动（预期：滚动，卡片高度不增长）；给一条 word/phrase 注入超长 `bookmark.text`，观察 `:54` 大字是否撑高卡片（预期：撑高，即真实 bug）。

### P2-1　方案 A（`TEXT_WRAP` 补 `minHeight: 0`）为 no-op，应移除或降级

`02` §三.1 建议在 `TEXT_WRAP` 统一加 `minHeight: 0`，并以「使 flex 列子项可收缩，让 `maxHeight` + `overflow-y` 真正生效」为理由。

经核（见 P1-1），三处滚动容器本就是 scroll container（自动最小尺寸 0），`maxHeight` 已经生效；对 5 处非滚动文本元素（:54/:99/:101/:106/:112），在无收缩压力的布局下 `minHeight: 0` 不改变渲染。故方案 A **不产生任何实际效果**。

**影响**：A 不会破坏任何东西（零风险），但把「修复滚动失效」作为其价值，会误导后续维护者以为滚动容器依赖 `minHeight: 0` 才能滚动。

**修正建议**（二选一，建议 b）：

- （a）直接从方案中**移除 A**，把 E 提升为「唯一根因修复」；
- （b）保留但**降级为注释性防御**，并在注释中写明「scroll container 本应滚动，此项仅为防御性冗余」，避免传递错误心智模型。

---

### P2-2　方案 C 的正当性论证与真实根因脱钩，应改为「短视口兜底」

`01` §二.3 / `02` §三.3 以「卡片撑高超过 90vh → 溢出视口且无法滚动」论证弹窗外层补 `overflowY: auto`（C）的必要性。

经核：

- 若真实根因仅剩 :54（修复 E 后），卡片在**正常视口**下不会超过 90vh，C 的原论证失效；
- 但 C **仍有独立价值**：卡片区 `minHeight: 360px` + 头部（约 48px）+ 进度条（约 19px）+ 控制条（约 52px）≈ **480px 的最小高度**，在**矮视口**（高度 < 约 533px，如横屏手机）下即便内容完全正常也会超过 90vh。此时外层滚动兜底是必要的，否则「下一张 / 完成」不可达。

**影响**：C 本身无害且应保留，但若按原论证实施，验收标准 #5「窄视口或超长数据下弹窗可滚动」中的「超长数据」部分在修复 E 后将无法复现，导致该验收项失效/无法验证。

**修正建议**：将 C 的论证改写为「卡片最小高度 + 头尾控件在矮视口下天然超过 90vh，需外层滚动兜底」，验收标准 #5 相应改为「矮视口（高度 < 约 550px）下弹窗内部可滚动，下一张 / 完成始终可达」。

### P3-2　「正常词/短语 1–2 行永不触发」对较长 phrase 略乐观

`02` §三.2 论证 `3.6em` 上限安全，理由为「正常词/短语为 1–2 行，永不触发」。经核，phrase 在本应用中是用户划选的多词片段，较长 phrase（如 8–10 词）在 `clamp(28px, 5vw, 42px)` 大字 + 约 480px 内容宽下可能达到 3 行，触发 3.6em 滚动。

**影响**：仅轻微；且 `02` §六风险表已含「`3.6em` 误伤正常长 phrase → 改为 `4.8em`」的兜底，属自洽。

**修正建议**：可将表述软化为「正常词/短语绝大多数 1–2 行；较长 phrase 偶触 3 行上限，属可接受」；或维持现状（风险表已覆盖）。

## 五、正面确认（经独立验证判定正确，予以肯定）

以下关键判定经独立回查全部成立，实施者可放心依赖：

1. **三处滚动容器的定位与属性准确**：`ReviewCard.jsx:58`（例句 `maxHeight: 8.5em` + `overflowY: auto`）、`:65`（长内容原文 `maxHeight: 10.5em` + `overflowY: auto`）、`:98`（背面主体 `maxHeight: 180px` + `overflowY: auto`）——逐一核对无漂移。✅
2. **`:54` 正面短类型大字无上限的判断准确**：该 `<p>` 无 `maxHeight`、无 `overflow`，仅 `...TEXT_WRAP`（`maxWidth: 100%` + `minWidth: 0` + 换行），`overflow` 为 visible——这是**真实的、唯一的无上限溢出点**（文档定位正确，仅优先级错置）。✅
3. **`TEXT_WRAP`（:10-15）只有 `minWidth: 0`、无 `minHeight: 0` 的判断准确**。✅
4. **卡片/翻转区/面板/弹窗均无 `maxHeight` 的判断准确**：`ReviewCard.jsx:207`（`minHeight: 320px`）、`:187-193`（`overflow: hidden`）、`ReviewPanel.jsx:134`（`minHeight: 360px`）、`ReviewModal.jsx:201`（`minHeight: 360px`，文档误写 :203，见 P3-1）。✅
5. **弹窗外层 `ReviewModal.jsx:123` 有 `maxHeight: 90vh`、无 `overflowY` 的判断准确**。✅
6. **「不改 `ReviewPanel`」的边界合理**：其所在页面（ImportPage `view === 'review'`）本身可滚动，卡片经 E 修复后自然有界。✅
7. **D4（不做固定高度）、D5（不做截断）的取舍合理**：固定高度会改变正常「词 + 例句」卡片的间距；截断会藏内容，违背复习「翻面看全文」的核心诉求。✅
8. **`3.6em` 的计算自洽**：`clamp(28px,5vw,42px)` × `lineHeight: 1.2` → 每行 1.2em，`3.6em` ≈ 3 行，与例句（`8.5em`）语义对称。✅
