# 回顾区卡片内容溢出 — 讨论和决策记录

> 日期：2026-09-19
> 状态：**已确认（修订版）**（依据 `03_实施前审核反馈` 修正根因叙事：真实无上限溢出点仅 `ReviewCard.jsx:54` 正面短类型大字；三处滚动容器本已正常滚动）
> 关联：`03_实施前审核反馈/实施前审核反馈.md`、`src/components/ReviewCard.jsx`（卡片正/反面）、`src/components/ReviewModal.jsx`（回顾弹窗）

## 一、背景与结论

- 用户提出：调查回顾区卡片在「收藏内容过长」时是否存在卡片溢出。
- 回顾卡片是闪卡：正面显示原文（词/句为大字，句/段为正文），翻面显示「原文 + 译文 + 例句 + 例句译文」，底部常驻「生疏 / 一般 / 熟练」反馈按钮。
- **结论（修订）**：真实且唯一的无上限溢出点是 `ReviewCard.jsx:54` 正面短类型（word/phrase）大字——它没有 `maxHeight`、没有 `overflow`，`overflow` 为 `visible`。当 `bookmark.text` 异常过长（如误划一整句被判成 phrase）时，会以 `clamp(28px, 5vw, 42px)` 的大字无上限撑高卡片。
- **澄清（修订）**：三处滚动容器（`:58` 例句、`:65` 长内容原文、`:98` 背面主体）均自带 `overflow-y: auto`，是 scroll container，其 `max-height`（8.5em / 10.5em / 180px）本就是硬约束，内容超长时在容器内部滚动、不会撑高卡片。「收藏内容过长」的常见形态（长句/段 → `:65`、长译文 → `:98`）**本已滚动**。
- 另有两个次要因素：① 卡片/翻转区/卡区均无 `maxHeight`；② 弹窗 `ReviewModal.jsx:123` 有 `maxHeight: '90vh'` 却无 `overflowY`，在矮视口下即便内容正常也会超 90vh。

---

## 二、根因与定位

### 1. 真实根因：正面短类型大字（:54）无上限

`ReviewCard.jsx:54` 的 `<p>`（word/phrase 的 `bookmark.text`）只 spread `TEXT_WRAP`（横向换行），无 `maxHeight`、无 `overflow`。这是唯一会因内容过长而「把卡片无限撑高」的位置。

### 2. 澄清：三处滚动容器本已正常滚动

| 位置 | 内容 | 上限 |
|---|---|---|
| `ReviewCard.jsx:58` | 正面短内容例句 | `maxHeight: '8.5em'` + `overflowY: 'auto'` |
| `ReviewCard.jsx:65` | 正面长内容原文 | `maxHeight: '10.5em'` + `overflowY: 'auto'` |
| `ReviewCard.jsx:98` | 背面主体（原文+译文+例句+例句译文） | `maxHeight: '180px'` + `overflowY: 'auto'` |

按 CSS Flexbox §4.5，设了 `overflow-y: auto` 的元素是 scroll container，其「自动最小尺寸」为 0（而非内容最小高度），故 `max-height` 是硬约束、内容在容器内滚动。因此这三处**无需改动**。

### 3. 卡片无高度上限（次要）

- 翻转区 `ReviewCard.jsx:207` 只有 `minHeight: '320px'`；卡片容器 `:187-193` 有 `overflow: hidden` 但无高度约束；面板卡区 `ReviewPanel.jsx:134` 与弹窗卡区 `ReviewModal.jsx:201` 都只有 `minHeight: '360px'`。

### 4. 弹窗在矮视口下天然超 90vh（次要）

弹窗最小高度 = 头部(~48px) + 进度条(~19px) + 卡片(~360px) + 控制条(~52px) ≈ **480px**；`ReviewModal.jsx:123` 只有 `maxHeight: '90vh'`、无 `overflowY`。当视口高度 < ~533px（横屏手机、窄窗口）时，即便内容完全正常也会超 90vh，底部「下一张 / 完成」被挤出屏幕。

---

## 三、影响范围与表现

1. **正面短类型（word/phrase）—— 真实缺陷**：`bookmark.text` 异常过长时（主要是 phrase 误划过整句），正面大字无上限撑高卡片。
2. **弹窗矮视口 —— 独立缺陷**：短视口下弹窗内容超 90vh 且不可滚动、按钮不可达（与 `:54` 无关，正常内容也会触发）。

---

## 四、方案对比与选择

| 方案 | 评价 |
|---|---|
| ~~A｜滚动容器补 `minHeight: 0`~~ | ❌ no-op：三处本就是 scroll container（自动最小尺寸 0）、已正常滚动，补了无效果 |
| **E｜正面短类型大字（:54）补 `maxHeight`** | ✅ **唯一真实修复**，封住唯一无上限区 |
| **C｜弹窗外层补 `overflowY: auto`** | ✅ 独立价值：矮视口兜底（卡片最小高度 + 头尾控件 ≈ 480px 超矮视口 90vh） |
| B｜固定卡片高度 | ❌ 挤压正常「词 + 例句」卡片，改变一般情况 |
| D｜行数截断 / 省略号 | ❌ 藏内容，违背复习「翻面看全文」 |

**选择 E + C。** 原则：正常长度内容渲染与现在逐像素一致；`:54` 超长时在卡片内部滚动；弹窗在矮视口下可滚动、按钮始终可达。

## 六、明确边界

- 不改数据模型、不改翻译/调度逻辑、不引入新依赖。
- 不改 `ReviewPanel`：其所在页面本身可滚动，卡片经 E 修复后自然有界。
- 不改三处滚动容器（`:58`/`:65`/`:98`，本已正常滚动）。
- 改动仅为样式层（两个组件、两处小改），对正常内容零影响。
