## 4. Netlify Function 设计

### 4.1 文件

`netlify/functions/generate-recommendation.js`（新建）

### 4.2 接口

**Request：**
```http
POST /.netlify/functions/generate-recommendation
Content-Type: application/json

{
  "articleText": "完整的文章原文...",
  "title": "文章标题",
  "author": "作者（可选）",
  "kind": "article | book",
  "provider": "deepseek-recommendation-preset",
  "requestId": "客户端生成的请求 ID（用于日志追踪）"
}
```

**Response (200)：**
```json
{
  "result": {
    "intro": "一段有吸引力的中文推荐语...",
    "keywords": ["keyword1", "keyword2", "keyword3"],
    "keywords_trans": ["关键词1", "关键词2", "关键词3"],
    "excerpts": [
      "原文摘录段落1...",
      "原文摘录段落2...",
      "原文摘录段落3..."
    ],
    "excerpts_trans": [
      "摘录1中文翻译...",
      "摘录2中文翻译...",
      "摘录3中文翻译..."
    ]
  },
  "perf": {
    "requestId": "...",
    "provider": "...",
    "model": "...",
    "providerMs": 3200,
    "functionTotalMs": 3350,
    "inputTokens": 7200,
    "outputTokens": 3400
  }
}
```

**Response (error)：**
```json
{
  "error": "错误描述",
  "code": "INPUT_TOO_LARGE | AI_API_ERROR | PARSE_ERROR | TIMEOUT"
}
```

### 4.3 内部逻辑

```
1. 解析 request body → articleText, title, author, kind, provider, requestId
2. 校验必填字段（articleText, title）
3. 输入上限校验：articleText.length > 100000 → 返回 413（审核反馈 S12）
4. 根据 provider 解析 preset 配置 → 获取 model
5. 读取对应环境变量中的 API key（优先推荐专用 key → 回退翻译通用 key）
6. 构造 Prompt（见 §8）
7. 调用 AI API（通过 netlify/lib/aiProviders.js 共享适配器）
8. 解析 AI 返回的 JSON → 校验字段完整性
9. 若 JSON 解析失败 → 同 provider 重试一次
10. 若重试仍失败 → 切换 fallbackPreset 再试一次（审核反馈 S6）
11. 若 fallback 也失败 → 返回 500 错误
12. 返回结构化结果 + 性能数据（含 inputTokens/outputTokens，若 API 返回）
```

### 4.4 Provider 故障转移（审核反馈 S6）

```
primary provider (activePreset)
    │
    ├── 成功 → 返回结果
    │
    └── 失败（API 错误 / 超时）
            │
            ├── 重试 1 次（同 provider）
            │     ├── 成功 → 返回结果
            │     └── 失败 ↓
            │
            └── 切换 fallbackPreset
                  ├── 成功 → 返回结果（标注 perf.fallback = true）
                  └── 失败 → 500 错误（触发前端降级）
```

## 6. SubmitRecommendationModal 改造

### 6.1 State 设计（审核反馈 B5：统一 state）

```js
// 基本属性（预填自选中 item，用户可编辑）
const [title, setTitle] = useState('')
const [author, setAuthor] = useState('')
const [kind, setKind] = useState('article')
const [sourceUrl, setSourceUrl] = useState('')

// 策展内容（AI 填充或手动填写，共用同一套 state）
const [intro, setIntro] = useState('')
const [keywords, setKeywords] = useState([])
const [keywordsTrans, setKeywordsTrans] = useState([])
const [excerpts, setExcerpts] = useState(['', '', ''])          // 固定 3 条
const [excerptsTrans, setExcerptsTrans] = useState(['', '', '']) // 固定 3 条

// AI 生成状态
const [generating, setGenerating] = useState(false)
const [generationFailed, setGenerationFailed] = useState(false)
const [generationError, setGenerationError] = useState('')
const [hasAiGenerated, setHasAiGenerated] = useState(false)  // 标记是否已 AI 填充
```

**关键设计**：不区分 "aiIntro" vs "intro"。AI 生成成功 → 填入 `intro` 等 state；降级模式 → 同一套 state 展示为空的可编辑字段；提交时统一取值。这消除了审核反馈 B5 指出的矛盾。

### 6.2 缓存管理（审核反馈 B2：提升至父组件）

**ImportPage.jsx 中新增：**
```js
const [recommendationCache, setRecommendationCache] = useState({})
// 结构: { [importItemId]: { intro, keywords, keywordsTrans, excerpts, excerptsTrans } }

// 传入弹窗：
<SubmitRecommendationModal
  ...
  generationCache={recommendationCache}
  onCacheUpdate={setRecommendationCache}
/>
```

**弹窗中消费：**
```js
// 选中 item 改变时：
if (generationCache[selectedId]) {
  // 缓存命中 → 直接填充
  const cached = generationCache[selectedId]
  setIntro(cached.intro)
  setKeywords(cached.keywords)
  setKeywordsTrans(cached.keywordsTrans)
  setExcerpts(cached.excerpts)
  setExcerptsTrans(cached.excerptsTrans)
  setHasAiGenerated(true)
}

// AI 生成成功后：
const content = { intro, keywords, keywordsTrans, excerpts, excerptsTrans }
onCacheUpdate(prev => ({ ...prev, [selectedId]: content }))
```

### 6.3 核心流程

```
选中 item 改变时：
  1. 从 eligibleItems 中查找选中 item
  2. 预填基本属性：title, author, kind, sourceUrl
  3. 检查 generationCache[item.id]：
     - 有缓存 → 填充策展内容 state，setHasAiGenerated(true)
     - 无缓存 → 清空策展内容 state，setHasAiGenerated(false)
  4. 清空 generationFailed 状态

点击「生成推荐内容」：
  1. setGenerating(true); setGenerationFailed(false)
  2. 拼接 item.sections → 全文（遍历所有 section.body.text）
     - 防护：若拼接后 < 100 字符 → 提示"文章内容不足，无法生成"，停止（审核反馈 S2）
  3. 创建 AbortController（见 §5.3）
  4. 调用 generateRecommendationContent({ articleText, title, author, kind, signal })
  5. 成功 → 填充 intro/keywords/keywordsTrans/excerpts/excerptsTrans
           → 写入 generationCache[item.id]
           → setHasAiGenerated(true)
  6. 失败 → setGenerationFailed(true); setGenerationError(e.message)
  7. finally → setGenerating(false); abortRef.current = null

提交：
  1. 校验：title 非空 + intro 非空 + excerpts 至少 1 条非空
  2. 调用 submitRecommendation（含基本属性覆盖值）
  3. 成功 → onSubmitted() → 关闭弹窗
  4. 失败 → 展示错误，保持弹窗打开
```

function parseAIResponse(raw) {
  // 1. 尝试直接解析
  try { return JSON.parse(raw) } catch {}

  // 2. 去除 markdown fence 后重试
  const cleaned = raw
    .replace(/^```json\s*/i, '')
    .replace(/^```\s*/i, '')
    .replace(/\s*```$/, '')
    .trim()
  try { return JSON.parse(cleaned) } catch {}

  // 3. 尝试提取第一个 { 到最后一个 } 之间的内容
  const match = raw.match(/\{[\s\S]*\}/)
  if (match) {
    try { return JSON.parse(match[0]) } catch {}
  }

  // 4. 解析失败 → 抛错，触发重试/降级
  throw new Error('AI 返回格式无法解析')
}

## 10. 错误处理矩阵

| 环节 | 错误类型 | 处理 |
|------|---------|------|
| 输入校验 | articleText > 100K 字符 | 返回 413，前端提示「文章过长」 |
| 输入校验 | articleText < 100 字符 | 禁用生成按钮，提示「文章内容不足」 |
| Netlify function 不可达 | NetworkError | 展示错误 + 降级手动模式 |
| AI API 返回错误 | APIError (4xx/5xx) | 同 provider 重试 1 次 → 切换 fallback → 仍失败则降级 |
| 前端超时 | AbortError | 展示「生成超时」+ 降级手动模式 |
| AI 返回非 JSON | ParseError | 重试一次 → 仍失败则降级 |
| AI 返回 JSON 缺字段 | ValidationError | 用默认值填充缺失字段（'' 或 []），不阻塞 |
| updateImportItem 失败 | 各种 | 终止提交流程，展示错误，弹窗保持 |
| submitRecommendation 失败 | 各种 | 展示错误信息，弹窗保持（属性已更新为良性状态） |
