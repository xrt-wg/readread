# 推荐提交审核发布 实施前审核反馈处理

## 1. 结论

实施前审核的四项阻塞反馈均已确认成立，并已修订进讨论记录和实施方案。12 项建议中，S1 至 S9、S11、S12 采纳；S10 不纳入本次功能实施，作为独立的后台死代码维护事项跟踪。

已确认的核心口径是：用户无法绕过审核直接写入公开推荐；内部审核信息不能暴露给提交者或公众；已发布内容必须先下架后编辑；任意状态的同内容记录均阻止新提交。

## 2. 阻塞项处理

| 编号 | 处理结论 | 方案更新 |
| --- | --- | --- |
| B1 | 采纳 | 删除用户直接 INSERT/UPDATE RLS 与权限，所有写入改为受控 SECURITY DEFINER RPC；增加绕过写入测试。 |
| B2 | 采纳 | `internal_note`、审核人移至管理员专用附属表；内容指纹和规范化来源链接移至私有快照表；主表不放敏感列。 |
| B3 | 部分采纳 | 采纳“统一文档口径”；不采纳“active 可直接编辑”。已确认规则为先下架、修改、恢复待发布、再发布。 |
| B4 | 采纳并完成规则收敛 | 指纹或规范化链接任一命中即重复；所有既有状态均阻止新记录；下架内容只能恢复原记录。 |

## 3. 建议项处理

| 编号 | 处理结论 | 方案更新 |
| --- | --- | --- |
| S1 | 采纳 | 周限额统计所有成功创建记录，包含后续 rejected 与 removed。 |

| S6 | 采纳 | 使用首次发布时间与最近发布时间；恢复发布清空当前下架信息，历史保留审计。 |

## 4. 实施约束

1. 本期不实施 AI 生成、积分、订阅兑换或通知。
2. 历史 `active` 记录保持公开；无正文快照的记录不得因迁移失败而中断上线，但应禁止新的加入书架并标记运营补录。
3. 数据库权限、状态约束和 RPC 验收必须先于前端界面上线。
4. 管理员下架后只能在非公开状态编辑，重新发布必须经过 `approved`。

## 5. 可进入实施的条件

讨论记录、实施方案和本反馈处理记录已经统一。后续实施必须以本文件的处理结论为准，并在完成后按安全、状态流、快照独立性、审计和用户体验五类验收项复核。
