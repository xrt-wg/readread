## 四、遗留问题

### 🟠 P1 — 审核后台缺少正文快照预览与内容指纹（方案明确要求的核心能力未落地）

**位置**：`RecommendationModerationPanel.jsx` vs 实施方案 §5.3.2、§5.3.7

方案要求审核工作区提供"提交元信息、来源链接、**内容快照预览和内容指纹**"以及"生命周期和审计摘要"。实现的审核面板只有表单字段与状态按钮：管理员无法阅读提交的正文快照、看不到内容指纹、看不到生命周期时间与审计摘要。快照表为审核而生的核心用途在 UI 层未落地——目前管理员等于在不读正文的情况下审核。

**建议**：面板增加快照正文预览（快照表管理员 RLS 已就绪，可直接查询）、内容指纹与 `first_published_at`/`published_at`/`reviewed_at` 生命周期行；导航项增加待审核计数（§5.3.1）。

### 🟠 P2 — 重新发布未清空下架信息，与决策 §9.7 直接冲突

**位置**：`admin_publish_recommendation`、`admin_approve_recommendation` vs 决策记录 §9.7

决策明确"当前下架原因和时间在重新发布时清空"。两个 RPC 均未清空 `removal_reason`/`removed_at`（approve 只清 rejection 字段）。后果：恢复发布的 `active` 记录残留过期下架原因，且因"Anyone can view active"是整行 SELECT，公众可直接读到该残留字段。

**建议**：在 publish RPC 中 `removal_reason = null, removed_at = null`（历史已在审计中保留）。

### 🟠 P3 — 历史 `active` 记录未回填 `published_at`

**位置**：主迁移 vs 实施方案 §6.2

方案明确要求"为历史公开记录补齐 `published_at`，无可靠原始时间时使用 `created_at`"。迁移只加了列，没有 UPDATE 回填语句。历史记录在"我的推荐"与管理端均无发布时间。

**建议**：补一个数据补丁迁移：`update ... set published_at = created_at, first_published_at = created_at where status = 'active' and published_at is null`。

### 🟠 P4 — 无快照历史记录的"加入书架"会硬崩溃，且"运营补录标记"未实现

**位置**：`addRecommendationToBookshelf` vs 审核反馈处理 §4.2

反馈处理要求"无正文快照的记录……禁止新的加入书架并标记运营补录"。两点均未落实：没有快照缺失标记字段；`get_recommendation_snapshot` 对无快照记录返回 null 后，`sourceItem.sections` 直接抛 TypeError，用户看到不友好错误而非受控提示。

**建议**：服务层对 null 快照返回带业务码的友好错误（如"该内容暂未开放加入书架"）；管理端列表标记快照缺失记录，交由运营补录。

### 🟡 P5 — 恢复发布复用 `recommendation.approved`，审计无法区分首次通过与下架恢复

方案 §3.3 审计清单含 `recommendation.reopened`；实现将 removed→approved 并入 approve RPC，审计动作同为 `recommendation.approved`。可在 payload 中记录前置状态以保留区分能力。

### 🟡 P6 — 书架条目"提交推荐"的预选功能丢失

`ImportPage` 仍向弹窗传 `preSelectedId`、`generationCache` 等旧 props，新弹窗全部忽略；从具体条目发起提交不再预选该条目，且 `recommendationCache` 成为死 state。建议恢复预选支持并清理死 props/state。

### 🟡 P7 — `migrateLegacyFeaturedArticles` 遗漏清理（S9 残留）

该函数仍导出，但其直写 INSERT 在权限撤销后必然逐条失败（静默 skip）。`featured_articles` 表已不存在，函数实为死代码，建议删除。

### 🟡 P8 — 新 UI 硬编码颜色回潮

`ImportPage` 我的推荐状态色（`#2563eb`、`#16a34a`）与弹窗成功图标色（`#16a34a`）为硬编码，与提交 `ff36b12` 确立的 CSS 变量规范相悖，夜间模式下可能失真。

### 🟡 P9 — "我的推荐"展示字段不全

方案 §5.2 要求展示提交时间、审核通过时间、发布时间及可见原因；实现仅在无原因时显示提交日期，`approvedAt`/`publishedAt`/`rejectionAt`/`removedAt` 已入 DTO 但未渲染。

### 🟡 P10 — 验证记录对关键安全项缺少执行证据

联调记录自述未覆盖：驳回流程、跨账号去重、每周限额、原文变更后的快照独立性；手册 §7/§8 的权限回归（直接 INSERT 被拒、内部备注不可见、他人记录不可见）亦无执行记录。这些恰是 B1/B2 的验收测试，建议补测并在记录中留证。

## 五、总结

### 结论

**有条件通过**。本次实施完整落实了实施前审核的全部 4 个阻塞项：审核不可绕过（B1）、敏感信息列级隔离（B2）、状态机口径统一（B3）、全状态去重（B4）均在数据库层真实生效，且 12 项建议中 10 项完整落实。核心闭环（提交→审核→发布→下架→快照加入书架）经联调验证与本审核的代码核验一致，构建独立验证通过。

2. P5–P10 可排入近期迭代，其中 P10 的权限回归补测建议与 P1–P4 修复后一并执行。
