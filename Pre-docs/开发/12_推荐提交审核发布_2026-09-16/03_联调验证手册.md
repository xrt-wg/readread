# 推荐提交审核发布：联调验证手册

> 更新时间：2026-09-17  
> 前置条件：`20260917000000_recommendation_moderation_workflow.sql` 已在 Supabase 成功执行。

## 1. 验证目标

确认用户侧、管理员侧与数据库状态流转一致，且用户不能绕过审核直接修改或发布推荐。

## 2. 测试准备

准备两个账号：

- 普通测试账号 A：书架中至少有一篇 `origin=imported` 的内容，且已标记阅读完成；该内容不要已有推荐提交。
- 管理员账号 B：`admin_roles` 中具备有效管理员角色。

建议使用与正式内容不同的测试标题，例如：`[联调] 推荐审核流程测试`。来源链接可留空。

## 3. 用户提交与状态可见性

1. 使用账号 A 登录，进入书架区的推荐页面。
2. 点击仅保留图标的“提交推荐”入口。
3. 从可选的已读完导入内容中选中测试素材；确认标题、作者、来源链接可调整，来源链接可留空。
4. 提交后应看到成功提示；打开“我的推荐”。
5. 验收：出现一条状态为“待审核”的记录；推荐语、标签、摘录等 AI 生成字段不再出现；没有撤回或重新提交入口。

## 4. 管理员审核与发布

1. 使用账号 B 登录，进入管理员后台 → “推荐审核”。
2. 在“待审核”队列选中测试记录。
3. 填写推荐语、至少一条摘录、可选标签，以及内部备注；点击“保存填写”。
4. 点击“通过审核”。
5. 验收：记录变为“已通过，待发布”，前台推荐发现页仍不可见。
6. 点击“发布”。
7. 验收：记录变为“已发布”，普通用户的“发现推荐”可见，并可加入书架。

## 5. 快照验证

1. 发布后，使用账号 A 修改或删除原始导入内容（标题以外的正文变化最易观察）。
2. 使用另一个普通账号，或清理账号 A 的同来源副本后，从推荐页将该推荐加入书架。
3. 验收：加入书架后的内容仍保留提交时的正文快照，不依赖原始书架内容是否存在。

## 6. 下架、修改、重发

1. 管理员在“已发布”筛选中选择测试记录，填写下架原因，点击“下架”。
2. 使用账号 A 打开“我的推荐”。
3. 验收：状态为“已下架”，可见下架原因；发现推荐中不可见。
4. 管理员现在可以修改推荐信息；保存后点击“通过审核”，再点击“发布”。
5. 验收：重新回到“已发布”。

## 7. 驳回与去重

1. 为避免影响主测试记录，提交另一篇可用测试素材。
2. 管理员填写驳回原因并点击“驳回”。
3. 验收：账号 A 的“我的推荐”显示“已驳回”和原因，且无重新提交按钮。
4. 再尝试提交同一素材或正文/标准化来源链接相同的内容。
5. 验收：服务端拒绝重复提交；即使绕过前端也不能成功写入。

## 8. 权限回归检查

使用普通账号 A 确认：

- 不能在浏览器网络请求中直接 `INSERT` 或 `UPDATE recommendation_submissions` 成功。
- 不能查看其他人的待审核、驳回或下架记录。
- 不能查看管理员内部备注。
- 只能在自己的记录中查看驳回原因和下架原因。

## 9. 完成后的测试数据处理

测试记录应由管理员通过“下架”保留审计轨迹；不要直接删除主表记录。若要继续保留作为演示内容，可由管理员完善文案后重新发布。
