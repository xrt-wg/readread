## 1. 目标与范围

为新账号及存量未使用空账号提供一次二选一阅读弹窗。用户点击一篇固定推荐文章后，系统完成推荐副本建立、进入阅读区和打开正文，用户无需访问中间页面。

本次只改动与上述路径必要相关的部分。回顾、推荐发现、导入方式、统计布局、全局导航不扩展改版。

## 3. 用户流程

### 3.1 正常路径

1. 账号初始化完成，确认可使用云端库。
2. 等待本地试用迁移完成；存在未解决的待迁移数据时不弹出。
3. 服务端查询账号首次选文状态及已有使用证据。
4. 若适用且未处理，读取两篇固定推荐的展示信息，并确认正文快照有效。
5. 两篇均可用后显示弹窗，标题“想先读哪一篇？”。
6. 点击卡片；界面锁定提交并显示所选卡片加载状态。
7. 服务端事务生成或复用阅读记录、进入 reading 状态、保存已选择状态，并返回 reading_id。
8. 读取完整正文，经正常 onOpen 路径进入 ReaderPage。
9. 返回后使用正常阅读区；不再次显示选文弹窗。

“推荐区→书架→阅读区”是业务语义，不需要渲染中间页面。数据库事务可在同一次提交内完成副本创建和最终 reading 状态，不需要让 unread 中间状态对用户可见。

### 3.2 关闭路径

关闭按钮或 Esc 触发账号级 dismissed 写入，界面随即退出弹窗。写入失败时本次会话仍不重新弹出，后台有限重试；必要时以轻量反馈告知同步失败。不得把本地标记当成跨设备成功。待请求结束后以服务端状态为准。

提交选择期间禁用重复选文和关闭，设置明确的超时恢复；不能永久锁住弹窗。网络结果不确定时先查询事务结果，再允许重试或关闭。

## 4. 资格及一次性状态

### 4.1 判定原则

- 未登录、受限账号、账号状态异常：不触发。
- 正在同步、数据加载失败、待迁移本地数据尚未处理：不把未知当作空。
- 已经 chosen、dismissed、suppressed：不触发。
- 存在任何个人阅读内容、有效进度或收藏：不触发，并记录 suppressed，避免日后清空内容又弹出。
- 能从软删除内容等历史记录证明曾使用：不触发。
- 完全没有使用证据且未处理：适用，包括上线前注册的空账号。

不以 readingZoneItems.length、注册日期或 last_seen_at 单独判定。历史数据若已经物理删除且没有保留使用记录，无法准确还原历史；实施前核查实际存储情况，对不可识别者按“无可见使用证据的空账号”处理并记录这一限制。

### 4.2 建议持久化结构

新增 user_first_reading_states，避免直接复用 profiles 的迁移标记：

| 字段 | 语义 |
| --- | --- |
| user_id | 主键，关联 auth.users；一账号一条。 |
| status | pending / chosen / dismissed / suppressed。 |
| selected_submission_id | 选中的推荐 ID，可空。 |
| selected_reading_id | 成功生成的个人阅读 ID，可空；删除关联内容时保留已处理状态。 |
| handled_at | chosen / dismissed / suppressed 的处理时间。 |
| created_at、updated_at | 状态时间。 |

只允许读取自己的状态；写入由受控 RPC 完成。账号从 pending 成功选择或关闭后不因刷新、换设备、配置换文章而重置。

保留阅读 ID 用于响应丢失后的恢复；chosen 表示业务事务成功，不表示客户端一定已经渲染正文。打开正文失败仍提供“重新打开”，不重新创建内容。

## 5. 两篇内容的配置与读取

### 5.1 配置

单行配置 first_reading_config 保存 enabled、两个不同的 submission_id、updated_at。按用户后续要求，新增“后台→首次阅读”配置 UI，通过管理员 RPC 选择和保存；不在源码写入文章 ID。普通用户无配置表写权限。

- 默认 disabled，禁止写入虚构文章 ID。
- 实施前取得用户指定的两篇文章，验证后写入并启用。
- 前端不能从推荐列表第一页截取两项，也不能按热度静默替换。
- 管理员从后台候选列表选择两篇，预览卡片后保存并启用；无需手动查询 ID。两管理员并发修改通过 updated_at 检查避免静默覆盖，每次保存写入审计日志。
- 两篇都必须 status=active，有合法、非空且能被阅读器处理的快照 sections。
- 卡片使用真实标题、短摘要、字数；字数来自正文快照的可靠统计。推荐列表现有字段没有提供完整正文统计，不能假设列表接口已包含字数。
- 卡片与实际副本标题尽量保持一致：若推荐运营标题与快照标题不同，使用同一明确来源或在上线核对时统一，避免点击后出现另一标题。

### 5.2 降级

未启用、配置错误、候选不足两篇、正文不可用或加载失败时，不弹出残缺的二选一，不自动加入任何内容；正常首页继续可用。本次挂载不循环弹窗或持续重试，保留 pending 以便后续进入时重试。

推荐在弹窗打开后被下架：提交时再次验证并返回简短错误；刷新候选，无法凑齐指定两篇时关闭选择界面并回正常首页。不替换成其他推荐。

## 6. 服务端事务与幂等

建议提供三个 RPC，名称可调整：

1. get_first_reading_offer：检查账号身份、状态及使用证据，返回资格、处理状态及两篇轻量卡片信息；若已选择，返回恢复所需的 reading_id。不得暴露其他用户的状态或私有快照。
2. dismiss_first_reading_offer：幂等记录关闭；不得覆盖已提交成功的 chosen。
3. choose_first_reading_offer(p_submission_id)：完成业务事务并返回 reading_id。

### 6.1 choose 事务顺序

1. 由 auth.uid() 确定用户，不信任客户端传入的 user_id；校验账号仍有效。
2. 创建并锁定该账号状态行。并发初始化用主键冲突处理后 SELECT FOR UPDATE，保证 A/B 同时提交只会有一个获胜。
3. 若已 chosen，返回既有结果，不再创建、切换为另一篇或重复计算新增行为；dismissed/suppressed 则返回不可选择。
4. 对 pending 再检查使用证据。其他标签页已导入或迁移内容时，不继续强行新手流程。
5. 校验传入 ID 属于启用配置，推荐仍 active，快照合法；锁定相关配置和推荐行，避免读取后状态变化造成不一致。
6. 按现有推荐副本规则组装 readings：保留标题、作者、格式、语言、来源、章节及统计；origin=featured，share_source_id 指向推荐，share_status=private；最终状态为 reading，写入开始时间。
7. 章节 ID、父子结构与字数归一化必须与 assembleSections / deriveParentIds 的当前输出语义一致。实施时抽取或实现等价校验，并用嵌套章节样例核对，不能直接复制可能不完整的 JSON 就视为完成。
8. 使用现有加入人数语义重算 add_count 和推荐得分，不做前端加一作为事实来源。
9. 将账号状态置为 chosen，写入 selected_submission_id、selected_reading_id、handled_at。
10. 同一事务提交；任何数据库步骤失败则整体回滚。

不要对所有普通推荐副本强加全局唯一约束，以免无意改变其他入口既有行为。首次流程的唯一性由账号状态锁和所选结果保证。

### 6.2 并发与生命周期

- 二选一、关闭和重试共享同一状态行锁，明确先提交者生效。
- 新增用户级锁若同时用于阅读区上限，需要现有 start_reading 及能直接创建 reading 状态的入口遵守相同锁协议；否则不得宣称解决了所有并发上限问题。实施时盘点这些入口，仅做必要的共享锁适配。
- 来源推荐在用户成功加入后被下架，不删除用户已获得的独立阅读副本；继续阅读遵循现有逻辑。
- 已选阅读被删除，不恢复新手资格，不通过重试偷偷重新创建；返回已处理结果并使用正常首页。
- RPC 固定 search_path，限定执行授权，显式校验 auth.uid() 和账号状态；RLS 阻止跨用户查询和任意改写首次状态。

## 7. 前端实现

### 7.1 组件与服务

- 新增 FirstReadingChoiceModal：只处理两篇展示、选择、关闭、加载和错误。
- 新增首次阅读服务模块，封装上述 RPC 和返回值；不要散落在 ImportPage 中直接拼数据库请求。
- ImportPage 负责在资格准备好后展示，并将选定 reading_id 交给现有正文打开逻辑。
- App 明确提供迁移就绪信号，避免 silentImporting 尚未来得及更新时先触发首次资格请求。迁移失败且本地仍有有效数据时暂不触发。
- 账户切换、退出、组件卸载后丢弃旧请求响应；取消本地请求不等于撤销已提交数据库事务。

### 7.2 交互与可访问性

- 标题：想先读哪一篇？无流程说明、功能导览或任务进度。
- 两张等权卡片展示标题、简短摘要、字数；整卡用 button 语义，不嵌套其他可点击按钮。
- 桌面并列，窄屏纵排；标题不因截断丢失关键辨识信息。
- 沿用现有主题变量，检查日间和夜间的对比度。
- dialog 语义、可读标题、焦点圈定、键盘选择、关闭后焦点恢复；遮罩后页面不可交互。
- 默认焦点不预先触发或暗示系统替用户选中某篇。
- 选择处理中所有选择动作禁用，错误反馈在弹窗内，重试不重复创建。

### 7.3 正常首页衔接

已登录阅读区为空时，不再复用游客营销 Hero。显示简短“当前没有正在读的内容”，并提供与账号内容相符的正常操作：书架有内容时“从书架选择”，没有内容时“添加内容”。这些按钮复用现有书架和导入能力，不增加教学说明。

未读完返回，文章出现在阅读区并保留进度；读完后沿用自动归架与推荐评分。关闭弹窗或读完后不追加回顾引导、不重新弹出选文。

游客首页和既有试用功能保持原有产品范围，仅拆开渲染分支，避免本次影响匿名访问。

## 12. 审核确认后的实施约束

1. **恢复分类（P1）**：getReading 成功返回 null 时回正常首页，不创建副本、不使用旧对象兜底；网络失败可重试，权限错误刷新账号身份，正文结构异常报告内容不可用。正常 chosen 状态不在每次进入时自动打开；仅当前提交/恢复动作打开正文。
2. **迁移门控（P2）**：每个认证账号都先检查本地三类试用键，不仅 anonymous→authenticated；解析失败/存储不可访问为 unknown。有效待迁移内容先同步；部分失败保留本地原始数据，绝不因捕获错误后继续执行而清空。重试不覆盖已经存在的云端阅读/收藏进展；只补未完成迁移。提供轻量重试反馈，不阻断其他正常使用；迁移未解决时不请求首次资格。迁移状态绑定 userId，换号不会复用成功标记。
3. **字段（P3）**：明确保留 cover_url 和合法 kind；kind 缺失时按格式兜底。现有 createReading 实际推断 kind，不是透传。正常推荐加入同步携带 kind，避免两个入口结果不一致。
4. **字数（P4）**：按现有英文空白分词统计，空文本为零；配置核对两篇字数与正文是否合理，不新增中文分词。
