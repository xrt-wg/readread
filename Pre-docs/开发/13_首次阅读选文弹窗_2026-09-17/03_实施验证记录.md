原生并发场景：

1. 同账号 A/B 同时选择，返回同一 reading_id，仅一条副本。
2. 普通导入持锁、choose 等待，导入提交后 choose 返回 suppressed。
3. dismiss 持锁并先提交，choose 返回 dismissed，不创建文章。
4. 两个直接写入竞争第 5 个在读名额，仅一个成功，最终 5 项。
5. 不同账号同时选择同一推荐，加入人数等于真实未删除副本的不同用户数。

本地 Docker 未运行；改用 npm 注册表下载的隔离测试依赖。原生 PostgreSQL 首次受 Windows 沙箱令牌限制启动失败，经工具授权在沙箱外完成测试。测试只监听 127.0.0.1:55439，结束后已停止；数据目录位于工作区被忽略的临时 node_modules 内，不连接 .env 指向的服务。

## 3. 复现

测试依赖安装在 .tmp-first-reading-validation，不改变项目 package.json 或 package-lock.json：

```powershell
npm install --prefix .tmp-first-reading-validation --no-save --package-lock=false @electric-sql/pglite embedded-postgres pg
node scripts/test-first-reading-sql.mjs
node scripts/test-first-reading-migration.mjs
node scripts/test-first-reading-concurrency.mjs
npm run build
```

原生并发测试脚本当前针对 Windows，使用独立临时目录和固定端口 55439；若端口冲突先修改测试端口。模拟架构用于精确验证本次迁移，不能替代项目完整 Supabase 环境联调。

## 4. 上线前仍需完成

1. 用户指定两篇真实推荐的标题与 recommendation_submissions.id。
2. 在目标环境应用迁移（本次未执行），先保持 disabled。
3. 核查两篇推荐 active、正文快照非空、标题对应、英文词数合理、排版/划词可用。测试环境分别用新账号和存量空账号完整走一次；核对实际 RLS、登录迁移、读完评分。
4. 由授权维护者将两个真实 ID 写入 first_reading_config，验证后启用。不得复制测试 fixture-a / fixture-b 或 SQL 测试 a / b。
5. 线上异常时仅关闭 enabled，不删除用户阅读、收藏和首次处理状态。

配置操作示意（命名参数由维护工具绑定真实 ID，不可原样运行占位字符串）：

```sql
update public.first_reading_config
set submission_a = :confirmed_submission_a,
    submission_b = :confirmed_submission_b,
    enabled = true,
    updated_at = now()
where id = true;
```

## 5. 已知边界

- 无法还原已物理删除且没有其他记录的历史使用；保持原方案口径。
- 从旧版本遗留且没有归属信息的本地数据，首次同步时绑定当前账号；之后换号会保留并阻止错误转移。损坏本地数据不会自动删除。
- 完成 chosen 后不在每次刷新强制打开；从正常阅读列表继续。当前提交中遇到响应丢失可重复调用 choose 恢复同一结果。
- 正式内容、生产迁移和完整 Supabase 线上联调尚未完成，不能把本地通过表述为已上线可用。
