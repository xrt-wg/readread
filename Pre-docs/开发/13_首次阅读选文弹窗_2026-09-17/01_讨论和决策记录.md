## 1. 问题与目标

已注册用户进入阅读区时，当前空状态仍展示品牌口号和“立即体验”，更接近访客介绍页，未直接承接阅读意图。当前空状态由阅读区为空触发，因此有书架内容、读完最后一篇或放回所有在读内容的用户也可能看到同一画面。

本次目标是让尚未开始使用的账号通过一次内容选择进入真实阅读。首次上手的核心是阅读；回顾、推荐、书架等功能由用户在正常使用中自行发现。

不以解释产品结构、完成教程或点击引导按钮作为成功标准。

## 2. 讨论收敛过程

1. 用户指出，登录后的初始化阅读首页不应仅复用网站初始页。
2. 初步分析提出欢迎信息、导入、示例和轻量说明等方案。
3. 用户明确修正：不应有过多文字指引和指导元素，应通过符合直觉的设计降低摩擦，使用户渐进式掌握。
4. 用户进一步明确：首次上手只聚焦阅读；首次登录显示弹窗，从推荐区选取两篇内容供用户选择，选中后自动完成“推荐区→书架→阅读区”，直接打开文章。
5. 助手补充关闭、已有数据延续、失败重试和读后返回的必要边界，用户同意继续整理。
6. 本轮补充确认：两篇文章固定指定，标题实施前补齐；已有空账号也弹出一次。

前期讨论中的欢迎任务页、首页三路引导、合并导入输入框、统计区和全局导航改版，不属于本次已确认方案，不得顺带实施。

## 3. 已确认产品决策

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D01 | 以开始真实阅读为首次上手目标 | 不附加回顾、推荐等教学任务，不要求收藏才能完成上手。 |
| D02 | 使用两篇文章的选文弹窗 | 文案简短，例如“想先读哪一篇？”，展示两张真实内容卡片。 |
| D03 | 两篇来自推荐区并固定指定 | 不随机、不按热度自动替换；标题与推荐提交 ID 在实施前补齐。 |
| D04 | 点击卡片即开始 | 不增加选中后的确认按钮；自动保存推荐副本、置为正在阅读、打开正文。 |
| D05 | 保留完整业务关联 | 推荐来源、快照、加入人数统计及读后评分沿用正常推荐内容语义。 |
| D06 | 可以关闭 | 用户不必选择；关闭后进入正常首页，不反复弹出。 |
| D07 | 状态按账号保存 | 选择完成或关闭后，重新登录、换设备均不再自动弹出。 |
| D08 | 已有空账号也适用 | 不是仅上线后新注册账号；存量尚无使用内容的账号也获得一次选文机会。 |
| D09 | 延续已有使用 | 有内容、进度、收藏或待迁移试用数据的账号优先延续原有使用，不覆盖为新手流程。 |
| D10 | 返回后回归正常产品 | 未读完返回时能看到所选文章；读完归架后不重新弹窗，也不返回“立即体验”营销空状态。 |
| D11 | 最少必要信息 | 卡片展示标题、短摘要、字数等决策信息；不解释内部搬运流程，不堆叠教程。 |

“已有空账号”是尚无内容或使用记录的存量账号，不等于只要当前阅读区为空。曾使用后主动清空内容的账号不应被重新视为新用户。

## 4. 经代码核对的业务事实

以下为本地代码核对结果，不代表已经完成线上运行验证。

| 事实 | 依据 |
| --- | --- |
| 阅读与书架共用 readings；阅读区为 reading 状态，其余相关状态归书架 | src/services/readings.js |
| 阅读区现有上限是 5 项；开始阅读调用 start_reading RPC | src/services/readings.js、20260711000000_unify_readings_table.sql |
| 推荐加入会复制已发布推荐的不可变快照，生成用户自己的阅读记录 | src/services/supabase/recommendationService.js、get_recommendation_snapshot RPC |
| 推荐副本使用 origin=featured、share_source_id 指回推荐 | addRecommendationToBookshelf |
| 当前推荐加入和开始阅读是分步调用，不能仅靠按钮禁用保证跨设备去重 | recommendationService.js、readings.js |
| 加入人数按未删除副本的不同用户数量重算，不是每次简单加一 | increment_recommendation_add_count RPC |
| 标记读完会尝试归架；推荐来源内容保留评分路径 | src/components/ReaderPage.jsx |
| 登录存在本地试用数据迁移，不能在迁移未完成时判断账号为空 | src/App.jsx |
| profiles 的 last_seen_at 在 ensure_profile 中刷新，不能用它直接识别首次业务使用 | src/services/supabase/profile.js、ensure_profile RPC |

历史文档中的“书架移入阅读区生成独立副本”不是当前统一模型。这里仅推荐内容加入个人库时生成跨用户副本，个人书架到阅读区是同一记录的状态变化。

## 5. 交互及异常边界

- 常态：两张文章卡片；桌面并列、窄屏纵向；整卡一个选择动作。
- 选择中：仅选中文章显示加载反馈，同时防止再次提交另一篇。
- 关闭：显式关闭按钮和 Esc，按账号记录关闭结果；遮罩点击默认不关闭，避免误触。
- 请求失败：短错误信息和重试；不跳到空白阅读器、不伪装成功。
- 推荐缺失、下架或正文不可用：不随机补位，不拿旧示例替代；完整二选一不可用时不阻塞用户进入正常首页。
- 两篇均可用才展示完整弹窗；短暂加载异常不消耗账号的一次机会。
- 已成功创建阅读但客户端未收到响应：重试复用同一结果。
- 完成后：依赖正常阅读行为继续使用，不自动打开回顾，不追加连续教程。

异常处理、事务划分与字段命名属于实施设计，详见配套方案，不把这些技术选择描述为用户逐项指定。

## 6. 范围

包含：选文弹窗、资格判定、账号级处理状态、固定文章配置、可靠的自动开始阅读、登录迁移衔接、已登录阅读区空状态的必要调整。

不包含：重做推荐或回顾模块、英语测试、学习目标、打卡、个性化推荐、全局导航和统计布局重设计、导入流程重构、会员或商业化设计。

游客原有试用入口不在本次重设计范围内。登录用户的营销空状态需拆分，避免完成首次阅读后体验回退。

## 8. 完成判定

合格账号看到固定两篇文章，单击任一篇后进入真实正文；该内容拥有正确的推荐关联和正在阅读状态；返回后可继续读，读完后沿用正常归架和评分。已处理账号不重复弹出，有既有内容的用户不被打断。故障与并发不会产生重复内容或错误完成状态。

## 9. 审核复核及范围补充（用户已确认）

2026-09-17 用户确认独立复核口径：P1–P5 按修正后的规则落实，不照搬审核中的不准确事实。实施包含必要的迁移失败保留和恢复、正常推荐加入的 kind 透传，以及跨入口并发控制。正文查询 null 只表示不可用，不断言已删除；权限错误不视为无限可重试的网络错误。字数继续采用英文空白分词口径。

状态行锁仅保证首次操作间互斥，不等同于普通导入和迁移已参与锁。实施以数据库用户级写入锁协调相关内容写入；审核中“资格复查天然覆盖所有竞态、无需其他锁适配”的结论不采纳。
