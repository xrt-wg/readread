## 三、重点核验问题清单

### 3.1 🔴 P1：S2 计数后端 + 后台可调阈值（最高优先级）

1. **计数表与原子性**：`translate_rate_limits` 主键是否 `(scope, scope_id)`；`consume_translate_quota` 是否用**单条 `insert ... on conflict (scope, scope_id) do update`** 原子固定窗口递增（窗口起点过期重置为 1），无 SELECT-then-UPDATE 竞态？
2. **阈值来源**：函数是否每次调用读 `translate_rate_limit_config`（`coalesce` 兜底默认），而非硬编码/环境变量？
3. **授权边界**：`consume_translate_quota` 是否 `revoke all ... from public, anon, authenticated`（仅 service_role 可调）；是否 `security definer set search_path=public`？
4. **失败语义**：LLM 路径计数后端不可用是否 **fail-closed（拒绝）**；直译路径是否 **fail-open（放行）**？
5. **环境变量**：函数是否读取 `SUPABASE_URL`/`SUPABASE_SERVICE_ROLE_KEY`/`SUPABASE_JWT_SECRET`，且 JWT 密钥来源正确（Supabase Dashboard → Settings → API → JWT Secret）？

### 3.2 🔴 F1：前端「已提交」判别（流程断点，最高优先级）

发码即建单后 `status='pending'` 从开弹窗即恒为真。请逐处核验：

1. `AuthPanel.jsx` 会员权益区（原 L303）「已提交，等待核对」的判别是否由 `paymentReq?.status === 'pending'` 改为 `paymentReq?.claimedAt != null`（或等价）？
2. `AuthPanel.jsx` 传 `PaymentModal` 的 `pending` prop（原 L459）是否同步改为 claimedAt 驱动？
3. `PaymentModal.jsx` 在 `pending=false`（发码未提交）时是否仍显示「我已支付，申请开通」按钮；在 `pending=true` 时才显示「已提交」？
