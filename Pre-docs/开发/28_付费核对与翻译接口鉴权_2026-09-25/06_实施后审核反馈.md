## 四、无新回归专项核验

### 4.1 S2 的 service_role 直连信任边界 — **无回归**

`translate.js` 以 `SUPABASE_SERVICE_ROLE_KEY` 直连，仅调用 `consume_translate_quota`（该函数被 `revoke all` 后仅 `grant to service_role`，是 service_role 侧唯一可达入口）。密钥仅在 Netlify 服务端 env，前端链路（`aiProviders`）只用 `getSession()` 注入用户 access_token、经 `getSupabaseClient()`（anon/authenticated）走 RPC，**service_role 密钥未进入前端 bundle**。边界成立，与 02 §关键口径一致。

### 4.2 F1 前端判别改动 — **无回归**

`paymentSubmitted` 叠加 `status==='pending'` 后：`granted` 行（claimed_at 非空、已发放）判 false，短暂窗口内「立即开通」按钮不会误触发建单（begin 会幂等复用/新建，且 admin 端 `status<>'pending'` 拦截重复确认）。rejected 行正确回到「立即开通」。无反向破坏。

### 4.3 JWT 验签 — **无回归**

`algorithms:['HS256']` 显式锁定，杜绝 RS256→HS256 算法混淆；`exp` 由 jsonwebtoken 默认校验；非法 token / 缺密钥均 401（LLM fail-closed）。`iss`/`aud` 未显式 pin，见 §五 O3（防御纵深项，非漏洞）。

## 五、新发现（P3 级，均非阻塞）

> 以下为独立复核中发现、超出 03/04 范围或属实现细节的改进建议，均不影响落库验收，建议按需采纳或记录为后置。

### O1 后台 admin 闸门强度与 recommendation 模块不一致

新增 admin RPC（`admin_reopen_payment`、`admin_get/save_translate_rate_limit_config`）的闸门仅 `is_current_user_admin()`（查 `admin_roles` 有效 admin 角色）。`recommendation_submission_config` 的同类 admin RPC 额外叠加 `exists(profiles where status='active')`。**但**这与既有 payment 模块 admin RPC（`admin_confirm/reject/list`）的写法一致，属模块内自洽，**非回归**。建议：若要统一收紧，可在后置清单记一条「admin 闸门统一叠加 profiles.status='active'」。

### O2 冷却过期仍显示「冷却至」+「复位冷却」

`PaymentRequestsPanel` `inCooldown = status==='rejected' && cooldownUntil != null`（L287）不区分是否已过期。冷却过期后 `cooldownUntil` 仍非空，后台仍显示「冷却至 <过去时间>」与「复位冷却」按钮。此时用户实际上已能重新申请（`begin` 的 `cooldown_until > now()` 不再命中），按钮只是清一个陈旧值、无害但误导。建议：前端改用 `new Date(r.cooldownUntil) > Date.now()` 判定有效冷却。

### O3 JWT 未 pin `iss`/`aud`

`verifyJwt` 用 `jwt.verify(token, secret, { algorithms:['HS256'] })`：`alg` 已锁定（关键）、`exp` 自动校验，但未显式校验 `iss`/`aud`。项目密钥独有、token 来自客户端 Supabase 会话，属可接受的防御纵深缺失。建议（可选）：补 `issuer`/`audience` 校验进一步收口。

### O4 `consume_translate_quota` 配置行缺失时「coalesce 兜底」不成立，且会反向破坏 fail-closed

`select coalesce(llm_per_user_limit,20), coalesce(llm_window_hours,1) into ... where id=true`：`coalesce` 只兜 NULL 列值，但列本身 `not null default`，实际兜不住「单行被删」的情况。若配置行缺失（当前无删除路径、迁移已 `insert ... on conflict do nothing` 播种，概率极低），`v_limit`/`v_window_hours` 为 NULL → `v_window_seconds` 为 NULL → 计数照常递增但不重置窗口 → 返回 `allowed = NULL`。此时 `translate.js` 的 `rl && rl.allowed === false` 判定为 false，**LLM 路径会放行而非 fail-closed**，与「fail-closed」意图相悖。建议：函数内补 `if not found then v_limit := 默认; v_window_hours := 默认; end if;`，使「兜底默认」名副其实。
