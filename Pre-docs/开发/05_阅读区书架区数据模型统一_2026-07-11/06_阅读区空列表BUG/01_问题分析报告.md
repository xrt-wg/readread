# 问题分析报告 — 阅读区列表空

- **日期**：2026-07-12
- **分支**：feat/unify-readings-model
- **问题**：阅读标签页中阅读区内容列表为空，无报错
- **严重程度**：P0 阻断
- **状态**：🔴 待修复

---

## 1. 现象

切换到「阅读」标签页，阅读区文章列表为空。控制台无任何红色报错。

---

## 2. 根因定位

### 2.1 直接原因

`ImportPage` 中 `listReadingZone()` 返回空数组，且错误被静默吞掉：

[ImportPage.jsx:246](src/components/ImportPage.jsx#L246)
```js
try { const zone = await listReadingZone({ canUseCloudLibrary, userId }); if (isActive) setReadingZoneItems(zone) } catch (_) {}
//                                                                                                       ^^^^^^^^
//                                                                                         任何错误都被静默吞掉
```

`listReadingZone` 查询 `readings` 表，条件为 `reading_status = 'reading'`：

[readings.js:237-243](src/services/readings.js#L237-L243)
```js
.from('readings')
.select(READING_COLUMNS)
.eq('user_id', options.userId)
.eq('reading_status', 'reading')
.is('deleted_at', null)
```

### 2.2 根本原因

`readings` 表和列均存在，`listReadingZone` 调用成功（已通过控制台手动调用验证），但返回空数组。数据验证：

```sql
SELECT reading_status, COUNT(*) FROM readings 
WHERE user_id = '3f0a83cd-40b6-4c55-93dc-2fc24aad95a6' AND deleted_at IS NULL 
GROUP BY reading_status;

-- reading_status | count
-- -------------- | -----
-- completed      | 4
-- in_progress    | 2
-- unread         | 8
-- (reading = 0)
```

14 条记录，0 条 `reading_status = 'reading'`。阅读区列表必然为空。

### 2.3 为什么迁移后没有 `reading` 状态的数据

[02_决策记录.md](02_决策记录.md) 定义了 `reading_status` 的状态机：

```
unread  →  reading     取书阅读
reading →  completed   标记读完
reading →  in_progress 中途放回
in_progress → reading  继续阅读
completed → reading    继续阅读
```

`reading` 是一个**瞬时状态**——表示用户当前正在阅读的内容。数据从 `articles` + `import_items` 迁移到 `readings` 时：

- 原书架素材（`import_items`）→ `unread` / `in_progress`
- 原已读完文章 → `completed`
- **没有任何内容被标记为 `reading`**——因为需要用户显式执行「取书」操作

旧模型中「阅读区 = 所有文章」，新模型中「阅读区 = `reading_status = 'reading'`」。迁移建立了正确的数据结构和初始状态，但未将旧文章的显示逻辑桥接到新模型——存量文章需要通过 UI 操作或数据脚本转入阅读区。

---

## 3. 证据链

| 步骤 | 发现 | 结论 |
|------|------|------|
| ① | 阅读区列表空，无报错 | `readingZoneItems` 为 `[]` 且未触发错误处理 |
| ② | `listReadingZone` 被 `catch (_) {}` 静默 | 失败不会暴露——但此处也未失败 |
| ③ | 控制台手动调用 `listReadingZone` 返回空数组 | 调用成功，数据层无异常 |
| ④ | SQL 查询 `reading_status` 分布：0 条 `reading` | 没有内容处于阅读状态 |
| ⑤ | 新模型：阅读区 = `WHERE reading_status = 'reading'` | 旧文章未被分配 `reading` 状态 |
| ⑥ | 迁移时 `reading` 是需用户操作触发的瞬时状态 | 存量数据必然为 0 |

---

## 4. 影响范围

阅读区是所有用户的核心入口。在新数据模型下，所有存量用户首次进入阅读区时均会看到空列表。

---

## 5. 完备性确认

- ✅ `readings` 表存在
- ✅ `reading_status` 列存在
- ✅ `listReadingZone` 调用成功无异常
- ✅ 数据完整性正常（14 条记录，分布合理）
- ✅ 根因与数据模型设计一致——`reading` 状态的设计意图即需用户主动触发

**结论：不是代码 bug，是数据模型迁移的后置步骤缺失——存量数据需要路径进入阅读区。**
