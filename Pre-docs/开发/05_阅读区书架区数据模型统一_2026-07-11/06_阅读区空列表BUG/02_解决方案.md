# 解决方案 — 阅读区列表空

- **日期**：2026-07-12
- **关联分析**：[01_问题分析报告.md](01_问题分析报告.md)

---

## 方案：初始化存量数据为"正在阅读"状态

### 核心思路

在新模型下，`reading_status = 'reading'` 是进入阅读区的门控条件。存量数据在迁移时被赋予了正确的初始状态（`unread` / `in_progress` / `completed`），但没有任何内容的初始状态为 `reading`。这与旧模型中"所有文章均在阅读区可见"的体验不一致。

**操作**：将书架中 `unread` 和 `in_progress` 的阅读内容批量转入阅读区。

---

### 实施

#### 数据库：新增 migration SQL

```sql
-- 将存量未读和进行中的内容批量转入阅读区
-- 仅处理 reading_status 不为 'reading' 且不为 'completed' 且未被删除的记录
update public.readings
set
  reading_status = 'reading',
  reading_started_at = coalesce(reading_started_at, timezone('utc', now())),
  updated_at = timezone('utc', now())
where reading_status in ('unread', 'in_progress')
  and deleted_at is null;
```

#### UI：无需更改

书架中已有「移入阅读区」操作（调用 `startReading`），未来新导入的内容通过此操作进入阅读区。迁移脚本仅处理此次存量数据的初始化。

---

### 有效性原理

| 之前 | 之后 |
|------|------|
| `readingStatus IN ('unread', 'in_progress')` → 书架可见，阅读区不可见 | `readingStatus = 'reading'` → 阅读区可见 |
| `listReadingZone()` → 空数组 → 空列表 | `listReadingZone()` → 10 条记录 → 列表正常 |
| 用户困惑"我的文章去哪了" | 文章在阅读区可见，体验与旧模型一致 |

### 设计一致性

此迁移不违反 [02_决策记录.md](02_决策记录.md) 的状态机设计：
- `unread` → `reading` 是合法转换（取书阅读）
- `in_progress` → `reading` 是合法转换（继续阅读）
- `completed` 不动——已读完的书保持在已完成状态

### 后续正常流程

迁移后，用户正常使用：
- 新导入 → `unread` → 书架可见 → 点击「移入阅读区」→ `reading`
- 阅读中 → 标记读完 → `completed` → 回到书架
- 阅读中 → 中途放回 → `in_progress` → 回到书架
- 重新阅读 → 点击「继续阅读」→ `reading`
