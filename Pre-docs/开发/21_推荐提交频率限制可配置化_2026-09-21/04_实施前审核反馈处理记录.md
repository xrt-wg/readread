**关键实现复核（超出文本一致性、核对到 SQL/PLpgSQL 语义）：**

- **M1**：`revoke` 仅作用于三个**新**函数，未误含 `submit_recommendation_for_review`（其 `create or replace` 保留原 grant，无需 revoke/重 grant）——作用域正确。
- **M2**：两处 `select submission_limit_days into v_limit_days ...; if not found then v_limit_days := 1; end if;` 中，`FOUND` 紧跟目标 `select`、无中间语句干扰，零行时正确置 1，fail-safe 成立。
- **H1**：`quota` 为 `null` 时，渲染条件 `quota && !quota.canSubmit` 为假、自然落到 `items.length === 0` 分支，降级路径与「仅列表、不做额度门控」描述一致，无安全缺口（后端提交校验仍为权威）。

### 复核中发现的其他小问题（非阻断，建议顺手统一，不阻塞实施）

1. `02` §二 数据模型表（L25）写 `updated_at ... NOT NULL DEFAULT now()`，与 §3.1 SQL（L56）的 `timezone('utc', now())` 措辞不一致——两者均生成 `timestamptz`（UTC），功能等价，可统一为 `timezone('utc', now())`。
